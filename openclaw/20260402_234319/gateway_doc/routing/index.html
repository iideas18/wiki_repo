Traffic Controller for OpenClaw

What Is This & Why Does It Exist?

Once a client is authenticated, its requests need to reach the right handler with the right session context. The Routing subsystem is the dispatcher that makes this happen.

💡 Real-world analogy

Think of Routing as a hotel concierge desk. The GatewayRequestHandlers map is the service directory — each RPC method name is a service (room service, spa, restaurant) and each GatewayRequestHandler is the staff member who fulfills it. GatewaySessionRow is the guest’s folio tracking everything from check-in time to room charges. resolveAssistantIdentity() assigns the personal butler (assistant) with the right name badge and uniform.

Code Examples

Defining a Request Handler

import { GatewayRequestHandler } from './server-methods/types';

const handleSessionsList: GatewayRequestHandler = async (opts) => {
  const { req, client, respond, context } = opts;
  const params = req.params as SessionsListParams;

  const result: SessionsListResult = await context.deps.sessionStore.list({
    limit: params.limit ?? 50,
    offset: params.offset ?? 0,
  });

  respond(true, result);
};

// Register in the handler map
const handlers: GatewayRequestHandlers = {
  'sessions.list': handleSessionsList,
  'sessions.send': handleSessionsSend,
  'config.get': handleConfigGet,
  // ... 80+ more methods
};

Resolving Assistant Identity

import {
  resolveAssistantIdentity,
  AssistantIdentity,
  DEFAULT_ASSISTANT_IDENTITY,
} from './assistant-identity';

const identity: AssistantIdentity = resolveAssistantIdentity({
  cfg: openClawConfig,
  agentId: 'main',
  workspaceDir: '/home/user/.openclaw',
});

// identity.name => "Assistant" (or custom name, max 50 chars)
// identity.avatar => "A" (or URL, max 200 chars)
// identity.emoji => undefined (or custom, max 16 chars)
