Infrastructure/caching/ — In-Memory State & Rate Limiting

In-memory caching, heartbeat coordination, and fixed-window rate limiting for OpenClaw services

The caching sub-module manages in-memory state maps, session-scoped event queues, heartbeat event coordination, and rate limiting. It prevents redundant work, deduplicates payloads, and protects external APIs from being overwhelmed by applying fixed-window rate limits with automatic retry-after computation.

📚 What is this & why does it exist?

The caching layer prevents redundant work and protects external APIs from being overwhelmed. Instead of hitting disk or network for every status check, the module maintains in-memory maps keyed by device ID or session key. Rate limiters use fixed-window algorithms that track consumption counts per time window, automatically computing retry-after delays. Heartbeat and system event buses coordinate ephemeral state across the application without persistent storage.

💡 Real-world analogy

Imagine a busy restaurant kitchen with a whiteboard (in-memory cache) near the door. Instead of walking to the storeroom every time to check ingredient stock, the chef glances at the whiteboard. The board has a timer—every 5 minutes the stock clerk wipes it clean and writes fresh counts. If too many orders come in at once, a bouncer (rate limiter) at the door tells new customers “please wait 30 seconds.” Meanwhile, a bell system (heartbeat events) lets the front-of-house know when the kitchen is alive and processing, while a ticket rail (system events) holds at most 20 active order slips per station to prevent overload.

Architecture

The caching sub-module is organized around three pillars: presence & state maps (system-presence), event buses (heartbeat-events, system-events), and rate control (fixed-window-rate-limit, retry-policy, dedupe). External callers interact through clean functional interfaces while internal state is managed via global singletons and scoped maps.

Code Examples

Example: Checking and Updating System Presence

import { getPresence, updatePresence } from "./system-presence";
import type { SystemPresence, SystemPresenceUpdate } from "./system-presence";

// Look up cached presence for a device
const current: SystemPresence | undefined = getPresence("device-abc-123");

if (!current) {
  // Self-presence initialization: hostname, IP, macOS model, version
  const entry: SystemPresence = {
    host: os.hostname(),
    ip: getLocalIP(),
    version: "2.4.1",
    platform: process.platform,
    deviceFamily: getMacModel(),
    lastInputSeconds: 0,
    mode: "active",
    deviceId: "device-abc-123",
    roles: ["editor"],
    scopes: ["read", "write"],
    instanceId: randomUUID(),
    text: "Online",
    ts: Date.now(),
  };

  // Stored with 5-min TTL, auto-evicted when map exceeds 200 entries
  const update: SystemPresenceUpdate = updatePresence("device-abc-123", entry);
  console.log("Changed fields:", update.changes);
}

Example: Subscribing to Heartbeat Events

import {
  emitHeartbeatEvent,
  onHeartbeatEvent,
  getLastHeartbeatEvent,
} from "./heartbeat-events";

// Subscribe — returns an unsubscribe function
const unsubscribe = onHeartbeatEvent((evt) => {
  console.log("Heartbeat received:", evt);
});

// Emit a heartbeat (broadcasts to all listeners via global singleton)
emitHeartbeatEvent({ ts: Date.now(), status: "alive" });

// Query the most recent event without subscribing
const last = getLastHeartbeatEvent();
console.log("Last heartbeat:", last?.ts);

// Cleanup
unsubscribe();

Example: Fixed-Window Rate Limiting with Retry

import { FixedWindowRateLimiter } from "./fixed-window-rate-limit";
import { createRateLimitRetryRunner } from "./retry-policy";

// Allow 100 requests per 60-second window
const limiter = new FixedWindowRateLimiter({
  maxRequests: 100,
  windowMs: 60_000,
});

const result = limiter.consume();
// result: { allowed: boolean, retryAfterMs: number, remaining: number }

if (result.allowed) {
  await fetch("https://api.example.com/data");
} else {
  console.warn(`Rate limited. Retry after ${result.retryAfterMs}ms`);
}

// Retry runner: 3 attempts, 400ms min, 30s max, 0.1 jitter
// Matches: /429|timeout|connect|reset|closed|unavailable|temporarily/i
const runner = createRateLimitRetryRunner({
  attempts: 3,
  minDelay: 400,
  maxDelay: 30_000,
  jitter: 0.1,
});

const response = await runner(() => fetch("https://api.example.com/send"));

Example: Pushing Session-Scoped System Events

import { pushSystemEvent, getSessionEvents } from "./system-events";
import type { SystemEvent } from "./system-events";

// Push an event into the session-scoped queue (max 20 per queue)
// Automatically deduplicates and emits to internal hooks
pushSystemEvent({
  text: "User connected",
  contextKey: "session-xyz",
  deliveryContext: "websocket",
  trusted: true,
});

// Retrieve events for a session
const events: SystemEvent[] = getSessionEvents("session-xyz");
events.forEach((e) => console.log(`[${e.ts}] ${e.text}`));
