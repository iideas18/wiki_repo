Infrastructure/store/ — Unified Persistence Layer

Atomic file I/O, sandboxed access, and multi-backend data storage

The store sub-module provides all data persistence for OpenClaw. It abstracts whether data lives in synchronous JSON files, async atomic JSON, or SQLite—exposing a unified API surface. Every write is atomic (UUID-temp-file → rename) to prevent corruption on crash, and sandboxed file operations prevent directory traversal and symlink attacks.

📚 What is this & why does it exist?

The store sub-module is OpenClaw’s unified persistence layer. It abstracts three storage backends (synchronous JSON, asynchronous atomic JSON, and SQLite) behind a consistent API so that callers never worry about file-level atomicity, locking, or path safety. Every write is staged to a temporary file first, then atomically renamed into place—meaning a crash mid-write can never leave corrupted data on disk. The sandboxed file operations (fs-safe.ts) add a security boundary that blocks directory traversal and symlink-following attacks.

💡 Real-world analogy

Think of the store like a bank vault with safety deposit boxes. Each box (JSON file) is opened with a key that’s been verified against a list of authorized paths. When you update the contents, a new box is prepared in a separate room (temp file), and only when it’s ready is it swapped into the main vault atomically—so no one ever sees a half-written box. The vault guard (fs-safe.ts) checks every access against a whitelist and refuses to follow redirects (symlinks) to unauthorized areas.

Architecture

The store follows an atomic write-ahead pattern: validate the target path → write to a PID-stamped temp file → rename into place. All file operations pass through boundary checks, symlink rejection, size limits, and finally the atomic commit.

Data Flow — Atomic Write Lifecycle

This sequence shows how an atomic write flows through the store, from the initial call to the final rename that makes the data visible.

sequenceDiagram
    participant Caller as Consumer Module
    participant Store as writeJsonAtomic()
    participant Lock as AsyncLock
    participant FS as fs-safe.ts
    participant Disk as Filesystem

    Caller->>Store: writeJsonAtomic(filePath, value)
    Store->>Lock: withLock(filePath)
    Lock-->>Store: Lock acquired
    Store->>FS: openFileWithinRoot(dir)
    FS->>FS: Validate path (no traversal)
    FS->>FS: Reject symlinks (O_NOFOLLOW)
    FS-->>Store: SafeOpenResult
    Store->>Disk: write ${filePath}.${pid}.tmp
    Disk-->>Store: Write complete
    Store->>Disk: fsync(fd)
    Disk-->>Store: Synced
    Store->>Disk: rename(tmp, filePath)
    Disk-->>Store: Atomic commit
    Store->>Lock: Release lock
    Lock-->>Caller: Resolved

Code Examples

Atomic JSON Write with Locking

import { writeJsonAtomic, createAsyncLock } from "./json-files";

const lock = createAsyncLock();

async function persistConfig(filePath: string, config: AppConfig): Promise<void> {
  await lock.withLock(async () => {
    await writeJsonAtomic(filePath, config, {
      mode: 0o600,
      mkdir: true,
    });
  });
}

Sandboxed File Read

import { readFileWithinRoot, SafeOpenErrorCode } from "./fs-safe";

async function loadUserFile(root: string, userPath: string): Promise<Buffer | null> {
  const result = await readFileWithinRoot(root, userPath);
  if (!result.ok) {
    switch (result.error) {
      case SafeOpenErrorCode.PATH_TRAVERSAL:
        throw new Error(`Blocked directory traversal: ${userPath}`);
      case SafeOpenErrorCode.SYMLINK:
        throw new Error(`Symlink not allowed: ${userPath}`);
      default:
        return null;
    }
  }
  return result.data;
}

Delivery Queue Lifecycle

import {
  enqueueDelivery,
  loadPendingDeliveries,
  ackDelivery,
  failDelivery,
  moveToFailed,
} from "./delivery-queue-storage";

const delivery: QueuedDelivery = {
  id: crypto.randomUUID(),
  channel: "whatsapp",
  to: "+1234567890",
  payloads: [{ type: "text", body: "Hello from OpenClaw" }],
  enqueuedAt: Date.now(),
  retryCount: 0,
};

await enqueueDelivery(stateDir, delivery);

const pending = await loadPendingDeliveries(stateDir);
for (const item of pending) {
  try {
    await sendMessage(item);
    await ackDelivery(stateDir, item.id);
  } catch (err) {
    await failDelivery(stateDir, item.id, err.message);
    if (item.retryCount >= MAX_RETRIES) {
      await moveToFailed(stateDir, item.id);
    }
  }
}

Device Auth Token Management

import {
  loadDeviceAuthToken,
  storeDeviceAuthToken,
  clearDeviceAuthToken,
} from "./device-auth-store";

// Load existing token (returns undefined if not found)
const auth = await loadDeviceAuthToken(stateDir);

if (!auth || isExpired(auth.tokens)) {
  const freshTokens = await refreshDeviceAuth(auth?.deviceId);
  await storeDeviceAuthToken(stateDir, {
    version: 1,
    deviceId: freshTokens.deviceId,
    tokens: freshTokens.tokens,
  });
}

// On logout, remove persisted credentials
await clearDeviceAuthToken(stateDir);
