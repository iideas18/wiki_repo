Heartbeats Graceful Restart Backoff & Retry Delivery Recovery

📚 What is this & why does it exist?

Scheduling orchestrates all time-dependent operations: periodic heartbeat messages, graceful process restarts, and delivery retry recovery. Without it, there would be no keepalive signals to channels, no way to restart without losing in-flight messages, and failed deliveries would be permanently lost.

💡 Real-world analogy

Think of scheduling like an airport control tower. The heartbeat runner is like the regular “all clear” radio check every few minutes. The restart controller is like coordinating a runway closure—you don’t shut it down until all planes in the air have landed (deferral polling). The delivery queue recovery is like re-routing delayed flights with increasing wait times between attempts.

Architecture

The scheduling sub-module is split into three pillars: heartbeat management (periodic keepalive signals), restart coordination (graceful process lifecycle), and delivery recovery (retry with backoff). Each pillar operates independently but shares common backoff and retry primitives.

Heartbeat Pipeline

The heartbeat system maintains channel liveness by periodically emitting keepalive signals. The pipeline resolves whether heartbeats are globally enabled, whether a specific agent should participate, calculates the interval, determines visibility rules, and finally emits a HeartbeatEventPayload.

heartbeat-runner.ts

The core heartbeat orchestrator at 250+ lines. Exports the HeartbeatDeps dependency type which composes OutboundSendDeps, ChannelHeartbeatDeps, and optional runtime hooks (runtime?, getQueueSize?, nowMs?). Key functions:

areHeartbeatsEnabled()booleanGlobal heartbeat kill switch
setHeartbeatsEnabled()voidToggle global heartbeat state
isHeartbeatEnabledForAgent(agentId)booleanPer-agent heartbeat gate
resolveHeartbeatIntervalMs(agentId, config)numberCompute interval in ms for a given agent
resolveHeartbeatSummaryForAgent(agentId)HeartbeatSummaryFull summary including reason, visibility, enabled flag

Restart Coordination

Graceful restart is critical for zero-downtime deployments. The restart subsystem ensures in-flight messages are drained before the process is replaced, supports three OS-specific restart methods, and enforces cooldown periods to prevent restart storms.

restart.ts

The restart controller at 500+ lines. Manages the full lifecycle from deferral to signal emission:

FunctionReturnsPurpose

emitGatewayRestart()voidEmit restart event for “emit” mode listeners
deferGatewayRestartUntilIdle(opts)ScheduledRestartWait for idle state before restarting (max 300s default)
scheduleGatewaySigusr1Restart(opts?)ScheduledRestartSchedule a SIGUSR1 restart with coalescing and cooldown
triggerOpenClawRestart()voidTop-level restart entry point

process-respawn.ts

restartGatewayProcessWithFreshPid() returns a GatewayRespawnResult with one of four modes:

ModeDescription
"spawned"New process launched directly
"supervised"Delegated to detected supervisor (launchd, systemd, schtasks)
"disabled"Respawn disabled via OPENCLAW_NO_RESPAWN environment variable
"failed"Respawn attempt failed; detail string explains why

supervisor-markers.ts

detectRespawnSupervisor(env, platform) inspects environment variables and the OS platform to detect if the process is managed by launchd (macOS), systemd (Linux), or schtasks (Windows). Returns RespawnSupervisor | null.

Delivery Recovery

When message delivery fails, the recovery subsystem retries with exponential backoff, filters out permanent errors, and produces a summary of outcomes.

delivery-queue-recovery.ts

Core recovery orchestrator with MAX_RETRIES=5 and a backoff schedule of [5s, 25s, 120s, 600s]. Includes 14 compiled regex patterns for permanent error detection.

FunctionReturnsPurpose
recoverPendingDeliveries(opts)RecoverySummaryMain entry point; iterates pending entries and retries eligible ones
computeBackoffMs()numberReturns delay in ms for current retry attempt
isPermanentDeliveryError()booleanTests error against 14 permanent error patterns
isEntryEligibleForRecoveryRetry()booleanChecks retry count, backoff, and error permanence

Code Examples

Example: Resolving Heartbeat Summary for an Agent

import {
  resolveHeartbeatSummaryForAgent,
  areHeartbeatsEnabled,
  setHeartbeatsEnabled,
  type HeartbeatSummary,
} from "./heartbeat-runner";

// Ensure heartbeats are globally enabled
if (!areHeartbeatsEnabled()) {
  setHeartbeatsEnabled(true);
}

// Resolve full summary for a specific agent
const summary: HeartbeatSummary = resolveHeartbeatSummaryForAgent("agent-42");
console.log(summary);
// {
//   intervalMs: 60000,
//   reason: "cron-event",
//   visibility: "silent",
//   enabled: true,
// }

Example: Scheduling a Graceful Restart with Deferral

import {
  setPreRestartDeferralCheck,
  deferGatewayRestartUntilIdle,
  scheduleGatewaySigusr1Restart,
  type ScheduledRestart,
} from "./restart";

// Register a deferral check that blocks restart while messages are in flight
setPreRestartDeferralCheck(() => {
  const queueSize = getQueueSize();
  return queueSize === 0; // only allow restart when idle
});

// Defer until idle, then restart via SIGUSR1
const result: ScheduledRestart = await deferGatewayRestartUntilIdle({
  maxWaitMs: 120_000,  // wait up to 2 minutes
  reason: "deployment",
});

console.log(result);
// {
//   ok: true,
//   pid: 48291,
//   signal: "SIGUSR1",
//   delayMs: 0,
//   reason: "deployment",
//   mode: "signal",
//   coalesced: false,
//   cooldownMsApplied: 30000,
// }

Example: Recovering Failed Deliveries with Backoff

import {
  recoverPendingDeliveries,
  isPermanentDeliveryError,
  computeBackoffMs,
  type RecoverySummary,
} from "./delivery-queue-recovery";
import { computeBackoff, type BackoffPolicy } from "./backoff";
import { retryAsync, type RetryConfig } from "./retry";

// Check if an error is permanent (won't benefit from retry)
const permanent = isPermanentDeliveryError(new Error("channel_not_found"));
// true — matches one of the 14 permanent error regex patterns

// Compute backoff for a specific attempt
const policy: BackoffPolicy = {
  initialMs: 5000,
  maxMs: 600_000,
  factor: 5,
  jitter: true,
};
const delayMs = computeBackoff(policy, 3); // ~625s + jitter

// Recover all pending deliveries
const summary: RecoverySummary = await recoverPendingDeliveries({
  maxRetries: 5,
  dryRun: false,
});
console.log(summary);
// {
//   recovered: 12,
//   failed: 2,
//   skippedMaxRetries: 1,
//   deferredBackoff: 3,
// }

// Generic retry wrapper for arbitrary async operations
const data = await retryAsync(
  () => fetchWithTimeout("/api/status", 5000),
  { attempts: 3, minDelayMs: 300, maxDelayMs: 30_000, jitter: true },
);
