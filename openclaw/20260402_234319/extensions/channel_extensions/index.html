Channel Extensions

Focus Deep-Dive

How messaging channel plugins connect users to the AI agent

Channel extensions implement the ChannelPlugin interface — a comprehensive adapter-based contract with 15+ pluggable adapters covering messaging, outbound delivery, security, threading, groups, gateway HTTP methods, and agent integration. Each channel (Telegram, Discord, Slack, etc.) composes the adapters it needs.

📚 What is this & why does it matter?

The ChannelPlugin interface is how OpenClaw bridges 20+ messaging platforms. Instead of writing platform-specific code throughout the core, each channel implements a set of adapter interfaces. The core sees uniform “send message,” “receive message,” and “check auth” operations — the channel adapter translates these into platform-specific API calls.

💡 Real-world analogy

Channel extensions are like interpreters at a multilingual conference. The speaker (agent engine) delivers one message. Each interpreter (channel extension) listens through the same headset (ChannelPlugin interface), then translates and delivers the message in the local language (Telegram Bot API, Discord REST, Slack Web API). They also listen for questions from the audience (inbound messages) and translate them back into the speaker’s language (normalized inbound events).

When an external platform sends a webhook (or the channel polls for updates), the gateway adapter receives the HTTP request, the messaging adapter normalizes it into an internal event, and the agent engine processes it. Responses flow back through the outbound adapter, which formats them for the specific platform.

The ChannelPlugin Interface

Core Structure

The ChannelPlugin type is a generic interface with 15+ optional adapter slots. Only id, meta, capabilities, and config are required:

type ChannelPlugin<ResolvedAccount = any, Probe = unknown, Audit = unknown> = {
  // Identity
  id: ChannelId;
  meta: ChannelMeta;
  capabilities: ChannelCapabilities;

  // Configuration (required)
  config: ChannelConfigAdapter<ResolvedAccount>;
  configSchema?: ChannelConfigSchema;

  // Setup & Pairing
  setup?: ChannelSetupAdapter;
  setupWizard?: ChannelPluginSetupWizard;
  pairing?: ChannelPairingAdapter;

  // Security & Access Control
  security?: ChannelSecurityAdapter<ResolvedAccount>;
  approvals?: ChannelApprovalAdapter;
  allowlist?: ChannelAllowlistAdapter;

  // Messaging (inbound & outbound)
  messaging?: ChannelMessagingAdapter;
  outbound?: ChannelOutboundAdapter;

  // Groups & Threading
  groups?: ChannelGroupAdapter;
  threading?: ChannelThreadingAdapter;

  // Gateway & HTTP
  gateway?: ChannelGatewayAdapter<ResolvedAccount>;
  gatewayMethods?: string[];

  // Status & Health
  status?: ChannelStatusAdapter<ResolvedAccount, Probe, Audit>;
  heartbeat?: ChannelHeartbeatAdapter;

  // Additional Adapters
  auth?: ChannelAuthAdapter;
  mentions?: ChannelMentionAdapter;
  elevated?: ChannelElevatedAdapter;
  commands?: ChannelCommandAdapter;
  lifecycle?: ChannelLifecycleAdapter;
  streaming?: ChannelStreamingAdapter;
  directory?: ChannelDirectoryAdapter;
  resolver?: ChannelResolverAdapter;
  actions?: ChannelMessageActionAdapter;

  // Agent Integration
  agentPrompt?: ChannelAgentPromptAdapter;
  agentTools?: ChannelAgentToolFactory | ChannelAgentTool[];

  // Reload
  reload?: { configPrefixes: string[]; noopPrefixes?: string[] };
  defaults?: { queue?: { debounceMs?: number } };
};

Channel Metadata

The meta object provides user-facing information for the channel selection UI, setup wizards, and documentation links:

type ChannelMeta = {
  id: ChannelId;
  label: string;                    // "Telegram"
  selectionLabel: string;           // "Telegram Bot"
  docsPath: string;                 // "/channels/telegram"
  blurb: string;                    // One-line description
  order?: number;                   // Sort order in UI lists
  aliases?: readonly string[];      // Alternative names for matching
  markdownCapable?: boolean;        // Whether the platform renders Markdown
  showConfigured?: boolean;         // Show a "configured" badge in UI
  quickstartAllowFrom?: boolean;    // Allow in quickstart wizard
  systemImage?: string;             // Platform icon identifier
};

Capabilities Declaration

The capabilities object tells the core which features this channel supports, preventing the agent from attempting unsupported operations:

type ChannelCapabilities = {
  chatTypes: Array<ChatType | "thread">;  // "direct", "group", "channel", "thread"
  polls?: boolean;
  reactions?: boolean;
  edit?: boolean;              // Can edit sent messages
  unsend?: boolean;            // Can delete sent messages
  reply?: boolean;             // Can reply to specific messages
  effects?: boolean;           // Visual effects (confetti, etc.)
  groupManagement?: boolean;   // Can manage group membership
  threads?: boolean;           // Supports threaded conversations
  media?: boolean;             // Supports image/video/audio
  nativeCommands?: boolean;    // Supports platform-native slash commands
  blockStreaming?: boolean;    // Disable streaming for this channel
};
Key detail: The capabilities object is checked before every agent action. If a channel sets threads: false, the agent will never attempt to create a thread even if the user asks for one.

Adapters form a pipeline: inbound webhooks flow through the gateway, security, and messaging adapters before reaching the agent. Outbound responses flow through the outbound, threading, and streaming adapters before reaching the platform API.

Annotated Code Walkthrough

Build a minimal channel extension step by step:

Define the channel plugin with metadata, capabilities, and the config adapter:

// extensions/my-channel/src/channel.ts
import type { ChannelPlugin, ChannelCapabilities, ChannelMeta } from "openclaw/plugin-sdk/core";

const meta: ChannelMeta = {
  id: "my-channel",
  label: "My Channel",
  selectionLabel: "My Channel Bot",
  docsPath: "/channels/my-channel",
  blurb: "Connect to My Channel messaging platform",
  markdownCapable: true,
};

const capabilities: ChannelCapabilities = {
  chatTypes: ["direct", "group"],
  reactions: true,
  edit: true,
  reply: true,
  threads: false,
  media: true,
};

export const myChannelPlugin: ChannelPlugin = {
  id: "my-channel",
  meta,
  capabilities,
  config: {
    resolve: (rawConfig) => ({
      botToken: rawConfig.myChannelBotToken,
      webhookUrl: rawConfig.myChannelWebhookUrl,
    }),
    validate: (resolved) => {
      if (!resolved.botToken) return { valid: false, error: "Bot token required" };
      return { valid: true };
    },
  },
};

Add the gateway adapter to handle inbound webhooks from the platform:

// extensions/my-channel/src/channel.ts (continued)
myChannelPlugin.gateway = {
  methods: ["POST"],
  handle: async (req, account) => {
    const body = await req.json();
    const event = normalizeInboundEvent(body);

    if (event.type === "message") {
      return {
        kind: "message",
        from: event.senderId,
        text: event.text,
        chatId: event.chatId,
        chatType: event.isGroup ? "group" : "direct",
      };
    }
    return { kind: "ignored" };
  },
};

myChannelPlugin.gatewayMethods = ["my-channel-webhook"];
Security note: Always validate webhook signatures in the gateway adapter. Unsigned webhooks allow message injection attacks.

Add the outbound adapter to send agent responses back to the platform:

// extensions/my-channel/src/channel.ts (continued)
myChannelPlugin.outbound = {
  send: async (ctx) => {
    const { account, target, message } = ctx;
    const response = await fetch(`https://api.mychannel.com/sendMessage`, {
      method: "POST",
      headers: {
        "Authorization": `Bearer ${account.botToken}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        chat_id: target.id,
        text: message.text,
        reply_to: message.replyTo ?? undefined,
      }),
    });
    return { success: response.ok, messageId: (await response.json()).id };
  },
};

Register the channel via defineChannelPluginEntry():

// extensions/my-channel/index.ts
import { defineChannelPluginEntry } from "openclaw/plugin-sdk/core";
import { myChannelPlugin } from "./src/channel.js";

export default defineChannelPluginEntry({
  id: "my-channel",
  name: "My Channel",
  description: "My Channel messaging integration",
  plugin: myChannelPlugin,
});

Real-World: Telegram Channel

The Telegram extension is one of the most feature-complete channels. Its api.ts barrel exports 25+ modules covering every aspect of the Telegram Bot API:

// extensions/telegram/api.ts (representative exports)
export * from "./src/accounts.js";           // Account management
export * from "./src/action-threading.js";   // Thread/reply handling
export * from "./src/allow-from.js";         // Allowlist configuration
export * from "./src/api-fetch.js";          // Telegram API HTTP client
export * from "./src/exec-approvals.js";     // Tool execution approval via DM
export * from "./src/group-policy.js";       // Group participation rules
export * from "./src/inline-buttons.js";     // Inline keyboard buttons
export * from "./src/model-buttons.js";      // Model selection buttons
export * from "./src/outbound-adapter.js";   // Message sending
export * from "./src/sticker-cache.js";      // Sticker metadata caching
export * from "./src/targets.js";            // Chat/user target resolution
export * from "./src/update-offset-store.js"; // Long-polling offset tracking
Pattern to follow: Telegram’s modular structure (one file per concern, barrel export in api.ts) is the recommended pattern for complex channel extensions with many features.
