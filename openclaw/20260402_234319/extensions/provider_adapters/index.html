Provider Adapters

Focus Deep-Dive

How AI provider extensions connect models to the agent engine

Provider adapters implement the ProviderPlugin interface — a rich contract covering authentication, model discovery, transport normalization, stream processing, and capability declaration. Each provider extension (OpenAI, Anthropic, Ollama, etc.) builds one or more ProviderPlugin objects and registers them via api.registerProvider().

📚 What is this & why does it matter?

The ProviderPlugin interface is the abstraction layer that lets OpenClaw talk to any LLM — cloud-hosted or self-hosted — through a uniform streaming interface. Without it, adding a new AI model backend would require rewriting the agent engine. With it, you implement a handful of methods (auth, model resolution, transport normalization) and the engine handles the rest.

💡 Real-world analogy

Provider adapters are like power adapters for international travel. Every country (AI vendor) has a different plug shape (API format) and voltage (auth scheme). The adapter translates your device’s power needs (agent engine’s streaming interface) into the local standard. The agent engine doesn’t care whether it’s plugged into a 110V US outlet (OpenAI) or a 220V EU outlet (Anthropic) — the adapter handles conversion.

How It Works

The ProviderPlugin Interface

The ProviderPlugin type defines 25+ optional methods. Only id, label, and auth are required — everything else has sensible defaults:

type ProviderPlugin = {
  // Identity
  id: string;                    // Unique provider ID (e.g., "openai")
  label: string;                 // Display name (e.g., "OpenAI")
  docsPath?: string;             // Path to documentation
  envVars?: string[];            // Expected env vars (e.g., ["OPENAI_API_KEY"])

  // Authentication
  auth: ProviderAuthMethod[];    // Ordered list of auth strategies

  // Model Discovery
  catalog?: ProviderPluginCatalog;
  resolveDynamicModel?: (ctx) => ProviderRuntimeModel | null;
  augmentModelCatalog?: (ctx) => ModelCatalogEntry[];

  // Transport
  normalizeTransport?: (ctx) => { api?: string; baseUrl?: string } | null;
  normalizeResolvedModel?: (ctx) => ProviderRuntimeModel | null;
  normalizeConfig?: (ctx) => ModelProviderConfig | null;

  // Streaming
  createStreamFn?: (ctx) => StreamFn | null;
  wrapStreamFn?: (ctx) => StreamFn | null;

  // Capabilities
  capabilities?: Partial<ProviderCapabilities>;
  supportsXHighThinking?: (ctx) => boolean;
  resolveDefaultThinkingLevel?: (ctx) => ThinkingLevel | null;

  // Usage & Billing
  resolveUsageAuth?: (ctx) => Promise<ProviderResolvedUsageAuth>;
  fetchUsageSnapshot?: (ctx) => Promise<ProviderUsageSnapshot>;

  // Error Messages
  buildMissingAuthMessage?: (ctx) => string | null;
  buildUnknownModelHint?: (ctx) => string | null;
};

Authentication Chain

Each provider declares one or more ProviderAuthMethod objects. The auth resolver tries them in order, returning the first that succeeds (API key present, OAuth token valid, etc.):

// From extensions/openai/openai-provider.ts
auth: [
  createProviderApiKeyAuthMethod({
    providerId: "openai",
    methodId: "api-key",
    label: "OpenAI API key",
    hint: "Direct OpenAI API key",
    optionKey: "openaiApiKey",
    flagName: "--openai-api-key",
    envVar: "OPENAI_API_KEY",
    promptMessage: "Enter OpenAI API key",
    defaultModel: "gpt-5.4",
    expectedProviders: ["openai"],
    applyConfig: (cfg) => applyOpenAIConfig(cfg),
    wizard: {
      title: "OpenAI Setup",
      steps: [/* interactive setup steps */],
    },
  }),
],
Key detail: The createProviderApiKeyAuthMethod helper generates a full auth method from a declarative config. It handles env var lookup, CLI flag parsing, config file resolution, interactive prompts, and setup wizard rendering.

Stream Processing

The streaming pipeline supports two extension points: createStreamFn (replace the entire stream) and wrapStreamFn (wrap the default stream with middleware):

// From extensions/openai/openai-provider.ts
wrapStreamFn: (ctx) => {
  return createOpenAIAttributionHeadersWrapper({
    innerStream: ctx.defaultStreamFn,
    modelId: ctx.model.id,
    providerFamily: "openai",
  });
},
Performance note: wrapStreamFn is preferred over createStreamFn when you only need to add headers or logging. It preserves the default streaming implementation and avoids re-implementing SSE parsing.

  Resolver->>Provider: resolveDynamicModel()
  Provider-->>Resolver: ProviderRuntimeModel
  Resolver->>Auth: prepareRuntimeAuth()
  Auth-->>Resolver: API key + headers
  Resolver->>Provider: normalizeTransport()
  Provider-->>Resolver: { baseUrl, api }
  Resolver->>Provider: wrapStreamFn()
  Provider-->>Resolver: Wrapped StreamFn
  Agent->>API: POST /v1/chat/completions (streaming)
  API-->>Agent: SSE token stream

The entire lifecycle from model selection to first token is typically under 100ms of local processing. Network latency to the vendor API dominates the total time-to-first-token.

Annotated Code Walkthrough

Walk through building a complete provider extension from scratch:

Define the provider metadata and auth chain. The id must be unique across all providers:

// extensions/my-provider/my-provider.ts
import { createProviderApiKeyAuthMethod } from "openclaw/plugin-sdk/core";
import type { ProviderPlugin } from "openclaw/plugin-sdk/core";

const PROVIDER_ID = "my-provider";

export function buildMyProvider(): ProviderPlugin {
  return {
    id: PROVIDER_ID,
    label: "My Provider",
    docsPath: "/providers/my-provider",
    envVars: ["MY_PROVIDER_API_KEY"],

    auth: [
      createProviderApiKeyAuthMethod({
        providerId: PROVIDER_ID,
        methodId: "api-key",
        label: "My Provider API key",
        envVar: "MY_PROVIDER_API_KEY",
        flagName: "--my-provider-api-key",
        defaultModel: "my-model-v1",
        expectedProviders: [PROVIDER_ID],
        applyConfig: (cfg) => ({
          ...cfg,
          baseUrl: "https://api.myprovider.com/v1",
        }),
      }),
    ],
  };
}

Add model catalog and dynamic resolution for forward compatibility with new models:

// Continue in my-provider.ts
export function buildMyProvider(): ProviderPlugin {
  return {
    // ... id, label, auth from Step 1 ...

    catalog: {
      models: [
        { id: "my-model-v1", label: "My Model v1", contextWindow: 128000 },
        { id: "my-model-v2", label: "My Model v2", contextWindow: 256000 },
      ],
    },

    resolveDynamicModel: (ctx) => {
      // Accept any model prefixed with "my-model-"
      if (ctx.modelId.startsWith("my-model-")) {
        return {
          id: ctx.modelId,
          label: ctx.modelId,
          provider: PROVIDER_ID,
        };
      }
      return null;
    },

    normalizeTransport: ({ provider, api, baseUrl }) => ({
      api: api ?? "openai",  // Use OpenAI-compatible API format
      baseUrl: baseUrl ?? "https://api.myprovider.com/v1",
    }),

    capabilities: { providerFamily: "openai" },
  };
}
Compatibility tip: Setting api: "openai" in normalizeTransport tells the engine to use the OpenAI-compatible chat completions format. Most providers support this, making integration trivial.

Register the provider in the extension entry point:

// extensions/my-provider/index.ts
import { definePluginEntry } from "openclaw/plugin-sdk/plugin-entry";
import { buildMyProvider } from "./my-provider.js";

export default definePluginEntry({
  id: "my-provider",
  name: "My Provider",
  description: "Custom LLM provider integration",
  register(api) {
    api.registerProvider(buildMyProvider());
  },
});

ScenarioBehaviorCode Location
No auth method succeedsbuildMissingAuthMessage() generates a user-friendly error with setup instructionsopenai-provider.ts
Unknown model ID requestedresolveDynamicModel() returns null; buildUnknownModelHint() suggests similar modelsProvider resolver
Vendor API returns 429 (rate limit)buildReplayPolicy() defines retry intervals with exponential backoffStream wrapper
Model deprecated by vendorsuppressBuiltInModel() hides it from catalog; augmentModelCatalog() adds replacementProvider plugin

Stream connection drops mid-responseEngine retries with partial context if buildReplayPolicy() permitsAgent engine
