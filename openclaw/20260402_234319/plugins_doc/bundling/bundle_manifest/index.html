Bundle Manifest

Deep Dive

Multi-format manifest detection, loading, and normalization

The bundle manifest system detects plugin descriptor files across three competing format conventions — Codex, Claude, and Cursor — reads their JSON manifests, and normalizes them into a single BundlePluginManifest type so the rest of the plugin pipeline can work with one consistent shape.

📚 What is this & why does it matter?

The Bundle Manifest module is the entry gate for every bundled plugin. Before OpenClaw can load a plugin’s commands, capabilities, or MCP servers, it first needs to read the plugin’s self-description: its ID, name, version, and the lists of files it provides. Because different AI-assistant ecosystems invented their own manifest formats, this module acts as a universal adapter that reads any of them and produces one normalized shape.

💡 Real-world analogy

Imagine an airport customs desk that accepts passports from three different countries, each with a different layout. The customs officer (Bundle Manifest) doesn’t need to know the quirks of each passport format — they extract the same core fields (name, nationality, photo) into a standard entry form. Downstream systems (border control, airline check-in) only ever see the normalized form.

The loader follows a strict probe order: it checks for format-specific directories inside the plugin root, reads the JSON manifest from the first match, then normalizes every field into the unified BundlePluginManifest shape that downstream consumers expect.

How It Works

Step 1 — Format Detection

detectBundleManifestFormat() probes the plugin root directory for well-known format marker directories. It returns the first matching BundleManifestFormat enum value, or undefined if no format is found.

// Probe order mirrors priority: Codex > Claude > Cursor
const FORMAT_MARKERS: Record<BundleManifestFormat, string> = {
  codex:  ".codex-plugin",
  claude: ".claude-plugin",
  cursor: ".cursor-plugin",
};

function detectBundleManifestFormat(
  rootDir: string
): BundleManifestFormat | undefined {
  for (const [fmt, dir] of Object.entries(FORMAT_MARKERS)) {
    if (existsSync(join(rootDir, dir, "manifest.json"))) {
      return fmt as BundleManifestFormat;
    }
  }
  return undefined;
}
Key detail: Detection checks for the manifest file inside the marker directory, not just the directory itself. A stale .codex-plugin/ folder with no manifest.json is correctly skipped.

Step 2 — Secure File Reading

Once a format is detected, the manifest JSON is read through openBoundaryFileSync(), which enforces a security boundary: the resolved path must remain inside the plugin root. Symlinks that escape are rejected.

Step 3 — JSON Parsing

The raw file content is parsed with JSON5 to tolerate trailing commas, single-quoted strings, and comments that some plugin authors include in their manifests.

Step 4 — Field Normalization

Core fields (id, name, description, version) are extracted directly. Path list fields (skills[], hooks[], capabilities[]) go through normalizeBundlePathList() which resolves relative paths, removes duplicates via mergeBundlePathLists(), and validates that each entry points to a real file.

Step 5 — Result Assembly

The function returns a BundleManifestLoadResult — a discriminated union of { ok: true, manifest } or { ok: false, error }.

Annotated Code Walkthrough

Trace through the full loadBundleManifest() pipeline from directory input to normalized result:

Detect which bundle format the plugin uses by probing for marker directories:

export function loadBundleManifest(
  rootDir: string
): BundleManifestLoadResult {
  const format = detectBundleManifestFormat(rootDir);
  if (!format) {
    return { ok: false, error: "no-manifest-format" };
  }

Resolve the manifest file path and read it through the security boundary checker:

  const manifestPath = join(
    rootDir,
    FORMAT_MARKERS[format],
    "manifest.json"
  );
  const raw = openBoundaryFileSync(rootDir, manifestPath);
  if (!raw.ok) {
    return { ok: false, error: "boundary-violation" };
  }
Security: openBoundaryFileSync() resolves symlinks and rejects any path that escapes rootDir. This prevents a malicious plugin from reading files outside its own directory.

Parse the JSON content with JSON5 for lenient formatting support:

  let parsed: unknown;
  try {
    parsed = JSON5.parse(raw.content);
  } catch (e) {
    return { ok: false, error: "invalid-json" };
  }

Extract core identity fields from the parsed manifest object:

  const obj = parsed as Record<string, unknown>;
  const id = typeof obj.id === "string" ? obj.id : undefined;
  const name = typeof obj.name === "string" ? obj.name : id;
  const description = typeof obj.description === "string"
    ? obj.description : undefined;
  const version = typeof obj.version === "string"
    ? obj.version : "0.0.0";

Normalize path lists, deduplicating entries and resolving relative paths:

  const skills = normalizeBundlePathList(rootDir, obj.skills);
  const hooks = normalizeBundlePathList(rootDir, obj.hooks);
  const capabilities = mergeBundlePathLists(
    normalizeBundlePathList(rootDir, obj.capabilities),
    normalizeBundlePathList(rootDir, obj.inlineCapabilities)
  );
Deduplication: mergeBundlePathLists() uses a Set internally, so overlapping entries in capabilities and inlineCapabilities are merged cleanly.

Assemble the normalized manifest and return the success result:

  return {
    ok: true,
    manifest: {
      format,
      id: id ?? path.basename(rootDir),
      name: name ?? id ?? path.basename(rootDir),
      description,
      version,
      skills,
      hooks,
      capabilities,
    },
  };
}
