📚 What is this & why does it exist?

The Plugin SDK (src/plugin-sdk/) is the public API surface that plugin developers use to build extensions. It provides typed interfaces for every extensibility point: channels, providers, memory engines, tools, hooks, commands, and services. The SDK follows a re-export architecture — it wraps internal modules into a clean, stable API boundary so that plugin authors don’t depend on internal file paths. The entry point (index.ts) deliberately keeps a tiny surface; specialized concerns live on dedicated subpaths like openclaw/plugin-sdk/channel-runtime or openclaw/plugin-sdk/provider-auth.

💡 Real-world analogy

The Plugin SDK is like a hardware manufacturer’s development kit (HDK). The internal modules are the raw circuit boards and chips; the SDK packages them into a clean breadboard with labeled pins. Plugin developers plug into the labeled pins (typed interfaces) without needing to understand the internal wiring. The re-export architecture ensures that if the internal wiring changes, the pin labels stay the same.

Code Examples

Example: Registering a Channel Plugin

// Plugin SDK usage — registering a channel plugin
import type { OpenClawPluginDefinition } from "openclaw/plugin-sdk";
import type { ChannelPlugin } from "openclaw/plugin-sdk/channel-runtime";

const myChannelPlugin: ChannelPlugin = {
  channelId: "my-channel",
  displayName: "My Channel",
  messaging: {
    async sendMessage(ctx, payload) {
      await myChannelApi.send(ctx.target, payload.text);
      return { delivered: true };
    },
  },
  inbound: {
    async handleWebhook(req, res) {
      const event = parseWebhookEvent(req);
      return { channelId: "my-channel", message: event.text };
    },
  },
};

export default {
  register(api) {
    api.registerChannel(myChannelPlugin);
    api.logger.info("My channel plugin registered");
  },
} satisfies OpenClawPluginDefinition;
