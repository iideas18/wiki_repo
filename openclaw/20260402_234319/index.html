OpenClaw

Personal AI Assistant Platform

OpenClaw is a self-hosted, multi-channel AI assistant that runs on your own devices. It connects to 25+ messaging platforms (WhatsApp, Telegram, Slack, Discord, Signal, iMessage, and more), orchestrates LLM-powered conversations with tool use, and supports an extensible plugin ecosystem. The gateway is the control plane — the product is the assistant.

🐚 TypeScript / Node.js 💬 25+ Channels 🔌 70+ Extensions 🤖 Multi-Model LLM

📚 What is this & why does it exist?

OpenClaw is an open-source personal AI assistant that you run on your own hardware. Unlike cloud-only assistants, OpenClaw gives you full control over your data, model providers, and integrations. It acts as a gateway between the messaging platforms you already use and any LLM provider, turning every chat app into an intelligent assistant interface.

💡 Real-world analogy

Think of OpenClaw as a multilingual personal secretary who sits at a reception desk with 25 phone lines. Each phone line connects to a different communication channel (WhatsApp, Slack, Discord, etc.). When a message comes in on any line, the secretary understands the context, consults the right expert (LLM provider), uses available tools (web search, image generation, MCP servers), and responds in the caller's language and format. You control which experts the secretary consults and what tools are available.

Core Engine

Agents

LLM orchestration, streaming, tool use, and multi-model reasoning

The execution engine of OpenClaw. Manages agent lifecycles, streams LLM responses, handles tool calls (function calling, MCP), patches, sandboxed code execution, and provider-specific adapters for OpenAI, Anthropic, Google, and 15+ more.

1,083 TS filesMulti-providerStreaming

Gateway

Control plane: authentication, boot, routing, and session management

The central multiplexing server that handles client pairing, authentication, rate limiting, message routing, and Android/iOS node capability negotiation. Coordinates all other modules during startup.

441 TS filesAuth + Rate LimitBoot Orchestration

Commands

Slash commands, admin tools, and natural-language command processing

Parses and dispatches user commands (/model, /image, /search, /admin), manages command aliases, permission gating, and provider-switching workflows.

Provides the common interface for 25+ messaging platforms. Handles message normalization, allowlists, command gating, reaction acknowledgment, and channel-specific configuration (presence, chat types, media).

Message Flow: Channel to Agent

This sequence shows the complete lifecycle of an incoming user message, from arrival on a messaging channel through to the AI-generated response.

sequenceDiagram
    participant User as User (WhatsApp/Telegram/...)
    participant Ch as Channel Extension
    participant GW as Gateway Router
    participant Cmd as Command Processor
    participant Agent as Agent Orchestrator
    participant LLM as LLM Provider
    participant Tool as Tool / MCP Server

    User->>Ch: Send message
    Ch->>GW: Normalized message (ChatMeta)
    GW->>GW: Auth check + rate limit
    GW->>Cmd: Route to command processor
    Note over Cmd: Check for slash command prefix
    alt Slash command (e.g. /model)
        Cmd->>Cmd: Execute command handler
        Cmd-->>Ch: Command response
    else Natural language
        Cmd->>Agent: Forward to agent
        Agent->>Agent: Build context (history + system prompt)
        Agent->>LLM: Stream request (OpenAI/Anthropic/...)
        loop Streaming tokens
            LLM-->>Agent: Token chunk
            Agent-->>Ch: Forward chunk to user
        end
        opt Tool call requested
            Agent->>Tool: Execute tool (MCP/function)
            Tool-->>Agent: Tool result
            Agent->>LLM: Continue with tool result
            LLM-->>Agent: Final response
        end
        Agent-->>Ch: Complete response
    end
    Ch-->>User: Deliver response
Key insight: The Gateway owns authentication and routing. The Channel layer normalizes platform-specific messages into a unified format. The Agent orchestrator manages the LLM conversation lifecycle including streaming, tool use, and multi-turn context. Extensions implement the actual provider and channel connections.

Build & Tech Stack

Docker, Fly.io, Render, self-hosted Node.js, Podman

Testing

Vitest with separate configs for unit, e2e, channels, contracts, extensions, gateway, live
