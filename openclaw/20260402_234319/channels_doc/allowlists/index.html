Channels/Allowlists — Access Control Engine

Pattern-Based Sender Filtering & Command Authorization

The Allowlists sub-module controls who can interact with the OpenClaw agent. It compiles sender identity patterns into fast lookup sets, resolves DM and group allowFrom sources, gates slash commands behind access groups, and enforces mention requirements in group chats.

📚 What is this & why does it matter?

Without access control, any user on any platform could invoke the agent and run arbitrary commands. The allowlists sub-module is the gatekeeper — it decides, for every inbound message, whether the sender is authorized and what level of access they have.

💡 Real-world analogy

Think of a nightclub with a guest list. The bouncer (allowlist engine) has a compiled list of VIP names. When someone arrives, the bouncer checks their ID (sender identity candidates) against the list. A wildcard * entry means “everyone gets in.” For the VIP lounge (slash commands), there’s an additional access check (command gating). In group settings, the bouncer also checks if the guest called out the club owner by name (mention gating).

Allowlist Matching Pipeline

The core matching function accepts a compiled allowlist and an ordered array of identity candidates. Each candidate has a value (the identifier string) and a source (how it was derived). The engine checks candidates in order; the first match wins.

Compilation

export function compileAllowlist(entries: ReadonlyArray<string>): CompiledAllowlist {
  const set = new Set(entries.filter(Boolean));
  return {
    set,
    wildcard: set.has("*"),
  };
}

export function mergeDmAllowFromSources(params: {
  allowFrom?: Array<string | number>;
  storeAllowFrom?: Array<string | number>;
  dmPolicy?: string;
}): string[] {
  const storeEntries = params.dmPolicy === "allowlist" ? [] : (params.storeAllowFrom ?? []);
  return [...(params.allowFrom ?? []), ...storeEntries]
    .map((value) => String(value).trim())
    .filter(Boolean);
}

Mention Gating

In group chats, the agent can require an @mention before processing. The system handles implicit mentions, bypass rules (authorized control commands), and detection capability flags.

export function resolveMentionGating(params: MentionGateParams): MentionGateResult {
  const implicit = params.implicitMention === true;
  const bypass = params.shouldBypassMention === true;
  const effectiveWasMentioned = params.wasMentioned || implicit || bypass;
  const shouldSkip = params.requireMention && params.canDetectMention && !effectiveWasMentioned;
  return { effectiveWasMentioned, shouldSkip };
}
