DM, Group & Channel Type Normalization

The chat type system normalizes platform-specific conversation type strings into a canonical three-value union. This normalization drives routing decisions, mention gating behavior, and allowlist context selection throughout the channels module.

3 Types Normalization Routing Driver Input Validation

📚 What is this & why does it matter?

Different platforms call the same thing different names: Telegram has “private” chats, Slack has “DMs,” Discord has “direct messages.” The chat type normalizer ensures the rest of the codebase only ever deals with three values: direct, group, or channel.

💡 Real-world analogy

Think of international shoe sizing. A US 10, UK 9, and EU 44 all mean the same shoe size. The normalizer converts every platform’s “sizing system” into one standard, so the warehouse (routing engine) only needs one shelf labeling system.

Contents

Type Definition

export type ChatType = "direct" | "group" | "channel";

Normalization Function

export function normalizeChatType(raw?: string): ChatType | undefined {
  const value = raw?.trim().toLowerCase();
  if (!value) return undefined;
  if (value === "direct" || value === "dm") return "direct";
  if (value === "group") return "group";
  if (value === "channel") return "channel";
  return undefined;
}

Thread vs. Chat Type

Note that "thread" is not a ChatType — it is handled by the ChannelCapabilities.chatTypes array, which can include "thread" alongside the standard types. Thread binding is managed separately by the thread binding system.
