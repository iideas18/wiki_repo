Command Parsing

Focus Deep-Dive

Extracting structured actions from raw user slash-command input

When a user types /model set gpt-4 or a plugin defines /tts, the command parsing layer is the first code that touches the raw text. It validates the slash prefix, extracts the action keyword and trailing arguments, and returns a strongly-typed discriminated union that downstream dispatchers can pattern-match without ever touching raw strings again.

📚 What is this & why does it matter?

Command parsing is the gateway between free-form user text and the type-safe command dispatch pipeline. Every slash command — whether built-in or provided by a plugin — passes through this layer before any business logic runs. Understanding this module is essential for debugging "command not found" errors, building new slash commands, or tracing why a particular input was routed to the agent instead of a command handler.

💡 Real-world analogy

Think of a restaurant maître d'. A guest walks in and says "table for two, near the window." The maître d' parses this into a structured request — party size: 2, preference: window — and routes it to the seating system. If the guest mumbles something unintelligible, the maître d' returns "invalid request" without bothering the kitchen. The command parser is that maître d' for every slash command.

Overview

Primary role

Parse raw user messages into structured SlashCommandParseResult discriminated unions with action and argument fields.

Main inputs

Raw message strings from any channel surface (Telegram, Discord, WebChat) plus the configured slash prefix (e.g. /).

Key decisions

Does the message start with the slash prefix? Is it empty after the prefix? Can we extract a valid action keyword?

Outputs / side effects

A SlashCommandParseResult — one of "no-match", "empty", "invalid", or "parsed" with action and args fields. No side effects.

Core Types

The parsing layer uses two key discriminated union types. SlashCommandParseResult represents the raw parse outcome, while ParsedSlashCommand wraps it with a boolean ok/error envelope for callers that prefer a simpler interface.

  | { kind: "empty" }
  | { kind: "invalid" }
  | { kind: "parsed"; action: string; args: string };

export type ParsedSlashCommand =
  | { ok: true; action: string; args: string }

How It Works

Command parsing operates in two stages: low-level extraction in commands-slash-parse.ts and plugin matching in plugins/commands.ts. The two stages are intentionally decoupled so that the parser has zero knowledge of registered commands.

Phase 1 — Slash Prefix Extraction

The parseSlashCommandActionArgs function is a pure function with no side effects. It receives the raw message and the slash prefix string, then applies a three-step pipeline: prefix check, emptiness check, and regex extraction.

// src/auto-reply/reply/commands-slash-parse.ts — lines 11-28
export function parseSlashCommandActionArgs(
  raw: string,
  slash: string,
): SlashCommandParseResult {
  const trimmed = raw.trim();
  const slashLower = slash.toLowerCase();
  if (!trimmed.toLowerCase().startsWith(slashLower)) {
    return { kind: "no-match" };
  }
  const rest = trimmed.slice(slash.length).trim();
  if (!rest) {
    return { kind: "empty" };
  }
  const match = rest.match(/^(\S+)(?:\s+([\s\S]+))?$/);
  if (!match) {
    return { kind: "invalid" };
  }
  const action = match[1]?.toLowerCase() ?? "";
  const args = (match[2] ?? "").trim();
  return { kind: "parsed", action, args };
}

Phase 2 — Convenience Wrapper

The parseSlashCommandOrNull function wraps the raw parser with a boolean ok/error envelope and a configurable default action for the empty case. Callers like the auto-reply router use this to avoid switch-casing over all four parse variants.

// src/auto-reply/reply/commands-slash-parse.ts — lines 30-46
export function parseSlashCommandOrNull(
  raw: string,
  slash: string,
  opts: { invalidMessage: string; defaultAction?: string },
): ParsedSlashCommand | null {
  const parsed = parseSlashCommandActionArgs(raw, slash);
  if (parsed.kind === "no-match") {
    return null;  // Not a command — pass through to agent
  }
  if (parsed.kind === "invalid") {
    return { ok: false, message: opts.invalidMessage };
  }
  if (parsed.kind === "empty") {
    return { ok: true, action: opts.defaultAction ?? "show", args: "" };
  }
  return { ok: true, action: parsed.action, args: parsed.args };
}

Phase 3 — Plugin Command Matching

After extraction, the parsed command body is passed to matchPluginCommand which looks up the action in the global plugin command registry. It checks both the primary key and all native name aliases, and enforces the acceptsArgs guard.

// src/plugins/commands.ts — lines 56-86
export function matchPluginCommand(
  commandBody: string,
): { command: RegisteredPluginCommand; args?: string } | null {
  const trimmed = commandBody.trim();
  if (!trimmed.startsWith("/")) {
    return null;
  }

  const spaceIndex = trimmed.indexOf(" ");
  const commandName = spaceIndex === -1
    ? trimmed
    : trimmed.slice(0, spaceIndex);
  const args = spaceIndex === -1
    ? undefined
    : trimmed.slice(spaceIndex + 1).trim();

  const key = commandName.toLowerCase();
  const command =
    pluginCommands.get(key) ??
    Array.from(pluginCommands.values()).find((candidate) =>
      listPluginInvocationNames(candidate).includes(key),
    );

  if (!command) {
    return null;
  }

  // Guard: if command doesn't accept args, don't match
  if (args && !command.acceptsArgs) {
    return null;
  }

  return { command, args: args || undefined };
}
