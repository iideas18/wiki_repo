Commands/Slash Commands/ — Parsing & Dispatch

Slash command parsing, routing, and dispatch infrastructure

The Slash Commands sub-module implements the core command processing pipeline for OpenClaw. It parses user input into structured command objects, resolves them against a registry of handlers, manages command aliases, and dispatches execution through the agent binding system with support for channel-specific routing and peer-level targeting.

📚 What is this & why does it exist?

Slash Commands is the front door of OpenClaw’s CLI. Every time a user types a command like openclaw agents add or openclaw models set gpt-4o, this sub-module is responsible for figuring out what the user wants, finding the right handler function, and routing the request to it. Without it, the system would have no way to interpret user intent.

💡 Real-world analogy

Think of Slash Commands like the reception desk at a large office building. When a visitor (user input) arrives, the receptionist (command parser) reads the visitor’s badge, checks their name against the directory (command registry), handles any name aliases (“go to Bob” actually means “go to Robert in Suite 401”), and then routes them to the correct office (command handler). The receptionist also checks if the visitor has an appointment with a specific person (agent binding) on a specific floor (channel routing).

Example: Agent Route Binding

export function describeBinding(binding: AgentRouteBinding): string {
  const match = binding.match;
  const parts = [match.channel];
  if (match.accountId) parts.push(`accountId=${match.accountId}`);
  if (match.peer) parts.push(`peer=${match.peer.kind}:${match.peer.id}`);
  if (match.guildId) parts.push(`guild=${match.guildId}`);
  if (match.teamId) parts.push(`team=${match.teamId}`);
  return parts.join(" ");
}
