Agents/Providers — Adapter Pattern

Focus Deep-Dive

Unified streaming interface across 12+ LLM providers

The provider adapter architecture wraps every supported LLM provider behind a common streaming interface. Each provider ships a dedicated stream-wrapper file that normalizes vendor-specific SSE formats, manages auth quirks, and emits a uniform chunk protocol consumed by the rest of OpenClaw.

Multi-Provider Adapter Pattern Schema Sanitization IAM Auth

📚 What is this & why does it matter?

Every LLM provider speaks a slightly different dialect of server-sent events, uses different auth mechanisms, and returns data in different shapes. The adapter pattern ensures the rest of the codebase never has to care about these differences — it always receives the same normalized stream chunks regardless of which provider is active.

💡 Real-world analogy

Think of an international power adapter kit. Every country has a different plug shape and voltage (providers), but your laptop charger (the core agent) only has one cable. The adapter (stream wrapper) converts the local electrical format into the standard your device expects. Swap countries, swap adapters — the charger never changes. Similarly, adding a new LLM provider means writing one new wrapper file without touching any core logic.

How It Works

The adapter pattern in OpenClaw follows a three-phase approach: resolve the target provider, wrap the provider-specific HTTP stream, and normalize the output into uniform chunks. Each wrapper file implements the same contract while encapsulating all provider-specific logic.

Phase 1: Model Resolution

The model registry in model.ts (24 KB) maps model identifiers to provider metadata. When a model string arrives, model.provider-normalization.ts normalizes provider prefixes — for example, Google models may arrive as google/gemini-pro or gemini-pro, and XAI models may use vendor-specific prefixes that need canonicalization.

// model.provider-normalization.ts — simplified provider resolution
export function normalizeProviderId(rawModel: string): ProviderInfo {
  const lower = rawModel.toLowerCase();

  // Google special cases: "google/gemini-*" or bare "gemini-*"
  if (lower.startsWith("google/") || lower.startsWith("gemini-")) {
    return { provider: "google", modelId: lower.replace("google/", "") };
  }

  // XAI special cases: "xai/grok-*" or "grok-*"
  if (lower.startsWith("xai/") || lower.startsWith("grok-")) {
    return { provider: "xai", modelId: lower.replace("xai/", "") };
  }

  // Default: split on first "/" — "anthropic/claude-3" → provider="anthropic"
  const slashIdx = lower.indexOf("/");
  if (slashIdx > 0) {
    return { provider: lower.slice(0, slashIdx), modelId: lower.slice(slashIdx + 1) };
  }

  // Bare model name: look up in registry
  return resolveFromRegistry(rawModel);
}
Key detail: The normalization function is intentionally order-sensitive. Google and XAI special cases are checked before the generic slash-split to avoid misrouting models with ambiguous prefixes.

Phase 3: Output Normalization

Every wrapper transforms raw provider events into the same chunk protocol. The normalization ensures that downstream code in attempt.ts and payloads.ts never needs provider-conditional logic.

// Simplified normalized chunk interface
interface NormalizedChunk {
  type: "text" | "tool_call" | "thinking" | "usage" | "done";
  content?: string;
  toolCall?: {
    id: string;
    name: string;
    arguments: string; // always JSON string
  };
  thinking?: string;
  usage?: { inputTokens: number; outputTokens: number };
}

// Each wrapper implements this contract:
type StreamWrapper = (
  response: Response,
  onChunk: (chunk: NormalizedChunk) => void,
  signal: AbortSignal,
) => Promise<void>;

Annotated Code Walkthrough

Walk through how an OpenAI-compatible stream wrapper normalizes SSE events into the common chunk protocol.

The wrapper receives the raw HTTP response and begins reading the SSE event stream line by line:

// openai-stream-wrappers.ts — entry point
export async function wrapOpenAIStream(
  response: Response,
  onChunk: (chunk: NormalizedChunk) => void,
  signal: AbortSignal,
): Promise<void> {
  const reader = response.body!.getReader();
  const decoder = new TextDecoder();
  let buffer = "";

  while (!signal.aborted) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split("\n");
    buffer = lines.pop() ?? "";
    for (const line of lines) {
      processSSELine(line, onChunk);
    }
  }
  onChunk({ type: "done" });
}

Each SSE line is parsed. The data: prefix is stripped and the JSON payload is transformed into a NormalizedChunk:

function processSSELine(
  line: string,
  onChunk: (chunk: NormalizedChunk) => void,
): void {
  if (!line.startsWith("data: ")) return;
  const payload = line.slice(6);
  if (payload === "[DONE]") return;

  const event = JSON.parse(payload);
  const delta = event.choices?.[0]?.delta;
  if (!delta) return;

  // Text content
  if (delta.content) {
    onChunk({ type: "text", content: delta.content });
  }

  // Tool call accumulation
  if (delta.tool_calls) {
    for (const tc of delta.tool_calls) {
      onChunk({
        type: "tool_call",
        toolCall: {
          id: tc.id ?? currentToolCallId,
          name: tc.function?.name ?? currentToolCallName,
          arguments: tc.function?.arguments ?? "",
        },
      });
    }
  }

  // Usage metadata (final chunk)
  if (event.usage) {
    onChunk({
      type: "usage",
      usage: {
        inputTokens: event.usage.prompt_tokens,
        outputTokens: event.usage.completion_tokens,
      },
    });
  }
}
Tool call deltas: OpenAI streams tool call arguments in fragments across multiple SSE events. The wrapper accumulates partial JSON in currentToolCallArgs and only emits the full tool call once the argument string is complete. This is why attempt.tool-call-argument-repair.ts exists — to fix malformed JSON from incomplete deltas.

For Anthropic, the wrapper injects cache-retention headers before initiating the stream:

// anthropic-cache-retention.ts — header injection
function buildAnthropicHeaders(baseHeaders: Headers, cacheConfig: CacheConfig): Headers {
  const headers = new Headers(baseHeaders);

  if (cacheConfig.enabled) {
    headers.set("anthropic-beta", "prompt-caching-2024-07-31");
    headers.set("anthropic-cache-control", JSON.stringify({
      type: "ephemeral",
      ttl: cacheConfig.ttlSeconds ?? 300,
    }));
  }

  return headers;
}

Anthropic Tool Call Compatibility

The anthropic-family-tool-payload-compat.ts module bridges the gap between OpenAI-style and Anthropic-style tool call formats. Anthropic expects tool inputs as a top-level input object rather than a function.arguments JSON string:

// anthropic-family-tool-payload-compat.ts — format bridge
export function toAnthropicToolUse(openaiToolCall: OpenAIToolCall): AnthropicToolUse {
  return {
    type: "tool_use",
    id: openaiToolCall.id,
    name: openaiToolCall.function.name,
    input: JSON.parse(openaiToolCall.function.arguments),
  };
}

export function fromAnthropicToolResult(result: AnthropicToolResult): OpenAIToolMessage {
  return {
    role: "tool",
    tool_call_id: result.tool_use_id,
    content: typeof result.content === "string"
      ? result.content
      : JSON.stringify(result.content),
  };
}
JSON.parse risk: If function.arguments contains malformed JSON (from incomplete streaming deltas), toAnthropicToolUse will throw. This is why the attempt.tool-call-argument-repair.ts module runs before compatibility conversion.
