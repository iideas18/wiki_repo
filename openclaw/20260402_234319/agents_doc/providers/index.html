Agents/Providers/ — Multi-Model Provider Adapters

Unified adapter layer for 12+ LLM providers with model fallback and auth management

The providers sub-module handles all communication between OpenClaw agents and external LLM APIs. It abstracts provider differences behind a common interface—normalizing payload formats, managing API key rotation, implementing cascading model fallback with error categorization, and performing provider-specific schema sanitization. Each provider adapter encapsulates authentication, request formatting, and response parsing so the rest of the agent system can remain provider-agnostic.

📚 What is this & why does it exist?

The providers layer is the translation bridge between OpenClaw’s agent runtime and the diverse world of LLM APIs. Each provider (OpenAI, Anthropic, Google Gemini, AWS Bedrock, Moonshot, Minimax, OpenRouter, Z AI, and others) expects requests in a different format, authenticates differently, and returns responses with different structures. This module normalizes all of that into a single interface the rest of the agent system consumes.

💡 Real-world analogy

Think of the United Nations interpreters’ booth. Delegates from 12+ countries each speak a different language (provider API). The interpreters (provider adapters) sit between the delegates and the assembly floor (agent runtime), translating every statement into a common protocol in real time. When one interpreter is unavailable (API key cooldown), the booth manager (auth-profiles.ts) seamlessly switches to a backup interpreter. If a delegate’s microphone fails entirely (provider outage), the fallback system (model-fallback.ts) routes the conversation to a different delegate who can cover the same topic. The assembly never sees the complexity—they just hear a smooth, unified feed.

Code Examples

Example: FallbackSummaryError Construction

// When all models in the fallback chain fail, FallbackSummaryError
// aggregates every per-model error into one structured report.
import { FallbackSummaryError } from './model-fallback';

const perModelErrors = [
  { model: 'openai/gpt-4o',       error: 'rate_limit',      status: 429 },
  { model: 'anthropic/claude-3.5', error: 'auth_expired',    status: 401 },
  { model: 'google/gemini-pro',    error: 'context_overflow', status: 400 },
];

throw new FallbackSummaryError(
  `All ${perModelErrors.length} fallback models exhausted`,
  perModelErrors,           // per-model error details
  'openai/gpt-4o',         // original requested model
  3,                        // total attempts
);
// FallbackSummaryError.perModelErrors gives structured access
// to each failure for logging and user-facing diagnostics.

Example: Auth Profile Ordering Logic

// resolveAuthProfileOrder() sorts credentials so the agent
// always tries the healthiest key first.
import { resolveAuthProfileOrder } from './auth-profiles';

const profiles = await resolveAuthProfileOrder('openai');
// Returns profiles sorted by:
//   1. AuthProfileHealth.ok        — fully healthy, preferred
//   2. AuthProfileHealth.expiring  — near expiry, usable
//   3. AuthProfileHealth.static    — static key, no refresh
//   4. (skipped) expired / missing — excluded from rotation
//
// Each profile tracks `soonestCooldownExpiry` so the system
// knows when to re-probe a previously failed credential.

for (const profile of profiles) {
  if (profile.cooldownExpiry && profile.cooldownExpiry > Date.now()) {
    continue; // still in cooldown, skip
  }
  return profile; // use first available
}
// If none available: trigger EXTERNAL_CLI_SYNC_TTL_MS refresh
// (900_000 ms = 15 min TTL) then retry.

Example: Gemini Schema Sanitization

import { cleanForGemini, GEMINI_UNSUPPORTED_SCHEMA_KEYWORDS } from './schema/clean-for-gemini';

// GEMINI_UNSUPPORTED_SCHEMA_KEYWORDS includes:
// '$ref', 'allOf', 'oneOf', 'anyOf', 'not', 'if', 'then', 'else', ...

const toolSchema = {
  type: 'object',
  properties: {
    query: { type: 'string', minLength: 1 },
    filter: { oneOf: [{ type: 'string' }, { type: 'number' }] },
  },
  $ref: '#/definitions/SearchParams',
};

const cleaned = cleanForGemini(toolSchema);
// Result: { type: 'object', properties: { query: { type: 'string' }, filter: {} } }
// '$ref', 'oneOf', and 'minLength' stripped — Gemini cannot process them.
