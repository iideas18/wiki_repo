💡 What is this & why does it exist?

Think of the core module as a flight simulator for GPU kernels. Just as a flight simulator recreates every control surface, weather system, and instrument reading so a pilot can train without risking an aircraft, the core module recreates every work-item thread, memory bank, and barrier synchronisation so a developer can test OpenCL kernels without needing actual GPU hardware — and with full visibility into what every instruction does.

At its heart sits an LLVM IR interpreter (WorkItem) that steps through compiled kernel bitcode instruction-by-instruction. Surrounding it are a faithful memory model with four address spaces, a barrier-aware work-group scheduler, and a plugin dispatch bus that fires callbacks on every memory access, instruction, and synchronisation event — enabling race detectors, uninitialised-read checkers, and custom analysis passes to observe execution without modifying the engine.

    Plugin Observer Interface

    The Plugin base class defines virtual hooks that any analysis pass can override. The Context iterates registered plugins and calls these on every simulation event:

    class Plugin
{
public:
  Plugin(const Context* context);
  virtual ~Plugin();

  virtual void instructionExecuted(const WorkItem* workItem,
                                   const llvm::Instruction* instruction,
                                   const TypedValue& result) {}
  virtual void memoryLoad(const Memory* memory, const WorkItem* workItem,
                          size_t address, size_t size) {}
  virtual void memoryStore(const Memory* memory, const WorkItem* workItem,
                           size_t address, size_t size,
                           const uint8_t* storeData) {}
  virtual void memoryAtomicLoad(const Memory* memory, const WorkItem* workItem,
                                AtomicOp op, size_t address, size_t size) {}
  virtual void workGroupBarrier(const WorkGroup* workGroup, uint32_t flags) {}
  virtual void kernelBegin(const KernelInvocation* kernelInvocation) {}
  virtual void kernelEnd(const KernelInvocation* kernelInvocation) {}

  virtual bool isThreadSafe() const;

protected:
  const Context* m_context;
};

    TypedValue — Size-Tagged Data Container

    Every SSA value produced by the interpreter is wrapped in a TypedValue. The struct provides typed accessors for the raw byte buffer:

    struct TypedValue
{
  unsigned size;        // bytes per element
  unsigned num;         // number of vector elements (1 for scalar)
  unsigned char* data;  // raw byte storage

  double   getFloat(unsigned index = 0) const;
  size_t   getPointer(unsigned index = 0) const;
  int64_t  getSInt(unsigned index = 0) const;
  uint64_t getUInt(unsigned index = 0) const;

  void setFloat(double value, unsigned index = 0);
  void setPointer(size_t value, unsigned index = 0);
  void setSInt(int64_t value, unsigned index = 0);
  void setUInt(uint64_t value, unsigned index = 0);

  struct TypedValue clone() const;
};

    Address Space & Atomic Enumerations

    The four OpenCL address spaces and supported atomic operations are defined as enums in common.h:

    enum AddressSpace
{
  AddrSpacePrivate  = 0,   // per-work-item scratch
  AddrSpaceGlobal   = 1,   // shared across all work-items
  AddrSpaceConstant = 2,   // read-only global
  AddrSpaceLocal    = 3,   // shared within a work-group
};

enum AtomicOp
{
  AtomicAdd, AtomicAnd, AtomicCmpXchg,
  AtomicDec, AtomicInc, AtomicMax,
  AtomicMin, AtomicOr,  AtomicSub,
  AtomicXchg, AtomicXor,
};
