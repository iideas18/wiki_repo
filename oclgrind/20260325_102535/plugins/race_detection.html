Data Race Detection

Shadow-memory tracking of per-work-item accesses, happens-before ordering via barriers, and inter-group race detection across a full kernel invocation.

1  Architecture Overview

The RaceDetector maintains shadow metadata for every byte touched during kernel execution. The design operates at two levels:

  • Intra-group — work-items within the same work-group are checked at every barrier() call and at work-group completion.
  • Inter-group — when a work-group completes, its accumulated global accesses are merged into a kernel-wide map and cross-checked against other groups.

2  WorkGroupState Data Structure

Each work-group gets a WorkGroupState containing three sets of per-address access maps:

struct WorkGroupState
{
  size_t numWorkItems;
  // Per work-item access maps for local memory
  std::vector<AccessMap> wiLocal;
  // Per work-item access maps for global memory
  std::vector<AccessMap> wiGlobal;
  // Merged work-group level global accesses
  AccessMap wgGlobal;
};

Each AccessMap is an unordered_map<size_t, AccessRecord> using a pool allocator for cache-friendly allocation. An AccessRecord holds at most one load and one store MemoryAccess per address — the detector keeps the "most interesting" (non-atomic) access to maximize detection coverage.

Why one load + one store per address? Storing every access would consume enormous memory. Instead, the detector greedily replaces atomic accesses with non-atomic ones (via the insert() method), since atomics can never race. This gives the best chance of detecting real races while keeping memory O(touched bytes).

3  MemoryAccess Bit-Packing

Each MemoryAccess is packed into an 8-bit info field plus entity ID and instruction pointer:

BitNameMeaning
0SET_BITAccess record is populated
1STORE_BIT1 = store, 0 = load
2ATOMIC_BITAccess used an atomic operation
3WG_BIT1 = work-group level, 0 = work-item level

The storeData field records the byte value written, enabling the uniform write optimization — if two work-items write the same value, it may be considered safe (controlled by OCLGRIND_UNIFORM_WRITES).

4  Happens-Before via Barriers

OpenCL's barrier(CLK_LOCAL_MEM_FENCE | CLK_GLOBAL_MEM_FENCE) establishes happens-before ordering. When the detector sees workGroupBarrier, it calls syncWorkItems for the relevant address space:

void RaceDetector::workGroupBarrier(const WorkGroup* workGroup,
                                    uint32_t flags)
{
  if (flags & CLK_LOCAL_MEM_FENCE)
  {
    syncWorkItems(workGroup->getLocalMemory(), STATE(workGroup),
                  STATE(workGroup).wiLocal);
  }
  if (flags & CLK_GLOBAL_MEM_FENCE)
  {
    syncWorkItems(m_context->getGlobalMemory(), STATE(workGroup),
                  STATE(workGroup).wiGlobal);
  }
}

syncWorkItems iterates all per-work-item access maps, cross-checks each against the accumulated work-group map for conflicts, merges them in, then clears per-work-item maps — establishing a new "epoch" where accesses before the barrier cannot race with accesses after it.

5  Race Classification: The check() Function

Two accesses are compared by the check() method. A race is reported only when:

  1. Both accesses are set (populated).
  2. They originate from different work-items.
  3. They are not both atomic (two atomics synchronize implicitly).
  4. At least one is a store — and either they form a read-write pair, or a write-write pair with non-uniform data (unless OCLGRIND_UNIFORM_WRITES is set).
Uniform writes caveat: By default, two work-items writing the same byte value to the same address are not flagged. Set OCLGRIND_UNIFORM_WRITES=1 to also flag these as races. This is conservative but may produce false positives for legitimate parallel-init patterns.

6  Inter-Group Detection

At workGroupComplete, the work-group's merged global accesses (wgGlobal) are checked against the kernel-wide m_globalAccesses map. A bank of 4096 mutexes (indexed by offset & 0xFFF) serializes concurrent work-group completions without a single global lock:

  • Three cross-checks are performed per address: load-vs-store, store-vs-load, and store-vs-store.
  • Races are deduplicated by instruction pair — if two entities produce the same instruction combination, only the lowest address is kept.
  • All detected races are logged at kernelEnd via logRace, which reports read-write or write-write type, memory address, and both entities' global/local/group IDs.

7  Thread Safety

The WorkerState uses THREAD_LOCAL storage so each CPU thread managing work-groups has its own state map. Only the inter-group merge path requires synchronization (via the mutex bank and kernelRacesMutex).

Pool Allocator: All AccessMap instances share a pool allocator with 8192-entry blocks. This dramatically reduces heap fragmentation when millions of addresses are tracked across many work-items.

8  The registerAccess Entry Point

Every memory hook (memoryLoad, memoryStore, memoryAtomicLoad, memoryAtomicStore) funnels into registerAccess. This function:

  1. Skips private and constant address spaces — private memory is per-work-item and cannot race; constant memory is read-only.
  2. Validates the address range with isAddressValid to avoid recording accesses to invalid memory.
  3. Constructs a MemoryAccess and computes the work-item's linear index within the work-group.
  4. Inserts the access into the correct per-work-item AccessMap (global or local, indexed by address space).
  5. For stores, records the data byte for uniform-write detection.
void RaceDetector::registerAccess(
  const Memory* memory, const WorkGroup* workGroup,
  const WorkItem* workItem, size_t address,
  size_t size, bool atomic, const uint8_t* storeData)
{
  unsigned addrSpace = memory->getAddressSpace();
  if (addrSpace == AddrSpacePrivate ||
      addrSpace == AddrSpaceConstant)
    return;
  if (!memory->isAddressValid(address, size))
    return;

  MemoryAccess access(workGroup, workItem,
                      storeData != NULL, atomic);

  // Compute linear WI index within work-group
  size_t index;
  if (workItem) {
    Size3 wgsize = workGroup->getGroupSize();
    Size3 lid    = workItem->getLocalID();
    index = lid.x + (lid.y + lid.z * wgsize.y) * wgsize.x;
  } else {
    index = STATE(workGroup).wiLocal.size() - 1;
  }

  // Select map by address space
  AccessMap& accesses =
    (addrSpace == AddrSpaceGlobal)
      ? STATE(workGroup).wiGlobal[index]
      : STATE(workGroup).wiLocal[index];

  // Record each byte individually
  for (size_t i = 0; i < size; i++) {
    if (storeData) access.setStoreData(storeData[i]);
    insert(accesses[address + i], access);
  }
}

9  Race Deduplication

The insertRace method prevents duplicate reports. Two races are considered identical if they involve the same pair of MemoryAccess records (regardless of order). When a duplicate is found, the detector keeps the entry with the lowest memory address — giving the user the most actionable location.

10  Logging Output

Each race report includes:

  • Race type — "Read-write" or "Write-write".
  • Address space and hex address — e.g., global memory address 0x4080.
  • Kernel name.
  • Both entities — showing Global ID, Local ID, and Group ID for work-items, or Group index for work-group-level accesses.
  • LLVM IR instruction for each entity, enabling precise source mapping.
Performance note: Race detection adds significant overhead. For large kernels (millions of work-items), the per-byte tracking can consume gigabytes of memory. Consider using OCLGRIND_DATA_RACES=0 when debugging only memory-validity issues with MemCheck.
