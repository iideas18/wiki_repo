📚 What is this & why does it exist?

Plugin Dev is the meta-plugin — it teaches Claude Code how to build other plugins. It provides structured knowledge about every plugin component type (commands, agents, skills, hooks, MCP servers, settings) through progressive disclosure: concise SKILL.md files for quick reference, detailed references for deep understanding, and working examples for implementation. The /create-plugin command orchestrates a guided 8-phase workflow from discovery to documentation.

💡 Real-world analogy

Imagine a master craftsperson's workshop that not only has every tool imaginable, but also comes with apprenticeship programs for each tool. The plugin-dev toolkit is that workshop. The 7 skills are like specialized training manuals (one for woodworking, one for metalwork, etc.), the 3 agents are expert instructors who can review your work, and the /create-plugin command is a guided project plan that walks you from concept to finished product.

Each skill uses progressive disclosure: metadata is always loaded (trigger matching), the core SKILL.md (1,500–2,000 words) provides essential API reference, references/ holds 2-4 detailed docs, examples/ provides 3-12 working samples, and scripts/ offers validation utilities.

🚶 Step-by-Step: Creating a Plugin from Scratch

Follow a /create-plugin "my-security-scanner" command through the 8-phase workflow:

  1. Phase 1 — Discovery — The command asks what your plugin does, who it serves, and what problem it solves. You describe a security scanner plugin.
  2. Phase 2 — Planning — Determines which component types you need: a command for scanning, a hook for real-time monitoring, and a skill for security knowledge.
  3. Phase 3 — Design — Clarifying questions about scope: which vulnerability patterns, what languages, blocking vs warning behavior.
  4. Phase 4 — Structure — Creates the directory layout: .claude-plugin/plugin.json, commands/, hooks/, skills/. Uses the plugin-structure skill for guidance.
  5. Phase 5 — Implementation — The agent-creator generates agent configurations. The hook-development skill guides PreToolUse hook creation. The command-development skill structures the slash command.
  6. Phase 6 — Validation — The plugin-validator agent checks manifest fields, directory structure, naming conventions, and security patterns. Reports critical issues vs warnings.
  7. Phase 7 — Testing — You test the plugin in a Claude Code session. The validator verifies hook responses and command behavior.
  8. Phase 8 — Documentation — Generates README.md with installation instructions, usage examples, and configuration reference. The skill-reviewer checks documentation quality.

Code Examples

Plugin Manifest (plugin.json)

{
  "name": "my-security-scanner",
  "version": "1.0.0",
  "description": "Scans code for security vulnerabilities during editing",
  "author": { "name": "Developer", "email": "dev@example.com" },
  "mcpServers": {}
}

Agent Configuration (agents/scanner.md)

---
name: security-scanner
description: |
  Use this agent when reviewing code for security vulnerabilities.
  Examples:
  <example>scan this file for XSS vulnerabilities</example>
  <example>check for SQL injection in the API routes</example>
model: sonnet
color: red
tools:
  - Read
  - Grep
  - Glob
  - Bash
---

You are a security scanning expert. Analyze code for vulnerability patterns...

Hook Configuration (hooks/hooks.json)

{
  "PreToolUse": [
    {
      "matcher": "Write|Edit|MultiEdit",
      "hooks": [
        {
          "type": "command",
          "command": "python3 hooks/security_check.py"
        }
      ]
    }
  ]
}
