Hookify — Python Rule Engine for Custom Hooks

Event-Driven Validation with Markdown Rules

Define validation rules in human-readable markdown with YAML frontmatter. A Python rule engine evaluates patterns against tool operations in real time, enabling warn/block actions across 4 hook event types.

📚 What is this & why does it exist?

Hookify bridges the gap between Claude Code's hook system and custom project rules. Instead of writing raw Python for every validation, you define rules as markdown files with YAML frontmatter specifying events, patterns, and actions. The Python rule_engine.py loads these rules via config_loader.py, evaluates each condition using 6 operators (equals, contains, matches, startsWith, endsWith, not), and returns warn or block decisions through JSON stdout.

💡 Real-world analogy

Think of airport security screening. Each security rule (no liquids over 100ml, no sharp objects) is written on a simple card that any officer can read. The X-ray machine (rule engine) scans every bag (tool operation) and checks it against all the rules. If something matches a “warn” rule, the officer flags it for inspection. If it matches a “block” rule, the bag doesn't get through. Hookify works the same way — readable rules, automated enforcement.

Rule Authoring Guide

Markdown Rule Format

Rules are markdown files in the rules/ directory with YAML frontmatter defining the rule metadata and a markdown body providing the human-readable description and rationale.

---
name: no-sudo
enabled: true
event: bash
tool_matcher: Bash
conditions:
  - field: command
    operator: contains
    pattern: sudo
action: block
message: "sudo commands are not allowed in this project"
---

# No Sudo Rule

This rule prevents execution of sudo commands through the Bash tool.
Elevated privileges should not be needed for development tasks.
If you need sudo access, contact the infrastructure team.

Operator Usage Examples

equals

conditions:
  - field: tool_name
    operator: equals
    pattern: "Write"

Exact match — tool name must be exactly “Write”.

matches (regex)

conditions:
  - field: file_path
    operator: matches
    pattern: "\\.(env|secret|key)$"

Regex match — catches .env, .secret, and .key files.

startsWith

conditions:
  - field: file_path
    operator: startsWith
    pattern: "/etc/"

Prefix match — blocks writes to system directories.

not (negation)

conditions:
  - field: file_path
    operator: not
    pattern: "src/"

Negated match — triggers when path does NOT contain “src/”.

Multi-Condition Rules

Rules can specify multiple conditions. All conditions must match (AND logic) for the rule to trigger:

---
name: large-file-warning
enabled: true
event: file
tool_matcher: Write
conditions:
  - field: file_path
    operator: matches
    pattern: "\\.(ts|py|js)$"
  - field: content_lines
    operator: gt
    pattern: "500"
action: warn
message: "File exceeds 500 lines - consider splitting"
---
