📚 What is this & why does it exist?

Security Guidance is a PreToolUse hook that acts as a real-time security linter for Claude Code. Before any file edit is applied, the Python hook scans the target file path and content for 9 known vulnerability patterns — from command injection in GitHub Actions to eval() and pickle deserialization. It uses session-scoped state tracking to avoid showing the same warning repeatedly, and auto-cleans stale state after 30 days. The goal is to catch security anti-patterns at the moment they’re introduced, not days later in a code review.

💡 Real-world analogy

Think of a spell-checker that only checks for dangerous words — not typos, but things like “rm -rf /” or “eval(user_input)”. Just as a spell-checker underlines problematic words as you type them, the Security Guidance hook underlines dangerous patterns the moment Claude tries to write them into a file. And like a smart spell-checker that stops highlighting a word after you’ve explicitly accepted it, the state tracker remembers which warnings you’ve already seen so it doesn’t nag you about the same pattern twice in one session.

Architecture

The hook intercepts file-edit tool calls before they execute. The Python script parses the tool input, matches file paths and content against 9 security pattern rules, checks session state to avoid duplicate warnings, and returns advisory messages when new patterns are detected.

State Management

Session-Scoped Warning Tracking

To prevent warning fatigue, the hook maintains a state file that tracks which pattern–file combinations have already triggered warnings in the current session. The state file is stored alongside the hook script and is automatically cleaned up after 30 days of inactivity.

📋 State File Format

JSON dictionary mapping pattern keys to timestamps of when the warning was last shown.

  • Key format: {pattern_id}:{file_path}
  • Value: ISO 8601 timestamp
  • Location: .security-state.json next to hook

🗑️ Auto-Cleanup

Stale entries are removed on each hook invocation to keep the state file compact.

  • Entries older than 30 days are pruned
  • Cleanup runs before pattern matching
  • Zero-entry state file is deleted entirely

"""PreToolUse hook: scan file edits for 9 security vulnerability patterns."""

import json, sys, os, datetime

     "msg": "GitHub Actions command injection — avoid interpolating untrusted input in run: blocks"},
    {"id": "child-process-exec", "path_ext": [".js", ".ts"], "substr": "child_process.exec",
     "msg": "child_process.exec is vulnerable to shell injection — use execFile() or spawn()"},
    {"id": "new-function", "path_ext": [".js", ".ts"], "substr": "new Function(",
     "msg": "new Function() enables dynamic code execution — equivalent to eval()"},
    {"id": "eval", "path_ext": [".js", ".ts", ".py"], "substr": "eval(",
     "msg": "eval() executes arbitrary code — use JSON.parse(), ast.literal_eval(), or a safe parser"},
    {"id": "dangerouslySetInnerHTML", "path_ext": [".jsx", ".tsx"], "substr": "dangerouslySetInnerHTML",
     "msg": "dangerouslySetInnerHTML enables XSS — sanitize with DOMPurify first"},
    {"id": "document-write", "path_ext": [".js", ".ts", ".html"], "substr": "document.write(",
     "msg": "document.write() enables DOM-based XSS — use textContent or createElement"},
    {"id": "innerHTML", "path_ext": [".js", ".ts"], "substr": ".innerHTML",
     "msg": ".innerHTML enables XSS — use textContent for text or sanitize HTML first"},
    {"id": "pickle", "path_ext": [".py"], "substr": "pickle.load",
     "msg": "pickle deserialization executes arbitrary code — use json or a safe format"},
    {"id": "os-system", "path_ext": [".py"], "substr": "os.system(",
     "msg": "os.system() is vulnerable to shell injection — use subprocess.run() with a list"},
]

Warning Examples

Example Security Advisory

When Claude attempts to edit a file containing a detected pattern:

⚠️ Security Advisory — child_process.exec
The file src/api/handler.js uses child_process.exec() which passes arguments through a shell, making it vulnerable to command injection.

Recommended: Use child_process.execFile() or child_process.spawn() with an argument array to avoid shell interpretation of special characters.

GitHub Actions Pattern

# ⚠️ DANGEROUS — PR title is attacker-controlled
- name: Greet
  run: echo "Hello ${{ github.event.pull_request.title }}"

# ✅ SAFE — use an environment variable
- name: Greet
  env:
    PR_TITLE: ${{ github.event.pull_request.title }}
  run: echo "Hello $PR_TITLE"
