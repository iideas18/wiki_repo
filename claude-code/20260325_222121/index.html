📚 What is this & why does it exist?

Claude Code is an open-source, AI-powered coding assistant that lives in your terminal. Unlike browser-based AI tools, it runs locally, reads your codebase directly, and executes real commands. Its plugin system allows community-built extensions for code review, feature development, security checks, and automated workflows.

💡 Real-world analogy

Imagine a senior developer who never sleeps, knows every file in your project, and can simultaneously review PRs, triage issues, write features, and manage git workflows. Claude Code is that developer, living in your terminal. The plugin system is like an app store — each plugin adds a specialized skill (code review, security scanning, etc.) that the AI can use on demand.

Plugin Execution Flow

sequenceDiagram
    participant User
    participant CLI as Claude Code CLI
    participant Plugin as Plugin System
    participant Hook as Hook Engine
    participant Agent as Specialized Agent
    participant Tool as Core Tools

    User->>CLI: /feature-dev "add auth"
    CLI->>Plugin: Resolve command
    Plugin->>Agent: Launch code-explorer agents (parallel)
    Agent->>Tool: Read files, grep patterns
    Tool-->>Agent: Codebase context
    Agent-->>Plugin: Architecture recommendations
    Plugin->>User: Present options, ask questions
    User->>Plugin: Choose approach
    Plugin->>Agent: Launch code-architect
    Agent->>Tool: Create/modify files
    Note over Hook,Tool: PreToolUse hooks validate each operation
    Hook->>Tool: Security check (hookify rules)
    Tool-->>Agent: Files written
    Agent-->>Plugin: Implementation complete
    Plugin->>Agent: Launch code-reviewer (parallel)
    Agent-->>Plugin: Review findings
    Plugin->>User: Summary with next steps
Key insight: Plugins orchestrate multi-agent workflows where specialized agents (explorer, architect, reviewer) work in parallel. Hooks intercept every tool operation for security validation. The CLI manages sessions, authentication, and tool execution.

How Plugins & GitHub Workflows Connect

sequenceDiagram
    participant GH as GitHub Event
    participant WF as GitHub Workflow
    participant CC as Claude Code CLI
    participant CMD as Commands
    participant SCR as Scripts

    GH->>WF: Issue opened
    WF->>CC: Run with /triage-issue
    CC->>CMD: Execute triage command
    CMD->>SCR: Call gh.sh (restricted)
    SCR-->>CMD: Issue data
    CMD->>SCR: Call edit-issue-labels.sh
    SCR-->>CMD: Labels applied
    CMD-->>CC: Triage complete

    Note over GH,SCR: Scheduled (twice daily)
    WF->>SCR: Run sweep.ts
    SCR->>GH: Mark stale, auto-close expired
Key insight: GitHub workflows trigger Claude Code sessions that execute commands, which in turn call specialized scripts. The scripts directory provides the low-level GitHub API operations. Workflows handle scheduling and event routing.
