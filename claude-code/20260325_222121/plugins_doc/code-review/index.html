📚 What is this & why does it exist?

Code Review automates the PR review process by deploying multiple specialized AI agents in parallel. Rather than a single-pass review, it uses a pipeline approach: two agents check CLAUDE.md compliance, one Opus-powered agent hunts for subtle bugs, and one examines git history for context. Results are aggregated with confidence scores, and only findings above the 80% threshold are surfaced. This mimics how a senior engineering team reviews code — multiple perspectives, each with domain expertise.

💡 Real-world analogy

Imagine a code review meeting with four specialists sitting around a table: a style guide enforcer who checks every line against the team's conventions, a second enforcer who catches what the first missed, a seasoned debugger who has an instinct for subtle logic errors, and a historian who remembers why every past decision was made. They each review independently, then combine notes — only sharing findings they're confident about. That's exactly what this plugin orchestrates, but with AI agents instead of humans.

Agent Specifications

📋 CLAUDE.md Compliance Agent (x2)

Two independent agents check every changed line against project-specific CLAUDE.md guidelines. Running two instances catches inconsistencies that a single pass might miss. Each produces findings with confidence scores.

  • Model: Sonnet (fast, cost-effective)
  • Focus: Style, naming, patterns, banned APIs
  • Output: List of violations with line numbers

🐛 Bug Detection Agent (Opus)

Uses the most capable model (Opus) to hunt for subtle logic errors, race conditions, null pointer risks, off-by-one errors, and security vulnerabilities. Expensive but high-value.

  • Model: Opus (maximum reasoning)
  • Focus: Logic bugs, security, edge cases
  • Output: Bug reports with severity and fix suggestions

📚 History Context Agent

Examines git log, blame data, and related PRs to understand why the code being changed was written the way it was. Flags changes that may break implicit contracts or revert intentional decisions.

  • Model: Sonnet
  • Focus: Context, intent preservation, regressions
  • Output: Context warnings and decision history

✅ Parallel Validators

Additional lightweight validators that run alongside the main agents: import sorting, test coverage delta, TODO/FIXME scanning, and dependency version checks.

  • Model: Haiku (fast checks)
  • Focus: Mechanical validations
  • Output: Pass/fail checklist items

Confidence Scoring

Each agent assigns a confidence score (0–100) to every finding. The aggregator applies these rules:

Score RangeActionLabel
90–100Always surfaced, highlightedCritical
80–89Surfaced in reportSuggestion
60–79Discarded (below threshold)Low Confidence
0–59Silently dropped—
