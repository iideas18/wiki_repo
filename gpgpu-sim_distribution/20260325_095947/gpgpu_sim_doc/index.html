gpgpu-sim — GPU Timing Simulation Engine

GPU Timing Simulation Engine

The performance-simulation core of GPGPU-Sim. Models a complete NVIDIA-style GPU micro-architecture at the cycle level — shader-core pipelines, L1/L2 cache hierarchy, on-chip interconnect, and DDR DRAM controllers — to produce detailed performance and power statistics for architectural research.

What Is This?

🎭 Analogy: Imagine a theme-park simulation game. Each ride is a shader core that processes visitors (threads) in groups (warps). The park’s road network is the interconnect shuttling people between attractions. Gift shops along the way are caches — if the souvenir you want is in stock (cache hit), you grab it instantly; otherwise an order goes to the central warehouse (DRAM). The park manager (gpgpu_sim::cycle()) advances every ride, road, and shop by one tick of the clock each cycle, collecting visitor-throughput statistics to optimize the park layout.

In reality, src/gpgpu-sim/ is the cycle-accurate timing model for every major GPU hardware block. It accepts CUDA kernel launches, distributes Cooperative Thread Arrays (CTAs) to shader cores, and simulates the full memory hierarchy from L1 through DRAM, producing the performance counters that drive GPU architecture research.

Step-by-Step Walkthrough

🚶 Tracing a Memory Load Instruction

Follow a single LDG (global load) instruction from fetch to data delivery:

  1. Fetch — The fetch stage round-robins across warps. When warp W has an empty instruction buffer slot and its PC maps to a valid L1I line, the instruction bytes are fetched into the ibuffer (2-entry FIFO).
  2. Decode — The instruction is decoded into a warp_inst_t identifying it as a memory operation targeting the ldst_unit functional unit.
  3. Scoreboard Check — The warp scheduler (e.g., GTO) calls Scoreboard::checkCollision(wid, inst). If the destination register has a pending write from an earlier instruction, the warp stalls.
  4. Issue & Register Reserve — The scheduler issues the instruction into the ldst_unit pipeline register. Scoreboard::reserveRegisters() marks the destination register as pending.
  5. Operand Collection — The opndcoll_rfu_t reads the base-address register from the banked register file via its crossbar arbiter. Once all source operands are ready, the instruction moves to execution.
  6. Address Generation & Coalescing — The ldst_unit computes per-thread effective addresses and coalesces them into one or more mem_access_t objects (128-byte sectors). Each becomes a mem_fetch envelope.
  7. L1D Probe — data_cache::access() probes the tag array. On a HIT, data returns in one cycle to the writeback stage. On a MISS, an MSHR entry is allocated and the mem_fetch is queued for the interconnect.
  8. Interconnect Transit — icnt_push() injects the request. The on-chip network (BookSim or local crossbar) routes it to the target memory partition based on the address decoder’s sub-partition mapping.
  9. L2 Probe — The memory_sub_partition receives the request from the ICNT-to-L2 queue. The L2 tag_array is probed. On a HIT, the reply is pushed to the L2-to-ICNT queue. On a MISS, the request passes through the ROP delay and enters the DRAM-to-L2 pipeline.
  10. DRAM Scheduling — The dram_t controller receives the request. The FR-FCFS scheduler bins it by (bank, row). If the target row is already open (row-buffer hit), a column command issues immediately; otherwise an ACTIVATE is needed first.
  11. DRAM Service — After the bank timing constraints (tRCD, CL, burst length) are satisfied, data is placed in the returnq. The controller pops it and pushes a fill response back to the L2 sub-partition.
  12. L2 Fill & Reply — The L2 cache allocates a line (RESERVED→VALID), writes the data, and pushes the reply into the L2-to-ICNT queue. The MSHR entry is released.
  13. Response Delivery — The interconnect routes the reply back to the originating shader cluster. icnt_pop() delivers it to the ldst_unit response FIFO.
  14. Writeback — The ldst_unit processes the response, writes data to the register file, and calls Scoreboard::releaseRegisters(). The destination register is no longer pending — dependent warps can now issue.

Deep-Dive Topics

📦 Cache Hierarchy

L1D/L1I/L1T/L1C and L2 caches with configurable associativity, sector support, and MSHR merging.

  • Tag probe with LRU/FIFO replacement
  • Sector-mask validity checking
  • RESERVATION_FAIL deadlock prevention
  • Write-back & write-through policies

⚡ DRAM Scheduling

FR-FCFS scheduler with row-buffer hit prioritization and read/write mode switching via watermarks.

  • Per-bank request binning by row
  • ACTIVATE / PRECHARGE / READ / WRITE commands
  • DDR timing: tRCD, tCAS, tRP, tRAS, tCCDL
  • Separate write queue with high/low watermarks

🔧 Shader Core Pipeline

5-stage pipeline executed in reverse order: writeback → execute → issue → decode → fetch.

  • Multi-scheduler support (1–4 per core)
  • Scoreboard-based RAW hazard detection
  • Operand collector with banked register file
  • SP, SFU, MEM functional units

🎲 Warp Scheduling

Pluggable scheduling policies that determine which warp issues each cycle.

  • GTO: Greedy-Then-Oldest (favors MLP)
  • LRR: Loose Round-Robin
  • Two-Level: active/pending warp pools
  • SWL: Static Warp Limiting

📌 Memory Coalescing & Address Decoding

Per-thread addresses coalesced into 128-byte sector accesses; configurable address-to-partition mapping.

  • Coalescing in ldst_unit
  • LINEAR / XOR / IPOLY partition indexing
  • Bit-field mask configuration
  • Sweep test for alias validation

Clock Domains

The main gpgpu_sim::cycle() loop drives four independent clock domains. The fastest-period domain fires first each tick:

DomainDefault FreqWhat Runs
CORE500 MHzShader clusters, CTA issue, power model
ICNT2 GHzInterconnect transfer, shader ↔ memory response routing
L22 GHzL2 cache cycles, icnt → mem pushes
DRAM2 GHzDRAM controller scheduling & DDR timing

Glossary

TermMeaning
CTACooperative Thread Array (thread block) — the unit of work distributed to a core
WarpGroup of 32 threads executing in SIMT lock-step
SIMT StackStack tracking thread divergence/reconvergence at branch points
MSHRMiss-Status Holding Register — tracks pending cache misses and merges requests
FR-FCFSFirst-Ready First-Come-First-Served — DRAM scheduling that prioritises row-buffer hits
Row BufferSense-amp row in a DRAM bank; an open row allows column commands without re-activation
mem_fetchEnvelope object tracking a single memory request through all hierarchy stages (26 states)
Operand CollectorHardware unit that reads source operands from banked register files before execution
Sector CacheCache where a line is divided into sectors; individual sectors can be valid/invalid independently
ROPRaster Operations Pipeline — fixed delay for memory requests before L2
