Allocators — Switch & VC Allocation Algorithms

Resolves contention when multiple input VCs compete for the same output port or output VC during the switch-allocation (SA) and VC-allocation (VA) stages of the router pipeline.

📚 What is this & why does it exist?

Inside every router on the Network-on-Chip, multiple packets arriving on different input ports may want to leave through the same output port at the same time. The allocators sub-module decides who wins that competition each cycle. Without fair, fast allocation the crossbar switch would be wasted and packets would stall needlessly.

💡 Real-world analogy

Imagine a busy airport with many gates (inputs) and a limited number of runways (outputs). Each gate wants to send a plane to a runway, but only one plane can use each runway at a time. The allocator is the air traffic controller: it collects all departure requests, applies a fairness policy (round-robin, priority, or random), and grants exactly one gate per runway each cycle — maximizing throughput while preventing starvation.

iSLIP Round-Robin Matching Focus

Iterative grant-accept protocol with rotating pointers that guarantees fairness and converges in O(1) iterations for uniform traffic.

Separable Two-Phase Allocation Focus

Decomposes NxM matching into per-input and per-output arbiter phases. Configurable with any arbiter type (round-robin, matrix, tree).

Wavefront & PIM Matching Focus

Dense-matrix algorithms: wavefront sweeps diagonals for O(N) matching; PIM uses randomized parallel iterations for distributed matching.

    for (int out = 0; out < _outputs; ++out) {
      auto &req = _out_req[out];
      int best = -1;
      for (auto &r : req) {
        if (_inmatch[r.first] == -1) {  // input not yet matched
