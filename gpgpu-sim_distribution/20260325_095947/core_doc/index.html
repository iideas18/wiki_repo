💡 What Is This Module?

Think of Core Infrastructure as the foundation and wiring of a building. The foundation (abstract_hardware_model) defines the structural shapes—walls, floors, load-bearing beams—that every room in the building must respect. The main electrical panel (gpgpusim_entrypoint) powers the entire structure and decides when the lights come on. The plumbing manifold (stream_manager) routes work orders to the right room. The control panel (option_parser) lets you reconfigure the building’s behaviour without tearing down walls. And the diagnostic wiring (debug + trace) lets you inspect any circuit at runtime.

No concrete timing logic lives here—this module defines the vocabulary (kernels, warps, instructions, memory accesses) that the timing model, cache hierarchy, and interconnect all speak.

🚶 Step-by-Step: Tracing a Kernel Launch from API Call to Execution

Follow a single cudaLaunchKernel() call as it flows through Core Infrastructure:

  1. Application calls cudaLaunchKernel() — The CUDA runtime intercept in libcuda captures the call, resolving the kernel function pointer to a function_info* object.
  2. Create kernel_info_t — libcuda allocates a kernel_info_t with grid/block dimensions, a unique UID, stream ID, argument list (gpgpu_ptx_sim_arg), and a snapshot of bound textures.
  3. Push to stream_manager — A stream_operation of type stream_kernel_launch is constructed and pushed into the target CUstream_st’s FIFO. A mutex protects the queue.
  4. Simulation thread wakes — In gpgpu_sim_thread_concurrent(), the spin-loop detects !empty_protected() and calls g_the_gpu->init() to reset cycle counters.
  5. Stream scheduling (stream_manager::front()) — The round-robin scheduler tries stream_zero first, then iterates named streams from m_last_stream. It selects the first non-busy, non-empty stream.
  6. Operation dispatch (do_operation()) — For a kernel launch, the code checks gpu->can_start_kernel() and waits for m_launch_latency to count down to zero (simulating CPU→GPU transfer delay).
  7. gpu->launch(kernel) — The kernel is handed to gpgpu_sim, which maps it to a grid-to-stream entry and begins distributing CTAs across shader cores based on resource availability (registers, shared memory, max CTAs per SM).
  8. Warp creation & SIMT stack init — Each CTA spawns warps. Per-warp simt_stack objects are initialized with the kernel entry PC and a full active mask (all 32 threads active).
  9. Fetch / Decode / Issue cycle — Each gpgpu_sim::cycle() tick drives shader cores. Instructions are fetched, decoded into warp_inst_t objects carrying opcode, operands, latency, and active mask.
  10. Branch divergence (simt_stack::update()) — When a branch diverges, threads are partitioned by next_pc. The PDOM reconvergence algorithm pushes taken/not-taken paths onto the stack with the post-dominator as the reconvergence PC.
  11. Memory coalescing (memory_coalescing_arch()) — For global/local loads and stores, per-thread addresses are mapped to segment-aligned transactions (128B → 64B → 32B reduction). Each reduced transaction becomes a mem_access_t pushed into the access queue.
  12. Kernel completion & cleanup — When all CTAs finish, gpgpu_sim calls stream_manager::register_finished_kernel(). The stream pops the operation via record_next_done(), unblocking any host-side synchronization.

Concurrent Simulation Main Loop

The heart of the simulator — the thread that drives cycle-by-cycle execution (gpgpusim_entrypoint.cc):

void *gpgpu_sim_thread_concurrent(void *ctx_ptr) {
  gpgpu_context *ctx = (gpgpu_context *)ctx_ptr;
  do {
    // Spin until work appears in any stream
    while (ctx->the_gpgpusim->g_stream_manager->empty_protected() &&
           !ctx->the_gpgpusim->g_sim_done)
      ;
    ctx->the_gpgpusim->g_sim_active = true;
    ctx->the_gpgpusim->g_the_gpu->init();
    bool active = false, sim_cycles = false;
    do {
      // Dispatch next stream operation; break if GPU idle
      if (ctx->the_gpgpusim->g_stream_manager->operation(&sim_cycles) &&
          !ctx->the_gpgpusim->g_the_gpu->active())
        break;
      // Performance simulation: one GPU cycle
      if (ctx->the_gpgpusim->g_the_gpu->active()) {
        ctx->the_gpgpusim->g_the_gpu->cycle();
        sim_cycles = true;
        ctx->the_gpgpusim->g_the_gpu->deadlock_check();
      }
      active = ctx->the_gpgpusim->g_the_gpu->active() ||
               !(ctx->the_gpgpusim->g_stream_manager->empty_protected());
    } while (active && !ctx->the_gpgpusim->g_sim_done);
    ctx->the_gpgpusim->g_sim_active = false;
  } while (!ctx->the_gpgpusim->g_sim_done);
}

Stream Operation Dispatch

How the stream manager dispatches queued CUDA operations (stream_manager.cc):

bool stream_operation::do_operation(gpgpu_sim *gpu) {
  switch (m_type) {
    case stream_memcpy_host_to_device:
      gpu->memcpy_to_gpu(m_device_address_dst, m_host_address_src, m_cnt);
      m_stream->record_next_done();
      break;
    case stream_kernel_launch:
      if (gpu->can_start_kernel() && m_kernel->m_launch_latency == 0) {
        gpu->set_cache_config(m_kernel->name());
        gpu->launch(m_kernel);
      } else {
        if (m_kernel->m_launch_latency) m_kernel->m_launch_latency--;
        return false;  // not ready yet
      }
      break;
    case stream_event:
      m_event->update(gpu->gpu_tot_sim_cycle, wallclock);
      m_stream->record_next_done();
      break;
    case stream_wait_event:
      if (m_event->num_updates() >= m_cnt) m_stream->record_next_done();
      else return false;
      break;
  }
  m_done = true;
  return true;
}
