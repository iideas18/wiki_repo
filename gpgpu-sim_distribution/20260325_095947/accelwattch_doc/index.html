AccelWattch — GPU Power Modeling Framework

GPU Power Modeling Framework

AccelWattch is the architectural power modeling component of GPGPU-Sim. Built on McPAT and CACTI, it estimates dynamic power, leakage power, and area for every major on-chip structure — cores, caches, register files, execution units, NoC, memory controllers, and I/O — by combining activity counters from cycle-level simulation with analytical circuit models. Validated against Volta-class GPUs.

💡 What is AccelWattch?

Analogy: Think of AccelWattch as an electricity bill estimator for a GPU factory. Imagine a massive factory (GPU chip) with assembly lines (SMs), warehouses (caches), conveyor belts (NoC), and loading docks (memory controllers). Each area has its own power meter. AccelWattch reads every meter every sampling interval, looks up the per-unit energy cost in a catalog (CACTI/McPAT technology tables), multiplies by how many operations each area performed, and produces a detailed bill — broken down by department — showing exactly where the watts are going.

It supports three modes: pure simulation (all counters from GPGPU-Sim), pure hardware (all from real GPU), and hybrid (selectively mixing real and simulated counters per component for validation).

🚶 Step-by-Step Narrated Walkthrough

Follow a single power estimation cycle as it flows through the entire AccelWattch pipeline:

  1. Sampling Trigger — The GPU simulator reaches a gpu_stat_sample_freq boundary (e.g., every 10,000 cycles). power_interface.cc::mcpat_cycle() fires.
  2. Counter Collection — The bridge layer iterates over every shader_core and memory_partition_unit, harvesting counters: total instructions, cache hits/misses, register reads/writes, ALU/FPU/SFU accesses, DRAM reads/writes, and NoC flits.
  3. Counter Injection — Each counter set is injected into gpgpu_sim_wrapper via 20+ typed set_*_power() methods (e.g., set_inst_power(), set_regfile_power(), set_exec_unit_power()). In hybrid mode, hardware counters may replace some simulated values.
  4. XML Stats Update — The wrapper writes injected counters into the ParseXML struct tree (root_system → system_core[i] → total_instructions, etc.), overwriting the TDP defaults with actual runtime values.
  5. Processor::compute() — The top-level Processor iterates over its component vectors: cores[], l2array[], l3array[], nocs[], mc, and I/O controllers, calling computeEnergy(false) on each.
  6. Core::computeEnergy() — Each Core (SM model) updates sub-unit stats and delegates: InstFetchU calculates icache + BTB power, EXECU calculates register file + ALU/FPU/MUL + bypass power, LoadStoreU calculates dcache/shared-memory power. Each sub-unit calls ArrayST::computeEnergy() which multiplies access count by CACTI’s pre-computed energy-per-access.
  7. CACTI Energy Lookup — For each array structure (icache, dcache, register file, TLB, BTB), the pre-solved uca_org_t provides energy per read/write/search operation. Runtime power = (accesses / total_cycles) × energy_per_access × clock_rate. Leakage is added from I_off × V_dd.
  8. SharedCache & MC — L2 cache arrays similarly compute energy. The MemoryController computes power for the front-end command queue, back-end protocol engine, PHY transceiver, and DRAM die refresh.
  9. NoC Power — The network-on-chip multiplies router/link energy by flit count, modulated by a traffic pattern factor (default 0.6).
  10. Power Aggregation — update_components_power() extracts 33 named component powers (IBP, ICP, DCP, TCP, RFP, FPUP, L2CP, MCP, NOCP, DRAMP, PIPEP, etc.) into the sample_cmp_pwr[] vector.
  11. Metrics Calculation — power_metrics_calculations() updates running average/max/min for each component and total GPU power across the kernel.
  12. Trace Output — dump() writes the current sample to gzip-compressed trace files (power_trace.gz, metric_trace.gz). Steady-state detection checks if power variance has converged below steady_power_deviation.

Sub-Modules & Logical Groupings

cacti/

Cache Access and Cycle Time model (HP Labs). Analytical SRAM/DRAM/CAM array solver providing area, timing, and power.

  • Exhaustive partition-space search (Ndwl × Ndbl × Nspd)
  • 22–180 nm ITRS technology database
  • Wire delay with repeater optimization
  • H-tree routing & NUCA mesh support

Core Components

GPU Streaming Multiprocessor power model — the largest component. Processor hierarchy and SM sub-units.

  • processor.h/.cc — top-level hierarchy
  • core.h/.cc — SM model (~290 KB)
  • logic.h/.cc — FU, pipeline, decoders
  • array.h/.cc — ArrayST CACTI bridge

Memory Controllers

DRAM controller hierarchy and shared cache models for L2/L3 with directory support.

  • memoryctrl.h/.cc — MC front/backend/PHY/DRAM
  • sharedcache.h/.cc — L2/L3 unified arrays
  • DDR2/3, GDDR3/5 protocol support

Interconnect / NoC

On-chip network and wire/bus modeling with process-scaled delay and power.

  • noc.h/.cc — router or bus-based NoC
  • interconnect.h/.cc — CACTI Wire wrapper
  • VC buffers, crossbar, arbiter

I/O Controllers

Off-chip interface power models with empirical area/power scaling by process node.

  • iocontrollers.h/.cc — NIC, PCIe, Flash
  • NIUController: Ethernet MAC+PCS+SerDes
  • PCIeController: multi-lane PHY

XML Parsing

Configuration loading pipeline: low-level DOM parsing and high-level struct population.

  • xmlParser.h/.cc — lightweight XML DOM
  • XML_Parse.h/.cc — config → root_system
  • 44 performance counter enums

CACTI Array Bridge — ArrayST

// array.h (simplified) — iterative timing relaxation
class ArrayST : public Component {
public:
  InputParameter l_ip;
  uca_org_t local_result;    // CACTI solution (timing, area, power)

  ArrayST(const InputParameter* ip, string name,
          enum Device_ty dev, bool opt_local = true);

  // Relax timing constraints to find minimum-energy configuration
  virtual void optimize_array() {
    while ((throughput_overflow || latency_overflow)
           && cycle_time_dev > 10) {
      compute_base_power();     // Calls CACTI solver
      cycle_time_dev -= 10;     // Relax by 10%
      if (meets_timing) candidates.push_back(local_result);
    }
    local_result = *min_energy(candidates);
  }

  void leakage_feedback(double temperature);
};
