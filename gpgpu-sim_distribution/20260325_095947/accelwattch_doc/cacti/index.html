CACTI — Cache Area, Timing & Power Modeling

Analytical model for SRAM/DRAM/CAM access time, cycle time, area, and power

CACTI (HP Labs) exhaustively searches the cache partition design space—varying word-line divisions, bit-line divisions, mux degrees, and wire types—to find Pareto-optimal configurations for any given cache geometry and technology node.

📚 What is CACTI & why does it exist?

CACTI answers the fundamental question: “If I build a cache with these dimensions, how fast, how big, and how power-hungry will it be?” Given parameters like cache size, block size, associativity, and technology node, CACTI explores millions of internal partitioning options and returns the access time, cycle time, die area, dynamic power, and leakage power of the optimal design. AccelWattch calls into CACTI every time it needs to model a GPU cache, register file, TLB, or any on-chip SRAM/CAM array.

💡 Real-world analogy

Think of CACTI as an architect’s cost estimator for buildings. When a client says “I want a 50-story office tower with 200 rooms per floor,” the estimator doesn’t just guess—they evaluate different floor plans, structural beam arrangements, elevator placements, and HVAC layouts. Each combination yields different costs (price), construction time (delay), and floor area (chip area). CACTI does exactly this for caches: it tries every combination of row/column partitions, wiring strategies, and decoder topologies, then picks the design that best balances speed, area, and power. The “building materials” are transistors and wires at a specific technology node (e.g., 22 nm).

Architecture

Data Flow — Cache Parameter Search

When AccelWattch needs power/area/timing for a cache structure, it calls cacti_interface() which triggers an exhaustive multi-threaded search over the partition space.

sequenceDiagram
    participant AW as AccelWattch (ArrayST)
    participant CI as cacti_interface()
    participant UC as Ucache::solve()
    participant CT as calculate_time()
    participant MT as Mat
    participant SA as Subarray
    participant WR as Wire
    participant UCA as UCA (assemble)

    AW->>CI: cacti_interface(InputParameter)
    CI->>CI: init_tech_params(F_sz_nm)
    CI->>UC: solve(&fin_res)
    UC->>UC: spawn N threads
    loop For each (Ndwl, Ndbl, Nspd, Ndcm, Ndsam) partition
        UC->>CT: calculate_time(is_tag, partition_params)
        CT->>SA: Subarray(rows, cols, cell)
        SA-->>CT: cell area, C_wl, C_bl
        CT->>MT: Mat(subarray, decoders, wire)
        MT->>MT: compute_bitline_delay()
        MT->>MT: compute_sa_delay()
        MT->>WR: Wire(type, length)
        WR-->>MT: wire delay, wire power
        MT-->>CT: mat delay, mat power, mat area
        CT-->>UC: mem_array* result
    end
    UC->>UC: filter_tag_arr(min_values)
    UC->>UC: filter_data_arr(min_values)
    UC->>UCA: UCA(tag_arr, data_arr)
    UCA->>UCA: combine via Htree2 routing
    UCA-->>UC: uca_org_t (access_time, power, area)
    UC-->>CI: fin_res
    CI-->>AW: uca_org_t result

Example 1: Calling CACTI from AccelWattch

// array.cc — ArrayST calls CACTI to size an SRAM array
ArrayST::ArrayST(const InputParameter *ip, string name, ...) {
    l_ip = *ip;  // copy cache geometry into local InputParameter
    l_ip.error_checking();

    // Call CACTI solver — returns timing, area, power
    local_result = cacti_interface(&l_ip);

    // Extract results into Component base class fields
    area.set_area(local_result.area * 1e6);  // mm² → µm²
    power = local_result.power;
    delay = local_result.access_time;
    cycle_time = local_result.cycle_time;
}

Example 2: Multi-threaded Partition Search (solve)

// Ucache.cc — exhaustive search over partition space
void solve(uca_org_t *fin_res) {
    init_tech_params(g_ip->F_sz_um, false);

    list<mem_array *> tag_arr(0), data_arr(0);

    // Spawn N threads, each searching a slice of the
    // (Ndwl × Ndbl × Nspd × Ndcm × Ndsam) partition space
    calc_time_mt_wrapper_struct *calc_array =
        new calc_time_mt_wrapper_struct[nthreads];
    pthread_t threads[nthreads];

    for (uint32_t t = 0; t < nthreads; t++) {
        calc_array[t].tid      = t;
        calc_array[t].pure_ram = pure_ram;
        pthread_create(&threads[t], NULL,
                       calc_time_mt_wrapper, &calc_array[t]);
    }
    for (uint32_t t = 0; t < nthreads; t++)
        pthread_join(threads[t], NULL);

    // Merge results and filter dominated solutions
    filter_tag_arr(&data_min, tag_arr);
    filter_data_arr(data_arr);

    // Combine best tag + data arrays via UCA/Htree
    // → fin_res contains optimal (access_time, power, area)
}

Example 3: Wire Delay with Repeater Optimization

// wire.cc — optimal repeater insertion for global wires
void Wire::delay_optimal_wire() {
    double len = wire_length;
    double r = wire_res(len);   // total wire resistance
    double c = wire_cap(len);   // total wire capacitance

    // Elmore delay without repeaters: τ = 0.5·R·C
    // With repeaters: insert every spacing_opt with size_opt
    repeater_spacing = sqrt(
        2 * deviceType->R_nch_on * deviceType->C_g_ideal /
        (wire_res(1) * wire_cap(1)));
    repeater_size =
        sqrt(wire_res(1) * wire_cap(1) /
             (deviceType->R_nch_on * deviceType->C_g_ideal));

    // Calculate buffered wire delay
    delay = repeater_spacing * wire_res(repeater_spacing) *
            (wire_cap(repeater_spacing) +
             deviceType->C_g_ideal * repeater_size);
    power.readOp.dynamic = 0.5 * repeater_size *
        deviceType->C_g_ideal * g_tp.peri_global.Vdd *
        g_tp.peri_global.Vdd * (len / repeater_spacing);
}
