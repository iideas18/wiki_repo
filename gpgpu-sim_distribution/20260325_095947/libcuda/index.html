libcuda — CUDA Runtime API Interception

CUDA Runtime API Interception Layer

Implements libcudart.so as a drop-in replacement for the NVIDIA CUDA runtime. Every CUDA API call from the application is intercepted and redirected into the GPGPU-Sim cycle-level simulator — memory allocation, data transfer, kernel launch, and synchronisation all run on the simulated GPU.

💡 What is libcuda?

Analogy: Think of libcuda as a customs checkpoint at a border crossing. Every CUDA call from your application tries to "cross the border" to the GPU. Instead of reaching real hardware, libcuda intercepts the call and routes it to GPGPU-Sim's simulated GPU — inspecting every packet (argument), stamping it (creating kernel_info_t), and forwarding it to the simulation pipeline.

🚶 Step-by-Step Narrated Walkthrough

Follow a single cudaLaunch(myKernel) call as it flows through the libcuda pipeline:

  1. Fat Binary Registration — At program start, __cudaRegisterFatBinary() extracts PTX from the CUDA fat binary using cuobjdump and builds a symbol_table.
  2. Function Registration — __cudaRegisterFunction() maps the host-side function pointer to a function_info* in CUctx_st::m_kernel_lookup.
  3. Configure Call — cudaConfigureCall(gridDim, blockDim, sharedMem, stream) pushes a kernel_config onto g_cuda_launch_stack.
  4. Setup Arguments — Each cudaSetupArgument() appends a gpgpu_ptx_sim_arg (pointer, size, offset) to the top config's argument list.
  5. Launch Resolution — cudaLaunch(hostFun) looks up function_info* via the host function pointer and pops the kernel config from the stack.
  6. Kernel Info Creation — A kernel_info_t is built with grid/block dims, the function entry point, arguments, and the target stream ID.
  7. Texture Snapshot — Texture binding state is copied into kernel_info_t so the kernel sees a consistent view.
  8. Stream Enqueue — stream_manager::push() places a stream_operation of type stream_kernel_launch into the command queue.
  9. Simulation Thread — gpgpu_sim_thread_concurrent() dequeues the operation and calls gpu→launch(kernel).
  10. Cycle Simulation — gpgpu_sim::cycle() runs the shader pipeline and memory hierarchy until all CTAs complete.

Code Snippets

Kernel Launch — cudaLaunch() core logic

// cuda_runtime_api.cc — simplified cudaLaunch flow
cudaError_t cudaLaunch(const char *hostFun) {
  // 1. Resolve device function from host pointer
  CUctx_st *ctx = GPGPUSim_Context();
  function_info *entry = ctx->get_kernel(hostFun);

  // 2. Pop kernel_config from launch stack
  kernel_config config = g_cuda_launch_stack.back();
  g_cuda_launch_stack.pop_back();

  // 3. Create kernel_info_t with grid/block dims
  kernel_info_t *grid = new kernel_info_t(
      config.grid_dim(), config.block_dim(),
      entry, config.get_args());

  // 4. Enqueue into stream_manager
  stream_operation op(grid, sim_mode, config.get_stream());
  g_stream_manager->push(op);
  return cudaSuccess;
}

Memory Allocation — GPU address space

// Device memory allocation tracking
std::map<unsigned long long, size_t> g_mallocPtr_Size;

void *gpu_malloc(size_t size) {
  unsigned long long addr = m_dev_malloc;  // starts at GLOBAL_HEAP_START
  m_dev_malloc += size;
  // Align to 256 bytes
  if (size % 256) m_dev_malloc += (256 - size % 256);
  g_mallocPtr_Size[addr] = size;
  return (void *)addr;
}
