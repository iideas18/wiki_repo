GPGPU-Sim

Cycle-Level GPU Simulator for CUDA & OpenCL Workloads

GPGPU-Sim is a detailed, cycle-level simulator that models contemporary graphics processing units (GPUs) running compute workloads written in CUDA or OpenCL. It includes an interconnection network simulator (BookSim-based InterSim2), a configurable power model (AccelWattch/McPAT), and a performance visualization tool (AerialVision). GPGPU-Sim has been rigorously validated against real NVIDIA hardware from various generations.

🎯 Cycle-Level Accuracy 🔌 CUDA 4.2 – 11 ⚡ Accel-Sim Compatible 💡 AccelWattch Power Model

📚 What is this & why does it exist?

GPGPU-Sim is a research simulator that lets you run real CUDA and OpenCL programs on a virtual GPU, modeling every cycle of the hardware pipeline. It exists because studying GPU microarchitecture on real hardware is extremely difficult — the internals are proprietary and invisible. GPGPU-Sim makes the GPU transparent: every cache miss, every warp stall, every DRAM bank conflict is observable and configurable.

💡 Real-world analogy

Imagine you want to understand how a massive airport operates — from check-in to landing. You cannot observe the real airport’s internal systems directly, so you build a detailed scale model where every gate, runway, baggage conveyor, and control tower operates exactly as the real one does. You can now change the number of runways, add terminals, reroute baggage, and watch the exact second-by-second consequences. GPGPU-Sim is that scale model for GPUs: it replaces the opaque silicon chip with a transparent software replica.

Core Simulation Engine

gpgpu-sim

GPU Timing Simulation — Shader Cores, Caches, DRAM

The heart of the simulator: models shader core arrays with warp schedulers, multi-level cache hierarchy (L1/L2), DRAM timing with bank-level parallelism, and the scoreboard for dependency tracking. Drives cycle-by-cycle execution of GPU kernels.

46 files25.5k LOCCaches · DRAM · Scheduler

cuda-sim

PTX Functional Simulation — Instruction Decode & Execute

Functionally simulates PTX instructions: loads PTX binaries, builds an IR, and executes each instruction including memory operations, control flow, and special functions. Provides the functional correctness layer that feeds the timing model.

28 files24.5k LOCPTX · Warp Execution

Core Infrastructure

Hardware Abstraction, Entry Point & Stream Management

The foundational layer: abstract_hardware_model defines kernel, warp, and instruction abstractions; gpgpusim_entrypoint bootstraps simulation; stream_manager handles CUDA streams and concurrency; option_parser manages configuration.

15 files5.3k LOCAbstractions · Config

Interconnect & Power

InterSim2

Interconnection Network Simulator (BookSim-based)

A full NoC simulator integrated into GPGPU-Sim: models various network topologies (mesh, torus, butterfly, fat-tree, dragonfly), virtual-channel routers, arbitration schemes, and credit-based flow control. Simulates flit-level traffic between shader cores and memory partitions.

115 files26.6k LOC7 topologies · 5 allocators

AccelWattch

GPU Power Modeling Framework (McPAT/CACTI-based)

Models GPU power consumption using analytical models derived from McPAT and CACTI. Estimates dynamic and leakage power for processor cores, shared caches, memory controllers, NoC, and I/O controllers. Validated against NVIDIA Volta hardware.

72 files49.4k LOCMcPAT · CACTI · Volta-validated

Runtime Libraries & Tools

libcuda

CUDA Runtime API Interception Library

Intercepts CUDA API calls from applications and redirects them to the GPGPU-Sim simulator instead of real GPU hardware. Handles kernel launches, memory allocation, and device management.

7 filesCUDA API

libopencl

OpenCL Runtime API Interception

Provides OpenCL API compatibility, allowing OpenCL workloads to run on the simulated GPU. Translates OpenCL constructs to the internal simulation model.

2 filesOpenCL API

cuobjdump_to_ptxplus

CUDA Binary Disassembly & PTXPlus Conversion

Parses cuobjdump output to extract and convert CUDA binary code into PTXPlus format, enabling simulation of pre-compiled CUDA binaries and SASS instructions.

14 filesLex/Yacc parsers

AerialVision

Performance Visualization Tool

A Python-based GUI tool for visualizing GPGPU-Sim simulation output: warp activity, memory access patterns, IPC over time, and other performance metrics. Uses log file parsing and interactive plotting.

9 filesPython · GUI

How the Modules Connect — A Memory Request Journey

This diagram traces a single memory load instruction from the application layer through functional simulation, timing simulation, the interconnect, and DRAM — showing how all major modules collaborate.

    APP->>LIB: cudaMemcpy / kernel launch
    LIB->>SM: enqueue kernel to stream
    SM->>SH: dispatch thread blocks to cores
    SH->>FS: functional execute instruction
    FS-->>SH: effective address computed
    SH->>L1: issue memory request (mem_fetch)
    Note over L1: L1 HIT: return data in ~28 cycles
    L1->>ICNT: L1 MISS: inject request flit
    ICNT->>L2: route flit to memory partition
    Note over ICNT: Mesh/crossbar traversal ~20-100 cycles
    L2->>DR: L2 MISS: issue DRAM command
    DR-->>L2: data returned after tRAS+tCAS
    L2-->>ICNT: reply flit with data
    ICNT-->>L1: deliver to requesting core
    L1-->>SH: unblock waiting warp
    SH->>PW: report activity counters
    PW-->>SH: power/energy estimate
Key insight: The boundary between functional and timing simulation is critical: cuda-sim computes what happens (correct addresses, values), while gpgpu-sim determines when it happens (cycle-accurate timing). The interconnect (InterSim2) faithfully models the latency and contention of moving data between cores and memory. AccelWattch observes hardware activity counters to estimate power.

Build & Tech Stack
