pred — Branch Prediction

The pred/ module implements gem5’s modular branch prediction framework. It provides a BPredUnit wrapper that orchestrates the Branch Target Buffer (BTB), conditional direction predictor, indirect branch predictor, and Return Address Stack (RAS). Multiple predictor algorithms are available — from Atomic and Timing Simple CPUs — gem5 Wiki" href="../simple/index.html">simple 2-bit counters to state-of-the-art TAGE-SC-L — allowing researchers to study branch prediction accuracy and its impact on pipeline performance.

⚙ 8+ Algorithms 🔨 TAGE-SC-L 🚀 Modular Design 🎯 Perceptron

📚 What is this module?

Every time a processor encounters a branch instruction (if/else, loops, function calls), it must predict whether the branch will be taken and where it will go — before the branch is actually resolved. A wrong prediction causes a pipeline flush (squash), wasting 10–20+ cycles of work. Modern branch predictors achieve 95–99% accuracy, making them critical for performance. The pred/ module lets researchers implement and compare different prediction strategies.

💡 Real-world analogy: GPS Navigation

Think of branch prediction like a GPS that tries to guess your route at every intersection before you signal. The BTB is like the GPS’s map of known intersections — it remembers where you turned last time. The conditional predictor (TAGE, tournament, etc.) is the pattern-matching algorithm that says “you turned left here the last 7 out of 8 times, so probably left again.” The RAS is like the GPS knowing that after you enter a building (function call), you’ll come back out the same door (return address). When the GPS gets it wrong, you have to make a U-turn (pipeline squash) and go back to the right intersection. The better the GPS algorithm, the fewer U-turns you make — and the faster you reach your destination.

Prediction Architecture

The branch prediction system has a layered architecture. BPredUnit is the top-level wrapper that coordinates three sub-predictors: the BTB for target addresses, a conditional predictor for direction (taken/not-taken), and a RAS for return addresses. The IndirectPredictor handles indirect branches (jumps through registers) separately.

Prediction Flow

When the Fetch stage encounters a branch instruction, it queries BPredUnit::predict(). The prediction flow involves multiple lookups happening in parallel:

sequenceDiagram
    participant FE as Fetch Stage
    participant BPU as BPredUnit
    participant BTB as BTB
    participant COND as ConditionalPredictor
    participant RAS as RAS
    participant IND as IndirectPredictor

    FE->>BPU: predict(PC, staticInst)
    BPU->>BTB: lookup(PC)

    alt BTB hit — known branch
        BTB-->>BPU: target address, branch type
        alt Conditional branch
            BPU->>COND: lookup(PC, branchHistory)
            COND-->>BPU: taken / not-taken
        else Return instruction
            BPU->>RAS: pop()
            RAS-->>BPU: return address
        else Call instruction
            BPU->>RAS: push(PC + instSize)
            BPU->>COND: lookup(PC, branchHistory)
            COND-->>BPU: taken (calls usually taken)
        else Indirect jump
            BPU->>IND: lookup(PC, history)
            IND-->>BPU: predicted target
        end
    else BTB miss — unknown branch
        BTB-->>BPU: no entry
        Note over BPU: Predict not-taken (fall through)
    end

    BPU-->>FE: prediction result (taken, target)
    Note over FE: Store prediction in predHist for later update

    Note over FE,BPU: Later, when branch resolves at Commit:
    FE->>BPU: update(PC, actualTaken, actualTarget)
    BPU->>BTB: update(PC, target)
    BPU->>COND: update(PC, taken, history)

Deep-Dive Topics

TAGE Geometric History

TAGE uses N tagged tables, each indexed by a different history length following a geometric series (e.g., 5, 10, 20, 40, 80, 160 bits). Longer histories capture far-reaching correlations, while shorter histories handle recent patterns. The provider component with the longest matching history wins.

Statistical Corrector

The SC in TAGE-SC-L is a secondary predictor that corrects systematic errors in the TAGE prediction. It uses additional small tables indexed by different features (bias, local history, global history) and adjusts the TAGE output when confidence is low.

Perceptron Learning

The multiperspective perceptron uses a vector of integer weights trained with a simple perceptron learning rule. The dot product of weights and history features determines the prediction. Weights are incremented/decremented based on correct/incorrect predictions.

Speculative State Management

Branch predictors maintain speculative state (global history register, RAS pointer). On a squash, this state must be rolled back. BPredUnit maintains a predHist deque that stores prediction records keyed by sequence number for rollback.

BTB Organization

The BTB is a set-associative cache with configurable sets and ways. Each entry stores the branch PC tag, target address, and branch type (conditional, unconditional, call, return, indirect). BTB misses cause the predictor to default to “not taken.”

Return Address Stack

The RAS is a circular stack that pushes the return address on function calls and pops on returns. Speculative calls/returns modify the RAS speculatively; the RAS checkpoint mechanism allows rollback on misprediction.

Code Example: BPredUnit Predict

// Simplified view of BPredUnit::predict() from pred/bpred_unit.cc
bool BPredUnit::predict(const StaticInstPtr &inst, InstSeqNum seqNum,
                        PCStateBase &pc, ThreadID tid)
{
    BranchType brType = getBranchType(inst);
    bool btb_hit = btb->lookup(pc.instAddr(), brType, tid);

    bool pred_taken = false;
    const PCStateBase *target = nullptr;

    if (btb_hit) {
        target = btb->getTarget(pc.instAddr(), tid);

        if (inst->isReturn()) {
            // Use RAS for return prediction
            target = ras->pop(tid);
            pred_taken = true;
        } else if (inst->isCondCtrl()) {
            // Query conditional predictor
            pred_taken = condPredictor->lookup(pc.instAddr(),
                                                branchHistory);
        } else if (inst->isIndirectCtrl()) {
            // Query indirect predictor
            target = indirectPredictor->lookup(pc.instAddr(),
                                                branchHistory);
            pred_taken = true;
        } else {
            pred_taken = true;  // Unconditional branch
        }
    }

    if (inst->isCall())
        ras->push(pc.instAddr() + inst->size(), tid);

    // Record prediction for later update/squash
    predHist[tid].emplace_front(seqNum, pred_taken,
                                 condPredictor->getState(), ...);
    return pred_taken;
}
