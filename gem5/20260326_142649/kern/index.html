Architecture Overview

The kern module provides OS-specific type definitions, structure layouts, and kernel event handlers needed by gem5's syscall emulation (SE) and full-system (FS) modes. It defines the target-side view of syscall structures — struct stat, struct rusage, utsname, etc. — so the simulator can correctly marshal data between simulated user programs and host-side implementations.

The module is intentionally small (~2.6K LOC across 17 files), as it primarily defines data structures and event hooks rather than complex logic. Each OS subclass inherits from OperatingSystem and provides target-specific structure layouts that the syscall emulation layer uses for data marshalling.

stat Structures

Linux defines two stat structure variants, matching the kernel's 32-bit and 64-bit ABIs:

  • tgt_stat — 32-bit stat structure with st_dev, st_ino, st_mode, st_nlink, st_uid, st_gid, st_size, st_atime, etc.
  • tgt_stat64 — 64-bit stat structure with wider fields for large file support

Architecture-specific variants exist under kern/linux/ subdirectories for AArch32, AArch64, TrustZone security extensions, SVE/SVE2 vector processing, PMU, and hardware transactional memory." href="../arch_doc/arm/index.html">ARM, x86, MIPS, SPARC, and RISC-V, handling ABI differences like padding and field ordering.

Linux Kernel Events

In full-system mode, kern/linux/events.hh provides PC-based event hooks for kernel debugging:

🚨 PanicOrOopsEvent

Triggers when the kernel hits a panic() or oops() address. Configurable behaviour: halt simulation, print warning, or dump dmesg buffer. Controlled by KernelPanicOopsBehaviour enum.

📝 DebugPrintk

Template class that intercepts kernel printk() calls, extracting the format string and arguments from simulated memory for console output during boot.

📋 dumpDmesg

Helper function that reads the kernel log ring buffer (__log_buf) from simulated memory using SETranslatingPortProxy. Essential for diagnosing boot failures.

Deep Dive: Kernel Events

Function Skipping

SkipFuncBase enables the simulator to skip expensive or problematic kernel functions during full-system simulation. When the PC matches a registered address, the event handler manipulates the thread context to return from the function immediately:

sequenceDiagram
    participant CPU as CPU Core
    participant PC as PCEvent System
    participant SF as SkipFuncBase

    CPU->>PC: PC matches registered address
    PC->>SF: process(ThreadContext*)
    SF->>SF: Capture return address
    SF->>SF: Set PC = return address
    SF->>CPU: Continue execution (function skipped)

This mechanism is used to skip slow initialization routines, hardware probes, and other functions that would take millions of simulated cycles without contributing useful information.

Panic/Oops Handling

The PanicOrOopsEvent class responds to kernel panics with configurable actions:

BehaviourAction
PanicOnOopsHalt simulation immediately, dump dmesg
WarnOnOopsPrint warning, dump dmesg, continue simulation
IgnoreOnOopsSilently continue execution

Configuration & Usage

Syscall Emulation Mode

In SE mode, the kern module is used implicitly — when you create a Process with a Linux binary, the syscall emulation layer automatically uses the Linux class for structure marshalling. No explicit configuration is needed.

Full-System Mode

In FS mode, kernel event handlers are registered at boot time. Key configuration points:

ParameterLocationDescription
panic_on_oopsSystem configEnable PanicOrOopsEvent at kernel panic address
kernel_panic_oops_behaviourSystem configAction on panic: halt, warn, or ignore
skip_functionsSystem configList of kernel functions to skip during boot
kernel_addr_checkBoot loaderVerify kernel symbol addresses for event registration

// kern/freebsd/freebsd.hh
class FreeBSD : public OperatingSystem
{
  public:
    static bool isTtyReq(unsigned req)
    {
        switch (req) {
          case TIOCGETA:
          case TIOCSETA:
          case FIONREAD:
            return true;
          default:
            return false;
        }
    }
};
