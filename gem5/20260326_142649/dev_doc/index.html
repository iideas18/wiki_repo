    Module Overview

    📚 What is this & why does it exist?

    The dev module is gem5's hardware peripheral layer. In a real computer, the CPU communicates with devices (network cards, disks, GPUs) through memory-mapped I/O (MMIO) and DMA. The dev module models these interactions so that a full operating system can boot, discover hardware, load drivers, and run I/O workloads inside the simulator.

    💡 Real-world analogy

    Think of the dev module as a collection of virtual appliances plugged into a simulated motherboard. Just as your physical PC has a network card in a PCIe slot, a SATA disk, and a USB controller — each with its own registers and DMA engine — gem5's device models present the same register interfaces and transfer mechanisms. The OS running inside gem5 sees "real" hardware and uses its normal drivers, even though everything is happening in software.

    Data Flow

    Devices communicate with the CPU and memory through two fundamental mechanisms: Programmed I/O (PIO) and Direct Memory Access (DMA).

    sequenceDiagram
    participant CPU as CPU Core
    participant BUS as Memory Bus
    participant NIC as NIC Device
    participant DMAPORT as DMA Port
    participant RAM as System Memory

    Note over CPU,RAM: PIO Read — CPU reads a device register
    CPU->>BUS: ReadReq (device MMIO addr)
    BUS->>NIC: PioPort.recvAtomic(pkt)
    NIC->>NIC: read(pkt) — decode register
    NIC-->>BUS: Response with data
    BUS-->>CPU: Data returned

    Note over CPU,RAM: DMA Write — Device writes to host memory
    NIC->>DMAPORT: dmaWrite(addr, size, data)
    DMAPORT->>DMAPORT: ChunkGenerator splits request
    DMAPORT->>BUS: WriteReq (chunk 1)
    BUS->>RAM: Store data
    RAM-->>BUS: WriteResp
    BUS-->>DMAPORT: Response
    DMAPORT->>BUS: WriteReq (chunk 2)
    BUS->>RAM: Store data
    RAM-->>DMAPORT: Response
    DMAPORT->>NIC: completionEvent fired

    Note over CPU,RAM: Interrupt — Device signals CPU
    NIC->>NIC: intrPost()
    NIC-->>CPU: Interrupt delivered via Platform

    Narrated Walkthrough: Network Packet Reception

    Follow the journey of an Ethernet frame arriving at a simulated NIC, being DMA'd to memory, and triggering an interrupt for the guest OS to process:

    Packet arrives at EtherLink. The EtherLink::Link models a fixed-bandwidth wire. The packet is queued with a propagation delay calculated from ticksPerByte * pkt.length + linkDelay.
    Network Device Models | gem5 Wiki" class="xref">EtherInt delivers to NIC. The EtherInt interface calls recvPacket() on the NIC model (e.g., IGbE or NsGigE). The NIC stores the packet in an internal FIFO.
    NIC checks receive descriptor ring. The NIC reads the guest OS's receive descriptor ring from memory via DMA to find the next available buffer address.
    DMA read of descriptor. DmaPort::dmaAction(ReadReq, descAddr, ...) issues a memory read. The ChunkGenerator splits the request into Cache Hierarchy | gem5 Wiki" href="../mem_doc/cache/index.html">cache-line-sized chunks.
    Descriptor parsed. The NIC decodes the descriptor to obtain the host memory buffer address and length where the packet data should be placed.
    DMA write of packet data. dmaWrite(bufferAddr, pkt.length, data) initiates a DMA transfer. Each chunk travels through the memory bus to DRAM.
    Completion event fires. When all DMA chunks are acknowledged, the completionEvent fires, telling the NIC the transfer is done.
    NIC updates descriptor status. The NIC writes back the descriptor status (packet length, checksum flags) to the descriptor ring via another DMA write.
    Interrupt posted. The NIC calls intrPost() which routes through the PCI host and Platform to deliver an interrupt to the CPU model.
    Guest OS processes interrupt. The CPU's interrupt handler runs the NIC driver, which reads the completed descriptor, passes the packet up the network stack, and replenishes the receive ring.

    Glossary

    TermDefinition
    PIOProgrammed I/O — CPU directly reads/writes device registers via memory-mapped addresses
    DMADirect Memory Access — device reads/writes system memory without CPU intervention
    BARBase Address Register — PCI config space register that maps a device's memory/IO region
    MSI/MSI-XMessage Signaled Interrupts — PCI interrupt mechanism using memory writes instead of dedicated lines
    VirtQueueShared memory ring buffer used by VirtIO for guest-host data exchange
    MMIOMemory-Mapped I/O — device registers accessible at physical memory addresses
    ECAMEnhanced Configuration Access Mechanism — PCIe standard for config space addressing
