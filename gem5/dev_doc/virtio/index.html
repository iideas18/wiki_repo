virtio — VirtIO Device Framework

Paravirtualized Device Interface with VirtQueues

The virtio sub-module implements the VirtIO paravirtualized device standard for gem5. Instead of emulating complex real hardware, VirtIO provides a clean, efficient guest-host interface using shared-memory ring buffers (VirtQueues). It includes block storage, serial console, random number generator, and 9P filesystem sharing devices.

VirtQueue Block Device Console 9P / RNG

📚 What is this?

VirtIO is a standardized interface for paravirtualized devices in virtual machines. Unlike traditional device emulation (e.g., emulating a real Intel NIC register-by-register), VirtIO defines a Atomic and Timing Simple CPUs — gem5 Wiki" href="../../cpu_doc/simple/index.html">simple, efficient contract between guest and host. The guest knows it is virtualized and uses a specialized VirtIO driver to communicate through shared memory ring buffers. This dramatically reduces the overhead of device simulation.

💡 Analogy: A Translator / Interpreter

Imagine you need to communicate with someone who speaks a different language. The traditional approach (hardware emulation) is like pretending you speak their language — you laboriously translate every word and gesture to match their expectations. The VirtIO approach is like hiring a professional interpreter: both sides agree on a simple, efficient communication protocol. The guest says "here's a buffer with data I need written to disk" and the host processes it directly. No need to emulate register timing, bus protocols, or hardware quirks. The VirtQueue is the shared notebook the interpreter uses — a ring buffer where both sides can leave messages without waiting for the other.

    Descriptor Chains

    A single I/O request is represented as a chain of descriptors linked by their next field. Each descriptor in the chain can be either read-only (data flowing guest→host) or write-only (data flowing host→guest):

    // vring_desc structure (from virtio_ring.h)
struct vring_desc {
    uint64_t addr;   // Guest physical address of buffer
    uint32_t len;    // Length of buffer in bytes
    uint16_t flags;  // VRING_DESC_F_NEXT, VRING_DESC_F_WRITE, VRING_DESC_F_INDIRECT
    uint16_t next;   // Index of next descriptor in chain
};

// VirtDescriptor wrapper in gem5
class VirtDescriptor {
  public:
    Index index() const;           // Descriptor index in table
    bool isIncoming() const;       // Guest→Host (read-only)
    bool isOutgoing() const;       // Host→Guest (write-only)
    bool hasNext() const;          // More descriptors in chain
    VirtDescriptor *next() const;  // Next descriptor

    void read(off_t offset, uint8_t *dst, size_t size) const;
    void write(off_t offset, const uint8_t *src, size_t size);
    void chainRead(off_t offset, uint8_t *dst, size_t size) const;
    void chainWrite(off_t offset, const uint8_t *src, size_t size);
};

    Transport Mechanisms

    VirtIO MMIO

    MmioVirtIO (in dev/arm/vio_mmio.hh) exposes VirtIO devices through memory-mapped I/O registers. This is the primary transport for AArch32, AArch64, TrustZone security extensions, SVE/SVE2 vector processing, PMU, and hardware transactional memory." href="../../arch_doc/arm/index.html">ARM platforms. The guest accesses device registers at a fixed MMIO address, and notifications are delivered through a platform interrupt.

    VirtIO PCI

    PciVirtIO (in dev/virtio/pci.hh) exposes VirtIO devices as PCI devices. The device registers are mapped through PCI BARs, and interrupts use PCI INTx or MSI. This transport is used on x86 and other PCI-based platforms.

    // PciVirtIO — PCI transport for VirtIO devices
class PciVirtIO : public PciEndpoint {
  protected:
    VirtIODeviceBase &vio;  // The wrapped VirtIO device

    Tick readDevice(PacketPtr pkt) override;
    Tick writeDevice(PacketPtr pkt) override;

    // BAR0 register layout:
    // 0x00-0x13: Device features, queue select, queue notify
    // 0x14-0x17: Device status
    // 0x18-0x1F: ISR, config MSI vector
    // 0x20+:     Device-specific config
};

    Concrete Device Implementations

    VirtIOBlock — Block Storage

    Provides a paravirtualized block device (virtual disk). The guest sends read/write requests through VirtQueues, and the device processes them against a DiskImage backend (same as used by IDE).

    QueuePurpose
    Queue 0 (requestq)Block I/O requests: read, write, flush
    // VirtIOBlock request header
struct BlkRequest {
    uint32_t type;    // VIRTIO_BLK_T_IN (read), VIRTIO_BLK_T_OUT (write)
    uint32_t reserved;
    uint64_t sector;  // Starting sector number
    // Followed by data buffer descriptors
    // Last descriptor: 1-byte status (0=OK, 1=IOERR, 2=UNSUPP)
};

    VirtIOConsole — Serial Console

    Provides a paravirtualized serial console. Used for guest terminal I/O without emulating a full UART. Connects to gem5's Terminal for I/O.

    QueuePurpose
    Queue 0 (receiveq)Data from host → guest (keyboard input)
    Queue 1 (transmitq)Data from guest → host (console output)

    VirtIORng — Random Number Generator

    Provides a paravirtualized entropy source. The guest requests random bytes by submitting empty buffers; the host fills them with random data from the simulation's RNG.

    QueuePurpose
    Queue 0Buffers to fill with random data

    VirtIO9P — 9P Filesystem Sharing

    Implements the 9P2000.L protocol over VirtIO for sharing a host directory with the guest. This allows the guest to mount a host filesystem, which is extremely useful for sharing binaries and data with the simulated system without creating disk images.

    QueuePurpose
    Queue 0 (requestq)9P protocol messages (Tread, Twrite, Twalk, etc.)
    // Python configuration for 9P filesystem sharing
vio_9p = VirtIO9PProxy(
    root='/path/to/shared/directory',
    tag='gem5_shared'  // Guest mount tag
)
vio_9p_pci = PciVirtIO(vio=vio_9p)
system.pci_host.attach(vio_9p_pci)

// Guest mount command:
// mount -t 9p -o trans=virtio gem5_shared /mnt/host

    VirtIO Data Flow — Block Read Example

    sequenceDiagram
    participant GUEST as Guest Driver
    participant AVAIL as Available Ring
    participant DESC as Descriptor Table
    participant USED as Used Ring
    participant HOST as VirtIOBlock (Host)
    participant IMG as DiskImage

    GUEST->>DESC: Write descriptor chain: header + data buffer + status
    GUEST->>AVAIL: Add chain head index to available ring
    GUEST->>HOST: Kick (write to notify register)
    HOST->>AVAIL: Read new available index
    HOST->>DESC: Walk descriptor chain
    HOST->>DESC: Read BlkRequest header (type=READ, sector=N)
    HOST->>IMG: DiskImage.read(sector_N, data)
    IMG-->>HOST: Sector data
    HOST->>DESC: Write data to output descriptor
    HOST->>DESC: Write status byte (0 = success)
    HOST->>USED: Add chain head to used ring with byte count
    HOST->>GUEST: Raise interrupt
    GUEST->>USED: Read used ring entry
    GUEST->>GUEST: Process completed request

    Creating a New VirtIO Device

    To add a new VirtIO device type, inherit from VirtIODeviceBase and override the key methods:

    // my_virtio_device.hh
#include "dev/virtio/base.hh"

namespace gem5 {

class MyVirtIODevice : public VirtIODeviceBase
{
  public:
    MyVirtIODevice(const Params &p);

    // Unique VirtIO device ID (assigned by OASIS VirtIO TC)
    DeviceId deviceId() const override { return 0x42; }

  protected:
    // Called when guest kicks the queue
    void kick() override {
        // Consume descriptors from queue
        VirtDescriptor *desc;
        while ((desc = queue.consumeDescriptor()) != nullptr) {
            // Read request from input descriptor
            MyRequest req;
            desc->chainRead(0, (uint8_t*)&req, sizeof(req));

            // Process request...
            MyResponse resp = processRequest(req);

            // Write response to output descriptor
            desc->next()->chainWrite(0, (uint8_t*)&resp, sizeof(resp));

            // Return descriptor to guest
            queue.produceDescriptor(desc, sizeof(resp));
        }
        // Notify guest of completed requests
        kick_guest();
    }

  private:
    VirtQueue queue;
    MyResponse processRequest(const MyRequest &req);
};

} // namespace gem5
