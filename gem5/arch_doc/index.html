arch — Instruction Set Architectures

ISA-specific implementations providing instruction decoding, register definitions, fault handling, and MMU logic for each supported architecture.

💡 Think of it like…

The arch module is like a universal translator. The generic sub-module defines the grammar rules (base classes), while each ISA folder (x86, AArch32, AArch64, TrustZone security extensions, SVE/SVE2 vector processing, PMU, and hardware transactional memory." href="arm/index.html">ARM, RISC-V) is a specific language dictionary. When gem5's CPU core encounters a binary instruction, it hands it to the appropriate ISA translator to decode, execute, and handle any exceptions — all through the same standardized interface.

Architecture Overview

gem5 supports multiple instruction set architectures through a plugin-style design. The arch/generic directory defines abstract base classes (InstDecoder, BaseMMU, BaseISA, BaseTLB), and each ISA directory provides concrete implementations. This allows the CPU models to remain ISA-agnostic while still accurately modeling architecture-specific behavior.

ISA Plugin Pattern

gem5's ISA abstraction uses a combination of C++ virtual interfaces and build-system-level selection. At compile time, one or more ISAs are enabled via the build configuration. The CPU model calls generic methods on InstDecoder, BaseISA, and BaseMMU, which dispatch to the ISA-specific implementation.

Generic Base Classes

// arch/generic/decoder.hh
class InstDecoder : public SimObject
{
  protected:
    void *machInst;  // ISA-specific machine instruction

  public:
    // Feed bytes from instruction fetch
    virtual void moreBytes(const PCStateBase &pc, Addr fetchPC) = 0;

    // Check if a complete instruction is available
    virtual bool instReady() const = 0;

    // Decode and return a StaticInst
    virtual StaticInstPtr decode(PCStateBase &nextPC) = 0;

    // Reset decoder state (e.g., on branch)
    virtual void reset() {}
};
// arch/generic/mmu.hh
class BaseMMU : public SimObject
{
  public:
    enum Mode { Read, Write, Execute };

    BaseTLB *dtb;  // Data TLB
    BaseTLB *itb;  // Instruction TLB

    // Address translation
    virtual Fault translateAtomic(const RequestPtr &req,
        ThreadContext *tc, Mode mode) = 0;

    virtual void translateTiming(const RequestPtr &req,
        ThreadContext *tc, Translation *translation,
        Mode mode) = 0;

    // TLB maintenance
    virtual void flushAll() = 0;
    virtual void demapPage(Addr vaddr, uint64_t asn) = 0;
};

PC State Abstraction

Each ISA has a different program counter representation. x86 needs microcode PC tracking, ARM needs Thumb/ARM mode bits, and RISC-V needs compressed instruction awareness. PCStateBase provides the polymorphic interface.

class PCStateBase
{
  protected:
    Addr _pc = 0;
    Addr _npc = 0;
    MicroPC _upc = 0;
    MicroPC _nupc = 0;

  public:
    Addr pc() const { return _pc; }
    Addr npc() const { return _npc; }
    MicroPC upc() const { return _upc; }

    virtual PCStateBase *clone() const = 0;
    virtual void advance() = 0;
    virtual bool branching() const = 0;
};

Instruction Decode Pipeline

    participant CPU as CPU Frontend
    participant Dec as InstDecoder
    participant Cache as StaticInst Cache
    participant Exec as Execution Unit

    CPU->>Dec: moreBytes(pc, fetchPC)
    Dec->>Dec: Buffer and parse bytes
    CPU->>Dec: instReady()?
    Dec-->>CPU: true
    CPU->>Dec: decode(nextPC)
    Dec->>Cache: lookup machInst
    alt Cache hit
      Cache-->>Dec: Return cached StaticInst
    else Cache miss
      Dec->>Dec: Create new StaticInst
      Dec->>Cache: Insert into cache
    end
    Dec-->>CPU: StaticInstPtr
    CPU->>Exec: execute(StaticInst, ThreadContext)

🔍 Narrated Walkthrough: From Binary to Execution

  1. Fetch — The CPU frontend reads bytes from the instruction Cache Hierarchy | gem5 Wiki" href="../mem_doc/cache/index.html">cache at the current PC. For x86, this may be a variable number of bytes; for RISC-V, 2 or 4 bytes.
  2. Feed Decoder — Fetched bytes are passed to the ISA-specific InstDecoder::moreBytes(). The decoder accumulates bytes until a complete instruction is recognized.
  3. Decode — decode() converts the raw machine instruction into a StaticInst object. For x86, this may produce multiple microops. For ARM, it selects between ARM/Thumb/AArch64 decoding.
  4. Cache — Decoded instructions are cached to avoid redundant decoding. The cache is keyed by the machine instruction encoding.
  5. Execute — The StaticInst::execute() method is called with a ThreadContext, which provides access to registers, memory, and ISA state.
  6. Faults — If execution triggers an exception (page fault, illegal instruction), the ISA's fault class handles the trap, updating PC to the exception vector.

Fault Hierarchy

Each ISA defines its own fault classes inheriting from FaultBase. Faults represent architectural exceptions (page faults, interrupts, traps) and carry ISA-specific information for handler dispatch.

// Generic fault base
class FaultBase : public RefCounted
{
  public:
    virtual const char *name() const = 0;
    virtual void invoke(ThreadContext *tc,
                        const StaticInstPtr &inst) = 0;
};

typedef RefCountingPtr<FaultBase> Fault;
const Fault NoFault = nullptr;
