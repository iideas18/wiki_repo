riscv — RISC-V ISA Implementation

Modular RISC-V instruction set support with standard extensions (M/A/F/D/C/V), privilege modes, PMP/PMA security, and compressed instruction decoding.

📚 What is this & why does it exist?

💡 Think of it like…

RISC-V is like a LEGO set. The base integer ISA (RV64I) is the starter kit — simple, clean, and complete on its own. Each extension snaps on like an expansion pack: M (multiply/divide), A (atomic ops), F/D (floating point), C (compressed instructions for code density), and V (vector processing). gem5 assembles whatever combination you configure, with the decoder automatically handling 16-bit compressed and 32-bit standard instructions.

Instruction Decoder

The RISC-V decoder is comparatively simple — instructions are either 16-bit (compressed) or 32-bit (standard). The two lowest bits of the instruction determine the length: 00, 01, or 10 = compressed (16-bit); 11 = standard (32-bit).

namespace RiscvISA {

class Decoder : public InstDecoder
{
  public:
    void moreBytes(const PCStateBase &pc, Addr fetchPC) override;
    bool instReady() const override;
    StaticInstPtr decode(PCStateBase &nextPC) override;

  private:
    bool aligned;       // Instruction alignment state
    MachInst machInst;  // Current raw instruction

    // Determine instruction length from first 2 bits
    bool isCompressed(MachInst inst) const {
        return (inst & 0x3) != 0x3;
    }

    // Expand compressed instruction to 32-bit equivalent
    MachInst expandCompressed(MachInst inst) const;

    // Decode 32-bit instruction by major opcode
    StaticInstPtr decodeInst(MachInst mach_inst);
};

Privilege Modes

RISC-V defines three privilege modes, each with increasing levels of access to the hardware:

Machine Mode (M-mode)

The most privileged mode — always present. Handles hardware initialization, interrupt routing, and provides the foundation for all other modes. Has direct access to all CSRs and physical memory.

Supervisor Mode (S-mode)

Operating system kernel mode. Manages virtual memory (Sv39/Sv48 page tables), handles page faults, and provides system call interface for user mode.

User Mode (U-mode)

Unprivileged application mode. Cannot access M/S-mode CSRs or execute privileged instructions. Memory access is controlled by S-mode page tables.

namespace RiscvISA {

// Privilege levels
enum PrivilegeMode : uint8_t {
    PRV_U = 0,  // User
    PRV_S = 1,  // Supervisor
    PRV_M = 3   // Machine
};

// Key CSRs (Control and Status Registers)
enum CSRIndex {
    // Machine-level
    CSR_MSTATUS    = 0x300,
    CSR_MISA       = 0x301,  // ISA extensions present
    CSR_MEDELEG    = 0x302,  // Exception delegation
    CSR_MIDELEG    = 0x303,  // Interrupt delegation
    CSR_MIE        = 0x304,  // Interrupt enable
    CSR_MTVEC      = 0x305,  // Trap vector base
    CSR_MEPC       = 0x341,  // Exception PC
    CSR_MCAUSE     = 0x342,  // Exception cause
    CSR_MTVAL      = 0x343,  // Trap value

    // Supervisor-level
    CSR_SSTATUS    = 0x100,
    CSR_SATP       = 0x180,  // Page table base (Sv39/Sv48)

    // Performance counters
    CSR_CYCLE      = 0xC00,
    CSR_INSTRET    = 0xC02,
};

} // namespace RiscvISA

PMP and PMA

RISC-V provides two hardware security mechanisms for memory protection:

Physical Memory Protection (PMP)

PMP allows M-mode to restrict physical memory access for S/U modes. Up to 16 PMP entries define address regions with read/write/execute permissions.

// PMP configuration
struct PMPEntry {
    enum AddrMatch { OFF, TOR, NA4, NAPOT };
    AddrMatch addressMatching;
    bool locked;
    bool readable;
    bool writable;
    bool executable;
    Addr address;
};

class PMP : public SimObject
{
  public:
    static const int MAX_PMP_ENTRIES = 16;

    // Check access permission
    Fault checkAccess(Addr addr, int size,
                      BaseMMU::Mode mode,
                      PrivilegeMode priv) const;

  private:
    PMPEntry entries[MAX_PMP_ENTRIES];
};

Physical Memory Attributes (PMA)

PMA defines hardware attributes for memory regions — cacheability, atomicity support, and memory ordering. This ensures correct behavior for MMIO regions vs. normal memory.

🔍 Narrated Walkthrough: Handling a Page Fault

  1. Access — A load instruction in U-mode accesses virtual address 0x1000_0000. The MMU walks the Sv39 page table starting from satp.ppn.
  2. TLB Miss — The TLB doesn't have a translation. The page table walker reads the 3-level page table from memory.
  3. Fault Detection — The PTE's Valid bit is 0. This triggers a Load Page Fault (cause = 13).
  4. Delegation Check — M-mode checks medeleg. If bit 13 is set, the fault is delegated to S-mode. Otherwise, M-mode handles it.
  5. Trap Entry — The processor saves pc → sepc, cause → scause (13), faulting address → stval (0x1000_0000).
  6. Handler Jump — PC is set to stvec (S-mode trap vector). The OS page fault handler allocates a physical page, updates the page table, and executes SRET to resume.
