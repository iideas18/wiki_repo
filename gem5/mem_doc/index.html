    Overview

    Analogy

    Think of the gem5 memory system as a postal service. A CPU generates a Packet (letter), which travels through Ports (mailboxes). The letter may be intercepted by a Cache (a local post office that keeps copies of popular items), or it may travel all the way to DRAM (the central warehouse). The Ruby system adds a full coherence protocol network — like a fleet of delivery trucks following traffic rules to prevent duplicate deliveries.

    The src/mem/ directory contains all memory-related simulation models in gem5. It spans from the low-level Packet and Port abstractions through full cache hierarchies (Classic and Ruby), DRAM/NVM controllers, QoS policies, and memory probes.

    Narrated Walkthrough: Cache Miss Request

    Follow a ReadReq packet from the CPU through to DRAM and back:

    CPU issues load — The CPU pipeline creates a Packet with command ReadReq and calls sendTimingReq() on its data port.
    L1 DCache receives request — The CpuSidePort::recvTimingReq() handler in BaseCache begins processing.
    Tag lookup — The cache checks its tag array. The CacheBlk is looked up via the indexing policy (e.g., set-associative).
    Miss detected — No valid block found. The cache allocates an MSHR (Miss Status Holding Register) to track the outstanding request.
    Forward to L2 — The L1 sends the request downstream via its MemSidePort using sendTimingReq().
    L2 tag lookup — Same process repeats. If the L2 also misses, another MSHR is allocated.
    Coherent XBar routing — The crossbar receives the request and routes it to the appropriate memory controller based on address ranges.
    Memory controller queuing — The MemCtrl places the request in its read queue. QoS policies may reorder requests based on priority.
    DRAM access — The controller issues the DRAM command sequence: activate row, read column, precharge. Timing is modeled cycle-accurately.
    Response propagation — Data travels back: DRAM → MemCtrl → XBar → L2 → L1, each level filling its cache block.
    MSHR deallocation — As each cache level receives the response, it deallocates its MSHR and unblocks any waiting requests for the same block.
    CPU receives data — The L1 sends the ReadResp back to the CPU via sendTimingResp(), completing the memory access.

    Glossary

    MSHR
    Miss Status Holding Register — tracks outstanding cache misses and coalesces duplicate requests to the same block.
    Snooping
    A coherence mechanism where caches monitor (snoop) bus transactions to maintain data consistency.
    SLICC
    Specification Language for Implementing Cache Coherence — a domain-specific language used by Ruby to define protocols.
    Garnet
    A detailed on-chip network model within Ruby that models routers, links, and virtual channels.
    XBar
    Crossbar interconnect that routes packets between multiple ports based on address ranges.
    QoS
    Quality of Service — policies that prioritize or schedule memory requests based on requestor identity or priority.
    Clusivity
    Describes cache inclusion policy: inclusive (all L1 data in L2), exclusive (no duplication), or mostly-inclusive.
