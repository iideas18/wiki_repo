Architecture Overview

The systemc module provides a complete SystemC/TLM 2.0 integration layer for gem5, enabling mixed-language simulation. It contains three main components: the TLM bridge for bidirectional transaction translation, a SystemC kernel implementation that schedules SC processes within gem5's event-driven framework, and port wrappers that adapt gem5's port model to SystemC interfaces.

Deep Dive: Bridge Mechanics

Gem5ToTlmBridge Internals

The Gem5ToTlmBridge contains an inner BridgeResponsePort that receives gem5 packets. On each timing request:

  1. The response port calls packet2payload() to convert the gem5 Packet to a TLM generic payload
  2. Address, data pointer, data length, and command are mapped to TLM equivalents
  3. Custom conversion steps are applied (registered via addPacketToPayloadConversionStep())
  4. The payload is sent via nb_transport_fw() on the Atomic and Timing Simple CPUs — gem5 Wiki" href="../cpu_doc/simple/index.html">simple initiator socket
  5. On response, the payload is converted back and sent via sendTimingResp()

TlmToGem5Bridge Internals

The reverse bridge uses a simple_target_socket to receive TLM transactions and a BridgeRequestPort to inject gem5 packets:

  1. Incoming TLM transactions arrive at nb_transport_fw() callback
  2. payload2packet() creates a gem5 Packet with proper MemCmd and data
  3. A RequestorID is assigned for gem5's coherence tracking
  4. The packet is sent via sendTimingReq() on the request port
  5. Responses trigger nb_transport_bw() with TLM completion phase

Extensible Conversion

Both bridges support a pipeline of conversion steps, enabling custom protocol extensions:

Deep Dive: SystemC Kernel

The core/ subdirectory implements a complete SystemC kernel that runs within gem5's event-driven simulation engine. This enables native SystemC modules to execute alongside gem5 components.

Process Model

The Process class manages SC_THREAD and SC_METHOD execution using gem5's Fiber-based context switching. Key state management:

  • needsStart() — process hasn't been started yet
  • suspended() / resume() — manual suspend/resume control
  • disable() / enable() — sensitivity disable/enable
  • kill() / reset() — process termination and restart
  • Reference counting via incref() / decref() for safe lifecycle management

  • ScPortWrapper can bind to ScPortWrapper (port-to-port) or ScInterfaceWrapper (port-to-interface)

Gem5-to-TLM Packet Conversion

// tlm_bridge/gem5_to_tlm.cc — Convert gem5 packet to TLM payload
template <unsigned int BITWIDTH>
void Gem5ToTlmBridge<BITWIDTH>::packet2payload(
    PacketPtr pkt, tlm_generic_payload &trans)
{
    trans.set_address(pkt->getAddr());

    // Map gem5 command to TLM command
    if (pkt->isRead())
        trans.set_command(tlm::TLM_READ_COMMAND);
    else if (pkt->isWrite())
        trans.set_command(tlm::TLM_WRITE_COMMAND);
    else
        trans.set_command(tlm::TLM_IGNORE_COMMAND);

    // Set data pointer and length
    trans.set_data_ptr(pkt->getPtr<unsigned char>());
    trans.set_data_length(pkt->getSize());
    trans.set_streaming_width(pkt->getSize());

    // Run registered conversion steps
    for (auto &step : conversionSteps)
        step(pkt, trans);
}

Port Wrapper Binding

// sc_port_wrapper.hh — Type-safe port adapter
template <typename IF>
class ScPortWrapper : public gem5::Port
{
    sc_core::sc_port<IF> &port_;
  public:
    ScPortWrapper(sc_core::sc_port<IF> &p, const std::string &name)
        : gem5::Port(name), port_(p) {}

    void bind(Port &peer) override
    {
        // Bind to another ScPortWrapper or ScInterfaceWrapper
        auto *iface = dynamic_cast<ScInterfaceWrapper<IF>*>(&peer);
        if (iface) {
            port_.bind(iface->interface());
            return;
        }
        auto *other = dynamic_cast<ScPortWrapper<IF>*>(&peer);
        if (other) {
            port_.bind(other->port());
            return;
        }
        gem5::fatal("Incompatible port binding");
    }

    void unbind() override { gem5::panic("Cannot unbind sc_port"); }
};
