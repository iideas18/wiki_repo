📚 What is this & why does it exist?

The git utilities module is how Claude Code understands your project's version control state. It detects whether you're in a git repository, reads the current branch and commit, generates diffs to show what you've changed, and manages gitignore rules. Instead of running git commands for every query (slow!), it reads .git/ files directly and caches results using a file watcher—making it fast enough for real-time status updates in the terminal UI.

💡 Real-world analogy

Imagine a building's security control room with monitors and sensors. Instead of sending a guard to physically check every door and window (spawning git subprocesses), the control room has live feeds from sensors on the doors themselves (filesystem watchers on .git/HEAD, .git/refs/). It caches the "all clear" status and only re-checks when a sensor triggers (file changed). For detailed inspections (diffs), it does dispatch a guard—but with strict time limits and area restrictions to prevent delays.

Caching Strategy

The GitFileWatcher class implements a dirty-flag caching pattern that watches .git/ files with fs.watchFile(). When a watched file changes, the corresponding cache entry is marked dirty rather than immediately recomputed. The next read triggers recomputation, avoiding wasted work when files change multiple times between reads.

  participant C as Caller
  participant GFW as GitFileWatcher
  participant FS as .git/ Files
  participant Cache as LRU Cache (50)

  C->>GFW: getCachedBranch()
  GFW->>Cache: Check dirty flag
  alt Cache clean
    Cache-->>GFW: Cached value
    GFW-->>C: Branch name
  else Cache dirty (file changed)
    GFW->>FS: readFile(.git/HEAD)
    FS-->>GFW: ref: refs/heads/main
    GFW->>Cache: Update value, clear dirty
    GFW-->>C: "main"
  end
  Note over GFW,FS: fs.watchFile(1000ms) sets dirty flag on change

Security Considerations

The git utilities implement multiple security measures to prevent injection attacks and protect repository integrity when processing untrusted data from .git/ files. All external inputs (ref names, SHAs, URLs) are validated before use in filesystem operations or subprocess commands.

Ref Name Validation

All ref and branch names read from .git/ are validated by isSafeRefName() before use in any filesystem or subprocess operations. This prevents path traversal attacks (e.g., ../../etc/passwd) and argument injection (e.g., --upload-pack=evil). Only alphanumeric characters, /, ., _, +, -, and @ are allowed.

SHA Validation

isValidGitSha() accepts only 40-character hex strings (SHA-1) or 64-character hex strings (SHA-256). This strict validation prevents injection of arbitrary content into git commands that accept SHAs as arguments, ensuring that only legitimate commit identifiers can flow through the system.

URL Normalization

normalizeGitRemoteUrl() handles CCR (Code Collaboration Relay) proxy URLs in addition to standard SSH and HTTPS formats. The normalized form (host/owner/repo) is used for hashing to create anonymous repository identifiers that don't leak the actual URL. This normalization is critical for telemetry and analytics where repository identity must be consistent regardless of the access protocol used.

Worktree Support

The git utilities fully support git worktrees, which create multiple working trees from a single repository. This is critical for Claude Code users who work on multiple branches simultaneously. The worktree detection system correctly handles the .git file (not directory) that worktrees use, and resolves shared refs and config through the commondir mechanism.

Diff Engine Limits

The diff engine applies multiple limits to prevent memory exhaustion and timeouts when dealing with large repositories or massive changesets. These limits use a V8-aware strategy: '' + line is used instead of line.slice() to break sliced string references and allow garbage collection of the underlying large buffer.

Example: Reading HEAD Without Subprocess

// Filesystem-based HEAD reading — no git subprocess needed
export async function readGitHead(
  gitDir: string,
): Promise<{ type: 'branch'; name: string } | { type: 'detached'; sha: string } | null> {
  try {
    const content = await readFile(join(gitDir, 'HEAD'), 'utf8');
    const trimmed = content.trim();

    // Symbolic ref: "ref: refs/heads/main"
    if (trimmed.startsWith('ref: ')) {
      const ref = trimmed.slice(5);
      const branchPrefix = 'refs/heads/';
      if (ref.startsWith(branchPrefix)) {
        return { type: 'branch', name: ref.slice(branchPrefix.length) };
      }
    }

    // Detached HEAD: raw SHA
    if (isValidGitSha(trimmed)) {
      return { type: 'detached', sha: trimmed };
    }

    return null;
  } catch {
    return null;
  }
}

Example: Normalizing Remote URLs

// Normalizes SSH and HTTPS remote URLs to canonical form
export function normalizeGitRemoteUrl(url: string): string | null {
  // SSH: git@github.com:owner/repo.git
  const sshMatch = url.match(/^git@([^:]+):(.+?)(?:\.git)?$/);
  if (sshMatch) {
    return `${sshMatch[1]}/${sshMatch[2]}`;
  }

  // HTTPS: https://github.com/owner/repo.git
  try {
    const parsed = new URL(url);
    const path = parsed.pathname.replace(/\.git$/, '').replace(/^\//, '');
    return `${parsed.host}/${path}`;
  } catch {
    return null;
  }
}

Example: Two-Phase Diff with Quick Probe

// fetchGitDiff uses a two-phase approach for efficiency:
// Phase 1: Quick --shortstat probe (O(1) memory)
// Phase 2: Per-file --numstat only if probe passes limits

export async function fetchGitDiff(): Promise<GitDiffResult | null> {
  if (!await getIsGit()) return null;
  if (await isInTransientGitState()) return null;

  // Phase 1: Quick probe
  const shortstat = await execFileNoThrow(gitExe(), [
    'diff', 'HEAD', '--shortstat',
  ], { timeout: GIT_TIMEOUT_MS });

  const quickStats = parseShortstat(shortstat.stdout);
  if (quickStats && quickStats.filesCount > MAX_FILES_FOR_DETAILS) {
    return { stats: quickStats, perFileStats: new Map(), hunks: new Map() };
  }

  // Phase 2: Detailed numstat
  const numstat = await execFileNoThrow(gitExe(), [
    'diff', 'HEAD', '--numstat', '--no-renames',
  ], { timeout: GIT_TIMEOUT_MS });

  return parseGitNumstat(numstat.stdout);
}
