📚 What is this?

The tasks module is the background job scheduler for Claude Code. When you run a shell command, spawn a sub-agent, or kick off a cloud task, this module tracks it through a well-defined state machine (pending → running → completed/failed/killed), captures output, and provides UI pill labels for the REPL status bar.

💡 Analogy

Think of the tasks module as an air-traffic control tower. Each task is an aircraft: LocalShellTask is a small prop plane (bash command), LocalAgentTask is a passenger jet (sub-agent), RemoteAgentTask is a satellite-linked drone (cloud agent), and DreamTask is a weather balloon (background dream). The tower tracks all of them on its radar (TaskState), assigns runways (pending → running), and handles emergency landings (stopTask).

🚶 Step-by-Step Walkthrough: Running a LocalShellTask

Trace a bash command from creation to completion:

  1. Task creation — User runs a shell command; a LocalShellTask instance is created with state pending.
  2. State transition — The scheduler moves the task to running and spawns a child process.
  3. Output capture — stdout and stderr are streamed into the task's output buffer.
  4. Pill label update — pillLabel() generates a status badge shown in the REPL status bar.
  5. Process exit — The child process exits with code 0 → state becomes completed.
  6. Error path — If exit code is non-zero, state becomes failed with captured stderr.
  7. Kill path — If user presses Ctrl+C, stopTask() sends SIGTERM → killed.
  8. Cleanup — Resources (file descriptors, temp dirs) are released regardless of outcome.
  9. Result return — The REPL reads the final output buffer and displays results.
