Slash Command System

The commands module implements 86 slash commands that users can invoke in the Claude Code CLI. Commands range from simple utilities (/help, /clear) to complex workflows (/review, /install-github-app, /plugin). Each command exports a definition object with name, description, argument schema, and execution handler.

    U->>CP: types "/mcp add server-name"
    CP->>CP: parse slash prefix + args
    CP->>CR: getCommands() lookup by name
    CR-->>CP: matched Command object
    CP->>CH: invoke command handler(args, context)
    CH->>AS: mutate state (add MCP server)
    AS->>UI: re-render with updated config
    UI-->>U: display confirmation message

🚶 Step-by-Step Narrated Walkthrough

Follow a single /mcp add command as it flows through the entire Commands pipeline:

  1. User input — The user types /mcp add my-server --transport stdio -- node server.js in the CLI prompt.
  2. Slash detection — The input handler recognizes the / prefix and routes to command processing instead of sending to the LLM.
  3. Command lookup — getCommands() returns the memoized COMMANDS() array merged with skill-dir commands, plugin commands, and bundled skills. The mcp command is matched by name.
  4. Argument parsing — The command’s argument schema parses the subcommand (add), server name (my-server), transport type (stdio), and the remaining args as the server launch command.
  5. Permission check — isCommandEnabled() verifies the command is available in the current environment (e.g., not filtered by isUsing3PServices() or feature flags).
  6. Handler execution — The mcp command handler receives the parsed args and the LocalJSXCommandContext containing appState, setAppState, cwd, and UI hooks.
  7. Config mutation — The handler writes the new MCP server configuration to .claude/settings.json or the global config, then calls setAppState() to register the server.
  8. MCP connection — The MCP subsystem spawns the server process, performs the initialize handshake, and discovers available tools and resources.
  9. Tool pool update — assembleToolPool() is called to merge the new MCP tools with built-in tools, making them available for the next model turn.
  10. UI feedback — A confirmation message is rendered showing the server name, transport, and number of tools discovered.

Sub-Modules

📂 Session Management

Commands for controlling the conversation lifecycle, context window, and session persistence.

  • /clear — reset conversation
  • /compact — compress context
  • /resume — restore previous session
  • /session — session info & management
  • /exit — terminate CLI
  • /rename — rename current session
  • /share — share conversation link

⚙ Configuration

Adjust model, theme, permissions, effort level, output format, and other settings.

  • /config — view/edit settings
  • /model — switch active model
  • /theme — toggle light/dark
  • /effort — set reasoning effort
  • /permissions — tool permission rules
  • /output-style — response formatting
  • /sandbox-toggle — enable/disable sandbox
  • /vim — toggle vim keybindings

🔧 Tool & Plugin System

Manage MCP servers, plugins, skills, and hooks that extend Claude’s capabilities.

  • /skills — list/manage skills
  • /hooks — event hook management
  • /reload-plugins — refresh plugin cache

🔍 Code Review & Analysis

AI-powered review, diff inspection, security scanning, and export.
