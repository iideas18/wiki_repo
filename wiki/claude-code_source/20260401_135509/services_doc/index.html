🚶 Step-by-Step Narrated Walkthrough

Follow a single API request as it flows through the entire Services pipeline:

  1. Client Bootstrap — bootstrap.ts creates the Anthropic SDK client via createAPIClient(), configuring base URL, auth headers, and proxy settings from environment variables and OAuth tokens.
  2. System Prompt Construction — buildSystemPromptBlocks() in claude.ts assembles the system prompt from environment context, tool definitions, memory contents, and hook instructions into cacheable blocks.
  3. Message Conversion — userMessageToMessageParam() and assistantMessageToMessageParam() transform internal message objects into API-compatible parameters, stripping excess media items to stay within limits.
  4. Cache Optimization — addCacheBreakpoints() inserts cache_control markers at strategic points in the conversation. promptCacheBreakDetection monitors for cache invalidation events to optimize subsequent calls.
  5. Streaming Request — queryModelWithStreaming() sends the request through the SDK. The withRetry wrapper applies exponential backoff on transient 429/500 errors, respecting retry-after headers.
  6. Response Processing — As deltas stream in, each content block (text, tool_use, thinking) is yielded to the caller. updateUsage() accumulates input/output token counts and cost estimates in real time.
  7. Error Handling — handleAPIError() in errors.ts classifies failures into rate-limit, auth, overload, and network categories. extractQuotaStatusFromError() extracts quota metadata for UI display.
  8. Tool Execution — When tool_use blocks arrive, StreamingToolExecutor in tools/ orchestrates parallel tool calls. toolOrchestration.ts manages the execution queue and permission checks.
  9. MCP Tool Dispatch — For MCP tools, callMCPToolWithUrlElicitationRetry() in mcp/client.ts routes to the appropriate server. processMCPResult() transforms the response into the expected format.
  10. Auto-Compaction — After each turn, autoCompactIfNeeded() checks if the conversation exceeds getAutoCompactThreshold(). If so, compactConversation() summarizes older messages, preserving recent context and file attachments.
  11. Session Memory — Periodically, sessionMemory() spawns a background agent to extract key decisions and context into a markdown memory file using buildSessionMemoryUpdatePrompt().
  12. Analytics Logging — Throughout the pipeline, logEvent() queues telemetry events. attachAnalyticsSink() routes them to Datadog via datadog.ts and first-party storage via firstPartyEventLogger.ts, with PII stripping by stripProtoFields().

Sub-Modules

api/

20 files — Anthropic Claude API client with streaming responses, exponential backoff retries, prompt caching, and usage tracking. The largest service at 10,477 lines.

  • Streaming and non-streaming model queries
  • Prompt cache breakpoint management
  • Automatic retry with backoff on transient errors

mcp/

23 files — Model Context Protocol integration for server lifecycle, tool execution, resource access, and multi-scope configuration management.

  • Server connection with lazy caching
  • Tool invocation with OAuth elicitation retry
  • XAA identity provider and channel permissions

compact/

11 files — Conversation compaction system reducing token usage through message summarization, auto-triggering, and post-compaction context restoration.

  • Full, partial, and micro compaction strategies
  • Auto-compact threshold with token budget tracking
  • Session memory integration during compaction

analytics/

9 files — Queue-based event logging with PII protection, Datadog telemetry, GrowthBook feature flags, and first-party analytics exporting.

  • Sink-based architecture avoiding init blocking
  • PII field stripping before export
  • Cached feature flag and dynamic config access

SessionMemory/

9 files — Automatic session note-taking that periodically extracts key decisions and context into persistent markdown memory files.

  • Background agent-based memory extraction
  • Configurable extraction thresholds
  • Template-driven prompt construction

lsp/

7 files — Language Server Protocol client providing diagnostics, completion, goto-definition, and passive feedback via stdio-based communication.

  • Server lifecycle management and spawning
  • Diagnostic registry for tracking issues
  • Passive feedback collection for analytics

oauth/

5 files — OAuth 2.0 authentication for Claude.ai and console login with PKCE code-challenge flow, token exchange, and profile retrieval.

  • Authorization URL construction with PKCE
  • Local HTTP server for auth code callback
  • Token refresh and profile fetching

tools/

4 files — Streaming tool execution engine that orchestrates parallel tool calls with permission validation and result aggregation.

  • StreamingToolExecutor for real-time execution
  • Tool orchestration with execution queue
  • Hook integration for pre/post execution

plugins/

3 files — Plugin marketplace management with background installation, state tracking, and reconciliation of plugin definitions.

  • Background plugin installation manager
  • Marketplace diff and reconciliation
  • CLI command integration for plugin ops

Other Services

Supporting services for dream consolidation, durable memory extraction, tips, policy limits, remote settings, and team memory sync.

  • autoDream — Dream session background learning
  • extractMemories — Persistent project-scoped memories
  • policyLimits — Rate limit and quota enforcement
