💡 Think of it like…

Memdir is like a librarian who knows exactly which reference books are relevant to your current research question. When you start a new conversation turn, the librarian doesn’t dump the entire library on your desk — instead, they pull from three shelves: your personal notes (~/.claude/CLAUDE.md), the project documentation (./CLAUDE.md), and shared team knowledge (team memory paths). Using embedding-based search, the librarian ranks which memories are most relevant to what you’re working on right now, assembles them into a tidy briefing, and slides it into the system prompt before the AI ever sees your question.

This is what makes Claude Code “remember” your preferences, project conventions, and team standards across sessions — without needing explicit reminders each time.

Architecture

The memdir pipeline flows from user query through memory retrieval to system prompt injection. Each file plays a specific role in locating, ranking, and assembling memory content.

  UQ["User Query"] --> FRM["findRelevantMemories"]
  FRM --> MS["memoryScan"]
  MS --> P["paths.ts"]
  MS --> TMP["teamMemPaths"]
  P --> CMD["CLAUDE.md Files"]
  TMP --> CMD
  CMD --> MA["memoryAge"]
  MA --> MT["memoryTypes"]
  MT --> LMP["memdir.loadMemoryPrompt"]
  LMP --> TMP2["teamMemPrompts"]
  TMP2 --> SP["System Prompt"]

The architecture separates discovery (path resolution and scanning) from ranking (embedding search and freshness) and assembly (prompt generation). This allows each concern to evolve independently — for example, adding a new memory layer only requires updating the path resolution and scan phases.

Memory Layers

Memory content is organized into three hierarchical layers, each scoped to a different audience and persistence level. The layering ensures that personal preferences never leak into team context, while team standards are available to everyone.

Layer Precedence

When memories conflict across layers, the resolution order is: Project > Team > User. Project-level instructions take the highest priority because they represent the most specific context. User-level memories serve as defaults that apply when no project or team override exists.

Narrated Walkthrough

🚶 Step-by-Step: Loading Memory Context for a New Conversation Turn

Follow the memory loading pipeline from the moment a new turn begins:

  1. Turn Initiated — A new conversation turn begins. The system needs to assemble relevant memory context before constructing the system prompt for the LLM.
  2. Path Resolution — paths.ts resolves the locations of CLAUDE.md files. getMemoryPaths() returns the user-level path (~/.claude/CLAUDE.md) and the project-level path (./CLAUDE.md). isExtractModeActive() checks if extract mode changes the resolution strategy.
  3. Team Path Resolution — teamMemPaths.ts resolves shared team memory file locations, adding any team-scoped CLAUDE.md paths to the search set.
  4. Filesystem Scan — memoryScan.ts scans all resolved paths for CLAUDE.md files at user, project, and team levels. It reads file contents and collects raw memory blocks.
  5. Freshness Check — memoryAge.ts evaluates memory freshness. Stale memories (not recently accessed or updated) may be deprioritized or flagged for the relevance ranker.
  6. Type Resolution — memoryTypes.ts provides the type definitions that structure each memory object — source origin, metadata, content, and staleness indicators.
  7. Relevance Ranking — findRelevantMemories.ts uses feature flags and embedding-based search to rank which memories are most relevant to the current conversation context. Irrelevant memories are filtered out.
  8. Memory Assembly — memdir.ts calls loadMemoryPrompt() to assemble the ranked, filtered memories into a coherent memory prompt string.
  9. Team Prompt Generation — teamMemPrompts.ts generates additional prompt fragments from team memory content, ensuring shared team knowledge is represented.
  10. System Prompt Injection — The assembled memory prompt is injected into the system prompt, giving the AI assistant full context from all three memory layers before it processes the user’s message.
