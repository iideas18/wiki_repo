Introduction

🏣 Think of it like a Diplomatic Embassy

RemoteSessionManager is the ambassador — it maintains the diplomatic connection to the foreign runtime, managing credentials, lifecycle, and protocol. SessionsWebSocket is the secure communication channel — the encrypted telegraph line with auto-reconnect, heartbeat keepalive, and authentication handshake. remotePermissionBridge is the translator who converts foreign permission requests into the local language your CLI understands. And sdkMessageAdapter is the dispatch converter who reformats every incoming dispatch from the foreign embassy into the local government’s standard document format.

WebSocket Protocol

The WebSocket connection follows a strict handshake-then-stream protocol. The client authenticates immediately after connecting, then receives a continuous stream of SDK messages that are adapted for the local REPL. Permission requests arrive as out-of-band messages that interrupt the stream. Close code 4003 (unauthorized) triggers permanent disconnection, while transient code 4001 (session not found during compaction) triggers a reconnection attempt.

Narrated Walkthrough

🚶 Connecting to a Remote CCR Session & Handling a Permission Request

Follow a remote session from connection through permission handling:

  1. Session Init — The user starts a remote session. A RemoteSessionConfig is constructed with sessionId, getAccessToken callback, orgUuid, and flags like hasInitialPrompt and viewerOnly.
  2. Manager Setup — RemoteSessionManager registers callbacks (RemoteSessionCallbacks): onMessage, onPermissionRequest, onPermissionCancelled, onConnected, and onDisconnected.
  3. WebSocket Connect — SessionsWebSocket opens a connection to wss://api.anthropic.com/v1/sessions/ws/{id}/subscribe. The WebSocketState transitions from connecting to open.
  4. Authentication — Immediately after connection, the client sends an auth handshake message with the access token. The CCR backend validates and acknowledges.
  5. Keepalive Loop — A ping/pong heartbeat fires every 30 seconds. If the connection drops, SessionsWebSocket retries up to MAX_RECONNECT_ATTEMPTS=5. Permanent close codes (4003 unauthorized) abort reconnection; transient code 4001 (session compaction) triggers retry.
  6. Message Streaming — SDK messages arrive from the CCR. sdkMessageAdapter converts them via convertStreamEvent, convertAssistantMessage, convertResultMessage, convertInitMessage, convertStatusMessage, convertToolProgress, or convertCompactBoundary into REPL-compatible message objects.
  7. Permission Request Arrives — The CCR requests local permission for a tool the remote session wants to execute. remotePermissionBridge calls createSyntheticAssistantMessage() to build a fake AssistantMessage and createToolStub() because the local CLI may not have the tool definition.
  8. User Decision — The permission UI is presented. The user either allows (producing a RemotePermissionResponse with allow and updatedInput) or denies (with a message). The response flows back through the manager to the CCR.
  9. Session End — When the session ends, the onDisconnected callback fires. The WebSocket is closed cleanly and resources are released.
