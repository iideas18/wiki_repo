💡 Think of it like a restaurant order ticket

When a waiter writes down your order, the ticket captures everything at that moment — the specials available, your allergies, the kitchen's capacity. Even if the menu changes mid-service, your ticket stays consistent. QueryConfig works the same way: it snapshots feature gates, token limits, and model preferences at query creation time, ensuring every decision within that query sees the same configuration state. No mid-flight surprises.

Configuration

QueryConfig captures settings at creation time. The configuration is deeply frozen to prevent mid-query mutations. Below shows how a query config is constructed:

// QueryConfig creation from query-config.ts
export interface QueryConfig {
  readonly model: ModelIdentifier;
  readonly tokenBudget: {
    readonly maxInputTokens: number;
    readonly maxOutputTokens: number;
    readonly contextWindow: number;
  };
  readonly featureGates: Readonly<Record<string, boolean>>;
  readonly stopBehavior: 'graceful' | 'immediate';
  readonly retryPolicy: {
    readonly maxRetries: number;
    readonly backoffMs: number;
  };
}

export function createQueryConfig(
  userPrefs: UserPreferences,
  globalConfig: GlobalConfig
): Readonly<QueryConfig> {
  const gates = snapshotFeatureGates(globalConfig.gates);
  const budget = calculateTokenBudget(userPrefs.model, gates);
  return Object.freeze({
    model: resolveModel(userPrefs, gates),
    tokenBudget: Object.freeze(budget),
    featureGates: Object.freeze(gates),
    stopBehavior: gates['graceful-stop'] ? 'graceful' : 'immediate',
    retryPolicy: Object.freeze({ maxRetries: 3, backoffMs: 1000 }),
  });
}

The immutability guarantee means any component receiving a QueryConfig can cache derived values without worrying about stale state.
