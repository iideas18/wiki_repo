💡 Think of it like a city's zoning map

A city's zoning map doesn't build anything — it defines what can be built where. Residential zones here, commercial there, industrial over there, with strict rules about what crosses each boundary. The types/ module works the same way: it defines the shapes and boundaries of every data structure in Claude Code without containing any business logic. A SessionId can't accidentally become an AgentId — the branded type system acts like zoning enforcement. Commands, permissions, hooks, and plugins all have their shapes defined here, and every other module imports these definitions to stay within the zoning rules.

Deep-Dive Topics

🏷️ Command Types

The three command variants serve different execution paths. PromptCommand sends text to the model API (e.g., /ask). LocalCommand runs entirely on the client (e.g., /clear). LocalJSXCommand renders a React component inline (e.g., /config showing a settings form). Each variant carries its own argument schema, help text, and permission requirements. The command registry uses a discriminated union on the type field for exhaustive pattern matching.

🔐 Permission Model

Permissions are a three-layer system. Modes set the global posture (allow-all, deny-all, ask-each). Rules define per-tool overrides with glob patterns (e.g., "allow bash only in ~/projects/**"). Decisions are the resolved yes/no outcomes cached per session. The types are designed so that the permission resolver can short-circuit: if the mode is allow, skip rules entirely. If a rule matches, skip the interactive prompt.

Configuration & Code Examples

Branded ID Pattern

// ids.ts — Branded types prevent accidental ID mixing
declare const SessionIdBrand: unique symbol;
declare const AgentIdBrand: unique symbol;

export type SessionId = string & { readonly [SessionIdBrand]: typeof SessionIdBrand };
export type AgentId = string & { readonly [AgentIdBrand]: typeof AgentIdBrand };

// Factory functions are the only way to create branded IDs
export function createSessionId(raw: string): SessionId {
  return raw as SessionId;
}
export function createAgentId(raw: string): AgentId {
  return raw as AgentId;
}

// This is a compile-time error:
// const session: SessionId = createAgentId("agent-1"); // ❌ Type error!

// command.ts — Discriminated union for all command types
export type Command = PromptCommand | LocalCommand | LocalJSXCommand;

export interface PromptCommand {
  type: 'prompt';
  name: string;
  description: string;
  argSchema: z.ZodSchema;
  userFacingName: () => string;
  isEnabled?: () => boolean;
  isHidden?: boolean;
}

export interface LocalCommand {
  type: 'local';
  name: string;
  description: string;
  handler: (args: string[], context: CommandContext) => Promise<void>;

Permission Types

// permissions.ts — Three-layer permission model
export type PermissionMode = 'allow' | 'deny' | 'ask';

export interface PermissionRule {
  tool: string;                    // tool name or glob
  pattern?: string;                // file path glob
  decision: PermissionDecision;    // pre-set outcome
  scope: 'session' | 'project' | 'global';
}

export interface PermissionDecision {
  allowed: boolean;
  reason: string;
  timestamp: number;
  expiresAt?: number;             // optional TTL
}

export interface PermissionContext {
  mode: PermissionMode;
  rules: PermissionRule[];
  sessionDecisions: Map<string, PermissionDecision>;
}

Hook Schema

// hooks.ts — Zod-validated hook definitions
import { z } from 'zod';

export const HookEventSchema = z.enum([
  'onSessionStart', 'onSessionEnd',
  'onToolCall', 'onToolResult',
  'onModelResponse', 'onError',
  'onFileChange', 'onCommandRun',
]);

export const HookDefinitionSchema = z.object({
  event: HookEventSchema,
  matcher: z.record(z.unknown()).optional(),
  handler: z.string(),  // path to handler module
  priority: z.number().default(0),
  enabled: z.boolean().default(true),
});
