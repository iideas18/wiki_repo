💡 Think of it like a hotel front desk

When you check into a hotel, the front desk verifies your reservation, assigns a room, gives you a key card, and manages your stay until checkout. The server module works the same way: it receives a session creation request (check-in), validates credentials, allocates a session with a unique ID (room key), and manages the session lifecycle from creation through active use to graceful teardown (checkout). If anything goes wrong, it handles errors like a concierge resolving booking issues.

Configuration

The server module is configured through the DirectConnectConfig type, which specifies connection parameters and session behavior. Configuration is typically loaded from the application's global config:

// Session types from types.ts
export interface DirectConnectConfig {
  host: string;
  port: number;
  basePath: string;
  tls: {
    enabled: boolean;
    certPath?: string;
    keyPath?: string;
  };
  session: {
    maxConcurrent: number;
    idleTimeoutMs: number;
    heartbeatIntervalMs: number;
    maxLifetimeMs: number;
  };
  auth: {
    type: 'bearer' | 'api-key';
    validationEndpoint?: string;
  };
}

export interface CreateSessionRequest {
  apiKey: string;
  clientVersion: string;
  capabilities: string[];
  preferredModel?: string;
}

export interface CreateSessionResponse {
  sessionId: string;
  token: string;
  expiresAt: string;
  endpoints: {
    query: string;
    stream: string;
    cancel: string;
  };
}

export type SessionState =
  | 'creating'
  | 'active'
  | 'idle'
  | 'terminating'
  | 'terminated';

Default session timeout is 30 minutes of inactivity. The heartbeat interval of 30 seconds ensures that stale sessions are detected and cleaned up promptly. Maximum concurrent sessions can be configured per deployment.
