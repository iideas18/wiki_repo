🚶 Walkthrough — Tool Permission Decision

1

Tool Invocation Requested

The assistant runtime emits a tool-use event (e.g., file_write). The component tree receives this via the message stream and needs to decide whether to allow, deny, or prompt the user.

2

useCanUseTool Evaluates Policies

useCanUseTool is called with the tool name and arguments. It loads the permission policies from toolPermission/ and evaluates path rules, sandbox boundaries, and user trust settings.

3

Permission Dialog (if needed)

When the decision is ASK, the hook triggers the PermissionDialog component. The user sees the tool name, affected files, and risk level. Their choice is cached for the session.

4

Decision Propagation

The decision (allow / deny) propagates back through the hook's return value. The component that triggered the tool invocation reads the result and either proceeds with execution or shows a denial message.

5

State Update & Notification

The notifs/ hooks fire a toast notification confirming the action. useAssistantHistory records the decision in the conversation log for auditability.
