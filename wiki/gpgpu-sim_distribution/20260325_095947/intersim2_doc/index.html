InterSim2 — Interconnection Network Simulator

Cycle-Accurate On-Chip Network Simulation for GPGPU-Sim

InterSim2 is a cycle-accurate interconnection network (NoC) simulator integrated into GPGPU-Sim, based on Stanford’s BookSim 2.0. It models flit-level routing, virtual-channel flow control, switch allocation, and crossbar traversal across configurable topologies — connecting shader cores to memory partitions with faithful timing.

💡 Think of it like a Highway System

Imagine the GPU die as a city. Shader cores (SMs) are factories producing goods (memory requests), and memory partitions are warehouses. InterSim2 is the highway network connecting them. Each flit is a delivery truck, routers are highway interchanges, virtual channels are lane markings that prevent a stalled truck from blocking the entire road, and credits are “space available” signs that tell upstream interchanges when to send the next truck. The allocators are traffic lights deciding which truck goes through an intersection each cycle.

🚶 Step-by-Step: Tracing a Flit Through the Network

Follow a single memory read request flit from a shader core to a memory partition:

  1. Push (Injection) — GPGPU-Sim calls InterconnectInterface::Push(sm_id, mem_id, mem_fetch*, size). The device IDs are mapped to internal network node IDs via _node_map, and subnet 0 is selected (shader→memory direction).
  2. Packetization — GPUTrafficManager::_GeneratePacket() splits the request into n_flits = ceil(size / flit_size) flit objects. The first is marked head=true, the last tail=true. The original mem_fetch* is attached to the head flit’s data pointer.
  3. Input Queue — Flits are pushed to _input_queue[subnet][node][class]. During the next _Step(), the _Inject() method moves them into _partial_packets and writes the head flit onto the network injection channel.
  4. Channel Traversal (Source→First Router) — The flit enters a FlitChannel with configurable latency. After the channel delay, the flit is available at the first router’s input port via ReadInputs().
  5. Route Computation (RC) — IQRouter::_RouteEvaluate() calls the topology’s routing function (e.g., XY for mesh) on the head flit. The result is an OutputSet listing valid output ports and VC ranges. The VC transitions from idle → routing.
  6. VC Allocation (VA) — _VCAllocEvaluate() submits the head flit’s request to the VC allocator (e.g., iSLIP). The allocator matches input VCs to available output VCs. On success, VC state advances to vc_alloc → active.
  7. Switch Allocation (SA) — _SWAllocEvaluate() requests a crossbar input→output connection. The switch allocator (e.g., iSLIP/Wavefront) resolves contention among all VCs competing for the same output. The router checks BufferState::IsFullFor(vc) to ensure downstream credits are available.
  8. Switch Traversal (ST) — _SwitchEvaluate() moves the flit across the crossbar into the output buffer. For multi-flit packets, hold_switch_for_packet can keep the crossbar path reserved.
  9. Credit Return — As the flit departs the input buffer, a Credit object is sent back upstream on the credit channel. The upstream router’s BufferState::ProcessCredit() increments its credit counter, allowing future injections.
  10. Hop-by-Hop Repetition — Steps 4–9 repeat at each intermediate router along the route. For a 4×4 mesh with XY routing, a corner-to-corner packet traverses up to 6 hops.
  11. Ejection — At the destination router, the flit is written to the ejection channel. TrafficManager::_RetireFlit() collects latency statistics and calls WriteOutBuffer().
  12. Boundary Buffer Reassembly — Transfer2BoundaryBuffer() moves the flit into _boundary_buffer[subnet][node][vc]. The interface waits for all flits (head through tail) before marking the packet as complete.
  13. Pop (Delivery) — GPGPU-Sim calls InterconnectInterface::Pop(mem_id). The interface round-robins across VCs, finds the reassembled packet, and returns the original void* (mem_fetch*) pointer to the memory partition.

Sub-Modules

allocators/

Switch & VC allocation algorithms that resolve contention when multiple VCs compete for crossbar ports.

  • iSLIP iterative round-robin matching
  • Wavefront diagonal-sweep matching
  • Separable (input-first / output-first)
  • PIM, LOA, MaxSize, SelAlloc

arbiters/

Low-level arbitration primitives that select one winner from competing requests on a single resource.

  • RoundRobin — rotating priority
  • Matrix — NxN priority with fair convergence
  • Priority — strict priority
  • Tree — hierarchical for scalability

routers/

Router microarchitectures implementing the pipeline that moves flits through the network.

  • IQRouter — primary VC router (RC→VA→SA→ST)
  • ChaosRouter — adaptive deflection routing
  • EventRouter — event-driven simulation
  • Speculative allocation & NOQ support

networks/

Network topology definitions — each computes router/channel counts and builds the interconnect graph.

  • KNCube (mesh & torus)
  • FatTree, CMesh, FlatFly
  • Butterfly, Dragonfly, AnyNet
  • 10 topologies with per-topology routing

power/

Power and activity monitoring — tracks buffer/crossbar utilization for dynamic and leakage power estimation.

  • Power_Module — analytical power model
  • SwitchMonitor — crossbar activity factors
  • BufferMonitor — buffer R/W activity
  • Technology file parameterization

How InterSim2 Connects to GPGPU-Sim Core

The sole interface is InterconnectInterface, accessed via the global g_icnt_interface. Shader cores call Push() to inject memory requests and Pop() at memory partitions to retrieve replies. The reverse path works identically on subnet 1.
