📚 What is this?

The kernel module provides the oclgrind-kernel command-line tool — a standalone entry point for executing OpenCL kernels without writing an OpenCL host application. Instead of calling clCreateContext, clBuildProgram, clSetKernelArg, etc., you describe everything in a simple text file (a “sim file”), and the Simulation class orchestrates the entire lifecycle for you.

💡 Real-world analogy

Imagine you are a chef who normally works in a large restaurant kitchen (the full OpenCL host program) — with waiters taking orders, a cashier, and a seating host. Now imagine a tiny food truck with a single window. You hand in a recipe card (the sim file) listing the dish name and ingredients, and the truck cooks it immediately — no waiters, no seating chart, no cashier. That food truck is oclgrind-kernel: a stripped-down shortcut to get straight to the cooking (kernel execution) without the ceremony of the full restaurant (runtime API).

Module Architecture

The kernel module consists of two key components: a Simulation class that manages the entire kernel execution lifecycle, and a CLI entry point that translates command-line flags into environment variables understood by the core engine.

  end

  KI-->>SIM: Execution complete
  SIM->>SIM: dumpArgument() for each dump-flagged arg
  SIM-->>CLI: return
  CLI-->>User: Output results

Simulation File Format

The sim file is a plain-text format parsed by Simulation::load(). Lines starting with # are comments. The format is:

// Sim file structure (parsed by Simulation::load):
// Line 1: program file path  (e.g., "vecadd.cl" or "vecadd.bc")
// Line 2: kernel name         (e.g., "vecadd")
// Line 3: NDRange x y z       (e.g., "1024 1 1")
// Line 4: work-group size x y z (e.g., "64 1 1")
// Lines 5+: argument headers + data, one per kernel argument
//
// Argument header format:  <token token ...>
// Tokens: size=N, type (int/float/...), fill=V, range=S:I:E,
//         dump, hex, noinit, null, ro, wo

Example Sim File

// vecadd.sim — add two vectors of 8 floats
vecadd.cl          # OpenCL source file
vecadd             # Kernel name
8 1 1              # NDRange: 8 work-items
8 1 1              # Work-group size: single group of 8

# Argument 0: input buffer A (read-only, 8 floats filled with 1.0)
<float size=32 ro fill=1.0>

# Argument 1: input buffer B (read-only, range 0..7)
<float size=32 ro range=0:1:7>

# Argument 2: output buffer C (write-only, dump results)
<float size=32 wo noinit dump>

int main(int argc, char* argv[])
{
  // Step 1: Parse CLI flags and set environment variables
  if (!parseArguments(argc, argv))
    return 1;

  // Step 2: Create simulation (allocates Context)
  Simulation simulation;

  // Step 3: Load sim file (compile program, create kernel, parse args)
  if (!simulation.load(simfile))
    return 1;

  // Step 4: Execute the kernel and dump results
  simulation.run(outputGlobalMemory);
}

Argument Parsing — Header Token Processing

// Simplified from Simulation::parseArgument()
// Each argument has a header like: <float size=32 ro fill=1.0 dump>
void Simulation::parseArgument(size_t index)
{
  size_t size = SIZE_MAX;
  ArgDataType type = TYPE_NONE;
  bool dump = false, hex = false, noinit = false, null = false;
  string fill, range;

  // Read header tokens between < and >
  // Recognized tokens: char/uchar/.../double, size=N, fill=V,
  //   range=S:I:E, dump, hex, noinit, null, ro, wo

  // After parsing: allocate buffer, store initial data
  Memory* globalMemory = m_context->getGlobalMemory();
  size_t address = globalMemory->allocateBuffer(size, flags);
  globalMemory->store(data, address, size);

  // Bind argument to kernel
  m_kernel->setArgument(index, value);
}
