📚 What is the Extensions ecosystem?

Extensions are self-contained plugin packages that add capabilities to OpenClaw without modifying its core. Each extension declares its capabilities in a package.json manifest with an openclaw.extensions field and exports a single entry point that receives the OpenClawPluginApi registration object. The core never deep-imports extension internals — all communication flows through the Plugin SDK contract.

💡 Real-world analogy

Think of extensions like USB peripherals. Each device (extension) conforms to the USB spec (Plugin SDK), declares its device class (provider, channel, tool), and plugs into any compatible port. The OS (OpenClaw core) discovers capabilities through a standard descriptor (manifest) and routes traffic without knowing the device’s internal wiring. You can hot-plug new devices or remove them — the system keeps running.

Architecture

Extensions sit between external services and OpenClaw’s core gateway. The Plugin SDK provides the contract boundary — extensions import only from openclaw/plugin-sdk/* subpaths, never from src/** internals.

Extension Registration Flow

When OpenClaw boots, the plugin loader scans package.json manifests, resolves entry points, and calls each extension’s register(api) function. The registration API accumulates providers, channels, hooks, tools, and HTTP routes into the core registry.

sequenceDiagram
  participant Loader as Plugin Loader
  participant Manifest as package.json
  participant Entry as Extension Entry
  participant API as OpenClawPluginApi
  participant Registry as Core Registry
  Loader->>Manifest: Read openclaw.extensions[]
  Loader->>Entry: import default export
  Entry->>API: definePluginEntry({ id, register })
  API->>Entry: register(api) callback
  Entry->>API: api.registerProvider(...)
  Entry->>API: api.registerChannel(...)
  Entry->>API: api.registerHook(...)
  API->>Registry: Accumulate registrations
  Registry-->>Loader: Extension ready

🚶 Step-by-Step: Loading the OpenAI Extension

Follow a single extension from discovery to active registration:

  1. Discovery — Plugin loader reads extensions/openai/package.json and finds "openclaw": {"extensions": ["./index.ts"]}.
  2. Import — The loader dynamically imports the default export from extensions/openai/index.ts.
  3. Entry Definition — definePluginEntry() wraps the metadata (id, name, description) and the register callback into a DefinedPluginEntry object.
  4. API Injection — Core creates an OpenClawPluginApi instance scoped to this extension, with config, logger, and runtime context.
  5. Registration — The register(api) callback fires. OpenAI registers a provider via api.registerProvider(), a speech provider via api.registerSpeechProvider(), and image generation via api.registerImageGenerationProvider().
  6. Auth Setup — Each provider declares auth methods (API key, OAuth) with env vars, flag names, and setup wizards.
  7. Model Catalog — The provider contributes models to the global catalog via augmentModelCatalog and resolveDynamicModel.
  8. Stream Wiring — wrapStreamFn adds OpenAI-specific attribution headers to streaming requests.
  9. Ready — The gateway can now route LLM requests to OpenAI through the registered provider interface.

Shared Extension Contract

Every extension follows the same discovery and registration contract. The entry point exports a DefinedPluginEntry created by one of two helper functions depending on the extension type:

General Plugins — definePluginEntry()

// extensions/openai/index.ts
import { definePluginEntry } from "openclaw/plugin-sdk/plugin-entry";
import { buildOpenAIProvider } from "./openai-provider.js";
import { buildOpenAISpeechProvider } from "./speech-provider.js";
import { buildOpenAIImageGenerationProvider } from "./image-generation-provider.js";

export default definePluginEntry({
  id: "openai",
  name: "OpenAI Provider",
  description: "Bundled OpenAI provider plugins",
  register(api) {
    api.registerProvider(buildOpenAIProvider());
    api.registerSpeechProvider(buildOpenAISpeechProvider());
    api.registerImageGenerationProvider(buildOpenAIImageGenerationProvider());
    api.registerCliBackend(buildOpenAICodexCliBackend());
  },
});

Channel Plugins — defineChannelPluginEntry()

// extensions/telegram/index.ts
import type { ChannelPlugin } from "openclaw/plugin-sdk/core";
import { defineChannelPluginEntry } from "openclaw/plugin-sdk/core";
import { telegramPlugin } from "./src/channel.js";
import { setTelegramRuntime } from "./src/runtime.js";

export default defineChannelPluginEntry({
  id: "telegram",
  name: "Telegram",
  description: "Telegram channel plugin",
  plugin: telegramPlugin as ChannelPlugin,
  setRuntime: setTelegramRuntime,
});
