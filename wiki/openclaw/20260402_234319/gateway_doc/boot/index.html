Boot — Startup Orchestration

Gateway Initialization Pipeline

The Boot subsystem orchestrates Gateway startup — executing the one-shot bootstrap sequence from BOOT.md, negotiating mobile node capabilities, coordinating health checks, and restoring session state from previous runs.

What Is This & Why Does It Exist?

A Gateway that isn’t properly initialized can’t serve traffic safely. The Boot subsystem ensures all dependencies are ready, the workspace is configured, and health monitoring is active before the first client connects.

💡 Real-world analogy

Think of Boot as a spacecraft pre-launch checklist. runBootOnce() is mission control running through every system: fuel (credentials), navigation (routing tables), life support (health checks), and comms (WebSocket bindings). The BOOT.md file is the mission-specific runbook. If any check fails, the launch is scrubbed (BootRunResult.status: "failed") rather than risking a flawed mission.

Code Examples

Running the Boot Sequence

import { runBootOnce, BootRunResult } from './boot';

const result: BootRunResult = await runBootOnce({
  cfg: openClawConfig,
  deps: createDefaultDeps(),
  workspaceDir: '/home/user/.openclaw',
  agentId: 'main',
});

switch (result.status) {
  case 'ran':
    console.log('Boot completed successfully');
    break;
  case 'skipped':
    console.log(`Boot skipped: ${result.reason}`);
    break;
  case 'failed':
    console.error(`Boot failed: ${result.reason}`);
    process.exit(1);
}
