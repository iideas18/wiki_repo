Command Registry

Focus Deep-Dive

Dual-layer registration: CLI core commands and runtime plugin commands

OpenClaw maintains two command registries that work in concert. The CLI core registry lazy-loads 18 built-in commands on demand, while the plugin registry accepts dynamically registered commands from plugins at runtime. Together they form the complete command surface available to users across every channel.

📚 What is this & why does it matter?

The command registry is the single source of truth for "what commands exist." When a user types /doctor, the registry determines whether that command exists, loads its handler module on demand, and dispatches execution. Understanding the registry is critical for adding new commands, diagnosing lazy-load failures, or resolving conflicts between plugin and built-in commands.

💡 Real-world analogy

Think of a phone switchboard at a large company. The core registry is the permanent directory of internal extensions — always available, loaded on first call. The plugin registry is a guest directory: external contractors register their lines at check-in, and those lines are removed when they leave. Both directories feed into the same switchboard, and the operator (parser) routes calls to whichever directory has the matching extension.

Overview

Primary role

Map command names to handler functions, supporting both lazy-loaded CLI commands and dynamically registered plugin commands.

Main inputs

CoreCliEntry[] for built-in commands; OpenClawPluginCommandDefinition objects for plugin commands.

Key decisions

Lazy vs eager loading, duplicate detection, registry locking during execution, reserved name enforcement.

Outputs / side effects

Registered handlers reachable via pluginCommands Map or Commander.js program tree. No persistent state beyond memory.

How It Works

Phase 1 — CLI Core Registration

The coreEntries array defines 18 built-in commands. Each entry contains a descriptor (name + description) and an async register function that dynamically imports the command module and attaches it to the Commander.js program tree.

// src/cli/program/command-registry.ts — lazy registration pattern
const coreEntries: CoreCliEntry[] = [
  {
    commands: [{ name: "doctor", description: "Health checks + quick fixes",
                 hasSubcommands: false }],
    register: async ({ program }) => {
      const mod = await import("./register.doctor.js");
      mod.registerDoctorCommand(program);
    },
  },
  {
    commands: [{ name: "models", description: "Model selection, configuration, auth",
                 hasSubcommands: true }],
    register: async ({ program }) => {
      const mod = await import("./register.models.js");
      mod.registerModelsCommand(program);
    },
  },
  // ... 16 more entries: setup, onboard, configure, config, backup,
  //     dashboard, reset, uninstall, message, mcp, agent, agents,
  //     status, health, sessions, tasks
];

Phase 2 — On-Demand Lookup

// src/cli/program/command-registry.ts — name-based lazy load
export async function registerCoreCliByName(
  program: Command,
  ctx: ProgramContext,
  name: string,
  argv: string[] = process.argv,
): Promise<boolean> {
  const entry = coreEntries.find((candidate) =>
    candidate.commands.some((cmd) => cmd.name === name),
  );
  if (!entry) {
    return false;
  }
  removeEntryCommands(program, entry);
  await entry.register({ program, ctx, argv });
  return true;
}

// src/plugins/command-registration.ts — registration with validation
export function registerPluginCommand(
  pluginId: string,
  command: OpenClawPluginCommandDefinition,
  opts?: { pluginName?: string; pluginRoot?: string },
): CommandRegistrationResult {
  if (isPluginCommandRegistryLocked()) {
    return { ok: false, error: "Cannot register commands while processing is in progress" };
  }

  const definitionError = validatePluginCommandDefinition(command);
  if (definitionError) {
    return { ok: false, error: definitionError };
  }

  const invocationKeys = listPluginInvocationKeys(command);
  const key = `/${command.name.trim().toLowerCase()}`;

  for (const invocationKey of invocationKeys) {
    const existing = pluginCommands.get(invocationKey) ??
      Array.from(pluginCommands.values()).find((candidate) =>
        listPluginInvocationKeys(candidate).includes(invocationKey),
      );
    if (existing) {
      return { ok: false,
        error: `Command "${invocationKey.slice(1)}" already registered by plugin "${existing.pluginId}"` };
    }
  }

  pluginCommands.set(key, { ...command, pluginId, pluginName: opts?.pluginName, pluginRoot: opts?.pluginRoot });
  return { ok: true };
}

Code Walkthrough

State initialization — The plugin registry uses a global singleton to survive module re-imports. A Symbol.for key ensures exactly one instance across the process.

// src/plugins/command-registry-state.ts — singleton state
const PLUGIN_COMMAND_STATE_KEY = Symbol.for("openclaw.pluginCommandsState");

const getState = () =>
  resolveGlobalSingleton<PluginCommandState>(PLUGIN_COMMAND_STATE_KEY, () => ({
    pluginCommands: new Map<string, RegisteredPluginCommand>(),
    registryLocked: false,
  }));

Proxy-based access — The exported pluginCommands is a Proxy that delegates all operations to the singleton state. This allows callers to import and use the Map normally, even if the underlying singleton is created lazily.

// src/plugins/command-registry-state.ts — proxy delegation
export const pluginCommands = new Proxy(
  new Map<string, RegisteredPluginCommand>(),
  {
    get(_target, property) {
      const value = Reflect.get(
        getPluginCommandMap(), property, getPluginCommandMap()
      );
      return typeof value === "function"
        ? value.bind(getPluginCommandMap())
        : value;
    },
  },
);

Command name validation — Every name passes through validateCommandName(), which enforces a strict pattern: must start with a letter, contain only [a-z0-9_-], and not collide with any of the 30 reserved built-in names.

// src/plugins/command-registration.ts — name validation
export function validateCommandName(name: string): string | null {
  const trimmed = name.trim().toLowerCase();
  if (!trimmed) return "Command name cannot be empty";
  if (!/^[a-z][a-z0-9_-]*$/.test(trimmed)) {
    return "Command name must start with a letter and contain " +
           "only letters, numbers, hyphens, and underscores";
  }
  reservedCommands ??= new Set([
    "help", "commands", "status", "whoami", "context", "btw",
    "stop", "restart", "reset", "new", "compact", "config",
    "debug", "allowlist", "activation", "skill", "subagents",
    "kill", "steer", "tell", "model", "models", "queue",
    "send", "bash", "exec", "think", "verbose", "reasoning",
    "elevated", "usage",
  ]);
  if (reservedCommands.has(trimmed)) {
    return `Command name "${trimmed}" is reserved by a built-in command`;
  }
  return null;
}

Reserved Command Names

The following 30 names are permanently reserved by the built-in command system. Plugins that attempt to register any of these names receive a validation error.

Session control

help, commands, status, whoami, context, btw

Lifecycle

stop, restart, reset, new, compact, config

Security

debug, allowlist, activation, skill, subagents, kill

Communication

steer, tell, model, models, queue, send

Execution

bash, exec, think, verbose, reasoning, elevated, usage

Plugin Lifecycle & Teardown

When a plugin is unloaded — either during a hot-reload or because the user disabled it — all commands registered by that plugin must be removed. The registry provides two teardown functions:

// src/plugins/command-registry-state.ts — teardown
export function clearPluginCommands(): void {
  pluginCommands.clear();
}

export function clearPluginCommandsForPlugin(pluginId: string): void {
  for (const [key, cmd] of pluginCommands.entries()) {
    if (cmd.pluginId === pluginId) {
      pluginCommands.delete(key);
    }
  }
}

export function getPluginCommandSpecs(
  provider?: string,
): Array<{ name: string; description: string; acceptsArgs: boolean }> {
  const providerName = provider?.trim().toLowerCase();
  if (providerName && providerName !== "telegram"
      && providerName !== "discord") {
    return [];
  }
  return Array.from(pluginCommands.values()).map((cmd) => ({
    name: resolvePluginNativeName(cmd, provider),
    description: cmd.description,
    acceptsArgs: cmd.acceptsArgs ?? false,
  }));
}
⚠ Registry locking: The registryLocked flag is set to true while a command handler is executing. Any registration attempt during this window is rejected to prevent iterator invalidation on the pluginCommands Map. The lock is automatically released when the handler completes.
