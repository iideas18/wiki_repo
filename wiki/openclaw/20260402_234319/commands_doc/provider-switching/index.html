Commands/Provider Switching/ — Model & Provider Management

Model selection, authentication flows, and search provider configuration

The Provider Switching sub-module manages the complete lifecycle of LLM provider interactions. It handles model selection with availability probing, orchestrates multi-strategy authentication flows (API key, OAuth, plugin provider), configures fallback models, manages model aliases, and sets up search providers — all through both interactive wizards and non-interactive batch operations.

📚 What is this & why does it exist?

Provider Switching is how OpenClaw talks to different AI brains. Users can switch between models from OpenAI, Anthropic, and other providers on the fly. This sub-module handles all the complexity of setting up credentials, checking which models are available, falling back to alternatives when a primary model is down, and remembering user preferences through aliases.

💡 Real-world analogy

Imagine a travel agent (OpenClaw) who can book flights with multiple airlines (providers). When you say “I want to fly to Paris,” the agent checks which airlines have available seats (model probing), verifies your loyalty card is valid (auth flow), and if your preferred airline is sold out, automatically checks your backup airline (fallback). You can also set nicknames like “the fast one” for a specific flight number (aliases). The search provider setup is like adding a rental car company to your travel bundle.

Code Examples

Example: Auth Choice Application

export async function applyAuthChoice(
  params: ApplyAuthChoiceParams,
): Promise<ApplyAuthChoiceResult> {
  const handlers: Array<
    (p: ApplyAuthChoiceParams) => Promise<ApplyAuthChoiceResult | null>
  > = [
    applyAuthChoiceLoadedPluginProvider,
    applyAuthChoiceOAuth,
    applyAuthChoiceApiProviders,
  ];

  for (const handler of handlers) {
    const result = await handler(normalizedParams);
    if (result) return result;  // First match wins
  }

  return { config: normalizedParams.config };
}
