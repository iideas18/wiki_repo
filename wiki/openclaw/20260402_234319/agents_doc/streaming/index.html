Agents/Streaming/ — LLM Response Streaming Pipeline

Real-time LLM response streaming with provider-specific adapters

The streaming sub-module manages the real-time flow of LLM responses from 12+ providers through a unified pipeline. Each provider has dedicated stream wrappers that normalize vendor-specific SSE formats into a common chunk protocol, handle thinking/reasoning streams, manage cache retention headers, and provide graceful error recovery mid-stream.

📚 What is this & why does it exist?

The streaming pipeline handles the real-time delivery of AI responses. Instead of waiting for the entire response to generate, it delivers text token-by-token as the LLM produces it. Each provider (OpenAI, Anthropic, Google, etc.) sends data in a different format, so this module normalizes everything into a common protocol that the rest of OpenClaw can consume.

💡 Real-world analogy

Imagine a simultaneous translator at the United Nations. Delegates speak in different languages (providers), but listeners all hear through the same headset channel (unified stream). The translator (stream wrapper) converts each language in real-time, sentence-by-sentence, without waiting for the entire speech. If a speaker pauses or stumbles (backpressure/error), the translator smoothly manages the gap, perhaps repeating the last phrase or signaling a brief pause, rather than crashing the entire session.

Error Handling

The streaming pipeline handles errors at multiple levels:

Error TypeDetectionRecovery Action
Context OverflowestimateTokens() > context_window - reserveTrigger adaptive compaction
Rate LimitHTTP 429 or provider-specific signalCascade to fallback model
Auth FailureHTTP 401/403Mark auth profile in cooldown, try next
Stream Timeoutllm-idle-timeout.ts timer expiryAbort stream, retry with next provider
Malformed Tool ArgsJSON parse failureRepair via attempt.tool-call-argument-repair.ts
Unexpected StopStop reason mismatchRecovery via attempt.stop-reason-recovery.ts
Provider ErrorHTTP 5xx or connection resetCascade to fallback model
Abort SignalExternal cancellationGraceful shutdown via abort.ts (5s settle)
