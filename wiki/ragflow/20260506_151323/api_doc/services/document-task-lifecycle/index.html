Document Upload to Task Execution Lifecycle

End-to-end walkthrough of document upload, background task execution, progress tracking, and error handling in RAGFlow.

Overview: The Document Lifecycle

When a user uploads a document to RAGFlow, several systems coordinate:

  1. API Handler (apps/): Receives HTTP POST with file upload.
  2. DocumentService: Validates, creates Document row, saves file to S3/blob storage.
  3. TaskService: Creates Task row (status: pending), pushes to Redis queue.
  4. API Returns 202: Immediate response to client with task_id (no blocking).
  5. Background Executor: Polls Redis queue, pulls task, processes (parse PDF, tokenize, embed chunks).
  6. Progress Updates: Executor updates Task.progress_json, broadcasts via WebSocket.
  7. Completion: Executor marks Task.status = 'done', cleanup.

Phase 1: API Handler (File Upload)

Handler Code: POST /api/documents/upload

from quart import request, g
from apps.documents import document_bp

@document_bp.route('/documents/upload', methods=['POST'])
@auth_required
@multi_tenant_required
async def upload_document():
    '''Handle file upload, create document, queue task.
    
    Returns:
        202 Accepted with task_id and document_id
    '''
    # Validate request
    if 'file' not in request.files:
        return {'error': 'file required'}, 400
    
    file = request.files['file']
    if not file.filename:
        return {'error': 'filename required'}, 400
    
    # Get authenticated tenant
    tenant_id = g.tenant_id  # From auth middleware
    user_id = g.user_id
    
    # Call service (synchronous, blocking on DB writes only)
    doc_service = DocumentService()
    try:
        result = doc_service.upload(
            file=file,
            tenant_id=tenant_id,
            kb_id=request.args.get('kb_id')
        )
        document = result['document']
        task = result['task']
        
        return {
            'document_id': document.id,
            'task_id': task.id,
            'status': 'processing'
        }, 202  # Accepted, async processing started
        
    except ValidationError as e:
        return {'error': str(e)}, 400
    except Exception as e:
        logger.exception(f"Upload error: {e}")

class DocumentService(CommonService):
    def upload(self, file, tenant_id: str, kb_id: str = None):
        '''Upload document: create DB row, save file, create task.'''
        
        # 1. Validate inputs
        if not file or not file.filename:
            raise ValidationError('file required')
        
        allowed_types = {'pdf', 'docx', 'xlsx', 'txt', 'pptx'}
        file_ext = file.filename.split('.')[-1].lower()
        if file_ext not in allowed_types:
            raise ValidationError(f'type {file_ext} not allowed')
        
        # 2. Create Document row (DB transaction)
        document = None
        try:
            document = Document.create(
                tenant_id=tenant_id,
                name=file.filename,
                file_type=file_ext,
                created_by=g.user_id
            )
            self._logger.info(f"Created document {document.id}")
        except IntegrityError as e:
            self._logger.error(f"Failed to create document row: {e}")
            raise InternalError("database error")
        
        # 3. Save file to blob storage (S3 or local)
        try:
            file_path = self._save_file_to_storage(file, document.id)
            document.file_path = file_path
            document.save()
        except Exception as e:
            # Rollback: soft delete document
            document.deleted_at = datetime.now()
            document.save()
            self._logger.exception(f"Failed to save file: {e}")
            raise InternalError("file upload failed")
        
        # 4. Add to knowledge base if provided
        if kb_id:
            kb_service = KnowledgebaseService()
            kb_service.add_document(kb_id, document.id, tenant_id)
        
        # 5. Create processing task (DB + Redis queue)
        task_service = TaskService()
        task = task_service.create(
            doc_id=document.id,
            task_type='parse_and_embed',
            tenant_id=tenant_id
        )
        
        return {
            'document': document,
            'task': task

Phase 4: Background Executor (Processing)

Background Executor: Polling & Processing

#!/usr/bin/env python3
'''Background executor process: polls Redis queue, processes tasks.'''

import redis
import json
from db.db_models import Task, Document, Chunk
from db.services import ParsingService, ChunkService, TaskService

class TaskExecutor:
    def __init__(self):
        self.redis = redis.Redis(host='localhost', port=6379)
        self.chunk_service = ChunkService()
        self.parsing_service = ParsingService()
        self.task_service = TaskService()
    
    def run(self):
        '''Main loop: poll queue, process tasks.'''
        while True:
            try:
                # Pop task from queue (blocking, 5s timeout)
                task_json = self.redis.blpop('tasks:queue', timeout=5)
                if not task_json:
                    continue  # Timeout, loop again
                
                task_data = json.loads(task_json[1])
                self.process_task(task_data)
            except Exception as e:
                logger.exception(f"Executor error: {e}")
                time.sleep(1)  # Back off on error
    
    def process_task(self, task_data: dict):
        '''Process a single task: parse document, embed chunks.'''
        
        task_id = task_data['task_id']
        doc_id = task_data['document_id']
        task_type = task_data['task_type']
        
        try:
            # Load task from DB
            task = Task.get_by_id(task_id)
            tenant_id = task.tenant_id
            
            # Stage 1: Parsing
            self.task_service.update_progress(
                task_id, tenant_id,
                {'percent': 10, 'stage': 'parsing', 'message': 'Extracting text from document...'}
            )
            
            doc = Document.get_by_id(doc_id)
            text = self.parsing_service.parse_file(doc.file_path, doc.file_type)
            
            # Stage 2: Chunking
            self.task_service.update_progress(
                task_id, tenant_id,
                {'percent': 30, 'stage': 'chunking', 'message': f'Splitting into chunks...'}
            )
            
            chunks = self._split_text_into_chunks(text)
            
            # Stage 3: Embedding
            self.task_service.update_progress(
                task_id, tenant_id,
                {'percent': 50, 'stage': 'embedding', 'message': f'Embedding {len(chunks)} chunks...'}
            )
            
            embedded_chunks = []
            for i, chunk in enumerate(chunks):
                embedding = self._embed_text(chunk['content'])
                chunk['embedding'] = embedding
                embedded_chunks.append(chunk)
                
                # Update progress every 10 chunks
                if i % 10 == 0:
                    self.task_service.update_progress(
                        task_id, tenant_id,
                        {'percent': 50 + int(40 * i / len(chunks)), 'stage': 'embedding'}
                    )
            
            # Stage 4: Store in DB
            self.task_service.update_progress(
                task_id, tenant_id,
                {'percent': 90, 'stage': 'storing', 'message': 'Storing in database...'}
            )
            
            self.chunk_service.batch_create(doc_id, embedded_chunks, tenant_id)
            
            # Mark complete
            self.task_service.mark_done(
                task_id, tenant_id,
                result={'chunk_count': len(chunks)}
            )
            
            logger.info(f"Task {task_id} completed: {len(chunks)} chunks")
            
        except Exception as e:
            logger.exception(f"Failed to process task {task_id}: {e}")
            self.task_service.mark_error(task_id, task.tenant_id, str(e))

Phase 5: WebSocket Progress Streaming

WebSocket Handler: Stream Progress Updates

from quart import websocket, g

@app.websocket('/ws/tasks/')
@auth_required
async def stream_task_progress(task_id):
    '''Stream task progress updates via WebSocket.'''
    
    tenant_id = g.tenant_id
    
    # Validate task belongs to tenant
    try:
        task = TaskService().get(task_id, tenant_id)
    except EntityNotFound:
        await websocket.close(code=4004, reason='Task not found')
        return
    
    # Subscribe to Redis Pub/Sub channel for this task
    pubsub = redis_client.pubsub()
    pubsub.subscribe(f'task:{task_id}:progress')
    
    try:
        while True:
            # Receive progress update from Redis
            message = pubsub.get_message()
            if message and message['type'] == 'message':
                progress = json.loads(message['data'])
                
                # Send to WebSocket client
                await websocket.send_json({
                    'task_id': task_id,
                    'progress': progress,
                    'timestamp': datetime.now().isoformat()
                })
            
            # Check if task is done
            task = TaskService().get(task_id, tenant_id)
            if task.status in ['done', 'error']:
                await websocket.send_json({
                    'task_id': task_id,
                    'status': task.status,
                    'progress': task.progress_json
                })
                break
            
            await asyncio.sleep(0.1)  # Small delay to avoid busy loop
    
    except websocket.Closed:
        pass
    finally:
        pubsub.close()

Phase 6: Error Handling & Retry

Failure Scenarios

Scenario Detection Handling
File upload fails (disk full, S3 error) Exception in DocumentService._save_file_to_storage() Soft delete Document, return 500 to client
Task execution crashes (parsing error, OOM) Exception in TaskExecutor.process_task() Catch, mark Task.status = error, store error message in progress_json
Database deadlock during chunk insert IntegrityError('Deadlock') in ChunkService.batch_create() Retry with exponential backoff (3 attempts)
Executor crashes mid-task Task remains in processing state indefinitely Scheduled cleanup job: mark stale tasks (>1h) as error
WebSocket client disconnects websocket.Closed exception Cleanup pubsub subscription, close cleanly

State Machine Diagram

Task Lifecycle States:

pending ──────────────> processing ───> done
   ^                        |             ^
   |                        | error       |
   |                        v             |
   └─────────────────── error ────────────┘

Transitions:
- pending → processing: when executor pulls task from queue
- processing → done: when all chunks embedded and stored
- processing → error: when any step fails (parse, embed, store)
- error → pending: manual retry (admin API)

Performance Considerations

  • Async Handlers: API returns 202 immediately; document processing happens in background. Client polls task status or subscribes to WebSocket for updates.
  • Chunking Strategy: Split by sentence boundaries (preserve context), aim for ~512 tokens per chunk (balance between embedding cost and search granularity).
  • Batch Embedding: Embed chunks in parallel (e.g., 10 concurrent embedding requests) to reduce total time.
  • Database Indexing: Index Chunk.document_id, Chunk.embedding (vector index if using PostgreSQL pgvector) for fast retrieval.
  • Executor Scaling: Run multiple executor processes (separate servers or containers) to parallelize task processing.

Security & Multi-Tenancy

  • Tenant Isolation: Every step (Document, Task, Chunk) validates tenant_id. Missing check = data leak.
  • File Validation: Only allow whitelisted file types (PDF, DOCX, etc.). Validate file content (magic bytes) to prevent abuse.
  • Credential Handling: Embedding API credentials stored encrypted in DB, decrypted only when needed for executor.
  • Resource Limits: Max file size, max chunks per document, timeout on parsing/embedding to prevent DoS.

Future Enhancements

  • Prioritization: Support task priority levels (urgent tasks processed first).
  • Cancellation: Allow users to cancel in-progress tasks.
  • Checkpointing: Save progress periodically so executor can resume after crash (don't re-embed already-done chunks).
  • Cost Tracking: Log embedding costs per document, bill users.
  • Dead Letter Queue: Move failed tasks to DLQ for manual inspection after 3 retries.
