Schema Overview

RAGFlow's database schema is organized around five core entity groups:

  1. Multi-Tenancy Core: Tenant, User (belongs to Tenant)
  2. Content Management: Document, Chunk, KnowledgeBase, File
  3. Conversation/Dialog: Dialog, Conversation, Message
  4. Task Queue: Task (background processing state)
  5. Context & Settings: Memory, LLMModel, TeacherModel

All tables include standard audit columns:

  • id (Primary Key, UUID or autoincrement)
  • created_at (Timestamp, auto-set on insert)
  • updated_at (Timestamp, auto-set on update)
  • deleted_at (Optional, NULL = active, set for soft-deleted rows)
  • tenant_id (Foreign Key to Tenant, for multi-tenancy isolation)

Model Definitions & Field Types

Peewee models map to MySQL tables. Here's a detailed breakdown of schema:

Tenant (Multi-tenancy root)

class Tenant(BaseModel):
    id = CharField(primary_key=True, default=uuid4)
    name = CharField(unique=True, max_length=255)
    description = TextField(null=True)
    created_by = ForeignKeyField(User, backref='created_tenants')
    created_at = DateTimeField(default=datetime.now)
    updated_at = DateTimeField(default=datetime.now)

User (Authentication & multi-tenancy)

class User(BaseModel):
    id = CharField(primary_key=True, default=uuid4)
    email = CharField(unique=True, max_length=255)
    password_hash = CharField()  # bcrypt hash, never plaintext
    tenant_id = ForeignKeyField(Tenant, backref='users')
    is_active = BooleanField(default=True)
    is_admin = BooleanField(default=False)
    created_at = DateTimeField(default=datetime.now)
    updated_at = DateTimeField(default=datetime.now)

Document (Content entity)

class Document(BaseModel):
    id = CharField(primary_key=True, default=uuid4)
    tenant_id = ForeignKeyField(Tenant)  # Multi-tenancy
    name = CharField(max_length=255)
    file_type = CharField()  # 'pdf', 'docx', 'txt', etc.
    file_path = CharField()  # Path in S3/blob storage
    created_by = ForeignKeyField(User)
    created_at = DateTimeField(default=datetime.now)
    updated_at = DateTimeField(default=datetime.now)
    deleted_at = DateTimeField(null=True, default=None)  # Soft delete

Chunk (Document chunks with embeddings)

class Chunk(BaseModel):
    id = CharField(primary_key=True, default=uuid4)
    document_id = ForeignKeyField(Document)  # Parent document
    content = TextField()  # Text content
    tokens = IntegerField()  # Token count
    embedding = ListField()  # Vector (stored as JSON array)
    created_at = DateTimeField(default=datetime.now)
    deleted_at = DateTimeField(null=True)  # Soft delete with parent doc

Task (Background processing state)

class Task(BaseModel):
    id = CharField(primary_key=True, default=uuid4)
    tenant_id = ForeignKeyField(Tenant)
    document_id = ForeignKeyField(Document, null=True)
    task_type = CharField()  # 'parse_and_embed', 'fine_tune', etc.
    status = CharField(
        default='pending',
        choices=['pending', 'processing', 'done', 'error']
    )
    progress_json = JSONField(default={})  # Custom field type
    created_at = DateTimeField(default=datetime.now)
    updated_at = DateTimeField(default=datetime.now)

Foreign Key Relationships

RAGFlow's schema uses foreign keys to express entity relationships:

Tenant (1) ---> (N) User
    |
    +---> (N) Document
    |       |
    |       +---> (N) Chunk
    |       |
    |       +---> (1) Task
    |
    +---> (N) Dialog
            |
            +---> (N) Conversation
                    |
                    +---> (N) Message

Document (1) ---> (N) KnowledgeBase (join table)
LLMModel (1) ---> (N) Dialog (config link)

Referential Integrity Rules:

  • ON DELETE CASCADE: Delete Tenant → delete all Users, Documents, Tasks, Dialogs in that tenant.
  • ON DELETE CASCADE: Delete Document → delete all Chunks, Tasks for that document.
  • ON DELETE CASCADE: Delete Dialog → delete all Conversations and Messages.
  • ON DELETE SET NULL: Delete User → set Message.user_id = NULL (preserve message history).

Custom Peewee Field Types

RAGFlow defines custom field types to handle complex data types in a portable way (works on MySQL and PostgreSQL).

JSONField (Semi-structured data)

class JSONField(TextField):
    '''Store Python dict/list as JSON, deserialize on fetch.'''
    
    def python_value(self, value):
        if value is None:
            return None
        return json.loads(value) if isinstance(value, str) else value
    
    def db_value(self, value):
        if value is None:
            return None
        return json.dumps(value)

# Usage:
task.progress_json = {'percent': 50, 'stage': 'embedding'}
task.save()

# When fetched, progress_json is automatically deserialized to dict:
fetched_task = Task.get_by_id(task_id)
progress = fetched_task.progress_json  # Already a dict, not JSON string

ListField (Arrays as JSON)

class ListField(JSONField):
    '''Store Python list as JSON array.'''
    
    def python_value(self, value):
        result = super().python_value(value)
        return result if isinstance(result, list) else []
    
    def db_value(self, value):
        return super().db_value(value if isinstance(value, list) else [])

# Usage:
doc.tags = ['important', 'finance', '2024-q4']
doc.save()

SerializedField (Object serialization)

import pickle

class SerializedField(TextField):
    '''Store Python object using pickle or JSON.'''
    
    def __init__(self, use_json=False, **kwargs):
        super().__init__(**kwargs)
        self.use_json = use_json
    
    def python_value(self, value):
        if value is None:
            return None
        if self.use_json:
            return json.loads(value)
        return pickle.loads(value)
    
    def db_value(self, value):
        if value is None:
            return None
        if self.use_json:
            return json.dumps(value)
        return pickle.dumps(value)

# Usage:
context = ConversationContext()
context.state = {'user_id': 123, 'prefs': {...}}
context.save()

Migration Patterns

RAGFlow uses Peewee migrations for schema changes. Typical workflow:

# Create new migration:
python manage.py makemigrations --name add_document_tags

# Review generated migration file in db/migrations/:
# 001_initial_schema.py
# 002_add_user_roles.py
# 003_add_document_tags.py (new)

# Apply migrations:
python manage.py migrate

# Rollback (undo last migration):
python manage.py migrate 002_add_user_roles

Best practices for migrations in production:

  • Backward compatibility: Add new columns as NULL-able or with defaults. Never drop columns without backfill.
  • Zero-downtime: Deploy app that reads both old and new columns, then migrate DB, then app code only uses new column.
  • Test on staging: Run migration on staging DB first, verify no data loss or performance degradation.
  • Rollback plan: Keep migrations reversible (down() methods) in case rollback needed.

Connection Pooling

RAGFlow uses Peewee's built-in connection pool to manage concurrent DB connections:

# Initialize database with pool:
from playhouse.pool import PooledMySQLDatabase

database = PooledMySQLDatabase(
    'ragflow_db',
    host='localhost',
    port=3306,
    user='root',
    password='...',
    max_connections=20,
    timeout=5  # Seconds to wait for connection from pool
)

# Pool behavior:
# 1. App server has N concurrent workers (e.g., 10 Gunicorn workers)
# 2. Each worker borrows a connection from pool when needed
# 3. Worker executes query, returns connection to pool
# 4. If all 20 connections in use, next request waits up to 5s
# 5. Timeout expires -> ConnectionTimeoutError

Tuning connection pool size:

  • Small (10–15): Development, low concurrency. Risk: pool contention under load.
  • Medium (20–30): Standard production (10–20 app workers). Good balance.
  • Large (40+): High concurrency or slow queries that hold connections longer. Monitor memory.

Deadlock Retry Pattern

MySQL InnoDB can deadlock when two transactions lock the same rows in opposite order:

import random
from peewee import IntegrityError

def retry_on_deadlock(max_retries=3, base_delay=0.1):
    '''Decorator: retry query on deadlock with exponential backoff.'''
    def decorator(func):
        def wrapper(*args, **kwargs):
            for attempt in range(max_retries):
                try:
                    return func(*args, **kwargs)
                except IntegrityError as e:
                    if 'Deadlock' in str(e) and attempt < max_retries - 1:
                        delay = base_delay * (2 ** attempt) + random.uniform(0, 0.1)
                        print(f"Deadlock on attempt {attempt + 1}, retrying in {delay:.2f}s")
                        time.sleep(delay)
                    else:
                        raise
        return wrapper
    return decorator

# Usage:
@retry_on_deadlock(max_retries=3)
def update_document_and_task(doc_id, task_id):
    '''Atomically update document and create task.'''
    with database.atomic():
        doc = Document.get_by_id(doc_id)
        doc.status = 'processing'
        doc.save()
        
        Task.create(document_id=doc_id, status='pending')

Query Optimization & Indexing

Performance-critical queries need indexes on frequently-filtered columns:

class Document(BaseModel):
    id = CharField(primary_key=True)
    tenant_id = ForeignKeyField(Tenant)  # Index: list by tenant
    created_by = ForeignKeyField(User)   # Index: list by user
    created_at = DateTimeField()          # Index: date range queries
    deleted_at = DateTimeField(null=True) # Index: filter active docs
    
    # Composite indexes for common queries:
    # (tenant_id, deleted_at) - list active docs in tenant
    # (tenant_id, created_at) - list by tenant ordered by time

# SQL:
# ALTER TABLE document ADD INDEX (tenant_id);
# ALTER TABLE document ADD INDEX (created_by);
# ALTER TABLE document ADD INDEX (deleted_at);
# ALTER TABLE document ADD INDEX (tenant_id, deleted_at);

Query optimization techniques:

  • Use indexes: Filter by indexed columns (tenant_id, created_by, created_at, deleted_at).
  • Pagination: Use LIMIT + OFFSET for large result sets. Avoid fetching all rows.
  • Selective fields: Use SELECT * or select(Model.id, Model.name) to fetch only needed columns.
  • Eager loading: Use prefetch() to batch-load related entities (avoid N+1 queries).
  • Query analysis: Use EXPLAIN to see execution plan, verify indexes are used.

Soft Delete Implementation

Soft deletes preserve data while marking it as inactive. Implementation details:

class BaseModel(Model):
    '''Base for all models.'''
    deleted_at = DateTimeField(null=True, default=None)
    
    def soft_delete(self):
        '''Mark as deleted without removing from DB.'''
        self.deleted_at = datetime.now()
        return self.save()
    
    def restore(self):
        '''Restore a soft-deleted entity.'''
        self.deleted_at = None
        return self.save()
    
    @classmethod
    def active(cls):
        '''Query only active (not soft-deleted) rows.'''
        return cls.select().where(cls.deleted_at.is_null())
    
    @classmethod
    def deleted(cls):
        '''Query only soft-deleted rows.'''
        return cls.select().where(cls.deleted_at.is_not_null())

# Usage:
# Soft delete document
doc = Document.get_by_id(doc_id)
doc.soft_delete()

# Query only active documents
active_docs = Document.active().where(Document.tenant_id == tenant_id)

# Restore deleted document
deleted_doc = Document.deleted().get(Document.id == doc_id)
deleted_doc.restore()

Benefits of soft deletes:

  • Preserves referential integrity (chunks still reference deleted documents)
  • Enables undo/restore operations
  • Supports audit trails (know when entities were deleted)
  • Simplifies cascading deletes (no need for ON DELETE CASCADE)

Drawbacks:

  • Storage overhead (soft-deleted rows take up space)
  • Query complexity (must always filter deleted_at.is_null())
  • Data privacy concerns (deleted data still in DB; need separate anonymization/purge mechanism)

Constraints & Validation

Database constraints enforce data integrity at the schema level:

  • PRIMARY KEY: Every model has a unique id (UUID or autoincrement).
  • UNIQUE: User.email is unique (no duplicate accounts).
  • FOREIGN KEY: Document.tenant_id must reference valid Tenant.id.
  • NOT NULL: Critical fields (name, tenant_id, created_at) are NOT NULL.
  • UNSIGNED: Numeric fields like Task.tokens are UNSIGNED (no negative values).

Services catch constraint violations and convert to domain exceptions:

try:
    user = User.create(email='duplicate@example.com', password_hash='...')
except peewee.IntegrityError as e:
    if 'UNIQUE' in str(e):
        raise ValidationError('Email already exists')
    raise InternalError(f'DB constraint violation: {e}')
