x86 — x86-64 ISA Implementation

Full x86-64 instruction set support with variable-length decoding, microcode engine, CPUID emulation, segmentation, and Local APIC interrupt controller.

📚 What is this & why does it exist?

💡 Think of it like…

The x86 ISA implementation is like a vintage clock repair shop — each instruction is a complex mechanism with variable-size gears (prefix bytes, opcodes, ModR/M, SIB, displacement, immediate). The decoder acts as a master watchmaker who first identifies each gear, then decomposes complex movements into Atomic and Timing Simple CPUs — gem5 Wiki" href="../../cpu_doc/simple/index.html">simple micro-operations that the CPU's simpler internal engine can execute one tick at a time.

Architecture Overview

The x86 ISA is one of gem5's most complex architecture implementations due to the CISC nature of x86-64. Key challenges include variable-length instruction encoding (1-15 bytes), the microcode decomposition of complex instructions, legacy segmentation support, and the full Local APIC interrupt controller model.

Instruction Decoder

The x86 decoder is a state-machine-based parser that handles the full complexity of x86 instruction encoding. It processes bytes sequentially through states: prefix parsing, opcode identification, ModR/M/SIB decoding, and displacement/immediate extraction.

namespace X86ISA {

class Decoder : public InstDecoder
{
  public:
    // Decoder states
    enum State {
        ResetState,
        PrefixState,
        TwoByteOpcodeState,
        ThreeByte0F38State,
        ThreeByte0F3AState,
        VexTwoByteState,
        VexThreeByteState,
        OneByteOpcodeState,
        ModRMState,
        SIBState,
        DisplacementState,
        ImmediateState,
        // ... additional states
    };

    void moreBytes(const PCStateBase &pc, Addr fetchPC) override;
    bool instReady() const override;
    StaticInstPtr decode(PCStateBase &nextPC) override;
    void reset() override;

  private:
    State state;
    ExtMachInst emi;        // Extended machine instruction
    uint8_t prefixes;        // Accumulated prefix bytes
    uint8_t rexPrefix;       // REX prefix for 64-bit mode
    int immediateSize;
    int displacementSize;

    // Microcode ROM for complex instructions
    StaticInstPtr decodeInst(ExtMachInst mach_inst);
};

Microcode Engine

Complex x86 instructions (e.g., REP MOVSB, CPUID, XSAVE) are decomposed into sequences of micro-operations. The microcode ROM maps each macroop to a sequence of microops that the CPU pipeline processes individually.

// A macroop decomposes into microops
class MacroopBase : public StaticInst
{
  protected:
    std::vector<StaticInstPtr> microops;
    uint32_t numMicroops;

  public:
    StaticInstPtr fetchMicroop(MicroPC upc) const override {
        return microops[upc];
    }
    bool isMacroop() const override { return true; }
    bool isMicroop() const override { return false; }
};

// Individual microop
class MicroopBase : public X86ISA::X86StaticInst
{
  public:
    bool isMicroop() const override { return true; }
    bool isLastMicroop() const override;
    bool isFirstMicroop() const override;
};

Fault Handling

x86 defines a complex fault hierarchy mapping to processor exceptions. Each fault carries a vector number and optional error code pushed onto the stack during exception delivery.

namespace X86ISA {

class X86Fault : public FaultBase
{
  protected:
    const char *faultName;
    uint8_t vector;       // IDT vector number
    bool errorCode;       // Whether error code is pushed

  public:
    void invoke(ThreadContext *tc, const StaticInstPtr &inst) override;
};

// Specific faults
class DivideError : public X86Fault { /* vector 0 */ };
class DebugException : public X86Fault { /* vector 1 */ };
class Breakpoint : public X86Fault { /* vector 3 */ };
class InvalidOpcode : public X86Fault { /* vector 6 */ };
class PageFault : public X86Fault {
    Addr addr;
    uint32_t errorCode;  // P, W/R, U/S, RSVD, I/D bits
};
class GeneralProtection : public X86Fault { /* vector 13 */ };

} // namespace X86ISA

Local APIC

The Local APIC (Advanced Programmable Interrupt Controller) model handles interrupt delivery, IPI (Inter-Processor Interrupt) routing, timer functionality, and interrupt prioritization.

class Interrupts : public BaseInterrupts
{
  public:
    // APIC registers
    uint32_t regs[NUM_APIC_REGS];

    // Interrupt request/service registers (256 bits each)
    ApicRegister IRR;  // Interrupt Request Register
    ApicRegister ISR;  // In-Service Register

    // Timer
    uint32_t initialCount;
    uint32_t currentCount;
    Tick timerPeriod;

    // Check for pending interrupts
    bool checkInterrupts() const override;
    Fault getInterrupt() override;
    void updateIntrInfo() override;

    // IPI interface
    void sendIPI(uint8_t destId, uint8_t vector, uint8_t deliveryMode);

    // MMIO interface for APIC register access
    Tick read(PacketPtr pkt) override;
    Tick write(PacketPtr pkt) override;
};

🔍 Narrated Walkthrough: Decoding a MOV Instruction

  1. Byte Fetch — CPU fetches bytes starting at the current PC. The decoder receives: 48 89 44 24 08 (MOV [RSP+8], RAX).
  2. Prefix Parse — 0x48 is a REX prefix (REX.W = 1, 64-bit operand size). Decoder records the prefix and advances.
  3. Opcode Decode — 0x89 is the MOV r/m64, r64 opcode. Decoder identifies this as a register-to-memory move.
  4. ModR/M — 0x44 decodes as Mod=01 (8-bit displacement), Reg=RAX, R/M=100 (SIB follows).
  5. SIB Byte — 0x24 decodes as Scale=1, Index=none, Base=RSP. The effective address is RSP + displacement.
  6. Displacement — 0x08 is the 8-bit signed displacement. Final address: [RSP + 8].
  7. StaticInst Creation — A Mov StaticInst is created with source=RAX, dest=memory(RSP+8). Since this is a simple MOV, no microcode decomposition is needed.
