What is this & why does it exist?

The graph module is the nervous system of the hedge fund. AgentState is a TypedDict with three fields — messages, data, and metadata — that every agent reads from and writes to. The merge_dicts reducer handles concurrent writes from parallel agents. The create_workflow() function in main.py builds a LangGraph StateGraph by connecting start_node → analyst agents (fan-out) → risk_manager → portfolio_manager → END. Although only ~180 lines, this is the most critical code — it defines how agents compose.

Real-world analogy

AgentState is like a shared whiteboard in a conference room. Each analyst (agent) walks up, reads what’s there, writes their analysis, and sits down. The merge_dicts operator ensures two analysts writing at the same time don’t erase each other’s work. The StateGraph is the meeting agenda — it says who presents when and in what order. The risk manager only speaks after all analysts have finished, and the portfolio manager always has the last word.

Why Is It Designed This Way?

LangGraph’s StateGraph was chosen over a hand-rolled orchestrator because it provides built-in support for parallel fan-out (all analyst agents run concurrently), typed state channels with reducer functions (so concurrent writes merge cleanly), and a compile-to-graph execution model that enables visualization and debugging. The AgentState TypedDict pattern gives type safety without runtime overhead — every agent declares exactly what it reads and writes. The merge_dicts reducer was chosen over operator.or_ because it preserves all keys from both dicts even when nested keys overlap.

Architecture

The workflow follows a fan-out / fan-in pattern: a single start node broadcasts to all selected analyst agents in parallel, their outputs converge at the risk manager, and finally the portfolio manager produces trading decisions.

  START --> A3["Analyst 3\n(e.g. cathie_wood)"]

Annotated Code Walkthrough

The most important code in this sub-module, annotated with WHY each piece exists:

AgentState & merge_dicts (graph/state.py)

from typing_extensions import Annotated, Sequence, TypedDict
import operator
from langchain_core.messages import BaseMessage

def merge_dicts(a: dict[str, any], b: dict[str, any]) -> dict[str, any]:
    # WHY: Shallow merge ensures parallel agents don't overwrite each other's keys.
    # operator.or_ (|) would work for flat dicts but merge_dicts is explicit and safe.
    return {**a, **b}

class AgentState(TypedDict):
    # WHY: Annotated channels tell LangGraph HOW to merge concurrent writes.
    messages: Annotated[Sequence[BaseMessage], operator.add]  # append-only
    data: Annotated[dict[str, any], merge_dicts]              # shallow merge
    metadata: Annotated[dict[str, any], merge_dicts]          # shallow merge

Line-by-line:

  • Annotated[..., operator.add]: Messages use list concatenation — each agent appends its messages rather than replacing. Without this, only the last agent’s message would survive parallel execution.
  • Annotated[..., merge_dicts]: Both data and metadata use shallow dict merge. When agent A writes {"analyst_signals": {"buffett": ...}} and agent B writes {"analyst_signals": {"graham": ...}}, the reducer produces a dict with both keys.
  • Three fields, not one: Separating messages (LLM conversation), data (business data), and metadata (config) prevents accidental overwrites and keeps each channel’s merge semantics clean.

create_workflow() (main.py)

def create_workflow(selected_analysts=None):
    """Create the workflow with selected analysts."""
    workflow = StateGraph(AgentState)
    workflow.add_node("start_node", start)

    analyst_nodes = get_analyst_nodes()

    # WHY: Default to all analysts when none selected (CLI passed empty list)
    if selected_analysts is None:
        selected_analysts = list(analyst_nodes.keys())

    # WHY: Dynamic wiring - only add nodes the user actually selected
    for analyst_key in selected_analysts:
        node_name, node_func = analyst_nodes[analyst_key]
        workflow.add_node(node_name, node_func)
        workflow.add_edge("start_node", node_name)  # fan-out from start

    # WHY: Risk and portfolio management are always present (non-optional)
    workflow.add_node("risk_management_agent", risk_management_agent)
    workflow.add_node("portfolio_manager", portfolio_management_agent)

    # WHY: Fan-in - every analyst must complete before risk assessment
    for analyst_key in selected_analysts:
        node_name = analyst_nodes[analyst_key][0]
        workflow.add_edge(node_name, "risk_management_agent")

    workflow.add_edge("risk_management_agent", "portfolio_manager")
    workflow.add_edge("portfolio_manager", END)
    workflow.set_entry_point("start_node")
    return workflow

Line-by-line:

  • StateGraph(AgentState): Binds the graph to the typed state — LangGraph validates that every node returns compatible state updates.
  • add_node + add_edge loop: Creates the fan-out pattern. Each add_edge("start_node", analyst) tells LangGraph to run these nodes in parallel after start_node completes.
  • Second loop for fan-in: Each add_edge(analyst, "risk_management_agent") creates the convergence point. LangGraph waits for ALL incoming edges before running risk management.
  • set_entry_point: Marks start_node as the first node to execute. Without this, LangGraph wouldn’t know where to begin.
