Signal aggregation, risk assessment, and final trading decisions

📚 What is this & why does it exist?

These two agents are the "decision makers" in the fan-in phase of the pipeline. After 19 analyst agents independently produce signals, someone needs to synthesize them. The risk manager acts as a safety check — evaluating overall exposure, correlation risk, and position sizing. The portfolio manager then makes final decisions considering available capital, existing positions, and the risk manager's limits. This two-stage decision process (risk first, then portfolio) prevents the system from taking on excessive risk even when all analysts are bullish.

💡 Real-world analogy

Think of a restaurant kitchen. The risk manager is the health inspector — they don't cook, but they set limits (temperature requirements, freshness standards, capacity limits). The portfolio manager is the head chef who creates the final menu (trading decisions) working within the inspector's constraints. The health inspector reviews conditions first and says "you can serve at most 50 covers tonight given your refrigeration capacity." Then the head chef decides which dishes to prepare, how many of each, considering both the inspector's limits and the available ingredients (capital). Neither can do the other's job, and the order matters: risk limits must be set before trading decisions are made.

🤔 Why Is It Designed This Way?

The two-stage architecture (risk manager then portfolio manager) reflects institutional trading practice where risk management is independent of trading decisions. The risk manager is purely algorithmic — it computes volatility-adjusted position limits using price data, correlation matrices, and portfolio exposure without any LLM calls. This ensures risk limits are deterministic and not subject to LLM hallucination. The portfolio manager, by contrast, uses an LLM to synthesize the qualitative reasoning from all analyst signals into coherent trading decisions. This hybrid approach gives the system the creativity of LLM reasoning for decision-making while keeping risk controls mathematically rigorous. The compute_allowed_actions function adds a second deterministic layer: even if the LLM suggests buying 1000 shares, the function clamps it to the risk-manager-approved maximum.

📑 Annotated Code Walkthrough

The portfolio manager's decision-making logic is the final stage of the entire pipeline. It synthesizes all upstream analysis into concrete buy/sell/hold orders.

portfolio_management_agent — Decision Synthesis

def portfolio_management_agent(state: AgentState, agent_id: str = "portfolio_manager"):
    """Makes final trading decisions and generates orders for multiple tickers"""
    portfolio = state["data"]["portfolio"]
    analyst_signals = state["data"]["analyst_signals"]
    tickers = state["data"]["tickers"]

    position_limits = {}
    current_prices = {}
    max_shares = {}
    signals_by_ticker = {}

    for ticker in tickers:
        # Find the paired risk manager by matching ID suffix
        if agent_id.startswith("portfolio_manager_"):
            suffix = agent_id.split('_')[-1]
            risk_manager_id = f"risk_management_agent_{suffix}"
        else:
            risk_manager_id = "risk_management_agent"

        # Extract risk limits set by the risk manager
        risk_data = analyst_signals.get(risk_manager_id, {}).get(ticker, {})
        position_limits[ticker] = risk_data.get("remaining_position_limit", 0.0)
        current_prices[ticker] = float(risk_data.get("current_price", 0.0))

        # Calculate maximum shares allowed
        if current_prices[ticker] > 0:
            max_shares[ticker] = int(position_limits[ticker] // current_prices[ticker])
        else:
            max_shares[ticker] = 0

        # Compress analyst signals to {sig, conf} for LLM prompt efficiency
        ticker_signals = {}
        for agent, signals in analyst_signals.items():
            if not agent.startswith("risk_management_agent") and ticker in signals:
                sig = signals[ticker].get("signal")
                conf = signals[ticker].get("confidence")
                if sig is not None and conf is not None:
                    ticker_signals[agent] = {"sig": sig, "conf": conf}
        signals_by_ticker[ticker] = ticker_signals

    # Generate final trading decisions via LLM
    result = generate_trading_decision(
        tickers=tickers,
        signals_by_ticker=signals_by_ticker,
        current_prices=current_prices,
        max_shares=max_shares,
        portfolio=portfolio,
        agent_id=agent_id,
        state=state,
    )

Line-by-line:

  • Lines 3-5: The portfolio manager reads three things from state: the current portfolio (cash, positions, margin), all analyst signals (the output of 19 agents), and the tickers to trade. It's the only agent that reads all other agents' output.
  • Lines 13-18: Dynamic risk manager pairing — supports multi-portfolio mode where portfolio_manager_1 pairs with risk_management_agent_1. This allows running multiple independent portfolios in the same LangGraph execution.
  • Lines 21-23: Risk data extraction — the risk manager's output is consumed as just another signal in analyst_signals, but it contains special fields (remaining_position_limit, current_price) that other agents don't have.
  • Lines 26-29: max_shares is a hard ceiling computed by integer division of the dollar limit by the share price. The int() cast floors the result, preventing fractional share orders.
  • Lines 32-38: Signal compression is crucial for LLM prompt efficiency. Instead of sending full reasoning from all 19 agents (which would exceed context limits), each signal is compressed to just {sig, conf}. The risk manager is explicitly excluded because its output is used for limits, not as a trading signal.
  • Lines 41-49: The LLM call receives everything needed for a decision: signals from all analysts, current prices, hard limits from risk management, and current portfolio state. The LLM synthesizes this into PortfolioManagerOutput.

# Calculate total portfolio value (Net Liquidation Value)
total_portfolio_value = portfolio.get("cash", 0.0)
for ticker, position in portfolio.get("positions", {}).items():
    if ticker in current_prices:
        total_portfolio_value += position.get("long", 0) * current_prices[ticker]
        total_portfolio_value -= position.get("short", 0) * current_prices[ticker]

The correlation matrix is key to portfolio-level risk: if two tickers are highly correlated (e.g., AAPL and MSFT), the risk manager reduces position limits for both to avoid concentrated sector exposure. The net liquidation value calculation accounts for both long and short positions at current market prices.

This function provides the critical safety net. Even if the LLM hallucinates a quantity of 10,000 shares, compute_allowed_actions clamps it to max_qty (from risk manager) and available cash. It also ensures you can't sell more shares than you own, or cover more shorts than you have open.
