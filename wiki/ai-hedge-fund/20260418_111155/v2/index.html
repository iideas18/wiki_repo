🎯 Why This Module Exists

While the v1 system (src/) relies entirely on LLM-based analysis, it has fundamental limitations: LLM calls are expensive ($0.01–$0.10 per agent per stock), non-deterministic (same input can yield different outputs), and slow (seconds per call). The v2 module exists to add a complementary quantitative layer using traditional finance methods. Pure numerical signals—momentum, mean-reversion, volatility—run in milliseconds with deterministic results. Portfolio optimization using the Markowitz mean-variance framework produces mathematically optimal weight allocations. Risk management with Value-at-Risk and drawdown controls provides systematic safeguards. The Almgren-Chriss execution model accounts for market impact—something the v1 system ignores entirely. v2 is designed to eventually either replace or augment v1: LLM agents could generate qualitative signals that feed into v2's quantitative optimizer for the best of both worlds. Currently a work in progress with interfaces defined and partial implementations.

💡 Real-world analogy

If v1 is like asking a panel of human experts for investment advice—subjective, expensive, and slow—then v2 is like building a spreadsheet model with formulas: objective, cheap, and fast. Each expert (LLM agent) charges a consulting fee and takes time to think. A spreadsheet, once set up, recalculates instantly for free. The ideal system uses both: human judgment for qualitative factors (management quality, competitive moats, market sentiment) and math for quantitative optimization (optimal portfolio weights, risk constraints, execution timing).

🚶 Step-by-Step Narrated Walkthrough

Follow a single portfolio rebalance for AAPL, GOOGL, MSFT as it flows through the v2 pipeline:

  1. Data Fetch — FDClient.get_prices() pulls 1 year of OHLC bars from the Financial Datasets API. Retries on 429 with exponential backoff (5s, 15s, 30s).
  2. Metrics Fetch — get_financial_metrics() retrieves TTM fundamentals: P/E, EV/EBITDA, margins. Returns Pydantic models, never raises.
  3. Signal Computation — Each BaseSignal subclass (momentum, value, etc.) calls compute(ticker, end_date) and returns a SignalResult with a score in [-1, +1]. Helpers like _compute_rsi() and _sigmoid() handle the math.
  4. Signal Aggregation — Individual signals are collected into a QuantSignals object per ticker, with an optional composite_score.
  5. Portfolio Optimization — The optimizer takes expected returns (from signals) and a covariance matrix, then solves for weights that maximize the Sharpe ratio subject to constraints.
  6. Risk Check — The risk manager validates: position-level concentration, portfolio VaR, max drawdown. Positions exceeding limits get scaled down.
  7. Order Generation — Target weights are compared to current holdings. Differences become TradeOrder objects with action, shares, estimated cost.
  8. Execution Simulation — Almgren-Chriss model estimates market impact and optimal execution schedule. Large orders are sliced to minimize price impact.
  9. Backtesting — The vectorized backtester replays the strategy historically with a 10bps fixed cost model and point-in-time data constraints.

class SignalResult(BaseModel):
    """Output of a single quantitative signal."""
    signal_name: str = Field(description="e.g. 'momentum', 'earnings_surprise'")
    value: float = Field(description="Signal strength from -1.0 (bearish) to +1.0 (bullish)")
    z_score: float | None = None
    percentile: float | None = None  # 0-100
    components: dict[str, float] = Field(default_factory=dict)
    metadata: dict[str, Any] = Field(default_factory=dict)

class PortfolioTarget(BaseModel):
    """Output of the portfolio optimizer -- target weights."""
    weights: dict[str, float] = Field(
        default_factory=dict, description="ticker -> target weight (-1 to +1)"
    )
    expected_return: float | None = None
    expected_risk: float | None = None

🏗️ Design Decisions

DecisionChoice MadeAlternatives ConsideredWhy This Approach
Data provider interfaceProtocol (structural typing)ABC inheritance, dependency injectionAny class with the right methods works automatically—no need to inherit from a base class. Easier to swap FDClient for YFinanceClient without touching pipeline code.
Signal output rangeNormalized [-1, +1]Raw scores, percentile ranks, z-scoresUniform range makes signals directly comparable and composable. Raw z-scores can blow up; percentiles lose magnitude information.
Error handling in data layerReturn empty list / None, never raiseRaise exceptions, Result monadPipeline must be resilient to partial data failures. One API error shouldn't crash the entire portfolio rebalance. Missing data gets default-scored rather than causing exceptions.
Models layerSingle models.py filePer-package model filesSingle source of truth prevents circular imports and makes the full schema visible in one place. At ~70 LOC, it doesn't warrant splitting.
API client retry strategyFixed delays (5s, 15s, 30s)Exponential backoff, jitterFinancial Datasets API rate limits are predictable. Fixed delays are simpler to reason about and debug. Three retries cover transient 429s without excessive waiting.

🔬 Algorithm Spotlight: Mean-Variance Optimization

Markowitz Mean-Variance (Planned)

The Problem: Given N stocks with expected returns and a covariance matrix, find the portfolio weights that maximize risk-adjusted return (Sharpe ratio).

The Approach: Formulate as a quadratic optimization: minimize w'*Sigma*w (portfolio variance) subject to w'*mu >= target_return and sum(w) = 1. The efficient frontier traces the set of optimal portfolios across all target returns. The tangency portfolio (max Sharpe) is the point where a line from the risk-free rate is tangent to the frontier.

Why This Algorithm: Mean-variance is the foundation of Modern Portfolio Theory. Black-Litterman and risk parity (also planned for v2) are extensions that address its sensitivity to input estimates. Plain mean-variance tends to produce extreme weights when expected return estimates are noisy—which is why v2 plans to add eigenvalue cleaning via the Marchenko-Pastur distribution to denoise the covariance matrix before optimization.

Trace through an example

Given: 3 stocks (AAPL, GOOGL, MSFT) with expected returns [0.12, 0.10, 0.08] and a 3x3 covariance matrix.

Step 1: Clean the covariance matrix—remove eigenvalues below the Marchenko-Pastur threshold (noise from finite sample size).

Step 2: Solve the QP: minimize w'*Sigma*w subject to w'*mu >= 0.10, sum(w) = 1, 0 <= w_i <= 0.4 (40% max position).

Step 3: Result: w = [0.40, 0.35, 0.25] — AAPL gets max weight due to highest Sharpe. Without the max-position constraint, naive MVO would put 100% in AAPL.

Result: PortfolioTarget(weights={"AAPL": 0.40, "GOOGL": 0.35, "MSFT": 0.25}, expected_return=0.104, expected_risk=0.18)

Data Client & Protocol

The data layer uses Python's Protocol for structural typing—any class implementing the right method signatures is automatically a valid DataClient, no inheritance needed.

@runtime_checkable
class DataClient(Protocol):
    """Protocol that all data providers must satisfy.
    Methods return empty lists or None on failure -- never raise."""

    def get_prices(self, ticker: str, start_date: str, end_date: str, **kwargs) -> list[Price]: ...
    def get_financial_metrics(self, ticker: str, end_date: str, ...) -> list[FinancialMetrics]: ...
    def get_news(self, ticker: str, end_date: str, ...) -> list[CompanyNews]: ...
    def get_insider_trades(self, ticker: str, end_date: str, ...) -> list[InsiderTrade]: ...
    def get_company_facts(self, ticker: str) -> CompanyFacts | None: ...
    def get_earnings(self, ticker: str) -> Earnings | None: ...

The concrete FDClient implements this protocol with retry logic (5s/15s/30s on HTTP 429), session-based connection pooling, and context-manager support.

Signal Framework

All quantitative signals extend BaseSignal, an abstract base class that enforces a consistent interface and provides shared math utilities:

class BaseSignal(ABC):
    @property
    @abstractmethod
    def name(self) -> str: ...

    @abstractmethod
    def compute(self, ticker: str, end_date: str, *, api_key: str | None = None) -> SignalResult: ...

    # Shared helpers available to all signals:
    @staticmethod
    def _safe_float(value, default=0.0) -> float: ...     # NaN/None guard
    @staticmethod
    def _percentile_rank(value, values) -> float: ...      # 0-100 rank
    @staticmethod
    def _normalize_to_signal(raw, low=-1.0, high=1.0): ... # clamp to range
    @staticmethod
    def _sigmoid(x, scale=5.0) -> float: ...               # tanh mapping
    @staticmethod
    def _compute_rsi(prices, period=14) -> float: ...      # RSI indicator
