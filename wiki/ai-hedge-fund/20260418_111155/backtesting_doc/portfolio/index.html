📚 What is this & why does it exist?

Without portfolio tracking and metrics, a backtest is just a list of decisions with no way to evaluate quality. This sub-module maintains the financial state of the simulated portfolio — tracking every position, cost basis, margin requirement, and realized/unrealized gain. The metrics module then analyzes this history using industry-standard measures. The Sharpe ratio tells you risk-adjusted return, maximum drawdown tells you worst-case loss, Sortino ratio penalizes only downside volatility, and benchmark comparison tells you whether the AI strategy beat simple index investing.

💡 Real-world analogy

Think of a sports team's season statistics tracker. The Portfolio class is the scoreboard — it shows the current score, who's on the field (positions), and how much time-out budget remains (cash and margin). The PerformanceMetricsCalculator is the analytics department — it computes win rate, points per game, and strength-of-schedule adjusted rankings (Sharpe, Sortino, drawdown). The BenchmarkCalculator is the league standings — it answers "are we doing better than average?" by comparing against the S&P 500. The OutputBuilder is the press release team — it formats all this data into tables that stakeholders can quickly scan. Without the analytics department, you'd know who won individual games but not whether the team is actually good.

🤔 Why Is It Designed This Way?

The portfolio sub-module follows an encapsulated-state + pure-functions pattern. The Portfolio class is the only mutable component — it owns all position state and provides atomic mutation methods (apply_long_buy, apply_short_cover, etc.) that enforce invariants (can't sell more shares than held, can't spend more cash than available). Everything else is a pure function or a stateless calculator: calculate_portfolio_value takes a portfolio and prices, returns a number; compute_metrics takes value history, returns metrics. This separation makes the financial math easy to unit-test without mocking any state. The MappingProxyType wrapper on get_positions() prevents callers from accidentally mutating internal state — mutations must go through the apply_* methods.

PerformanceMetricsCalculator.compute_metrics() — Risk-Adjusted Returns

def compute_metrics(self, values: Sequence[PortfolioValuePoint]) -> PerformanceMetrics:
    import pandas as pd
    import numpy as np

    if not values:                                                  # [1]
        return {"sharpe_ratio": None, "sortino_ratio": None, "max_drawdown": None}

    df = pd.DataFrame(values)
    df = df.set_index("Date")
    df["Daily Return"] = df["Portfolio Value"].pct_change()         # [2]
    clean_returns = df["Daily Return"].dropna()
    if len(clean_returns) < 2:                                      # [3]
        return {"sharpe_ratio": None, "sortino_ratio": None, "max_drawdown": None}

    daily_rf = self.annual_rf_rate / self.annual_trading_days       # [4]
    excess = clean_returns - daily_rf                               # [5]
    mean_excess = excess.mean()
    std_excess = excess.std()

    if std_excess > 1e-12:                                          # [6]
        sharpe = float(np.sqrt(self.annual_trading_days) * (mean_excess / std_excess))
    else:
        sharpe = 0.0

    downside_diff = np.minimum(excess, 0)                           # [7]
    downside_dev = float(np.sqrt(np.mean(downside_diff**2)))
    if downside_dev > 1e-12:
        sortino = float(np.sqrt(self.annual_trading_days) * (mean_excess / downside_dev))
    else:
        sortino = float("inf") if mean_excess > 0 else 0.0         # [8]

    rolling_max = df["Portfolio Value"].cummax()                    # [9]
    drawdown = (df["Portfolio Value"] - rolling_max) / rolling_max
    max_drawdown = float(drawdown.min() * 100.0)                   # [10]

Line-by-line:

  • [1] Guard clause: Returns None metrics for empty input — prevents index errors downstream.
  • [2] Daily returns: pct_change() computes (V[t] - V[t-1]) / V[t-1]. The first row is NaN (no previous value), which is dropped.
  • [3] Minimum data check: At least 2 clean returns needed for standard deviation. With 0 or 1 points, std is undefined.
  • [4] Daily risk-free rate: Annualized rate (4.34%) divided by 252 trading days. This is the daily "free money" baseline.
  • [5] Excess returns: Subtracting risk-free rate answers "how much did we beat a treasury bill by?" each day.
  • [6] Epsilon guard: If std_excess is nearly zero (flat line portfolio), division would explode. Returns 0 instead of infinity.
  • [7] Downside deviation: np.minimum(excess, 0) keeps only negative excess returns. Sortino only penalizes downside volatility, unlike Sharpe which penalizes all volatility.
  • [8] Infinite Sortino: If there are no down days but positive mean return, Sortino is infinite — all returns exceeded the risk-free rate.
  • [9] Rolling maximum: cummax() tracks the highest portfolio value seen so far. Drawdown is measured from this peak.
  • [10] Max drawdown: The worst peak-to-trough decline as a percentage. -5.2 means the portfolio fell 5.2% from its peak at the worst point.

Portfolio.apply_long_buy() — Weighted-Average Cost Basis

def apply_long_buy(self, ticker: str, quantity: int, price: float) -> int:
    if quantity <= 0:
        return 0
    position = self._portfolio["positions"][ticker]
    cost = quantity * price

    if cost <= self._portfolio["cash"]:                            # [A]
        old_shares = position["long"]
        old_cost_basis = position["long_cost_basis"]
        total_shares = old_shares + quantity
        if total_shares > 0:
            total_old_cost = old_cost_basis * old_shares           # [B]
            total_new_cost = cost
            position["long_cost_basis"] = (total_old_cost + total_new_cost) / total_shares  # [C]
        position["long"] = old_shares + quantity
        self._portfolio["cash"] -= cost
        return quantity

    max_quantity = int(self._portfolio["cash"] / price)            # [D]
    if max_quantity > 0:
        # ... same cost-basis logic for partial fill ...
        return max_quantity
    return 0

Line-by-line:

  • [A] Cash check: If the full order is affordable, execute in full. Otherwise fall through to partial fill logic.
  • [B] Old total cost: old_cost_basis * old_shares reconstructs the total dollars invested in existing shares. This is needed for weighted averaging.
  • [C] Weighted-average cost basis: New basis = (old investment + new investment) / total shares. This correctly handles adding 100 shares at $50 to 200 shares bought at $40 → basis = (200*40 + 100*50) / 300 = $43.33.
  • [D] Partial fill: Integer division gives the max whole shares affordable. Remaining cash stays available for other tickers. This mirrors real-broker behavior where you can't buy fractional shares.

Example: Portfolio Lifecycle

from src.backtesting.portfolio import Portfolio
from src.backtesting.valuation import calculate_portfolio_value, compute_exposures

# Initialize with $100k and 2 tickers
portfolio = Portfolio(
    tickers=["AAPL", "TSLA"],
    initial_cash=100000.0,
    margin_requirement=0.5,
)

# Buy 100 shares of AAPL at $150
executed = portfolio.apply_long_buy("AAPL", 100, 150.0)
# executed = 100, cash now = $85,000

# Price rises to $160 — check NAV
prices = {"AAPL": 160.0, "TSLA": 250.0}
nav = calculate_portfolio_value(portfolio, prices)
# nav = 85000 + (100 * 160) = $101,000

# Sell 50 shares — realize gain
sold = portfolio.apply_long_sell("AAPL", 50, 160.0)
# realized_gain = (160 - 150) * 50 = $500

# Check exposures
exp = compute_exposures(portfolio, prices)
# Long Exposure = 50 * 160 = $8,000
# Short Exposure = $0
