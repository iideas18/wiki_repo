📚 What is this & why does it exist?

The engine is the core loop of the backtesting system. It iterates through each trading day in a historical range, running the complete LangGraph agent pipeline as if it were live — agents can only see data up to that day, preventing future-data leakage. The controller manages agent invocation and output normalization, the engine manages the day loop (fetch prices, call agents, execute trades, compute value), and the trader translates decisions into portfolio changes. This three-layer separation keeps each concern clean, testable, and independently replaceable.

💡 Real-world analogy

Think of a time machine for trading. The engine "travels" to each historical date, runs the AI agents as if they were making real-time decisions, then "travels" forward to the next business day. The BacktestEngine is the time machine itself — it transports you to each date, sets the scene (fetches prices, prepares the portfolio snapshot), and records what happened. The AgentController is the machine operator — it programs the destination parameters (which tickers, which analysts, which date range) and ensures the crew follows protocol. The TradeExecutor is the crew member who actually pulls the trading lever at each stop, converting abstract decisions ("buy 50 shares of AAPL") into concrete portfolio mutations.

🤔 Why Is It Designed This Way?

The engine follows a pipeline-of-components pattern where each class owns exactly one responsibility. The BacktestEngine could have been a single monolithic class that fetches data, calls agents, executes trades, and computes metrics all in one loop body. Instead, it delegates to specialized components — AgentController for agent I/O normalization, TradeExecutor for position mutations, PerformanceMetricsCalculator for analytics, and OutputBuilder for display. This decomposition was driven by testability: each component can be unit-tested in isolation with mock inputs. The trade-off is more indirection (you must trace across 4+ files to understand one day's flow), but this is acceptable because the flow is strictly linear — no callbacks, no branching pipelines.

The most important code in this sub-module — the core simulation loop inside BacktestEngine.run_backtest():

BacktestEngine.run_backtest() — The Day Loop

def run_backtest(self) -> PerformanceMetrics:
    self._prefetch_data()                                          # [1]

    dates = pd.date_range(self._start_date, self._end_date, freq="B")  # [2]
    if len(dates) > 0:
        self._portfolio_values = [
            {"Date": dates[0], "Portfolio Value": self._initial_capital}  # [3]
        ]

    for current_date in dates:                                     # [4]
        lookback_start = (current_date - relativedelta(months=1)).strftime("%Y-%m-%d")
        current_date_str = current_date.strftime("%Y-%m-%d")
        previous_date_str = (current_date - relativedelta(days=1)).strftime("%Y-%m-%d")

        # Fetch current prices for all tickers
        current_prices: Dict[str, float] = {}
        missing_data = False
        for ticker in self._tickers:
            try:
                price_data = get_price_data(ticker, previous_date_str, current_date_str)
                if price_data.empty:
                    missing_data = True; break
                current_prices[ticker] = float(price_data.iloc[-1]["close"])  # [5]
            except Exception:
                missing_data = True; break
        if missing_data:
            continue                                               # [6]

        agent_output = self._agent_controller.run_agent(           # [7]
            self._agent, tickers=self._tickers,
            start_date=lookback_start, end_date=current_date_str,
            portfolio=self._portfolio, ...)

        for ticker in self._tickers:                               # [8]
            d = agent_output["decisions"].get(ticker, {"action": "hold", "quantity": 0})
            executed_qty = self._executor.execute_trade(
                ticker, d["action"], d["quantity"], current_prices[ticker], self._portfolio)

        total_value = calculate_portfolio_value(self._portfolio, current_prices)  # [9]

        if len(self._portfolio_values) > 3:                        # [10]
            computed = self._perf.compute_metrics(self._portfolio_values)
            if computed:
                self._performance_metrics.update(computed)

    return self._performance_metrics

Line-by-line:

  • [1] Prefetch: Warms the API cache for all tickers and SPY. Without this, every day in the loop would trigger network requests, making the backtest orders of magnitude slower.
  • [2] Business-day range: freq="B" skips weekends and generates only trading days. This ensures the simulation never tries to trade on non-market days.
  • [3] Initial equity point: Seeds the equity curve with starting capital at day 0. Required so that return calculations have a baseline reference point.
  • [4] Day loop: Each iteration represents one simulated trading day. The lookback window is 1 month — agents see only this window of historical data to avoid look-ahead bias.
  • [5] Close price: Uses iloc[-1]["close"] to get the most recent closing price. The query range is [previous_day, current_day] to handle weekends/holidays gracefully.
  • [6] Skip missing data: If any ticker lacks price data for this day, the entire day is skipped rather than trading with partial information. This prevents mismatched position valuations.
  • [7] Agent invocation: The controller normalizes agent output — coercing actions to the Action enum, quantities to floats, and filling missing tickers with hold/0.
  • [8] Trade execution: Each ticker is executed sequentially. The executor dispatches to the correct Portfolio method (buy/sell/short/cover) and returns the actual executed quantity (may be less than requested if insufficient cash).
  • [9] Valuation: After all trades, the portfolio's total value is computed: cash + long positions - short positions. This is appended to the equity curve.
  • [10] Metrics gate: Performance metrics are only computed when 3+ data points exist. Computing Sharpe or Sortino with fewer points would produce meaningless results.

Code Examples

Example: Launching a Backtest from CLI

# Construct and run the engine programmatically
from src.backtesting.engine import BacktestEngine
from src.main import run_hedge_fund

engine = BacktestEngine(
    agent=run_hedge_fund,
    tickers=["AAPL", "GOOGL", "MSFT"],
    start_date="2025-01-01",
    end_date="2025-06-01",
    initial_capital=100000,
    model_name="gpt-4o",
    model_provider="OpenAI",
    selected_analysts=["technical_analyst", "fundamentals_analyst"],
    initial_margin_requirement=0.5,
)

metrics = engine.run_backtest()
print(f"Sharpe: {metrics.get('sharpe_ratio', 'N/A')}")
print(f"Max DD: {metrics.get('max_drawdown', 'N/A')}%")

# Access the full equity curve
values = engine.get_portfolio_values()
for point in values[-3:]:
    print(f"{point['Date']}: ${point['Portfolio Value']:,.2f}")

Example: TradeExecutor Dispatch

from src.backtesting.trader import TradeExecutor
from src.backtesting.portfolio import Portfolio

portfolio = Portfolio(tickers=["AAPL"], initial_cash=50000, margin_requirement=0.5)
executor = TradeExecutor()

# Buy 100 shares at $150
bought = executor.execute_trade("AAPL", "buy", 100, 150.0, portfolio)
# bought = 100 (cash: 50000 - 15000 = 35000)

# Try to short 200 shares at $150 — margin limits apply
shorted = executor.execute_trade("AAPL", "short", 200, 150.0, portfolio)
# margin_required = 200 * 150 * 0.5 = 15000
# available_cash = 35000 - 0 = 35000 (enough for full order)

# Hold action returns 0 with no side effects
held = executor.execute_trade("AAPL", "hold", 50, 150.0, portfolio)
# held = 0
