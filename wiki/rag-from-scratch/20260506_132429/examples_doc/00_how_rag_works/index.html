📚 What is this & why does it exist?

Before showing the reader the modern stack (embeddings, vector DBs, LLMs), this lesson establishes a baseline they can see fail. It implements traditional keyword retrieval — str.includes() with stop-word filtering — on a small document collection and runs queries that obviously match in meaning but don't share any literal words. The output makes the limitation viscerally obvious in 30 seconds of console output.

💡 Real-world analogy

It's the "before" photo in a renovation pitch. Until you see the cracked tile and chipped paint of keyword search — "user types 'dog', misses every document about 'puppy' or 'canine'" — you don't appreciate why the embedding section exists. The lesson resists the temptation to skip ahead; it makes you live with the broken kitchen for 200 lines so the upgrade feels earned.

🎯 Why This Component

This lesson exists because RAG tutorials that start with "and now embeddings" leave readers with a vague sense that embeddings are better without a concrete sense of why. By implementing the dumb thing first, the reader builds intuition for the gap. When lesson 02 introduces semantic similarity and asks the same query against the same documents, the reader sees synonyms work and has the "aha" moment that justifies the rest of the curriculum.

It's also fast. No model downloads, no GGUF, no GPU; node 00_how_rag_works/01_basic_search.js runs in milliseconds. This is the "kick the tires" lesson — the one a reader can complete on a phone tethered to coffee-shop wifi.

📝 Annotated Code Walkthrough — 01_basic_search.js

Set up the corpus

const documents = [
    "Dogs need consistent training and patience.",
    "Cats are independent and aloof.",
    "How to housetrain a puppy: a beginner's guide.",
    "Reinforcement learning trains agents through rewards.",
    // ...
];

Hardcoded so the reader can scan it. Note "puppy" appears in one doc and "dog" in another — the synonym test is set up.

Tokenise the query

function tokenize(s) {
    return s.toLowerCase().split(/\s+/).filter(Boolean);
}

Whitespace split, lowercased. No stemming, no lemmatisation — the reader sees how dumb the matching is.

Score each document

function score(query, doc) {
    const qTokens = tokenize(query);
    const dTokens = tokenize(doc);
    let hits = 0;
    for (const t of qTokens) {
        if (dTokens.includes(t)) hits++;
    }
    return hits;
}

One point per query token that appears literally in the document. No TF-IDF, no IDF; bare hit counting. Replace with anything fancier and the failure mode disappears prematurely.

Rank and print

function search(query, docs) {
    return docs
        .map((d, i) => ({ doc: d, idx: i, score: score(query, d) }))
        .sort((a, b) => b.score - a.score)
        .slice(0, 5);
}

const query = "puppy training";
console.log(`Query: "${query}"`);
search(query, documents).forEach((r, rank) => {
    console.log(`  ${rank + 1}. (score=${r.score}) ${r.doc}`);
});

The output is the punchline: the doc about "Dogs need consistent training" scores the same as "How to housetrain a puppy", and a doc that's clearly about agentic RL ranks above the actual answer because it shares the word "training". Embeddings will fix this in lesson 02.

Deep-Dive Highlights

Why no TF-IDF? Pedagogy

TF-IDF would mask the failure — rare terms get extra weight, sometimes accidentally fixing synonym cases. The lesson's job is to show the floor, not patch it.

The synonym trap Failure Mode

"puppy" and "dog" share zero characters but mean (almost) the same thing. Keyword search has zero awareness; embedding similarity is >0.7.

What lesson 02 fixes Forward Pointer

Re-runs the same queries with cosine similarity over bge embeddings. The ranking flips correctly. The contrast is the curriculum's hook.

⚠ Edge Cases & Boundaries

ScenarioWhat Actually Happens
Empty querytokenize returns []; every doc scores 0; output is the first 5 docs unchanged.
Query is a stop-word ("the")Almost every doc matches; ranking is meaningless. Sub-lesson 03 demonstrates this.
Multi-word phrase ("machine learning")Treated as two independent tokens; a doc containing "learning machine" matches the same as "machine learning".
All zero scoresStable JS sort returns docs in original order — misleadingly suggests doc 0 is "the answer".
Case sensitivityHandled by toLowerCase(). Without it, "Puppy" and "puppy" wouldn't match.
