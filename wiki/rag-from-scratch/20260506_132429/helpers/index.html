📚 What is this & why does it exist?

helpers/ is the infrastructure boundary between every lesson and the outside world (terminal, OpenAI, llama.cpp). Without it, every example.js would re-implement chalk-coloured headers, ora spinners, OpenAI API boilerplate, and llama.cpp model-loading. By centralising these, the lessons can focus on the concept being taught without drowning in setup boilerplate.

💡 Real-world analogy

Picture a cooking show kitchen. The aprons, the stage lights, the camera angles, the chyron at the bottom of the screen — none of it is the recipe. But without it, the chef would be cooking in a dark, unlabelled kitchen and you couldn't follow along. helpers/ is that production crew. Critically, you don't ship the production crew with the recipe book (src/) — the crew exists for the demos, not the dish.

🎯 Why This Module Exists

helpers/ exists because every lesson needs the same chrome and the same minimal LLM client, but neither belongs in src/. The src/ library is what a downstream consumer imports; helpers are what the demos rely on for chrome and CLI ergonomics. They're stylistic, not architectural — and that distinction is enforced by directory placement.

Without this module: every example.js would carry its own try/catch wrapping for timing, its own chalk-coloured headers, its own ora spinner setup, its own OpenAI client construction. We'd see 50 lines of identical boilerplate at the top of each lesson. With helpers/, the lessons are 50 lines shorter and visually consistent.

📝 Annotated Code Walkthrough — OutputHelper.runExample

The single most-reused function in the project. It's the demo shell that wraps every example.js body.

Render the header

static async runExample(title, fn, subtitle = '') {
  this.createHeader(title, subtitle);

Why first? Because if fn() throws immediately, the reader still sees what lesson they were attempting. Without this, a missing GGUF would just print a stack trace with no context.

Capture start time

  const t0 = Date.now();

Wall-clock timing. performance.now() would be more precise but the lessons are second-grain — Date.now() is plenty.

Run the lesson body

  try {
    await fn();

The lesson body is async-by-construction (every interesting RAG operation is async). The try/catch is what turns a stack trace into a friendly red line.

Success path: report timing

    console.log(chalk.green(`\nCompleted in ${(Date.now() - t0) / 1000}s\n`));

Green on success matches every other tool the reader will encounter (npm, pytest, etc.). The trailing newline gives the next lesson room to breathe.

Failure path: red message

  } catch (e) {
    console.error(chalk.red(`Failed: ${e.message}`));
  }
}

Note e.message only — the full stack would dominate the terminal. The reader gets the gist; process.env.DEBUG would let them re-run with full trace if they wanted (not implemented today).

Subtle bug to be aware of: analyzeChunks(chunks) calls sizes.sort((a,b) => a-b) in-place. If the caller reuses sizes after, it's been mutated. The lessons throw the array away immediately, so this never bites — but it's a code smell to remember if the helper is generalised.

await OutputHelper.runExample('Lesson 03 — Text Splitting', async () => {
