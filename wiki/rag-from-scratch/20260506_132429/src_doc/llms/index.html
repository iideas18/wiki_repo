📚 What is this & why does it exist?

llms/ is the generation half of RAG. Once you've retrieved relevant context, you stuff it into a prompt and ask a language model to answer. LlamaCpp handles raw completion; ChatLlamaCpp handles role-tagged conversations with the model's native chat template (e.g., Llama-3's <|begin_of_text|><|start_header_id|>...). The two factories in llama_cpp.js make instantiation a one-liner.

💡 Real-world analogy

A chat model is a multilingual diplomat. You hand them a script in English ({"role":"user","content":...}) and they translate it into the formal protocol the host country (the LLM family) expects — the bowing, titles, and salutations of Llama-3's special tokens. The base completion model is a calligrapher: you hand them text, they extend it in the same hand. Both speak to the same printer (llama.cpp), just with different etiquette.

🎯 Why This Component

The hard problem this module hides is chat-template fragmentation. Llama-3, Qwen, Phi, and Gemma all use different special tokens to demarcate system/user/assistant turns. Hand-rolling a prompt for each family is fragile and error-prone — one missing <|eot_id|> and the model rambles forever or repeats the user input. node-llama-cpp's LlamaChatSession reads the template from the GGUF metadata and applies it correctly. ChatLlamaCpp wraps that session API behind LangChain's {role, content}[] message shape so callers don't need to know which family they're talking to.

📝 Annotated Code Walkthrough — ChatLlamaCpp.stream

Guard initialization

async *stream(messages) {
    this._ensureInitialized();

Throws if the user constructed but didn't await initialize(). The factory hides this from the user; the manual path still has the safety net.

Extract latest user message + history

    const last = messages[messages.length - 1];
    if (last.role !== 'user') throw new Error('last message must be user');
    const history = messages.slice(0, -1);

The session API expects the next user prompt + system/historical context separately. Lessons construct messages as [{role:'system'}, {role:'user'}, {role:'assistant'}, {role:'user'}] — we split the tail off.

Sync session history

    if (history.length) {
        await this.session.setChatHistory(this._formatHistory(history));
    }

Re-priming the session lets the same instance handle independent conversations — useful in batch evaluation. Without this, the session would carry stale history across calls.

Stream via callback bridge

    const queue = [];
    let done = false;
    let resolveNext;
    const promise = this.session.promptWithMeta(last.content, {
        temperature: this.temperature,
        topP: this.topP,
        maxTokens: this.maxTokens,
        onToken: (tokens) => {
            const text = this.model.detokenize(tokens);
            queue.push(text);
            if (resolveNext) { resolveNext(); resolveNext = null; }
        }
    }).then(() => { done = true; if (resolveNext) resolveNext(); });

The bridge. node-llama-cpp's API is callback-based (onToken); the consumer-friendly contract is an async generator. We bridge by buffering tokens in queue[] and using a wake-up promise resolveNext to coordinate.

Drain loop

    while (!done || queue.length) {
        if (!queue.length) await new Promise(r => { resolveNext = r; });
        while (queue.length) yield queue.shift();
    }
    await promise;
}

Two-phase: wait for tokens, then drain everything queued. The final await promise surfaces any error from promptWithMeta; without it, errors during generation would be silently swallowed after the consumer's loop ended.

Deep-Dive Highlights

Callback-to-generator bridge Pattern

The onToken callback gets adapted into an async generator via a queue + wake-up promise. Any callback API can be lifted this way.

Why use the session API Robustness

GGUF embeds the chat template as metadata. LlamaChatSession reads it, so swapping Llama-3 for Qwen-2 is a model-path change, no code change.

Cleanup ordering Resource Mgmt

Dispose session before context before model. Wrong order can leave a zombie llama.cpp thread.

⚠ Edge Cases & Boundaries

ScenarioWhat Actually Happens
Last message is not userThrows synchronously — the chat template only generates an assistant turn from a trailing user prompt.
Context overflowllama.cpp truncates oldest tokens silently. Reduce contextSize or compress history; this module doesn't auto-summarise.
maxTokens exceededGeneration stops mid-sentence. The streamed partial is what the consumer gets.
Model file missingloadModel throws ENOENT; bubbles through initialize().
Calling invoke while a stream is runningSequence/session is single-threaded — second call blocks. Use one instance per concurrent stream.
Repeat penalty too highOutput devolves to disconnected tokens. Defaults are conservative (1.1).

Code Examples

Streamed chat with system prompt

import { createChatLlamaCpp } from './src/llms/llama_cpp.js';

const chat = await createChatLlamaCpp({
    modelPath: './models/Llama-3.2-3B-Instruct-Q4_K_M.gguf',
    contextSize: 4096, temperature: 0.7, maxTokens: 512,
    systemPrompt: 'You are a precise technical assistant.'
});

for await (const chunk of chat.stream([
    { role: 'user', content: 'Explain RAG in one paragraph.' }
])) {
    process.stdout.write(chunk);
}
console.log();
await chat.cleanup();

Inside a RAG loop

const context = retrievedDocs.map(d => d.pageContent).join('\n\n');
const messages = [
    { role: 'system', content: 'Answer using only the provided context.' },
    { role: 'user', content: `Context:\n${context}\n\nQuestion: ${query}` }
];
const answer = await chat.invoke(messages);

Raw completion (non-chat)

import { createLlamaCpp } from './src/llms/llama_cpp.js';

const llm = await createLlamaCpp({ modelPath: './models/qwen2.5-1.5b.gguf', maxTokens: 100 });
