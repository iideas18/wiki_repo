Protocol Negotiation Focus Deep-Dive

The getStatus handshake, version pinning, and capability flags that keep a four-SDK matrix compatible with a moving CLI.

The SDK and CLI do not trust each other's versions. On every Start(), the SDK calls getStatus; the CLI responds with its highest protocol version and capability flags. If the overlap fails the minimum required by the SDK, Start() fails immediately with a helpful message, rather than the user discovering garbled events at message 50.

📚 What is this & why does it exist?

A version handshake, identical in shape across all four SDKs. The SDK sends getStatus; the CLI returns {protocolVersion: 3, capabilities: ["permissions_v2", "hooks_extended", "session_fs_v2"]}. The SDK compares this to its own SDK_PROTOCOL_VERSION constant and minimum MIN_PROTOCOL_VERSION constraint. Mismatches throw a typed error (NO_RESULT_PERMISSION_V2_ERROR in Node) rather than failing at some later opcode.

💡 Real-world analogy

Think of two radios tuning into each other. Before either side starts broadcasting music, they exchange a beep sequence: "I speak English, French, and German." "I speak English only." They then both switch to English. If one only speaks Klingon while the other speaks English, they stop the conversation with a clear "we can't talk" message — not garbled noise that gets blamed on the song three minutes later.

🎯 The Problem

The CLI is released on its own cadence; SDKs are released on theirs. Users install @github/copilot-sdk@0.3 today but upgrade the CLI tomorrow (npm i -g @github/copilot@latest). Or vice versa — a Python environment pinned at a specific SDK interacts with a freshly updated bundled CLI. The SDK must not assume version equality, but also must not silently degrade. Specific risks:

  • A new event type ships that older SDKs don't know — causes JsonConverter exceptions in .NET.
  • A method's parameter shape changes — silently sends malformed JSON and gets -32602 errors with no context.
  • Permissions v2 introduces a new result-shape; a v1 SDK would misinterpret v2 events as malformed.

🔧 The Approach

A two-value handshake: version + capabilities. The version is a single integer (currently 3). Capabilities are named strings that gate individual features. Capabilities avoid version-number inflation when a feature is opt-in (SDK doesn't need permissions_v2? Don't care whether the CLI has it).

Each SDK embeds its own generated SDK_PROTOCOL_VERSION (not a hand-picked constant; the codegen step emits it from the schema). The Node SDK additionally exposes MIN_PROTOCOL_VERSION = 2 — it can talk to any CLI with version ≥ 2, even though its own schema targets 3.

Capability Flags

SDK declares required capabilities implicitly

// nodejs/src/client.ts (conceptual)
const required = ["permissions_v2"]; // because we call session.onPermissionRequest
for (const cap of required) {
    if (!status.capabilities.includes(cap)) {
        throw new Error(NO_RESULT_PERMISSION_V2_ERROR);
    }
}

The SDK only enforces capabilities it actually uses. A user who never registers a permission handler doesn't need permissions_v2 and can talk to an older CLI.

Python mirrors the same check

# python/copilot/client.py
async def _negotiate(self):
    status = await self._rpc.get_status()
    if status.protocol_version < MIN_PROTOCOL_VERSION:
        raise RuntimeError(f"CLI protocol v{status.protocol_version} < minimum v{MIN_PROTOCOL_VERSION}")
    self._negotiated_version = min(status.protocol_version, SDK_PROTOCOL_VERSION)
    self._capabilities = set(status.capabilities)

Go uses constants embedded from codegen

// go/sdk_protocol_version.go
const SDKProtocolVersion = 3

func (c *Client) negotiate(ctx context.Context) error {
    status, err := c.rpc.GetStatus(ctx)
    if err != nil { return err }
    if status.ProtocolVersion < minProtocolVersion {
        return fmt.Errorf("CLI protocol %d below minimum %d", status.ProtocolVersion, minProtocolVersion)
    }
    c.negotiated = status.ProtocolVersion
    c.caps = make(map[string]bool, len(status.Capabilities))
    for _, cap := range status.Capabilities { c.caps[cap] = true }
    return nil
}

.NET throws a typed exception

if (status.ProtocolVersion < MinProtocolVersion) {
    throw new IncompatibleCliException(
        $"The Copilot CLI reports protocol version {status.ProtocolVersion}, " +
        $"but this SDK requires at least {MinProtocolVersion}. " +
        "Upgrade the CLI with: npm i -g @github/copilot@latest");
}

    Active --> Stopped : Stop()
    Stopped --> [*]

💥 Failure Recovery

If handshake fails, the SDK closes pipes, sends SIGTERM (CTRL_BREAK on Windows), and returns a typed error from Start(). There is no retry — version incompatibility is deterministic. The error string includes the exact version reported and the upgrade command. Pending tasks are rejected with the same error so await client.CreateSessionAsync() fails fast even if it was already queued.

Blast radius is minimal: a failed handshake leaves no user-visible state (no sessions created, no events emitted, no files written). The user either updates the CLI and retries or pins the SDK to an older version.
