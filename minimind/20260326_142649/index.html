💡 What is this?

MiniMind is a minimalist open-source project that lets you train a GPT-style language model entirely from scratch. Think of it as a teaching hospital for LLMs: small enough to understand every layer, yet complete enough to cover the full training lifecycle — from BPE tokenizer training through pretraining, supervised fine-tuning (SFT), LoRA adaptation, and reinforcement learning from human feedback (DPO, PPO, GRPO, SPO). The smallest config (26M params) trains on a single consumer GPU, making it ideal for learning how transformers really work.

Training Data Flow

Every training recipe follows a similar pipeline. Raw text is tokenised, batched by the dataset classes, passed through the model, and gradients flow back through the optimizer.

    participant M as MiniMindForCausalLM

    participant O as Optimizer
(AdamW)
    T->>D: Encode raw text → token IDs
    D->>M: Batched input_ids + labels
    M->>M: Embedding → N×(RMSNorm → Attention → RMSNorm → FFN) → LM Head
    M->>L: logits + labels → loss
    L->>O: loss.backward()
    O->>M: parameter update (lr=5e-4, weight_decay=0.1)
    Note over M,L: MoE adds aux_loss for load balancing

Narrated Walkthrough

🚶 Following the Full Training Pipeline

Step 1 — Tokenizer Training (trainer/train_tokenizer.py): Train a BPE tokenizer on your corpus to produce a 6,400-token vocabulary. This creates the tokenizer.model file consumed by all downstream stages.

Step 2 — Pretraining (trainer/pretrain.py): Feed raw text through PretrainDataset into MiniMindForCausalLM with standard cross-entropy loss. The model learns general language patterns over ~10B tokens. Distributed training via DDP is supported.

Step 3 — Supervised Fine-Tuning (trainer/train_sft.py): Switch to SFTDataset with instruction/response pairs. The loss mask ignores prompt tokens so the model only learns to generate responses.

Step 4 — LoRA Adaptation (trainer/train_lora.py): Freeze the base model, inject LoRA low-rank matrices into Q/V projections, and fine-tune on domain data with ~0.1% trainable params.

Step 5 — Preference Alignment (trainer/train_dpo.py): Use DPODataset to learn from chosen/rejected response pairs. DPO directly optimises the policy without a separate reward model.

Step 6 — GRPO Reinforcement (trainer/train_grpo.py): Group Relative Policy Optimization samples multiple completions per prompt, ranks them, and updates the policy using relative advantages — no critic network needed.

Step 7 — Deployment (scripts/serve_api.py): Wrap the trained model in an OpenAI-compatible FastAPI server. The scripts/web_demo.py Streamlit app provides a chat interface for interactive testing.
