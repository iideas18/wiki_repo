🏪 Bakery Storefront Analogy

Think of the scripts module as the storefront and packaging department of a bakery. The model (bread) has been baked in the training kitchen — now it needs to be displayed and served. serve_openai_api.py is the counter where customers (clients) place orders via a standard menu (OpenAI API format). web_demo.py is the cozy café area with a tasting counter. convert_model.py is the packaging station — slicing, boxing, and labeling products for different distribution channels (HuggingFace, Llama format). And chat_openai_api.py is the mystery shopper testing the service.

    API Request Flow

    sequenceDiagram
    participant Client as Client / WebUI
    participant API as FastAPI Server
    participant Streamer as CustomStreamer
    participant Model as MiniMind Model
    participant LoRA as LoRA Weights (opt)

    Client->>API: POST /v1/chat/completions
    API->>API: Parse ChatRequest
    API->>Model: Load base weights
    API-->>LoRA: Merge LoRA (if present)

    alt Streaming Mode
        API->>Streamer: Create queue-based streamer
        API->>Model: model.generate(streamer=...)
        loop Token by token
            Model->>Streamer: put(token)
            Streamer->>API: yield from queue
            API->>Client: SSE data chunk
        end
        API->>Client: SSE [DONE]
    else Non-Streaming
        API->>Model: model.generate()
        Model->>API: full response
        API->>Client: JSON response
    end

    🔌 OpenAI API Compatibility

    How serve_openai_api.py mirrors the OpenAI /v1/chat/completions schema — request validation, response formatting, tool calling support, and drop-in SDK compatibility.

    📡 Streaming Architecture

    The CustomStreamer queue pattern: how tokens flow from model.generate() through a thread-safe queue into SSE chunks, enabling real-time token-by-token responses.

    Three-way conversion between native MiniMind .pth, HuggingFace Transformers, and LlamaForCausalLM formats — weight mapping, precision handling, and config generation.

    Starting the API Server

    Bash — Launch OpenAI-compatible server
    # Start the MiniMind API server on default port 8998
python scripts/serve_openai_api.py

# Test with curl
curl -X POST http://localhost:8998/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "MiniMind2",
    "messages": [{"role": "user", "content": "Hello!"}],
    "stream": true,
    "temperature": 0.7
  }'

    Model Format Conversion

    Python — Convert between model formats
    from scripts.convert_model import (
    convert_torch2transformers_minimind,
    convert_torch2transformers_llama,
    convert_transformers2torch,
)

# Native MiniMind → HuggingFace Transformers
convert_torch2transformers_minimind(
    input_path="weights/minimind2.pth",
    output_dir="weights/hf_minimind2"
)

# Native → LlamaForCausalLM (ecosystem compatible)
convert_torch2transformers_llama(
    input_path="weights/minimind2.pth",
    output_dir="weights/llama_minimind2"
)

# HuggingFace → Native .pth (fp16)
convert_transformers2torch(
    input_dir="weights/hf_minimind2",
    output_path="weights/minimind2_fp16.pth"
)

    Using the Chat Test Client

    Python — Streaming chat client
    from openai import OpenAI

client = OpenAI(base_url="http://localhost:8998/v1", api_key="none")

response = client.chat.completions.create(
    model="MiniMind2",
    messages=[{"role": "user", "content": "Explain transformers briefly"}],
    stream=True
)

for chunk in response:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
