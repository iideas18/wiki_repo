💡 Think of it like a browser engine — for the terminal

Just as Chrome has Blink to turn HTML into pixels, Ink is the engine that turns React components into terminal characters. The reconciler.ts is the equivalent of the DOM diffing engine, dom.ts is the virtual DOM, the layout/ directory is the CSS layout engine (powered by Yoga/Flexbox), and render-to-screen.ts is the "painter" that writes ANSI escape codes to your terminal buffer. Every <Box> and <Text> you see goes through this pipeline.

🚶 Walkthrough — Render Cycle

1

State Change Triggers Re-render

A React useState setter fires (e.g., new message arrives). React schedules a fiber reconciliation pass. frame.ts batches rapid-fire updates into a single frame to avoid flickering.

2

Reconciler Diffs the Fiber Tree

reconciler.ts walks the changed fibers and calls createInstance, commitUpdate, or removeChild on the virtual DOM. New DOMElement nodes are created in dom.ts with updated style props.

3

Yoga Computes Layout

The layout/ module maps each DOMElement's style to a Yoga node. calculateLayout() runs the flexbox algorithm, producing absolute x/y positions and computed widths/heights for every node in the tree.

4

Node-to-Output Serialization

render-node-to-output.ts walks the positioned tree, "painting" each node into a 2D character buffer. Text is wrapped, borders are drawn, colors are applied as ANSI codes. The result is an Output grid.

5

Screen Diff & Terminal Write

render-to-screen.ts diffs the new output buffer against the previous frame. Only changed cells emit ANSI escape sequences. terminal.ts flushes the minimal diff to stdout, producing a flicker-free update in the user's terminal.
