CLI — Transport & Session Layer

Transport & Session Layer

The CLI module owns the I/O boundary between Claude Code’s core loop and the outside world. It provides pluggable transport implementations (WebSocket, SSE, Hybrid), a structured bidirectional SDK protocol, the main headless session loop, and CLI subcommand handlers for auth, plugins, agents, and updates.

💡 Think of it like… a Postal Sorting Office

The CLI module is the postal sorting office sitting between Claude’s brain and the user’s terminal. StructuredIO is the front desk that reads/writes parcels (SDK messages). RemoteIO extends it for remote deliveries. The transports folder holds different delivery trucks — WebSocket for real-time two-way radio, SSE for one-way radio + mail drops, and Hybrid for a mix. SerialBatchEventUploader is the loading dock that ensures only one truck backs up at a time, preventing jams. runHeadless is the postmaster running the entire mail loop.

🚶 Step-by-Step Narrated Walkthrough

Follow a single remote headless session message through the CLI pipeline:

  1. Entry — runHeadless() initializes the session, loading conversation history for resume if applicable.
  2. Transport Init — RemoteIO calls getTransportForUrl() to select WebSocket, Hybrid, or SSE transport based on environment variables.
  3. Connection — The transport establishes its connection (WS handshake, SSE stream, or HTTP POST channel) with auto-reconnect configured.
  4. Message Read — StructuredIO.read() yields parsed SDK messages from stdin or the transport’s data callback.
  5. API Call — runHeadless sends the user message to the Claude API and processes the streaming response.
  6. Tool Execution — Tool-use blocks trigger permission checks via createCanUseToolWithPermissionPrompt() and auto-mode rules.
  7. Response Write — RemoteIO.write() enqueues the response; the transport batches stream_events for 100ms before flushing.
  8. Batch Upload — SerialBatchEventUploader serializes one POST at a time, using exponential backoff on failure.
  9. Text Coalescing — accumulateStreamEvents() in CCRClient merges text deltas into full snapshots per flush interval.
  10. Reconnect — On connection loss, the transport retries with exponential backoff (1s→30s) within a 10-minute budget; sleep detection resets the budget.

Code Examples

Selecting and Using a Transport

import { getTransportForUrl } from "./cli/transports/transportUtils";

const transport = getTransportForUrl(
  streamUrl,
  { Authorization: `Bearer ${token}` },
  sessionId,
  async () => ({ Authorization: `Bearer ${await refreshToken()}` })
);

transport.setOnData((message) => {
  console.log("Received:", message.type);
});

transport.setOnClose((code, reason) => {
  console.log(`Closed: ${code} - ${reason}`);
});

await transport.connect();
await transport.write({ type: "stream_event", data: payload });

StructuredIO Bidirectional Protocol

import { StructuredIO } from "./cli/structuredIO";

const io = new StructuredIO(stdin, stdout);

// Read incoming SDK messages as async generator
for await (const message of io.read()) {
  if (message.type === "user_message") {
    // Process user input
    const response = await callClaudeAPI(message.content);
    io.write({ type: "assistant_message", content: response });
  } else if (message.type === "control_response") {
    // Resolve pending permission request
    io.processResponse(message);
  }
}

CCR v2 Client Text Delta Coalescing

import { createStreamAccumulator, accumulateStreamEvents } from "./cli/transports/ccrClient";

// The accumulator merges text deltas into full snapshots
const state = createStreamAccumulator();

// As stream_event messages arrive from the assistant:
function onStreamEvent(events: StdoutMessage[]) {
  // Coalesces text_delta chunks into full text snapshots
  // Emitted every STREAM_EVENT_FLUSH_INTERVAL_MS (100ms)
  const coalesced = accumulateStreamEvents(events, state);
  // coalesced contains self-contained snapshots — safe for
  // clients that connect mid-stream
  transport.writeBatch(coalesced);
}

// When a message completes, clear accumulated state
clearStreamAccumulatorForMessage(state, messageId);
