Data Flow

Hooks follow React's unidirectional data flow. Each hook subscribes to a state source or event emitter and returns reactive values that trigger re-renders in the Ink component tree.

🚶 Step-by-Step Narrated Walkthrough

Follow a single tool permission request as it flows through the Hooks module:

  1. Tool Invocation — The agent decides to run a tool (e.g., bash). The useCanUseTool hook is invoked in the component that manages the tool execution flow.
  2. Permission Context Lookup — PermissionContext.ts provides the current permission state via React context. The hook reads the user's permission rules and auto-mode state.
  3. Handler Selection — Based on the session type, one of three handlers is selected: interactiveHandler (normal CLI), coordinatorHandler (swarm leader), or swarmWorkerHandler (swarm worker).
  4. Permission Evaluation — The selected handler evaluates the tool use against the permission rules. If auto-approved, execution proceeds immediately.
  5. Notification Dispatch — If the permission requires user interaction, notification hooks like useStartupNotification ensure the UI is ready. The useDeferredHookMessages hook queues any hook-generated messages.
  6. Interactive Prompt — The interactiveHandler triggers the permission dialog component. User input is captured via useTextInput and useGlobalKeybindings.
  7. Decision Logging — permissionLogging.ts records the user's decision (allow/deny) with analytics metadata for telemetry.
  8. State Update — The permission result propagates back through React state. useSettingsChange detects if the user added a new rule and triggers a settings cache refresh.
  9. Re-render Cascade — Components subscribed to the permission context re-render. The tool execution resumes or aborts based on the decision.
  10. Cleanup — When the component unmounts, all hook subscriptions are cleaned up via useEffect return functions, preventing memory leaks.
