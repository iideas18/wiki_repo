Bridge — Remote Session Protocol

Remote Session Protocol

The Bridge module implements Claude Code’s remote session infrastructure — enabling users on claude.ai to connect to long-running Claude Code sessions on developer machines. It handles environment registration, session spawning, message routing, and crash recovery across WebSocket, SSE, and HTTP transports.

💡 Think of it like… an Airport Control Tower

The Bridge module works like an airport control tower managing multiple runways (sessions). It registers landing strips (environments) with the central authority, polls for incoming flights (work items), acknowledges clearance, and routes cockpit communications (messages) between pilots (web users) and ground crew (local Claude Code processes). If a storm hits (crash), a pointer beacon lets the next controller resume operations.

🚶 Step-by-Step Narrated Walkthrough

Follow a single remote session lifecycle as it flows through the Bridge pipeline:

  1. Registration — bridgeMain calls registerBridgeEnvironment() to register with the Environments API, receiving an environmentId.
  2. Polling — The bridge enters a capacity-aware poll loop via pollForWork(), sleeping longer at full capacity.
  3. Work Arrival — A WorkData item arrives; the bridge calls acknowledgeWork() and decodes the WorkSecret.
  4. Session Spawn — sessionRunner forks a child process with the SDK URL, sandbox flags, and permission mode.
  5. Ingress Routing — bridgeMessaging.handleIngressMessage() routes incoming messages, deduplicating echoes via BoundedUUIDSet.
  6. Activity Tracking — Child stdout is parsed by extractActivities() into a ring buffer (max 10) for the terminal UI.
  7. Permission Round-Trip — Child emits control_request; the bridge forwards it to the API; the web user approves; a control_response returns.
  8. Token Refresh — createTokenRefreshScheduler() decodes the JWT expiry and schedules refresh 5 minutes before expiry.
  9. Crash Recovery — writeBridgePointer() persists {sessionId, environmentId} to disk; readBridgePointerAcrossWorktrees() restores it within the 4-hour TTL.
  10. Teardown — On session completion, archiveSession() is called and the bridge pointer is cleared.

Code Examples

Creating a Bridge API Client

import { createBridgeApiClient } from "./bridge/bridgeApi";

const client = createBridgeApiClient({
  apiBaseUrl: "https://api.claude.ai",
  getAccessToken: () => oauthTokenStore.getToken(),
  onTokenRefresh: (newToken) => oauthTokenStore.save(newToken),
  onDebug: (msg) => logger.debug(msg),
});

// Register environment and start polling
const envId = await client.registerBridgeEnvironment(bridgeConfig);
const work = await client.pollForWork(envId, secret, signal, 5000);
await client.acknowledgeWork(envId, work.id, work.token);

Crash Recovery via Bridge Pointer

import {
  writeBridgePointer,
  readBridgePointerAcrossWorktrees,
  clearBridgePointer,
} from "./bridge/bridgePointer";

// Persist pointer immediately after session creation
writeBridgePointer(projectDir, {
  sessionId: "cse_abc123",
  environmentId: "env_xyz789",
  source: "repl",
});

// On restart, recover session (checks staleness < 4h)
const pointer = await readBridgePointerAcrossWorktrees(projectDir);
if (pointer) {
  await client.reconnectSession(pointer.environmentId, pointer.sessionId);
}

// Clean shutdown
clearBridgePointer(projectDir);

Capacity-Aware Polling

import { createCapacityWake } from "./bridge/capacityWake";

const capacityWake = createCapacityWake(outerAbortSignal);

// Poll loop sleeps longer when at capacity
while (!signal.aborted) {
  if (activeSessionCount >= maxSessions) {
    // Sleep at capacity interval; wakes early when session freed
    await sleep(600_000, capacityWake.signal());
  } else {
    const work = await client.pollForWork(envId, secret, signal, 5000);
    if (work) {
      activeSessionCount++;
      spawnSession(work);
    }
    await sleep(2_000, signal);
  }
}

// Called when a session completes — wakes the poll loop
function onSessionComplete() {
  activeSessionCount--;
  capacityWake.wake();
}
