Top-Level React Screen Components

The screens module provides the 3 top-level React screen components that power Claude Code's terminal interface. Built on the Ink renderer (React for CLI), these screens orchestrate the entire user experience — from diagnostics to interactive conversation to session resumption.

💡 What Is This Module?

Think of the three screens like the three main rooms of a house. The REPL is the living room — it's where daily life happens, where you converse with the assistant, run tools, and get work done. The Doctor screen is the utility room — you visit it for maintenance checks, diagnostics, and making sure everything is in working order. And ResumeConversation is the attic — you go there to retrieve stored conversations and pick up right where you left off. The app's router decides which room you walk into based on the command you invoke.

Narrated Walkthrough

🚶 Launching Claude Code and Entering the REPL Screen

Trace the journey from typing claude in your terminal to an interactive REPL session:

  1. CLI Invocation — The user types claude in the terminal. The entrypoint parses CLI flags (--continue, --resume, /doctor) and determines which screen to launch.
  2. Router Decision — Without resume or doctor flags, the router selects REPL.tsx as the target screen component and passes the resolved configuration (tools, MCP clients, thinking config).
  3. REPL Initialization — The REPL component mounts. It fires useRemoteSession and useDirectConnect to establish any remote or SSH connections. useAssistantHistory loads prior messages if available.
  4. Hook Orchestra — Approximately 50 hooks spin up: useSSHSession for tunnels, token budget trackers, notification managers, vim mode state, cost tracking, and permission caches.
  5. Prompt Ready — The PromptInput component renders. The user sees the interactive prompt, the status line shows model info and token budget, and Claude Code is ready for conversation.
  6. Conversation Loop — Each user message triggers assistant response streaming, tool calls with permission gates, and result rendering. The REPL maintains this loop until the user exits.
  7. Skill Surveys & Search — Periodically, the REPL may surface skill improvement surveys or enable transcript search via the search overlay, all managed by dedicated hooks.

Screen Details

Doctor.tsx — Diagnostic Screen

Invoked via the /doctor command, this screen performs a comprehensive health check of the Claude Code installation. It leverages React Suspense to load diagnostic data asynchronously, displaying a loading state while checks complete. The screen validates:

  • System information (OS, Node.js version, shell)
  • Claude Code version and available updates via DistTagsDisplay
  • Settings file validity and permission configuration
  • MCP server connectivity and status for all configured servers
  • Sandbox environment availability and configuration
  • Version lock status via VersionLockInfo
  • Active agent configuration via AgentInfo
  • Keybinding conflicts and warnings

REPL.tsx — Main Interactive Screen

The largest and most complex screen, REPL.tsx is the heart of Claude Code. It orchestrates dozens of hooks to provide a seamless conversational interface. Key subsystems include:

  • Message pipeline — Streaming assistant responses with Markdown rendering
  • Permission system — Interactive approve/deny dialogs for tool invocations
  • Session management — Remote (useRemoteSession), direct (useDirectConnect), and SSH (useSSHSession) connections
  • Search & navigation — Transcript search overlay and history navigation via useAssistantHistory
  • Cost tracking — Real-time token usage and API cost display
  • Vim mode — Full vim keybinding support for the input prompt

ResumeConversation.tsx — Session Resume Screen

Displayed when the user passes --continue or --resume flags. This screen reads stored conversation logs and presents a searchable, filterable list. Advanced features include:

  • PR filtering — Filter sessions by associated pull request
  • Fork sessions — Branch off from a point in a previous conversation
  • Cross-project resume — Resume sessions started in different repositories
  • Worktree restoration — Restore git worktree state from the original session
  • Agent context — Restore agent configuration and tool permissions
