State — Central State Management

Central State Management

The State module implements Claude Code’s single-store state management system. A generic createStore factory powers an immutable AppState object with 100+ properties, wrapped in React Context for component access. Centralized side-effect handling via onChangeAppState ensures permission mode sync, config persistence, and auth cache clearing all flow through a single choke point.

💡 Think of it like… a City Hall Registry

The State module is City Hall’s central registry office. AppStateStore.ts is the master ledger — a single document with 100+ fields tracking everything from building permits (permissions) to citizen records (tasks). store.ts is the clerk’s desk that accepts updates and notifies subscribers. onChangeAppState.ts is the compliance officer who watches every edit and automatically files paperwork with external agencies (CCR, SDK). selectors.ts is the search desk that answers queries. teammateViewHelpers.ts handles the visitor log for agent viewing.

🚶 Step-by-Step Narrated Walkthrough

Follow a single permission mode change through the State pipeline:

  1. User Action — The user presses Shift+Tab, types /plan, or triggers a rewind. Multiple callsites converge on a single setAppState() call.
  2. Store Mutation — store.setState() applies the updater function immutably, producing a new AppState object.
  3. Listener Notification — All subscribed listeners (React components via useAppState) are notified and re-render if their selector output changed.
  4. onChange Trigger — onChangeAppState() fires with { newState, oldState }, checking each field category for changes.
  5. Permission Externalization — Internal modes (bubble, ungated-auto) are mapped to external equivalents (default) via toExternalPermissionMode().
  6. CCR Notification — If the external mode changed, notifySessionMetadataChanged() pushes the new mode to the CCR service.
  7. SDK Status — notifyPermissionModeChanged() sends the mode change to the SDK status stream for web UI consumers.
  8. Config Persistence — Model, view, and verbose changes are persisted to saveGlobalConfig() or saveUserSettings().
  9. Auth Cache Clear — If settings changed, API key and cloud credential caches are invalidated and environment variables re-applied.

Code Examples

Creating and Using the Store

import { createStore, type Store, type OnChange } from "./state/store";

interface CounterState {
  count: number;
  label: string;
}

const onChange: OnChange<CounterState> = ({ newState, oldState }) => {
  if (newState.count !== oldState.count) {
    console.log(`Count changed: ${oldState.count} → ${newState.count}`);
  }
};

const store: Store<CounterState> = createStore(
  { count: 0, label: "clicks" },
  onChange
);

// Subscribe to changes
const unsubscribe = store.subscribe(() => {
  console.log("State:", store.getState());
});

// Immutable update
store.setState((prev) => ({ ...prev, count: prev.count + 1 }));

Using AppState Hooks in Components

import { useAppState, useSetAppState } from "./state/AppState";
import { getActiveAgentForInput } from "./state/selectors";
import { enterTeammateView, exitTeammateView } from "./state/teammateViewHelpers";

function AgentPanel() {
  // Selector-based subscription: only re-renders when this slice changes
  const viewMode = useAppState((s) => s.viewSelectionMode);
  const tasks = useAppState((s) => s.tasks);
  const setAppState = useSetAppState();

  // Pure selector for input routing
  const activeAgent = useAppState((s) => getActiveAgentForInput(s));

  const handleViewAgent = (taskId: string) => {
    enterTeammateView(taskId, setAppState);
    // Sets viewingAgentTaskId, viewSelectionMode, retain=true
  };

  const handleExit = () => {
    exitTeammateView(setAppState);
    // Clears viewingAgentTaskId, releases task to stub form
  };
}
