Six files across the query/ directory and root orchestrate every interaction from input to final response.

Introduction

🎵 Think of it like an orchestra

QueryEngine is the stage manager — it sets up the venue, arranges the musicians, and handles logistics like loading memory and checking permissions. query() is the conductor, leading the performance measure by measure: calling the API, streaming events, cueing tool execution, and managing retries. config and deps provide the sheet music and instruments — feature gates and injected dependencies. stopHooks handles the curtain call, running post-turn tasks like memory extraction and job classification. Finally, tokenBudget watches the clock, deciding when the performance must end based on token thresholds and diminishing returns.

Narrated Walkthrough

🚶 A Single Query Turn: Input to Response

Trace what happens when a user sends “refactor this function”:

  1. QueryEngine.processUserInput — The engine receives the user message, builds the system prompt with project context, loads CLAUDE.md memory files, and records cost tracking metadata for the session.
  2. buildQueryConfig — A QueryConfig is constructed with the current sessionId and feature gates: streamingToolExecution, emitToolUseSummaries, isAnt, and fastModeEnabled.
  3. productionDeps — QueryDeps are assembled: callModel (the streaming API caller), microcompact and autocompact (context compressors), and uuid for message IDs.
  4. query() Generator Starts — The core async generator normalizes message history, processes any queued slash commands, and enters the main retry loop.
  5. API Call via callModel — queryModelWithStreaming sends the message array to the Claude API. On transient failure, the loop retries with exponential backoff.
  6. Stream Events — As tokens arrive, the generator yields SDK message events. Text blocks stream to the UI in real time. Tool-use content blocks are collected for execution.
  7. Tool Execution — Each tool_use block is dispatched to its handler (e.g., file edit, bash, search). Results are appended as tool_result messages. If streamingToolExecution is enabled, tools run in parallel with streaming.
  8. Auto-Compaction — If the conversation exceeds context limits, autocompact summarizes older turns. Reactive compaction triggers when the API returns a context-length error. Context collapse is a last-resort full rewrite.
  9. handleStopHooks — The async generator runs post-turn hooks: extract memories to CLAUDE.md, classify the job type, check task completion, and notify idle teammates. Returns a StopHookResult with any blockingErrors and a preventContinuation flag.
  10. checkTokenBudget — The BudgetTracker evaluates cumulative token usage against the 90% threshold and checks for diminishing returns. Returns a ContinueDecision (loop again) or StopDecision (halt).
  11. Continue or Stop — If the budget allows and stop hooks don’t prevent continuation, the loop issues another API call with the updated message history. Otherwise, the generator returns and QueryEngine finalizes session persistence.
  12. Response Delivered — The final assistant message is emitted to the SDK, costs are recorded, file history is updated, and the user sees the rendered output.
