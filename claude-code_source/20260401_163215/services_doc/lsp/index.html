services/lsp/ — Language Server Protocol Service

Code intelligence via Language Server Protocol

Manages multiple language server processes, provides go-to-definition, find-references, hover info, and real-time diagnostics. Uses a factory-function architecture with closures for state management, routing requests to the correct server based on file extensions. The eyes and ears that let Claude Code understand your codebase.

📚 What is this & why does it exist?

The LSP service gives Claude Code the ability to understand code structurally, not just as text. When you ask "where is this function defined?" or "what calls this method?", the LSP service routes that question to the right language server (TypeScript, Python, Rust, etc.) and returns precise, compiler-grade answers. It also passively collects diagnostics — errors and warnings — so Claude can proactively notice when its edits break something.

💡 Real-world analogy

Think of a large hospital with specialist departments — cardiology, neurology, orthopedics. The LSP Manager is the front-desk receptionist who knows which department handles which condition. When a patient (file) arrives, the receptionist checks their symptoms (file extension), routes them to the right specialist (language server), and makes sure the specialist is staffed and ready. Each specialist can diagnose problems (diagnostics), point to related cases (references), and explain medical history (hover info). If a specialist crashes, the receptionist tries to restart them up to three times before giving up.

Diagnostic Severity Mapping

LSP numeric severity values are mapped to human-readable strings for Claude's consumption:

// passiveFeedback.ts — mapLSPSeverity()
function mapLSPSeverity(lspSeverity: number | undefined): string {
  switch (lspSeverity) {
    case 1: return 'Error';     // DiagnosticSeverity.Error
    case 2: return 'Warning';   // DiagnosticSeverity.Warning
    case 3: return 'Info';      // DiagnosticSeverity.Information
    case 4: return 'Hint';      // DiagnosticSeverity.Hint
    default: return 'Error';    // Unknown → treat as Error
  }
}
// Diagnostics sorted by severity so Errors are delivered first
// when volume limits truncate results

Code Examples

Example 1: Server Instance with Transient Error Retry

import { createLSPServerInstance } from './LSPServerInstance';

const instance = createLSPServerInstance('typescript', {
  command: 'typescript-language-server',
  args: ['--stdio'],
  extensionToLanguage: { '.ts': 'typescript', '.tsx': 'typescriptreact' },
  maxRestarts: 3,
});

await instance.start();

// Requests automatically retry on ContentModified (-32801) errors
// with exponential backoff: 500ms, 1000ms, 2000ms
try {
  const result = await instance.sendRequest('textDocument/definition', {
    textDocument: { uri: 'file:///project/src/index.ts' },
    position: { line: 42, character: 10 },
  });
  console.log('Definition at:', result);
} catch (error) {
  // After MAX_RETRIES_FOR_TRANSIENT_ERRORS (3), throws with full context
  console.error(`LSP request failed: ${error.message}`);
}

Example 2: File Synchronization Protocol

import { createLSPServerManager } from './LSPServerManager';

const manager = createLSPServerManager();
await manager.initialize();

// Open a file — auto-routes to the right server via extensionMap
// Sends textDocument/didOpen with languageId from extensionToLanguage
await manager.openFile('src/app.ts', fileContent);

// After editing — sends textDocument/didChange (full content replacement)
// If file wasn't previously opened, auto-promotes to didOpen
await manager.changeFile('src/app.ts', updatedContent);

// After saving — sends textDocument/didSave
await manager.saveFile('src/app.ts');

// Check if file is tracked
console.log(manager.isFileOpen('src/app.ts')); // true

// Close — sends textDocument/didClose and removes from tracking
await manager.closeFile('src/app.ts');

Example 3: Diagnostic Collection with Deduplication

import { registerLSPNotificationHandlers } from './passiveFeedback';
import {
  checkForLSPDiagnostics,
  registerPendingLSPDiagnostic,
} from './LSPDiagnosticRegistry';

// Register handlers on all running servers
const result = registerLSPNotificationHandlers(manager);
console.log(`Registered on ${result.successCount}/${result.totalServers} servers`);

// Diagnostics arrive asynchronously via textDocument/publishDiagnostics
// and are queued in the registry. To retrieve them:

const diagnostics = checkForLSPDiagnostics();
// Returns deduplicated results:
//   - Within-batch dedup (same file + range + message)
//   - Cross-turn dedup via LRU cache (won't re-report same error)
//   - Sorted by severity: Error < Warning < Info < Hint
//   - Capped: 10 per file, 30 total across all files

for (const file of diagnostics) {
  console.log(`${file.uri}: ${file.diagnostics.length} issues`);
  for (const d of file.diagnostics) {
    console.log(`  [${d.severity}] L${d.range.start.line}: ${d.message}`);
  }
}
