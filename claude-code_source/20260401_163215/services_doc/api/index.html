services/api/ — Anthropic API Client Service

HTTP client for the Anthropic Claude API

Handles streaming responses, retry logic with exponential backoff, error classification, rate-limit awareness, token counting, and multi-provider support (Bedrock, Vertex AI, Azure Foundry). The core communication layer between Claude Code and the model.

📚 What is this & why does it exist?

The API service is Claude Code's telephone line to the Anthropic model. Every time the user asks Claude a question, this module packages the request, dials out to the right provider (Anthropic direct, AWS Bedrock, Google Vertex AI, or Azure Foundry), streams back the response token-by-token, and gracefully handles dropped connections, overloaded servers, and expired credentials.

💡 Real-world analogy

Think of a seasoned travel agent who can book flights with four different airlines (Anthropic, Bedrock, Vertex, Foundry). When one airline's phone line is busy (rate limit), the agent waits and redials with exponential backoff. If the line keeps dropping (529 overloaded), the agent tries a partner airline (model fallback). The agent also keeps detailed logs of every call (prompt dumping) and caches frequent-flyer data (bootstrap) so repeat trips are faster.

sequenceDiagram
  participant App as Claude Code
  participant WR as withRetry
  participant Client as AnthropicClient

  App->>WR: operation(client, retryContext)
  WR->>Client: getAnthropicClient(provider)
  Client->>API: POST /v1/messages (stream)
  alt Success
    API-->>WR: SSE token stream
    WR-->>App: yield tokens
  else 429 Rate Limited
    API-->>Err: APIError(429)
    Err->>WR: retryAfterMs
    WR->>WR: sleep(backoff)
    WR->>Client: retry request
  else 529 Overloaded
    API-->>Err: APIError(529)
    Err->>WR: consecutive529Errors++
    alt Under MAX_529_RETRIES
      WR->>Client: retry with backoff
    else Over threshold
      WR->>App: FallbackTriggeredError
    end
  end

Example 2: Resilient Retry with Model Fallback

import { withRetry, FallbackTriggeredError } from './withRetry';

const retryOptions: RetryOptions = {
  maxRetries: 10,
  model: 'claude-opus-4-20250514',
  fallbackModel: 'claude-sonnet-4-20250514',
  thinkingConfig: { enabled: true },
  signal: abortController.signal,
  querySource: 'repl_main_thread',
};

try {
  // withRetry is an async generator — yields error messages, returns final result
  const generator = withRetry(getAnthropicClient, sendRequest, retryOptions);
  for await (const errorMsg of generator) {
    // Display retry status to user (e.g., "Retrying in 2s...")
    displaySystemMessage(errorMsg);
  }
  const result = generator.return; // Final successful response
} catch (err) {
  if (err instanceof FallbackTriggeredError) {
    // Switch to fallback model and re-run
    retryOptions.model = err.fallbackModel;
  }
}

Example 3: File Upload with Retry

import { uploadSessionFiles, parseFileSpecs } from './filesApi';

const files = parseFileSpecs(['file_abc123:src/index.ts']);
const config: FilesApiConfig = {
  oauthToken: accessToken,
  sessionId: currentSessionId,
  baseUrl: 'https://api.anthropic.com',
};

// Uploads with exponential backoff (BASE_DELAY_MS=500, MAX_RETRIES=3)
// Path validation prevents directory traversal attacks
// MAX_FILE_SIZE_BYTES = 500MB per file
const results = await uploadSessionFiles(files, config);
for (const r of results) {
  if (r.success) console.log(`Uploaded ${r.path} → ${r.fileId}`);
  else console.error(`Failed ${r.path}: ${r.error}`);
}
