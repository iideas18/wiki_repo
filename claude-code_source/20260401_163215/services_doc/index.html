💡 Think of it this way: If Claude Code were a company, the services/ module is the entire back-office infrastructure. The API service is the mail room — every outgoing request and incoming response passes through it. OAuth is the security desk checking badges at the door. MCP is the intercom system connecting departments to outside vendors. Rate limiting is the traffic controller preventing hallway congestion. Analytics is the accounting department tracking every transaction. Session memory is the filing cabinet that remembers past conversations. No user-facing feature works without these back-office departments running smoothly behind the scenes.

Architecture

The services layer sits between the UI/REPL shell and external providers. Each service is a focused module with a clean boundary — services communicate through typed interfaces, not direct imports of each other's internals.

🚶 Step-by-Step Narrated Walkthrough

Follow a single user query from the REPL through the API service and back as it flows through the entire services pipeline:

  1. REPL Capture — The user types a query in the terminal. The REPL component serialises it into a UserMessage and dispatches it to the API service.
  2. OAuth Gate — oauth/ validates the stored access token. If expired, it silently refreshes via the refresh-token flow before proceeding.
  3. Rate-Limit Check — policyLimits/ evaluates per-minute and daily token quotas. If the user is over budget, the request is queued with exponential back-off.
  4. Token Estimation — tokenEstimation/ runs a fast BPE approximation over the full message history to calculate the context window footprint.
  5. Compaction Decision — If estimated tokens exceed the model's context window minus a safety margin, compact/ summarises older turns, preserving tool-use blocks and system prompts.
  6. Request Assembly — api/index.ts constructs the final HTTP payload: model, temperature, system prompt, tools array, and the (possibly compacted) message history.
  7. Streaming POST — The request is sent to the Anthropic Messages API with stream: true. An SSE parser begins consuming content_block_delta events.
  8. Chunk Relay — Each delta chunk is forwarded to the Ink renderer in real time. Tool-use blocks are detected and dispatched to the tool executor as soon as the block closes.
  9. Analytics Emission — On stream completion, analytics/ records token counts, latency percentiles, model version, and GrowthBook experiment assignments.
  10. Session Memory Update — SessionMemory/ appends the assistant turn. extractMemories/ scans the response for facts worth persisting to the CLAUDE.md memory file.

Sub-Modules

api/

Anthropic Messages API client — streaming, retries, and error mapping.

  • SSE-based streaming with back-pressure
  • Automatic retry with exponential back-off
  • Token usage tracking per request
  • Structured error classification

mcp/

Model Context Protocol — tool-server discovery, connection, and invocation.

  • JSON-RPC transport over stdio & SSE
  • Dynamic tool registration from servers
  • Server lifecycle management
  • Permission-scoped tool execution

lsp/

Language Server Protocol — code intelligence for diagnostics and completions.

  • Multi-language server management
  • Real-time diagnostics collection
  • Workspace symbol resolution
  • Hover & go-to-definition support
