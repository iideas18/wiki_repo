📚 What is this & why does it exist?

The MCP service is Claude Code's plugin system. It lets external tools — file editors, databases, web scrapers, custom APIs — plug into Claude Code through a standardized protocol. This module handles everything from discovering what tools a server offers, to authenticating with OAuth, to actually calling those tools and returning results to the model.

💡 Real-world analogy

Imagine a universal remote control (Claude Code) that can operate any brand of TV, sound system, or smart home device. Each device speaks its own language, so the remote has a translation chip (MCP protocol). When you press a button, the remote first discovers what the device can do (tool discovery), checks if you're authorized to use it (OAuth + permissions), and then sends the right signal over the right channel — infrared for the TV (stdio), Wi-Fi for the speaker (HTTP/SSE), Bluetooth for the smart lock (WebSocket). The config file is like programming the remote's memory buttons for each room.

Tool Naming Convention

MCP tools follow the triple-underscore naming pattern: mcp__<serverName>__<toolName>. The mcpStringUtils.ts module provides parsing and generation utilities:

import { mcpInfoFromString, buildMcpToolName, getMcpDisplayName } from './mcpStringUtils';

// Parse: "mcp__github__search_repos" → { server: "github", tool: "search_repos" }
const info = mcpInfoFromString('mcp__github__search_repos');

// Build: ("github", "search_repos") → "mcp__github__search_repos"
const fullName = buildMcpToolName('github', 'search_repos');

// Display: strip prefix for user-facing name
const display = getMcpDisplayName('mcp__github__search_repos', 'github');
// → "search_repos"

Code Examples

Example 1: Multi-Scope Config Aggregation

import { getAllMcpConfigs } from './config';

// Aggregates from all sources with precedence:
//   1. Enterprise managed-mcp.json (highest)
//   2. User ~/.claude/settings.json
//   3. Project .mcp.json
//   4. Plugin-provided servers (dynamic scope)
//   5. Claude.ai organization servers
const configs = await getAllMcpConfigs();

for (const [name, config] of Object.entries(configs)) {
  console.log(`${name} [${config.scope}]:`);
  if (config.type === 'stdio') {
    console.log(`  command: ${config.command} ${config.args?.join(' ')}`);
  } else if (config.type === 'sse' || config.type === 'http') {
    console.log(`  url: ${config.url}`);
    if (config.headersHelper) {
      console.log(`  headers via: ${config.headersHelper}`);
    }
  }
}

Example 2: MCP Tool Execution with OAuth Retry

import { MCPTool, createMcpClientConnection } from './client';
import { getMcpServerHeaders } from './headersHelper';

// Establish connection with transport auto-detection
const connection = await createMcpClientConnection(serverName, config);
if (connection.type !== 'connected') {
  throw new Error(`Connection failed: ${connection.type}`);
}

// Discover available tools
const tools = await fetchToolsForClient(connection.client);
const searchTool = tools.find(t => t.name === 'mcp__myserver__search');

// Execute with automatic OAuth 401 retry (max 2 attempts)
if (searchTool instanceof MCPTool) {
  const result = await searchTool.call(
    { query: 'find all TypeScript files' },
    { timeout: 30000 }
  );
  // Results are auto-truncated if too large
  console.log(result.content);
}
