📚 What is this & why does it exist?

BashTool is the primary way Claude Code interacts with the user’s operating system. When the AI needs to run a build, execute tests, install packages, or perform any shell operation, it invokes BashTool. The tool streams output back in real-time, handles timeouts for long-running processes, and enforces strict security rules to prevent destructive or malicious commands.

💡 Real-world analogy

Think of BashTool as a remote control for your terminal — the AI can press buttons, but security guards (permission layers) check each command first. Just like a hotel concierge who can call any department on your behalf, but only after verifying your room key and making sure you’re not asking them to open someone else’s safe. The concierge (BashTool) can run errands in the background, report back with results, and even switch departments (working directories), but always within the boundaries of what’s allowed.

Permission Resolution Flow

The permission system uses a fail-closed strategy where commands must be explicitly allowed. The resolution order is:

  1. Mode auto-approval — In acceptEdits mode, safe filesystem commands (mkdir, touch, rm, rmdir, mv, cp, sed) are auto-approved
  2. Classifier evaluation — Async risk assessment classifier evaluates command semantics
  3. Exact rule matching — User-defined rules checked for exact command string match
  4. Wildcard/prefix matching — Glob-style pattern rules evaluated against normalized command
  5. Operator decomposition — Compound commands (&&, ||, pipes) split and each segment validated
  6. Subcommand analysis — Up to 50 subcommands analyzed with suggested rules for compounds
  7. User confirmation — If no rule matches, prompt user for explicit approval

Example: Permission Flow Entry Point

// bashPermissions.ts — Main permission entry point
export async function bashToolHasPermission(
  input: { command: string; timeout?: number },
  context: ToolPermissionContext,
): Promise<PermissionResult> {
  // 1. Mode-based auto-approval (acceptEdits allows mkdir, touch, rm, etc.)
  const modeResult = checkPermissionMode(input.command, context);
  if (modeResult) return modeResult;

  // 2. Async classifier evaluation for risk assessment
  const classifierResult = await evaluateClassifier(input, context);
  if (classifierResult.behavior === 'deny') return classifierResult;

  // 3. Exact command matching against user-defined rules
  const exactMatch = matchExactRule(input.command, context.rules);
  if (exactMatch) return exactMatch;

  // 4. Operator permission checking (pipes, &&, ||)
  const operatorResult = checkCommandOperatorPermissions(input.command, context);
  if (operatorResult.behavior !== 'allow') return operatorResult;

  // 5. Subcommand analysis for compound commands
  return checkCommandAndSuggestRules(input.command, context);
}

Example: Command Exit Code Interpretation

// commandSemantics.ts — Semantic exit code mapping
export function interpretCommandResult(
  command: string,
  exitCode: number,
): string | undefined {
  const baseCmd = command.split(/\s+/)[0];
  switch (baseCmd) {
    case 'grep': case 'rg':
      // 0 = matches found, 1 = no matches (not an error), ≥2 = real error
      if (exitCode === 1) return 'No matches found (not an error)';
      if (exitCode >= 2) return 'Error occurred during search';
      break;
    case 'diff':
      // 0 = identical, 1 = differences found, ≥2 = error
      if (exitCode === 1) return 'Files differ (expected behavior)';
      break;
    case 'test': case '[':
      // 0 = condition true, 1 = condition false, ≥2 = error
      if (exitCode === 1) return 'Condition evaluated to false';
      break;
  }
  return undefined;
}
