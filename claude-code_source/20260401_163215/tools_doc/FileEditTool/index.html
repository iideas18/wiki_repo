📚 What is this & why does it exist?

FileEditTool is the surgical precision editor for Claude Code. Instead of rewriting entire files, it finds the exact passage to change and replaces just that section. This approach minimizes risk — only the targeted text changes, everything else stays intact. The tool enforces a strict read-before-write discipline and detects if the file was modified by another process between reads, preventing accidental overwrites.

💡 Real-world analogy

Imagine a meticulous copy editor working on a manuscript. Before making any change, they photograph the current page (read the file). They find the exact sentence to modify (old_str match), cross it out, and write the replacement (new_str). If someone else edited the same page while they were working, the editor notices the page looks different and asks to re-read it first. They also handle typography carefully — if the manuscript uses fancy curly quotes but the edit instructions use straight quotes, they automatically preserve the original style.

Atomicity & Critical Section

The edit pipeline is carefully structured to prevent race conditions. The critical section between staleness check and file write must be synchronous with no async yields:

  1. Pre-critical (async allowed) — Skill discovery, directory creation, file history backup
  2. Critical section (sync only) — Read file → check staleness → normalize quotes → apply edit → write to disk
  3. Post-critical (async allowed) — LSP notifications, state updates, analytics logging, git diff

Source comments explicitly warn: “Do not add async operations between the staleness check and the write operation.”

// utils.ts — Find actual string with curly-quote normalization
export function findActualString(
  fileContent: string,
  searchString: string,
): string | null {
  // 1. Try exact match first — most common case
  if (fileContent.includes(searchString)) {
    return searchString;
  }

  // 2. Normalize both sides: curly quotes → straight quotes
  const normalizedContent = normalizeQuotes(fileContent);
  const normalizedSearch = normalizeQuotes(searchString);

  const idx = normalizedContent.indexOf(normalizedSearch);
  if (idx === -1) return null;

  // 3. Extract actual substring from original file,
  //    preserving the curly quotes as they appear on disk
  return fileContent.substring(idx, idx + normalizedSearch.length);
}

Example: Atomic Edit Pipeline

// FileEditTool.ts — Core call() edit pipeline (simplified)
async call(input: FileEditInput, context): Promise<{ data: FileEditOutput }> {
  // Pre-edit: activate conditional skills (non-blocking)
  discoverSkillsForPath(input.file_path, context.dynamicSkillDirTriggers);

  // CRITICAL SECTION: no async yields between staleness check and write
  const { content, encoding, lineEndings } = readFileForEdit(input.file_path);

  // Staleness detection: timestamp-based, content fallback
  if (context.userModified(input.file_path)) {
    throw new Error(FILE_UNEXPECTEDLY_MODIFIED_ERROR);
  }

  // Quote normalization: find actual string preserving file's typography
  const actualOld = findActualString(content, input.old_string) ?? input.old_string;
  const actualNew = preserveQuoteStyle(input.old_string, actualOld, input.new_string);

  // Generate structured patch
  const { patch, updatedFile } = getPatchForEdit({
    filePath: input.file_path,
    fileContents: content,
    oldString: actualOld,
    newString: actualNew,
    replaceAll: input.replace_all,
  });

  // Write atomically with original encoding and line endings
  writeTextContent(input.file_path, updatedFile, { encoding, lineEndings });

  // Post-edit: LSP notifications (non-blocking failures)
  await lspManager.didChange(input.file_path, updatedFile);
  await lspManager.didSave(input.file_path);

  return { data: { filePath: input.file_path, structuredPatch: patch,
    originalFile: content, replaceAll: input.replace_all } };
}
