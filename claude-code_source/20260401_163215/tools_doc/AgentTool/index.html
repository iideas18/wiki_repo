tools/AgentTool/ — Sub-Agent Orchestration Tool

Spawns child agent tasks for parallel or delegated work

Creates sub-agents that can independently use tools, process queries, and return results. Core of the multi-agent architecture (swarms). Manages agent lifecycle, configuration loading, memory persistence, prompt caching, and result aggregation across built-in, custom, and plugin agent types.

📚 What is this & why does it exist?

AgentTool is how Claude Code delegates complex tasks to specialized sub-agents. Instead of one monolithic AI trying to do everything, AgentTool lets the parent agent spawn child workers — each with its own tool access, working directory, and system prompt. This is the foundation for features like parallel task execution, specialized exploration agents, and team-based multi-agent swarms.

💡 Real-world analogy

Think of AgentTool as a team lead who can hire temporary contractors. Each sub-agent gets its own workspace (potentially an isolated git worktree), tool access (a filtered set of available tools), and a clear assignment (the prompt). The team lead tracks progress, can run multiple contractors in parallel, and aggregates their reports into a final deliverable. Some contractors are built-in specialists (Explore, Plan), while others are custom-trained for specific project needs. The team lead manages their memory so past learnings carry forward across sessions.

Agent Source Priority

When multiple sources define agents with the same type, higher-priority sources override lower ones. The resolution order (highest to lowest):

  1. CLI argument agents — Passed via command-line flags, highest priority
  2. User agents — Defined in ~/.claude/agents/ (markdown or JSON)
  3. Project agents — Defined in .claude/agents/ (shared via VCS)
  4. Local agents — Machine-specific, not in version control
  5. Managed agents — Organization-provided agent definitions
  6. Plugin agents — Loaded from MCP plugin servers
  7. Built-in agents — Explore, Plan, Fork (lowest priority, always available)

Example: Agent Tool Resolution with Wildcards

// agentToolUtils.ts — Resolve agent tool spec to actual tools
export function resolveAgentTools(
  agentDef: AgentDefinition,
  availableTools: Tools,
): ResolvedAgentTools {
  const toolSpec = agentDef.tools ?? ['*'];
  const hasWildcard = toolSpec.includes('*');

  if (hasWildcard) {
    // Expand '*' to all available tools minus restricted set
    const restricted = new Set([
      ...ALL_AGENT_DISALLOWED_TOOLS,
      ...(agentDef.disallowedTools ?? []),
    ]);
    return {
      hasWildcard: true,
      validTools: availableTools
        .filter(t => !restricted.has(t.name))
        .map(t => t.name),
      invalidTools: [],
      resolvedTools: availableTools.filter(t => !restricted.has(t.name)),
    };
  }

  // Explicit tool list — validate each name exists
  const validTools: string[] = [];
  const invalidTools: string[] = [];
  for (const name of toolSpec) {
    if (name.startsWith('mcp__') || availableTools.find(t => t.name === name)) {
      validTools.push(name);
    } else {
      invalidTools.push(name);
    }
  }
  return { hasWildcard, validTools, invalidTools,
    resolvedTools: availableTools.filter(t => validTools.includes(t.name)) };
}

Example: Fork Message Building for Cache Sharing

// forkSubagent.ts — Build byte-identical prefixes for fork children
export function buildForkedMessages(
  directive: string,
  assistantMessage: AssistantMessage,
): MessageType[] {
  // All fork children share identical placeholder results for tool_use blocks
  // Only the final directive text differs per child → maximizes cache hits
  const placeholderResults = assistantMessage.content
    .filter(block => block.type === 'tool_use')
    .map(block => ({
      type: 'tool_result' as const,
      tool_use_id: block.id,
      content: 'Fork started — processing in background',
    }));

  return [
    ...historyMessages,
    { role: 'assistant', content: assistantMessage.content },
    { role: 'user', content: [
      ...placeholderResults,
      { type: 'text', text: buildChildMessage(directive) },
    ]},
  ];
}
