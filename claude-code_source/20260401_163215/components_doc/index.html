🏢 Think of It Like a Building

If Claude Code were a building, the components module is every room and piece of furniture inside it. The design-system primitives (Dialog, Tabs, Pane, ThemedText) are the standardized building materials—walls, doors, and light switches that every room shares. PromptInput is the front desk where visitors (users) speak. Messages is the main hall displaying the conversation. FullscreenLayout is the blueprint that decides where the hall, front desk, and side rooms go. Specialized rooms like permissions, mcp, and Settings are offices where specific business gets handled. And VirtualMessageList is the clever concierge who only turns on the lights in rooms that guests can actually see, keeping energy costs (render cycles) low.

🚶 Step-by-Step Narrated Walkthrough

Follow a single user message from typing to rendered response as it flows through the components pipeline:

  1. Keystroke Capture — The user presses a key. Ink’s useInput hook fires inside TextInput.tsx, updating the internal buffer and cursor position. In vim mode the keystroke is routed through the vim state machine first.
  2. PromptInput Processing — PromptInput.tsx (2,338 lines) receives the updated buffer. If the character is @, the typeahead menu opens via useTypeahead. Arrow keys trigger useArrowKeyHistory to cycle through past inputs.
  3. Suggestion Overlay — usePromptSuggestion queries model-powered completions. If matches exist, a FuzzyPicker overlay appears in the modal slot, navigable with arrow keys.
  4. Submit — User presses Enter. PromptInput calls onSubmit(userMessage), passing the text to the REPL engine. The input buffer is cleared and the prompt resets.
  5. API Streaming — The REPL engine sends the message to the Claude API. Token chunks arrive via streaming. Each chunk is appended to the in-progress AssistantMessage in state.
  6. Message Normalization — Messages.tsx (833 lines) receives the updated message array. It collapses consecutive same-type blocks, groups tool_use/tool_result pairs, and filters for brief mode if active.
  7. Lookup Tables — buildMessageLookups() creates indices: tool name → block, UUID → message index, in-progress tool IDs. These are passed as props to avoid re-computation in children.
  8. Virtual Scroll Calculation — VirtualMessageList uses cached heights (WeakMap) and cumulative sums. A binary search finds the first visible message index given the current scrollTop. Only messages in the viewport plus a small buffer are rendered.
  9. Message Routing — Each visible message hits Message.tsx (626 lines), which routes by type: UserTextMessage, AssistantTextMessage, ToolUseMessage (with spinner while shouldAnimate=true), or ThinkingMessage.
  10. Terminal Render — Ink compiles the React tree to terminal escape sequences. Blit caching ensures only changed cells are redrawn. Memoized subtrees (LogoHeader, completed Messages) produce zero writes, keeping the frame budget under 16ms even for 2,800-message transcripts.

Sub-Modules

PromptInput/

Primary REPL input system — 21 files handling all user input modalities.

  • Normal, Vim, and Voice input modes
  • Arrow-key history & Ctrl+R search
  • @-mention typeahead & prompt suggestions
  • Multiline editing & inline paste

Messages/

Message rendering pipeline — 33+ files for all block types and transcript display.

  • Normalization, collapsing & grouping
  • VirtualMessageList (lazy render + binary search)
  • Specialized renderers: text, tool use, thinking, attachments
  • Brief mode filtering & transcript mode

agents/

Agent task status views — 13 files for coordinator and sub-agent tracking.

  • Agent task progress & status badges
  • Coordinator hierarchy display
  • Parallel task monitoring

design-system/

Core terminal UI primitives — 16 files providing the shared component vocabulary.

  • Dialog, Tabs, Pane, ProgressBar
  • FuzzyPicker, ThemedText, ThemeProvider
  • Color tokens & layout utilities

permissions/

Tool permission dialogs — 15 files gating bash, file edit, web fetch, and more.

  • Risk assessment display
  • Approve / Reject keybinding flow
  • Sticky footer for scroll-aware prompts

mcp/

MCP server management — 12 files for server connections and approval dialogs.

  • Server connection status
  • Approval workflows
  • Tool discovery & listing
