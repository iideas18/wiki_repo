🚶 Step-by-Step Narrated Walkthrough

Follow a single file permission check as it flows through the utils permission engine:

  1. Tool Invocation — FileEditTool receives a request to write /etc/hosts. Before any I/O, it must consult permissions/.
  2. Rule Set Loading — permissions/ruleLoader.ts reads the active rule set from settings/ (managed, project, and user-level rules merged by priority).
  3. Tool Name Matching — The engine matches the tool identifier (file_edit) against rule patterns — exact matches are tried first, then wildcards.
  4. Path Pattern Evaluation — Each rule that matched the tool is tested against the target path /etc/hosts. Glob patterns like /etc/** are evaluated via glob.ts.
  5. Priority Resolution — Rules are sorted by priority (managed > project > user > default). The first matching rule wins — in this case, a managed rule blocks /etc/* writes.
  6. Dangerous Pattern Detection — Even without an explicit rule, the classifier checks a built-in deny list (e.g., rm -rf /, writes to /etc). This is a safety net.
  7. Decision Assembly — The engine builds a result: { allowed: false, reason: "Managed rule blocks /etc/** writes", source: "managed" }.
  8. Telemetry Emission — telemetry/ records the decision: tool name, path, outcome, rule source, and latency (~2 ms typical).
  9. User Notification — The decision propagates back to the tool, which surfaces a permission-denied message to the user with the reason string.
  10. Audit Trail — sessionStorage.ts appends the permission event to the session log for post-session review and compliance reporting.

Sub-Modules

git/

Git operations, repository detection, worktree management, and diff generation.

  • Cached findGitRoot() with LRU memoization
  • Worktree activation / deactivation lifecycle
  • Structured diff generation with context lines
  • Shallow clone detection and branch operations

permissions/

Fine-grained permission rule engine governing tool and file access control.

  • 24 files — rule loading, pattern matching, classifier
  • Priority-based resolution (managed → project → user)
  • Dangerous-pattern deny list as safety net
  • Audit trail integration with telemetry

sandbox/

Sandbox adapter for secure, isolated command execution environments.

  • Process isolation boundary enforcement
  • Adapter pattern for pluggable sandbox backends
  • Integration with permissions engine
  • Resource limit configuration

model/

Model options, capabilities, cost estimation, and provider selection.

  • 16 files covering model metadata and pricing
  • Provider-aware capability detection
  • Cost estimation for token budgeting

shell/

Shell provider abstraction — Bash, Zsh, PowerShell detection and configuration.

  • Platform-adaptive shell selection algorithm
  • Output size limits and stream management
  • Subprocess environment setup

telemetry/

Event logging, tracing (Perfetto format), session tracing, and analytics export.

  • Structured event emission with attributes
  • Perfetto-compatible trace generation
  • Statistics collection and BigQuery export
