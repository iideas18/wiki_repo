utils/permissions/ — Permission Engine

Security layer controlling what tools can do and when user approval is required

A 24-file permission system implementing rule-based access control for all tool operations. Manages permission modes (default, plan, acceptEdits, bypassPermissions, auto), path-based filesystem restrictions, shell command classification, dangerous pattern detection, and an AI-powered YOLO classifier for autonomous execution decisions.

📚 What is this & why does it exist?

The permissions module is the security gatekeeper of Claude Code. Every time the AI wants to run a shell command, edit a file, or access the network, it must pass through this system. The engine evaluates rules from 5 sources (user settings, project settings, local settings, CLI args, session), checks for dangerous patterns, and decides: allow silently, ask the user, or deny outright. It prevents the AI from accidentally deleting your git history, running rm -rf /, or accessing files outside your project.

💡 Real-world analogy

Think of airport security. Every passenger (tool action) must go through screening. There's a tiered system: trusted travelers with pre-check (allowlisted tools) walk through quickly, regular passengers (normal tools) go through standard screening (ask mode), and flagged individuals (dangerous patterns) get additional inspection or are denied boarding entirely. The security rules come from multiple authorities (TSA, airline, airport) just like permission rules come from user, project, and policy settings. A killswitch can shut down the fast lane if something goes wrong.

Example: Permission Rule Matching for Shell Commands

// Shell permission rules support 3 formats:
// 1. Exact: "npm install"
// 2. Prefix (legacy): "npm:*"
// 3. Wildcard: "npm * --save"

export function parsePermissionRule(rule: string): ShellPermissionRule {
  if (rule.includes(':*')) {
    // Legacy prefix format: "npm:*" matches "npm install", "npm run build"
    return { type: 'prefix', prefix: rule.replace(':*', '') };
  }
  if (hasWildcards(rule)) {
    // Wildcard: "git commit -m *" matches any commit message
    return { type: 'wildcard', pattern: rule };
  }
  // Exact match
  return { type: 'exact', command: rule };
}

Example: Permission Mode Cycling

// Mode cycling on Shift+Tab keypress
export function cyclePermissionMode(
  current: PermissionMode,
  isAntUser: boolean,
): PermissionMode {
  if (isAntUser) {
    // Ant users: default → bypassPermissions → auto → default
    const cycle: PermissionMode[] = ['default', 'bypassPermissions', 'auto'];
    const idx = cycle.indexOf(current);
    return cycle[(idx + 1) % cycle.length]!;
  }

  // External users: default → acceptEdits → plan → bypassPermissions → default
  const cycle: PermissionMode[] = [
    'default', 'acceptEdits', 'plan', 'bypassPermissions',
  ];
  const idx = cycle.indexOf(current);
  return cycle[(idx + 1) % cycle.length]!;
}

Example: Denial Tracking Circuit Breaker

// Tracks consecutive and total classifier denials to prevent loops
const DENIAL_LIMITS = { maxConsecutive: 3, maxTotal: 20 };

export function createDenialTrackingState(): DenialTrackingState {
  return { consecutive: 0, total: 0 };
}

export function recordDenial(state: DenialTrackingState): void {
  state.consecutive++;
  state.total++;
}

export function recordSuccess(state: DenialTrackingState): void {
  state.consecutive = 0; // Reset consecutive on any success
}

// When limits are hit, fall back to user prompting
export function shouldFallbackToPrompting(
  state: DenialTrackingState,
): boolean {
  return (
    state.consecutive >= DENIAL_LIMITS.maxConsecutive ||
    state.total >= DENIAL_LIMITS.maxTotal
  );
}
