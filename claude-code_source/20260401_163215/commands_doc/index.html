🔵 Slash Commands 🟢 Skills & Plugins 🟡 Lazy Loading 🔴 Auth-Gated

What are commands? Commands are the primary interface between the user and Claude Code's capabilities. When a user types /commit or /config, the commands module resolves the input to a registered handler, validates permissions, assembles context, and dispatches execution—either locally or through the model.

💡 Analogy: Think of commands as the speed-dial buttons on an office phone. Each button is labeled, pre-configured for a specific destination, and handles all the dialing complexity behind a single press. Some buttons connect you internally (LocalCommand), some patch you through to an operator (PromptCommand), and some light up a fancy display panel (LocalJSXCommand).

🚶 Step-by-Step: /config Through the Full Lifecycle

Follow a single /config set theme dark invocation as it flows through the entire commands pipeline:

  1. Input Parsing — The CLI input loop detects the / prefix and extracts the raw token "config" plus arguments ["set", "theme", "dark"].
  2. Command Lookup — findCommand("config") searches the command registry. The registry is lazily populated on first access; if the config module hasn't been loaded yet, its dynamic import() fires now (~2 ms).
  3. Type Resolution — The registry identifies /config as a LocalJSXCommand, meaning it renders a React (Ink) component rather than invoking the model.
  4. Auth Gate — validateAuth() checks whether the current session has the required permissions. /config is available to all users—no auth gate blocks it.
  5. Argument Validation — The command's argument schema (sub-command set, key theme, value dark) is validated against its declared options. Invalid keys produce a helpful error message.
  6. State Read — The config command reads the current configuration from ~/.claude/settings.json and the project-level .claude/settings.json, merging them with precedence rules.
  7. Mutation — The set sub-command writes theme: "dark" into the appropriate config file. A file lock prevents concurrent writes from parallel sessions.
  8. JSX Render — The ConfigView Ink component receives the updated config object and renders a confirmation panel: a diff of old → new values, styled with the new theme colors.
  9. Side Effects — A configChanged event is emitted on the global event bus, triggering subscribers (the theme engine, prompt builder, and telemetry collector) to reload their cached values.
  10. Completion — Control returns to the input loop. The user sees ✅ theme → dark and the UI instantly re-renders with the dark palette. Total wall time: ~15 ms.

Code Example — Registering a Command

import { registerCommand, PromptCommand } from "../registry";

const commitCommand: PromptCommand = {
  name: "commit",
  description: "AI-assisted git commit with generated message",
  aliases: ["ci"],
  category: "git",
  authRequired: false,

  async buildPrompt(args, context) {
    const diff = await context.git.getStagedDiff();
    return {
      system: "You are a commit message generator...",
      user: `Write a commit message for:\n\n${diff}`,
    };
  },

  async onComplete(result, context) {
    await context.git.commit(result.message);
    context.display.success(`Committed ${result.hash}`);
  },
};

registerCommand(commitCommand);
