💡 Think of it like an airport check-in counter

Just as an airport check-in counter validates your ticket, checks your baggage, assigns you a gate, and routes you toward the correct terminal — the CLI module validates command-line arguments, resolves environment variables, selects the right sub-command handler, and routes execution to the appropriate part of the application. Every interaction with Claude Code begins here, at the front desk.

Configuration

The CLI module is configured through a combination of Commander.js option definitions and environment variable mappings. Key configuration points include:

// Flag definition example from flags.ts
export const globalFlags = {
  model: {
    flag: '--model <name>',
    env: 'CLAUDE_MODEL',
    description: 'Override the default AI model',
    default: 'sonnet',
    choices: ['sonnet', 'opus', 'haiku'],
  },
  verbose: {
    flag: '--verbose',
    env: 'CLAUDE_VERBOSE',
    description: 'Enable verbose debug logging',
    default: false,
    type: 'boolean',
  },
  outputFormat: {
    flag: '--output-format <fmt>',
    description: 'Response output format',
    choices: ['text', 'json', 'stream-json'],
    default: 'text',
  },
  allowedTools: {
    flag: '--allowedTools <tools...>',
    description: 'Restrict available tool set',
    type: 'string[]',
  },
};

Environment variables always take precedence over defaults but are overridden by explicit command-line flags. Profiles provide a way to group flag presets under a named configuration.
