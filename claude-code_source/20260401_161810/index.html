Claude Code

AI-Powered Terminal Assistant

Claude Code is an AI-powered CLI tool by Anthropic that enables conversational coding directly in the terminal. It features a React-based terminal UI (Ink), modular tool system, slash commands, MCP integration, IDE bridging, multi-agent orchestration, and comprehensive permission management across 1900+ TypeScript/TSX files.

🏙️ What is this?

Think of Claude Code as a city with districts. The CLI district is the main gate where users enter commands. The UI district (React/Ink) renders everything you see in the terminal — permission dialogs, tool output, streaming markdown. The Tools district is the industrial zone where real work happens: editing files, running bash, fetching web pages, spawning sub-agents. The Services district connects the city to the outside world via MCP servers, LSP language services, OAuth providers, and IDE bridges. And the Infrastructure district keeps the lights on — utilities, state management, migrations, and configuration constants that every other district depends on.

This wiki maps every street in the city. Start here at the hub, pick a district, then drill into individual buildings (sub-modules) to see exactly how each piece works.

Request Flow — How Modules Connect

Trace a single user request from keyboard input through to rendered response.

sequenceDiagram
    participant User as  User Input
    participant CLI as CLI Parser
    participant Screen as REPL Screen
    participant Query as Query Engine
    participant Model as Model API
    participant Tools as Tool Execution
    participant Hooks as Hook Pipeline
    participant Render as Response Rendering

    User->>CLI: Type command or prompt
    CLI->>Screen: Route to REPL screen
    Screen->>Query: Build query with context
    Note over Screen,Query: context + memdir + state assembled
    Query->>Model: Send to Claude API
    Note over Query,Model: Token budget, streaming config applied

    loop Tool Use Loop
        Model->>Tools: Request tool call
        Note over Tools: Permission check via hooks
        Tools->>Hooks: Check permissions
        Hooks-->>Tools: Grant / deny / ask user
        Tools->>Tools: Execute tool (bash, edit, fetch...)
        Tools-->>Model: Return tool result
        Note over Model: Cost tracking updated
    end

    Model->>Render: Stream final response
    Render->>Screen: Render markdown in terminal
    Screen->>User: Display formatted output
    Note over User,Render: Conversation stored in state for /compact and resume
Key insight: The Query Engine is the central hub — it assembles context from context/, sends requests through services/, and dispatches tool calls through the permission-gated tools/ system. Every tool execution passes through the hooks pipeline for permission checks, cost tracking, and telemetry. The state module persists the full conversation so sessions can be compacted or resumed.

Build & Tech Stack

TypeScript

1900+ .ts / .tsx files. Strict mode with comprehensive type definitions. TSX used for React/Ink terminal components.

React / Ink

Terminal UI built on React with a custom Ink renderer. Components use hooks for state, effects, and lifecycle — just like web React, but rendered to ANSI terminal output.

Bun Runtime

Built and executed with Bun for fast startup, native TypeScript support, and efficient bundling. Uses Bun's built-in test runner for the test suite.

MCP Protocol

Model Context Protocol integration for extensibility — connect to external tools, data sources, and services through a standardized JSON-RPC interface.
