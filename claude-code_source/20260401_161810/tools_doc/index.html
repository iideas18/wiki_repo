    The tools module contains 40+ modular tool implementations that extend Claude's capabilities. Each tool follows a consistent buildTool() factory pattern with Zod schema validation, permission integration, and structured I/O. Tools are the primary interface for executing file operations, shell commands, code searches, web fetching, and multi-agent orchestration.

    Architecture Overview

    Tools are grouped by functional category. The buildTool() factory wires each tool with schema validation, permission checks, and output formatting. Cross-cutting concerns like concurrency safety and cost tracking are handled at the router level.

    Data Flow

    Every tool invocation follows the same lifecycle: the model emits a structured tool call, the router validates input via Zod, the permission system gates execution, and results flow back through a formatter.

    sequenceDiagram
    participant M as Model
    participant TR as ToolRouter
    participant PC as PermissionCheck
    participant TE as ToolExec
    participant RF as ResultFormatter
    participant FS as FileSystem
    participant SH as Shell
    participant SA as SubAgent

    M->>TR: tool_call(name, params)
    TR->>TR: Zod schema validation
    TR->>PC: check permissions(tool, params)
    PC-->>TR: allowed / denied
    alt Denied
        TR-->>M: PermissionError
    end
    TR->>TE: execute(validated_params)

    alt BashTool
        TE->>SH: spawn process
        SH-->>TE: stdout/stderr
    else FileEditTool
        TE->>FS: read → patch → write
        FS-->>TE: updated content
    else AgentTool
        TE->>SA: spawn sub-agent
        SA-->>TE: agent result
    end

    TE->>RF: format result
    RF-->>M: structured output + cost

    Narrated Walkthrough: File Edit Operation

    Tracing a FileEditTool invocation end-to-end illustrates the shared lifecycle all tools follow, plus edit-specific logic like fuzzy matching and diff generation.

    Model sends FileEditTool call — The model emits a structured call with file_path, old_str, and new_str parameters.
    Zod schema validation — Input is validated against the tool's Zod schema. Missing or malformed fields produce immediate errors with helpful messages.
    Permission check — The permission system verifies filesystem access rules for the target path, including workspace boundaries and deny-list checks.
    Fuzzy string matching — findActualString() performs fuzzy matching with quote-character preservation to locate old_str in the file content, tolerating minor whitespace variations.
    File content read — The file is read from disk. For large files, streaming is used. The MAX_EDIT_FILE_SIZE limit (1 GiB) is enforced.
    Diff generation — getPatchForEdit() generates a unified diff showing the change context, used both for display and audit logging.
    Content write — The new content (with old_str replaced by new_str) is written atomically to the file.
    Result formatting — The result is formatted with a diff preview, line numbers of the change location, and a snippet of surrounding context.
    Cost tracking — Token usage for the operation is tracked and attributed to the current session's cost budget.
    UI display — The UI renders the edit diff with syntax highlighting, showing the before/after state of the modified region.

    Sub-Module Overview

    🖥️ BashTool

    Shell command execution with command classification (read-only vs write), sandbox isolation, timeout management, and structured stdout/stderr capture.

    shellsandboxprocess

    ✏️ FileEditTool

    Surgical file edits via old_str→new_str replacement. Fuzzy matching with findActualString(), unified diff generation via getPatchForEdit(), and atomic writes.

    editdifffuzzy-match

    📖 FileReadTool

    Reads files with support for PDF extraction, Jupyter notebook rendering, image base64 encoding, line range selection, and large-file streaming.

    readpdfnotebook

    🤖 AgentTool

    Spawns sub-agents with isolated contexts. Supports worktree-based git isolation, context cloning, token budget inheritance, and result aggregation.

    agentworktreeorchestration

    🔍 GrepTool

    Ripgrep integration with configurable output modes (content, files, count), context line flags (-A, -B, -C), glob filtering, and multiline support.

    searchripgrepregex

    🌐 WebFetchTool

    Fetches URLs with HTML-to-markdown conversion, host approval gating, content truncation, LLM post-processing for readability, and raw HTML mode.

    webfetchmarkdown

    🔌 MCPTool

    Invokes tools exposed by Model Context Protocol servers. Handles server discovery, tool listing, parameter marshalling, and authentication flows.

    mcpprotocolintegration

    📋 TaskTools

    Background task lifecycle — TaskCreate, TaskStop, TaskGet, TaskList, TaskOutput, TaskUpdate. Manages async agent execution with progress polling.

    taskasynclifecycle

    📦 shared/

    Common infrastructure: git operation tracking for diff attribution, multi-agent spawn helpers, tool registry utilities, and cross-tool type definitions.

    sharedgitinfra
