💡 Think of it like a diplomatic embassy

An embassy acts as a bridge between two countries with different languages, laws, and protocols. It translates documents, relays permission requests, and ensures both sides understand each other. The remote module serves as the embassy between a local Claude Code instance and a remote Claude Compass/CCR session — translating SDK message formats, bridging permission requests so the local user can approve remote actions, and maintaining a persistent WebSocket channel like a diplomatic hotline between the two environments.

Configuration

The remote module is configured through RemoteSessionConfig, which specifies the CCR endpoint, authentication, and connection behavior. WebSocket parameters control reconnection and heartbeat timing:

// Remote session configuration from types.ts
export interface RemoteSessionConfig {
  ccrEndpoint: string;
  sessionId: string;
  authToken: string;
  websocket: {
    reconnectBaseMs: number;
    reconnectMaxMs: number;
    reconnectJitter: number;
    heartbeatIntervalMs: number;
    heartbeatTimeoutMs: number;
    messageQueueMaxSize: number;
  };
  permissions: {
    autoApproveRead: boolean;
    autoApproveWrite: boolean;
    promptTimeout: number;
    defaultDeny: boolean;
  };
  sdkAdapter: {
    localVersion: string;
    remoteVersion: string;
    strictMode: boolean;
  };
}

// Default remote configuration
export const defaultRemoteConfig: Partial<RemoteSessionConfig> = {
  websocket: {
    reconnectBaseMs: 1000,
    reconnectMaxMs: 30000,
    reconnectJitter: 0.3,
    heartbeatIntervalMs: 15000,
    heartbeatTimeoutMs: 5000,
    messageQueueMaxSize: 100,
  },
  permissions: {
    autoApproveRead: false,
    autoApproveWrite: false,
    promptTimeout: 60000,
    defaultDeny: true,
  },
};

Permission bridging defaults to requiring explicit user approval for all actions (defaultDeny: true). The autoApproveRead and autoApproveWrite flags can be enabled for trusted remote environments where manual approval would be disruptive.
