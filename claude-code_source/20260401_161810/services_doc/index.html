Backend Service Layer

The services module provides 20+ background service modules that power Claude Code's infrastructure. This includes MCP (Model Context Protocol) server management, LSP integration, OAuth authentication, analytics/telemetry, session memory compaction, rate limiting, plugin management, voice input, and diagnostic tracking. Services run independently of the UI layer and provide data/functionality to commands and components.

🏗️ Architecture Overview

The services module is organised into seven functional clusters. Protocol services handle external tool & language-server communication; Intelligence services manage memory and summarisation; Monitoring captures events and diagnostics; and Control services enforce policies and sync settings across instances.

🚶 Walkthrough — Trace an MCP Tool Invocation

Follow a single MCP tool call from user configuration to final display, touching permission checks, server communication, analytics, and token accounting.

  1. User configures MCP server in settings
    Server endpoint, authentication, and capability metadata are persisted to the local configuration store.
  2. MCP service discovers and connects to server
    The mcp/ module reads config, opens a transport channel, and performs the MCP handshake.
  3. Server capabilities registered as available tools
    Returned tool schemas are normalised and merged into the global tool registry.
  4. Model requests MCP tool execution
    During inference, the model emits a tool_use block targeting a registered MCP tool.
  5. Permission check against MCP server approval rules
    The request is evaluated against server-level and tool-level approval policies.
  6. Tool call forwarded to MCP server process
    Serialised arguments are sent over the transport; the server executes the operation.
  7. Response received and formatted
    The raw response is deserialised, validated, and transformed into the internal result format.
  8. Analytics event logged
    analytics/ records the tool call, latency, and outcome for telemetry.
  9. Token usage tracked
    tokenEstimation.ts accounts for input/output tokens consumed by the tool call.
  10. Result displayed in UI
    The formatted result is handed to the rendering pipeline and shown to the user.
