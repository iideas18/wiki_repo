📚 What is this & why does it exist?

While the persona agents bring qualitative judgment, the quantitative agents provide systematic, data-driven analysis. The fundamentals agent examines financial statements, the technicals agent analyzes price and volume patterns, the sentiment agent gauges market mood from insider trades and news, and the valuation agent calculates intrinsic value using DCF and comparables. Together they form a comprehensive quantitative foundation that the persona agents' qualitative insights build upon.

💡 Real-world analogy

These four agents are like the instruments in a medical checkup. The fundamentals agent is the blood test (financial health metrics — profitability, growth, debt levels). The technicals agent is the EKG (heart rhythm patterns mapped to price and volume patterns). The sentiment agent is the patient interview ("how are you feeling?" mapped to insider trading behavior and news mood). And the valuation agent is the diagnostic assessment (here's what we think you're worth based on multiple models). Each instrument measures something different, and the doctor (Portfolio Tracking & Performance Metrics" href="../../backtesting_doc/portfolio/index.html">portfolio manager) needs all of them to make a diagnosis.

🤔 Why Is It Designed This Way?

The quantitative agents use a fundamentally different approach from the persona agents. Instead of sending data to an LLM with a philosophical prompt, they compute signals algorithmically using threshold-based scoring and weighted ensemble methods. The fundamentals agent checks whether ROE exceeds 15%, the technicals agent calculates moving average crossovers, and the sentiment agent counts bullish vs. bearish insider trades. This deterministic approach makes the quantitative agents faster, cheaper (no LLM calls for most), and reproducible. The valuation agent is the exception — it uses four mathematical models (Owner Earnings, DCF with WACC, comparable multiples, and residual income) and aggregates them with configurable weights. The trade-off is less nuance than LLM-based agents, but the consistency and speed are worth it for systematic metrics.

📑 Annotated Code Walkthrough

The fundamentals agent demonstrates the threshold-based scoring approach used by quantitative agents. Unlike persona agents that rely on LLM reasoning, this agent deterministically scores each financial dimension.

fundamentals_analyst_agent — Threshold-Based Analysis

def fundamentals_analyst_agent(state: AgentState, agent_id: str = "fundamentals_analyst_agent"):
    """Analyzes fundamental data and generates trading signals for multiple tickers."""
    data = state["data"]
    end_date = data["end_date"]
    tickers = data["tickers"]
    api_key = get_api_key_from_state(state, "FINANCIAL_DATASETS_API_KEY")
    fundamental_analysis = {}

    for ticker in tickers:
        financial_metrics = get_financial_metrics(
            ticker=ticker, end_date=end_date, period="ttm", limit=10, api_key=api_key,
        )
        if not financial_metrics:
            continue

        metrics = financial_metrics[0]  # Most recent period
        signals = []
        reasoning = {}

        # 1. Profitability Analysis
        return_on_equity = metrics.return_on_equity
        net_margin = metrics.net_margin
        operating_margin = metrics.operating_margin

        thresholds = [
            (return_on_equity, 0.15),   # Strong ROE above 15%
            (net_margin, 0.20),          # Healthy profit margins
            (operating_margin, 0.15),    # Strong operating efficiency
        ]
        profitability_score = sum(
            metric is not None and metric > threshold
            for metric, threshold in thresholds
        )

        signals.append(
            "bullish" if profitability_score >= 2
            else "bearish" if profitability_score == 0
            else "neutral"
        )

        # 2. Growth Analysis
        revenue_growth = metrics.revenue_growth
        earnings_growth = metrics.earnings_growth
        book_value_growth = metrics.book_value_growth

        thresholds = [
            (revenue_growth, 0.10),    # 10% revenue growth
            (earnings_growth, 0.10),   # 10% earnings growth
            (book_value_growth, 0.10), # 10% book value growth
        ]
        growth_score = sum(
            metric is not None and metric > threshold
            for metric, threshold in thresholds
        )

        # 3. Financial Health
        current_ratio = metrics.current_ratio
        debt_to_equity = metrics.debt_to_equity
        health_score = 0
        if current_ratio and current_ratio > 1.5:
            health_score += 1
        if debt_to_equity and debt_to_equity < 0.5:
            health_score += 1

Line-by-line:

  • Line 10-12: Fetches TTM metrics with limit=10 periods. The agent only uses financial_metrics[0] (most recent), but the API call pattern mirrors persona agents for consistency.
  • Line 13-14: Early exit on missing data — if the API returns nothing, the ticker is silently skipped. No fallback or default signal is emitted.
  • Line 15: metrics = financial_metrics[0] picks only the most recent TTM snapshot, discarding historical data. This is a key design difference from persona agents (e.g., Buffett uses all 10 periods for trend analysis).
  • Lines 24-31: The threshold pattern: each metric is compared against a hard-coded threshold using a list comprehension. The metric is not None guard prevents TypeError when the API returns null values. Scoring is binary: meet threshold = 1 point, miss = 0.
  • Lines 33-37: Signal mapping uses a 2/3 majority rule: 2+ out of 3 metrics passing = bullish, 0 passing = bearish, otherwise neutral. This is simpler than the persona agents' LLM-based scoring but highly reproducible.
  • Lines 54-56: Health scoring uses different threshold types — current ratio must be above 1.5 (liquidity) while D/E must be below 0.5 (low leverage). The asymmetry shows domain knowledge encoded as rules.
