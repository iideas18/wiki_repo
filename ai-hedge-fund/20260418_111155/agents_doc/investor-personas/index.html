📚 What is this & why does it exist?

These 13 agents are the creative heart of the system. Each encodes decades of a real investor's published philosophy, books, and interview quotes into an LLM system prompt. The agent then uses this persona to interpret financial data — the same P/E ratio that excites a growth investor like Cathie Wood might horrify a value investor like Ben Graham. This diversity of perspective is the core insight: no single philosophy works in all markets.

💡 Real-world analogy

Imagine a book club where each member reads the same novel but interprets it through their professional lens. A psychologist focuses on character motivations (Buffett analyzes Portfolio Management" href="../management/index.html">management quality), a statistician tracks plot patterns (the technical analyst tracks price patterns), and a critic evaluates literary technique (Graham evaluates balance sheet quality). Same data, radically different interpretations — and the discussion between them produces richer understanding than any single perspective.

🤔 Why Is It Designed This Way?

The persona-agent pattern encodes domain expertise as natural-language system prompts rather than hard-coded rules. Each agent follows an identical structural contract — (state: AgentState) → {signal, confidence, reasoning} — but swaps in a different philosophical framework via its prompt. This design was chosen over a single agent with a "style" parameter because each investor's logic requires different sub-analyses: Buffett needs moat analysis while Taleb needs tail-risk metrics. Separating agents also allows LangGraph to run them in parallel across the fan-out phase, maximizing throughput. The trade-off is code duplication across agents, but the domain separation makes each agent independently testable and modifiable.

Common Signal Contract

Every persona agent, regardless of which investor it embodies, must produce output conforming to this contract. The signal is always one of three values, confidence is always 0-100, and reasoning is free-form text explaining the investment thesis. This uniformity is what allows the risk manager and portfolio manager to treat all 13 agents identically.

class InvestorSignal(BaseModel):
    signal: Literal["bullish", "bearish", "neutral"]
    confidence: int = Field(description="Confidence level 0-100")
    reasoning: str = Field(description="Investment thesis reasoning")

Sub-Analysis Scoring Pattern

Each persona agent runs multiple domain-specific sub-analyses. While the exact analyses differ (Buffett runs 7, Graham runs 3, Taleb runs 4+), they all follow the same scoring pattern: each sub-analysis returns a dict with a score key and domain-specific details. Scores are aggregated, normalized against max_possible_score, and then passed to the LLM for final interpretation through the persona's philosophical lens.

📑 Annotated Code Walkthrough

The most important code in this sub-module: Warren Buffett's core agent function, which exemplifies the pattern all 13 persona agents follow.

warren_buffett_agent — Core Analysis Pipeline

def warren_buffett_agent(state: AgentState, agent_id: str = "warren_buffett_agent"):
    """Analyzes stocks using Buffett's principles and LLM reasoning."""
    data = state["data"]
    end_date = data["end_date"]
    tickers = data["tickers"]
    api_key = get_api_key_from_state(state, "FINANCIAL_DATASETS_API_KEY")
    analysis_data = {}
    buffett_analysis = {}

    for ticker in tickers:
        # Step 1: Fetch raw financial data
        progress.update_status(agent_id, ticker, "Fetching financial metrics")
        metrics = get_financial_metrics(ticker, end_date, period="ttm", limit=10, api_key=api_key)

        # Step 2: Run Buffett-specific sub-analyses
        fundamental_analysis = analyze_fundamentals(metrics)
        consistency_analysis = analyze_consistency(financial_line_items)
        moat_analysis = analyze_moat(metrics)
        pricing_power_analysis = analyze_pricing_power(financial_line_items, metrics)
        book_value_analysis = analyze_book_value_growth(financial_line_items)
        mgmt_analysis = analyze_management_quality(financial_line_items)
        intrinsic_value_analysis = calculate_intrinsic_value(financial_line_items)

        # Step 3: Aggregate sub-analysis scores
        total_score = (
            fundamental_analysis["score"] +
            consistency_analysis["score"] +
            moat_analysis["score"] +
            mgmt_analysis["score"] +
            pricing_power_analysis["score"] +
            book_value_analysis["score"]
        )

        # Step 4: Calculate margin of safety (Buffett's key metric)
        margin_of_safety = None
        intrinsic_value = intrinsic_value_analysis["intrinsic_value"]
        if intrinsic_value and market_cap:
            margin_of_safety = (intrinsic_value - market_cap) / market_cap

        # Step 5: Send to LLM with Buffett persona prompt
        buffett_output = generate_buffett_output(
            ticker=ticker, analysis_data=analysis_data[ticker],
            state=state, agent_id=agent_id,
        )

        # Step 6: Store in standard signal format
        buffett_analysis[ticker] = {
            "signal": buffett_output.signal,
            "confidence": buffett_output.confidence,
            "reasoning": buffett_output.reasoning,
        }

    # Write signals to shared state
    state["data"]["analyst_signals"][agent_id] = buffett_analysis

Line-by-line:

  • Line 1-2: Standard signature — every persona agent takes AgentState and a default agent_id. The ID is used as the key in analyst_signals so downstream consumers know which persona produced which signal.
  • Line 6: API key extraction from state allows different API keys per run (multi-tenant), rather than relying on environment variables.
  • Lines 12-13: Buffett uses TTM (trailing twelve months) with 10 periods — he cares about recent performance trends, not just the latest quarter.
  • Lines 16-22: The six sub-analyses are Buffett-specific. Other agents have entirely different analyses (Taleb has analyze_tail_risk, Cathie Wood has analyze_disruptive_potential). This is why each persona needs its own file.
  • Lines 30-32: Margin of safety — Buffett's most famous concept. He only buys when intrinsic value exceeds market price by a significant margin. This raw metric is passed to the LLM for interpretation.
  • Lines 35-38: The LLM call is where the persona really lives. generate_buffett_output wraps the analysis data in a system prompt that channels Buffett's voice and priorities.
  • Lines 41-44: Output is normalized to the standard {signal, confidence, reasoning} format that the risk manager and portfolio manager expect from all agents.

Code Examples

Example: Ben Graham's Score-Based Signal Mapping

Graham's agent demonstrates the simpler scoring approach where scores directly map to signals without an LLM call for the initial assessment, though the LLM refines the final output:

# Aggregate scoring from three sub-analyses
total_score = (
    earnings_analysis["score"] +
    strength_analysis["score"] +
    valuation_analysis["score"]
)
max_possible_score = 15  # 5 per analysis

# Direct score-to-signal mapping (deterministic)
if total_score >= 0.7 * max_possible_score:     # >= 10.5
    signal = "bullish"
elif total_score <= 0.3 * max_possible_score:    # <= 4.5
    signal = "bearish"
else:
    signal = "neutral"
