What is this & why does it exist?

The backend translates HTTP requests into agent pipeline executions. When a user clicks “Run” in the web UI, the backend receives the React Flow Orchestration" href="../../core_doc/graph/index.html">graph definition (nodes + edges), builds a LangGraph StateGraph from it using create_graph(), compiles and invokes it, and streams progress events (Start → Progress → Complete/Error) back to the browser via Server-Sent Events. The repository pattern abstracts SQLite access for flow persistence, and Alembic handles schema migrations.

Real-world analogy

The backend is an air traffic control tower. The frontend is the radar screen (visual display), but the tower (backend) actually coordinates takeoffs and landings (agent executions), maintains flight records (database), and broadcasts status updates to all screens (SSE streaming). The create_graph() function reads the flight plan (React Flow definition) and creates the actual route (LangGraph). The repository is the flight log book — every flow configuration and run result is recorded for replay and audit.

Why Is It Designed This Way?

SSE was chosen over WebSockets because the communication is unidirectional (server → client) and SSE is simpler to implement with FastAPI’s StreamingResponse. The create_graph() function dynamically builds a StateGraph from React Flow node/edge definitions rather than hardcoding the pipeline because the web UI allows users to compose arbitrary agent topologies. The repository pattern decouples database access from route handlers, making it easy to swap SQLite for PostgreSQL. The extract_base_agent_key() function strips random suffixes from React Flow node IDs to match against the canonical ANALYST_CONFIG dictionary.

SSE Streaming Data Flow

The most distinctive pattern: a single HTTP POST triggers an async generator that yields SSE events as agents complete their work.

sequenceDiagram
  participant Browser
  participant Route as /hedge-fund/run
  participant Graph as GraphService
  participant LG as LangGraph Runtime
  participant Progress as progress tracker

  Browser->>Route: POST {nodes, edges, tickers, model}
  Route->>Graph: create_graph(nodes, edges)
  Graph-->>Route: compiled StateGraph
  Route-->>Browser: SSE: StartEvent
  Route->>LG: graph.invoke(state) [async task]
  loop Agent Execution
    LG->>Progress: update_status(agent, ticker, status)
    Progress->>Route: progress_handler callback
    Route-->>Browser: SSE: ProgressUpdateEvent
  end
  LG-->>Route: final_state
  Route-->>Browser: SSE: CompleteEvent {decisions, signals}

Annotated Code Walkthrough

The most important code in this sub-module, annotated with WHY each piece exists:

SSE Streaming Endpoint (routes/hedge_fund.py)

async def run(request_data: HedgeFundRequest, request: Request,
              db: Session = Depends(get_db)):
    # WHY: Hydrate API keys from DB when frontend doesn't send them
    if not request_data.api_keys:
        api_key_service = ApiKeyService(db)
        request_data.api_keys = api_key_service.get_api_keys_dict()

    portfolio = create_portfolio(request_data.initial_cash, ...)

    # WHY: Build graph from React Flow nodes/edges - not hardcoded
    graph = create_graph(
        graph_nodes=request_data.graph_nodes,
        graph_edges=request_data.graph_edges
    )
    graph = graph.compile()

    async def event_generator():
        progress_queue = asyncio.Queue()

        # WHY: Progress handler bridges sync agent code to async SSE stream
        def progress_handler(agent_name, ticker, status, analysis, timestamp):
            event = ProgressUpdateEvent(agent=agent_name, ticker=ticker,
                                        status=status, timestamp=timestamp)
            progress_queue.put_nowait(event)

        progress.register_handler(progress_handler)

        # WHY: Run graph in background task so we can yield SSE events concurrently
        run_task = asyncio.create_task(run_graph_async(graph=graph, ...))
        disconnect_task = asyncio.create_task(wait_for_disconnect())

        yield StartEvent().to_sse()

        while not run_task.done():
            # WHY: Detect client disconnect to cancel wasted work
            if disconnect_task.done():
                run_task.cancel()
                return
            try:
                event = await asyncio.wait_for(progress_queue.get(), timeout=1.0)
                yield event.to_sse()
            except asyncio.TimeoutError:
                pass  # Keep polling

        result = await run_task
        yield CompleteEvent(decisions=result["decisions"], ...).to_sse()

    return StreamingResponse(event_generator(), media_type="text/event-stream")

Line-by-line:

  • asyncio.Queue bridge: Agent code is synchronous (LangGraph invokes agent functions in threads). The progress handler is a sync callback that pushes events into an async queue, bridging the two worlds.
  • wait_for_disconnect(): A concurrent task that monitors the HTTP connection. If the user closes the browser tab, this task completes, and the generator cancels the expensive LLM execution.
  • asyncio.wait_for(queue.get(), timeout=1.0): Polls the queue with a 1-second timeout. This prevents the generator from blocking indefinitely when no progress events are available, allowing disconnect detection to work.
  • StreamingResponse: FastAPI’s built-in SSE support. Each yield sends one SSE frame to the browser.
