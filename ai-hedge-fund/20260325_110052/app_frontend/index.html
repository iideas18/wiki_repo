📚 What is this & why does it exist?

Financial analysts traditionally orchestrate research pipelines through code—writing scripts to chain data feeds, analyst models, and portfolio optimisers. This frontend replaces that code with a visual circuit board for trading strategies.

💡 Real-world analogy

Imagine a music producer’s DAW (Digital Audio Workstation). Each “track” is a node—a Stock Analyzer node feeds ticker data like a MIDI input, Agent nodes are effects pedals (sentiment analysis, technical analysis, risk evaluation), a Portfolio Manager node is the mixing desk that blends all signals into buy/sell decisions, and the Output node is the master output that records the final mix. You drag cables between them, hit Play, and watch the meters bounce in real time via SSE streaming.

Deep Dive

Context Provider Architecture

Four React contexts wrap the entire application in a strict nesting order: ReactFlowProvider → FlowProvider → TabsProvider → LayoutProvider. Each context follows the provider-value-hook triad: a *Provider component holds state, a *Context object carries the value, and a use*Context() hook provides typed access.

Flow isolation is the most critical design decision. NodeContext keys all runtime data with composite keys "flowId:nodeId", preventing cross-contamination when users switch between flow tabs. useNodeState mirrors this with "flowId:nodeId:stateKey" for persistent configuration. When FlowContext.loadFlow() is called, it sets the flow ID before restoring nodes so that downstream hooks resolve to the correct data partition.

SSE Streaming Pipeline

The api.runHedgeFund() function in services/api.ts opens a fetch-based SSE stream to POST /hedge-fund/run. The response body is read as a ReadableStream, accumulated into an event buffer, and split on double-newlines. Each event is parsed with regex:

const eventTypeMatch = eventText.match(/^event: (.+)$/m);
const dataMatch = eventText.match(/^data: (.+)$/m);
const eventType = eventTypeMatch[1];  // "start" | "progress" | "complete" | "error"
const eventData = JSON.parse(dataMatch[1]);

On progress events, the agent name (e.g. stock_analyzer_agent) is mapped to a node ID via extractBaseAgentKey(), and NodeContext.updateAgentNode() sets the node to IN_PROGRESS or COMPLETE. On complete, setOutputNodeData() populates the output node with decisions, signals, and metrics. A 30-second timer auto-resets the connection state to idle. The function returns an abort callback bound to an AbortController.

Node State Management

useNodeState<T>(nodeId, stateKey, defaultValue) is a persistent drop-in for useState. Under the hood, FlowStateManager (a global singleton) stores values in a Map<string, any> keyed by "flowId:nodeId:stateKey". Every set call notifies listeners, triggering React re-renders only in the affected hook instance. When FlowContext saves a flow, it calls FlowStateManager.getAllStatesForFlow() and embeds them in node.data.internal_state; on load, states are restored from that payload. UI-only fields (selection, dragging) are excluded from snapshots.

SSE Event Dispatch — Progress Handler

// services/api.ts  —  inside runHedgeFund() SSE reader
case 'progress': {
  const { agent, ticker, status, analysis, timestamp } = eventData;
  const nodeId = extractBaseAgentKey(agent);  // "stock_analyzer_agent" → node ID
  const isDone = status === 'Done';
  nodeContext.updateAgentNode(flowId, nodeId, {
    status: isDone ? 'COMPLETE' : 'IN_PROGRESS',
    ticker,
    message: status,
    analysis: analysis ?? null,
    timestamp,
    lastUpdated: Date.now(),
  });
  break;
}
