💡 What is this?

Think of this module as the assembly line blueprint for the hedge fund. Just as a car factory defines which stations (welding, painting, inspection) run in what order, this module defines which AI analyst agents run, how their outputs merge, and when the final portfolio manager makes a decision. AgentState is the shared clipboard every worker writes to; create_workflow() is the foreman wiring the stations together via a LangGraph StateGraph.

    Architecture Overview

    graph LR
  START([start_node]) --> A1[Analyst 1]
  START --> A2[Analyst 2]
  START --> AN[Analyst N]
  A1 --> RM[risk_management_agent]
  A2 --> RM
  AN --> RM
  RM --> PM[portfolio_manager]
  PM --> END_NODE([END])

    The workflow is a fan-out / fan-in DAG. The start_node broadcasts state to every selected analyst in parallel. All analyst outputs merge via the merge_dicts reducer, then flow sequentially through risk management and the portfolio manager.

    State Flow

    stateDiagram-v2
  [*] --> start_node : HumanMessage
  start_node --> analysts : fan-out
  analysts --> risk_management : merge signals
  risk_management --> portfolio_manager : risk-adjusted
  portfolio_manager --> [*] : trading decisions

    Example 2 — Understanding the merge_dicts Reducer

    from src.graph.state import merge_dicts

# When two analyst nodes return simultaneously, LangGraph
# calls the reducer to combine their outputs:
state_a = {"analyst_signals": {"tech": {"signal": "buy"}}}
state_b = {"analyst_signals": {"fundamental": {"signal": "sell"}}}

merged = merge_dicts(state_a, state_b)
# Result: {"analyst_signals": {"fundamental": {"signal": "sell"}}}
# NOTE: This is a SHALLOW merge — nested keys are overwritten.
# Each agent writes to its own top-level key to avoid collisions.

    Example 3 — Custom Workflow with Subset of Analysts

workflow = create_workflow(["technical_analyst", "sentiment_analyst"])

# The resulting graph: start → tech + sentiment → risk → portfolio → END
