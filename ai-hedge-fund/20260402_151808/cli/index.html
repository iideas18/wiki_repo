💡 What is this module?

The cli module is the front door to the AI Hedge Fund when running from the terminal. It collects all user inputs — which tickers to analyse, which analysts to run, which LLM to use, date ranges, and portfolio parameters — and packages them into a CLIInputs dataclass.

"Think of it as a concierge desk at a hotel — when you walk in, the concierge (CLI) greets you, asks what you need (ticker selection, model choice), validates your request (date parsing), and hands you a neatly prepared itinerary (CLIInputs) before sending you on your way."

Architecture Overview

The CLI module has a single main entry point — parse_cli_inputs() — that orchestrates argparse for non-interactive flags and questionary for interactive prompts. The result is a CLIInputs dataclass consumed by the main orchestrator.

Deep Dive

📦 CLIInputs Dataclass

All user configuration in one object: tickers, selected_analysts, model_name, model_provider, start_date, end_date, initial_cash, margin_requirement, show_reasoning.

🎯 Analyst Selection

Interactive checkbox with questionary — Space toggles individual analysts, 'a' selects all, Enter confirms. Shows analyst display_name and description from ANALYST_CONFIG.

🤖 Model Selection

Dropdown showing all available models grouped by provider. When Ollama is selected, an additional text prompt asks for the custom model name to pull.

📅 Date Resolution

resolve_dates() handles multiple date formats, applies sensible defaults (last 3 months), and validates that start_date precedes end_date.

# CLIInputs dataclass — the output of the CLI module
from dataclasses import dataclass, field

@dataclass
class CLIInputs:
    tickers: list[str] = field(default_factory=list)
    selected_analysts: list[str] = field(default_factory=list)
    model_name: str = "gpt-4o"
    model_provider: str = "OpenAI"
    start_date: str = ""
    end_date: str = ""
    initial_cash: float = 100_000.0
    margin_requirement: float = 0.0
    show_reasoning: bool = False
    show_tool_calls: bool = False
# Interactive analyst selection with questionary
import questionary
from utils.analysts import ANALYST_CONFIG, ANALYST_ORDER

def select_analysts() -> list[str]:
    choices = [
        questionary.Choice(
            title=f"{cfg['display_name']} — {cfg['description']}",
            value=key,
            checked=True,
        )
        for key in ANALYST_ORDER
        if (cfg := ANALYST_CONFIG[key])
    ]
    selected = questionary.checkbox(
        "Select analysts to run:",
        choices=choices,
        instruction="(Space=toggle, a=all, Enter=confirm)",
    ).ask()
    return selected or ANALYST_ORDER  # default to all
# Model selection with Ollama custom input support
def select_model() -> tuple[str, str]:
    models = get_models_list()
    choices = [f"{m.display_name} ({m.provider.value})" for m in models]
    answer = questionary.select("Select LLM model:", choices=choices).ask()

    selected = models[choices.index(answer)]
    if selected.provider == ModelProvider.OLLAMA:
        custom = questionary.text(
            "Enter Ollama model name:",
            default=selected.model_name,
        ).ask()
        return custom, selected.provider.value

    return selected.model_name, selected.provider.value
