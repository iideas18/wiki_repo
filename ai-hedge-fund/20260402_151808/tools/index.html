💡 What is this module?

The tools module is the sole data-fetching layer for the AI Hedge Fund. Every piece of financial data — prices, metrics, insider trades, news — flows through here.

"Think of it as a research librarian — you ask for a financial document, it knows exactly which shelf (API endpoint) to look on, checks if it already has a copy (cache), and politely waits if the library is busy (rate limiting)."

Architecture Overview

The tools module follows a layered design: public API functions delegate to a private _make_api_request() that handles HTTP requests, rate-limit retries, and error handling. Results flow through Pydantic models before being cached.

Deep Dive

🔌 api.py

Core API wrapper — 7 public functions + 1 private request handler. Manages all communication with the Financial Datasets API including rate limiting and caching.

⚡ Rate Limiting

Implements linear backoff on 429 responses: 60s + 30s × attempt. Retries up to 3 times before raising. Logs warnings for each retry attempt.

📦 Caching Strategy

Uses the data.cache module for in-memory caching. Each API function checks cache before making network requests, reducing redundant calls.

✅ Pydantic Validation

All API responses are parsed through Pydantic response models (PriceResponse, FinancialMetricsResponse, etc.) ensuring type safety.

# Internal _make_api_request with rate-limit retry
def _make_api_request(url: str, params: dict) -> dict:
    headers = {"X-API-Key": os.getenv("FINANCIAL_DATASETS_API_KEY")}
    for attempt in range(3):
        response = requests.get(url, headers=headers, params=params)
        if response.status_code == 429:
            wait = 60 + 30 * attempt
            logger.warning(f"Rate limited. Waiting {wait}s...")
            time.sleep(wait)
            continue
        response.raise_for_status()
        return response.json()
    raise Exception("Max retries exceeded")
