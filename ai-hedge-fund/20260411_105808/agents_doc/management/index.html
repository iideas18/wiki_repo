Risk & Portfolio Management

The Safety Net — Deterministic Constraints Over LLM-Generated Signals

2 Agents Sequential Pipeline Deterministic + LLM Hybrid

💡 What is this? Think of an airport control tower. The 19 analyst agents are like pilots requesting permission to land (buy/sell stocks). The Risk Manager is air traffic control — it checks runway capacity (portfolio limits), weather conditions (market volatility), and separation rules (correlation constraints) before clearing each flight. Some flights get denied; others have their altitude (position size) reduced. The Portfolio Manager is the airport director — once flights are cleared, it decides which runway (execution strategy) to use and in what order planes actually land. Critically, both operate on deterministic constraints first, then consult the LLM for nuanced judgment. The math always has veto power over the AI.

Architecture — Risk → Portfolio Pipeline

Unlike the analyst agents which run in parallel via fan-out, the management agents run sequentially. The Risk Manager must complete before the Portfolio Manager can begin, because the portfolio agent needs the risk-adjusted constraints to make valid decisions.

Annotated Code Walkthrough — compute_allowed_actions()

This is the most critical function in the entire system. It is fully deterministic — no LLM, no randomness. It computes exactly what the Portfolio Manager is allowed to do for each ticker, acting as a hard constraint that the LLM cannot override.

Function signature. Takes a single ticker plus all context needed to make the constraint decision. Returns a structured dict of allowed actions with maximum quantities. 
def compute_allowed_actions(
    ticker: str,
    analyst_signals: dict,
    portfolio: dict,
    volatility_metrics: dict,
    correlation_multiplier: float,
    portfolio_value: float,
    max_position_pct: float = 0.25
) -> dict:
Calculate the base position limit. The maximum dollar amount for any single position is capped at max_position_pct of total portfolio value (default 25%). This prevents catastrophic concentration. 
    # Hard cap: no single position > 25% of portfolio
    base_limit = portfolio_value * max_position_pct
Apply volatility adjustment. High-volatility stocks get smaller position limits. The adjustment uses the stock's ATR (Average True Range) relative to its price, normalized against a baseline volatility. 
    vol = volatility_metrics.get(ticker, {})
    atr_pct = vol.get("atr_pct", 0.02)  # ATR as % of price

    # Baseline: 2% daily ATR. Higher vol = smaller position.
    vol_adjustment = min(1.0, 0.02 / atr_pct) if atr_pct > 0 else 1.0
    vol_adjusted_limit = base_limit * vol_adjustment
Apply correlation multiplier. If this stock is highly correlated with existing portfolio positions, reduce the limit further to prevent hidden concentration. 
    # correlation_multiplier is in [0.5, 1.0]
    # 1.0 = uncorrelated (full limit), 0.5 = highly correlated (halved)
    final_limit = vol_adjusted_limit * correlation_multiplier
Determine current position. Check what we already own. This determines whether buy, sell, or both are allowed. 
    current_position = portfolio.get("positions", {}).get(ticker, {})
    current_shares = current_position.get("shares", 0)
    current_value = current_position.get("market_value", 0)
    current_price = current_position.get("current_price", 0)
Compute allowed buy quantity. We can only buy up to the remaining room under the position limit. If we already hold the max, buying is disallowed. 
    remaining_room = max(0, final_limit - current_value)
    max_buy_shares = int(remaining_room / current_price) if current_price > 0 else 0
    available_cash = portfolio.get("cash", 0)
    cash_limited_shares = int(available_cash / current_price) if current_price > 0 else 0
    max_buy = min(max_buy_shares, cash_limited_shares)

    allowed_actions = {"hold": True}  # Hold is always allowed
    if max_buy > 0:
        allowed_actions["buy"] = {"max_quantity": max_buy}
Compute allowed sell quantity. We can only sell what we own. Short selling is not currently supported. 
    if current_shares > 0:
        allowed_actions["sell"] = {"max_quantity": current_shares}

    return {
        "ticker": ticker,
        "allowed_actions": allowed_actions,
        "position_limit": final_limit,
        "volatility_adjustment": vol_adjustment,
        "correlation_multiplier": correlation_multiplier,
    }

Design Rationale

Why Separate Risk from Portfolio Management

The separation of Risk Manager from Portfolio Manager implements the financial industry's principle of segregation of duties. In real trading operations, the person who decides what to trade should never be the same person who controls risk limits. This prevents a single agent from both wanting to buy a stock and approving its own purchase.

In the AI Hedge Fund, this separation is implemented structurally: the Risk Manager computes constraints (what's allowed), and the Portfolio Manager makes decisions within those constraints. The Risk Manager cannot generate trades, and the Portfolio Manager cannot modify risk limits. They are separate functions in separate files with separate responsibilities.

Why Deterministic Constraints Before LLM

The most important design principle in the management layer: the math always has veto power over the AI. The compute_allowed_actions() function is fully deterministic — no LLM, no randomness, no prompt sensitivity. Its output is a hard constraint that the Portfolio Manager's LLM call cannot override.

This means that even if the LLM "hallucinates" a desire to put 50% of the portfolio into a single meme stock, the deterministic position limit (25% max) will prevent it. The LLM can only choose among options the math has already approved. This is defense-in-depth: the LLM adds value through nuanced judgment, but cannot cause catastrophic losses through bad judgment.

Why Volatility-Adjusted Position Sizing

A fixed position size (e.g., "always buy $10,000 worth") ignores the fact that $10,000 of a volatile biotech stock represents far more risk than $10,000 of a blue-chip utility. Volatility-adjusted sizing normalizes risk exposure: a stock with 4% daily ATR gets half the position size of a stock with 2% daily ATR, so both positions contribute approximately equal risk to the portfolio.

Algorithm Deep-Dives

1. Volatility-Adjusted Position Sizing

The core formula maps a stock's volatility into a position size multiplier:

def calculate_volatility_adjusted_limit(
    atr_pct: float,
    portfolio_value: float,
    max_position_pct: float = 0.25,
    baseline_atr: float = 0.02
) -> float:
    """Convert volatility into a position size limit.

    Args:
        atr_pct: Stock's ATR as a percentage of price (e.g., 0.03 = 3%)
        portfolio_value: Total portfolio value in dollars
        max_position_pct: Maximum position as fraction of portfolio
        baseline_atr: The "normal" ATR level (2% daily)

    Returns:
        Maximum dollar value for this position

    Example:
        - Stock with 2% ATR → full 25% position allowed ($250K on $1M)
        - Stock with 4% ATR → halved to 12.5% ($125K on $1M)
        - Stock with 1% ATR → capped at 25% (never exceed max)
    """
    base_limit = portfolio_value * max_position_pct

    if atr_pct <= 0:
        return base_limit  # No volatility data → allow full position

    vol_multiplier = min(1.0, baseline_atr / atr_pct)
    return base_limit * vol_multiplier

2. Correlation Multiplier Calculation

If you already hold tech stocks and want to buy another tech stock, the true portfolio risk is higher than if you're buying an uncorrelated asset. The correlation multiplier reduces position limits for correlated additions.

def calculate_correlation_multiplier(
    candidate_returns: list,
    portfolio_returns: list,
    high_corr_threshold: float = 0.7,
    min_multiplier: float = 0.5
) -> float:
    """Reduce position size for assets correlated with existing portfolio.

    Uses Pearson correlation between candidate stock returns and
    portfolio-weighted average returns.

    Returns:
        Multiplier in [min_multiplier, 1.0]
        - 1.0 = uncorrelated, full position allowed
        - 0.5 = highly correlated, position halved
    """
    if not candidate_returns or not portfolio_returns:
        return 1.0  # No data → assume uncorrelated

    n = min(len(candidate_returns), len(portfolio_returns))
    x = candidate_returns[-n:]
    y = portfolio_returns[-n:]

    # Pearson correlation
    mean_x = sum(x) / n
    mean_y = sum(y) / n
    cov = sum((xi - mean_x) * (yi - mean_y) for xi, yi in zip(x, y)) / n
    std_x = (sum((xi - mean_x)**2 for xi in x) / n) ** 0.5
    std_y = (sum((yi - mean_y)**2 for yi in y) / n) ** 0.5

    if std_x < 1e-10 or std_y < 1e-10:
        return 1.0  # Zero variance → can't compute correlation

    correlation = cov / (std_x * std_y)
    abs_corr = abs(correlation)

    if abs_corr < high_corr_threshold:
        return 1.0  # Below threshold → no reduction

    # Linear reduction from 1.0 at threshold to min_multiplier at corr=1.0
    reduction = (abs_corr - high_corr_threshold) / (1.0 - high_corr_threshold)
    return max(min_multiplier, 1.0 - reduction * (1.0 - min_multiplier))

3. Allowed Actions Computation — The Full Picture

The allowed-actions computation is a pipeline of constraints, each narrowing the set of possible actions:

# Constraint pipeline (each stage can only reduce, never expand)
base_limit = portfolio_value * 0.25          # Stage 1: concentration cap
vol_limit = base_limit * vol_multiplier      # Stage 2: volatility reduction
corr_limit = vol_limit * corr_multiplier     # Stage 3: correlation reduction
final_limit = corr_limit                     # No further reductions

# Example for a high-vol, correlated stock:
# $1M portfolio × 25% = $250K base
# × 0.5 (high vol) = $125K
# × 0.6 (moderate correlation) = $75K final limit

Edge Cases & Error Handling

ScenarioAgentHandling
All 19 analysts disagree — no consensus signalPortfolio ManagerWhen the weighted average of signals is near zero (no consensus), the PM defaults to hold for that ticker. The LLM reasoning will note analyst disagreement as a reason for caution.
Insufficient position data — new portfolio with no historyRisk ManagerCorrelation multiplier defaults to 1.0 (full position allowed). Volatility metrics use a wider lookback window or default baseline values if price history is too short.
Extreme volatility event — ATR spikes 3x normalRisk ManagerThe vol_multiplier drops proportionally. A stock with 6% daily ATR (3x baseline) gets min(1.0, 0.02/0.06) = 0.33, cutting the position to one-third of normal max. This is automatic and deterministic.
Zero cash available — fully invested portfolioPortfolio ManagerAll buy actions have max_quantity: 0. The PM can only hold or sell. The LLM receives this constraint and cannot override it.
Price data unavailable — market holiday, delisted stockRisk ManagerVolatility metrics return defaults (baseline ATR). Correlation cannot be computed → multiplier = 1.0. Position limits use last known prices with a warning flag.
