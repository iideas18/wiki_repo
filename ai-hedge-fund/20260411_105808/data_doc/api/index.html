📚 What is this & why does it exist?

The Financial API client is the system's single gateway to external market data. Every agent's analysis — from Warren Buffett's owner earnings calculation to the technical analyst's Hurst exponent — depends on this layer for prices, financial metrics, insider trades, and news. It wraps the financialdatasets.ai REST API with in-memory caching, rate-limit handling, and Pydantic validation, ensuring agents get clean, typed data without worrying about HTTP details.

💡 Real-world analogy

Think of the API client as a concierge at a financial library. You ask for 'AAPL prices, January to June' and the concierge knows exactly which shelf to check. If they've fetched the same book recently, it's still on the desk — no need to walk to the stacks again. And if the library is too busy (HTTP 429), the concierge politely waits 60 seconds before trying again, rather than pestering the librarian.

Annotated Code Walkthrough: get_prices()

Let's walk through the get_prices() function step-by-step, annotating each section with its purpose and design rationale.

Function signature and cache key construction. The function accepts a ticker symbol and date range. The first thing it does is build a composite cache key — this ensures that different date ranges for the same ticker don't collide.

def get_prices(ticker: str, start_date: str, end_date: str) -> list[Price]:
    """Fetch daily OHLCV prices for a ticker within a date range."""
    cache_key = f"{ticker}_{start_date}_{end_date}"

Cache lookup. Before making any network call, check the in-memory cache. If data exists for this exact key, return immediately. This is the fast path — sub-millisecond.

    cached = cache_get(cache_key)
    if cached:
        return cached

HTTP request with retry loop. On cache miss, issue the HTTP request to the external API. The retry loop handles rate limiting: if the server returns 429, wait 60 seconds and try again (up to 3 times).

    url = f"{BASE_URL}/prices"
    params = {"ticker": ticker, "start_date": start_date, "end_date": end_date}
    headers = {"Authorization": f"Bearer {API_KEY}"}

    for attempt in range(3):
        response = requests.get(url, params=params, headers=headers)
        if response.status_code == 429:
            time.sleep(60)
            continue
        response.raise_for_status()
        break

JSON extraction. Parse the raw response body. The API returns a JSON object with a prices key containing the array of price records.

    data = response.json()
    raw_prices = data.get("prices", [])

Pydantic validation. Each raw JSON record is parsed into a Price model. This validates types and required fields. If the API returns malformed data, Pydantic raises ValidationError — failing fast rather than propagating bad data downstream.

    prices = [Price(**p) for p in raw_prices]

Cache storage with dedup. Store the validated prices in the cache. The dedup_field="time" parameter tells the cache to merge by timestamp — if prices for some dates already exist from a prior overlapping query, they won't be duplicated.

    cache_set(cache_key, prices, dedup_field="time")
    return prices

Design Rationale

Why a Single API Provider?

The system uses financialdatasets.ai as its sole external data source. This was a deliberate choice: maintaining a unified schema across multiple data providers introduces enormous complexity (field mapping, deduplication, conflict resolution). A single provider keeps the API layer thin, the Pydantic models simple, and the cache keys predictable. If a second provider is added in the future, the cache layer already supports key-based routing via the composite key pattern.

Why In-Memory Cache (Not Redis)?

The AI hedge fund runs as a single process. An in-memory Python dictionary provides:

  • Zero serialization cost — Pydantic objects stay as Python objects
  • Zero network latency — no TCP roundtrip to a cache server
  • Simplicity — no infrastructure dependency, no connection pooling

The tradeoff is that cache is lost on process restart. For a system that fetches data at the start of each analysis run, this is acceptable.

Why Pydantic Validation on Every Response?

External APIs are inherently untrusted. Field names change, types shift, new fields appear. Pydantic validation on every response ensures that if the API contract breaks, the system fails immediately with a clear ValidationError rather than silently propagating None values or wrong types into agent analysis.

Deep-Dive Topics

⏱️ Rate Limiting Strategy

The API client uses a 60-second linear backoff when it receives HTTP 429 (Too Many Requests). Unlike exponential backoff, linear is used because the external API's rate window is fixed. After 3 failed attempts, the function raises an exception rather than blocking the pipeline indefinitely. The wait time is intentionally conservative — 60 seconds is longer than most API cooldown windows — to minimize the chance of a second 429.

🔀 Cache Merge Algorithm

When storing data for a key that already has cached entries, the cache doesn't overwrite — it merges. The algorithm builds a set of existing values for the dedup field (e.g., timestamps), then appends only records whose dedup field value is not in the set. This handles overlapping date ranges gracefully: requesting Jan–Jun then Mar–Dec produces a single merged dataset with no duplicate records.

📋 Pydantic Data Models

The 15+ Pydantic models serve as the system's type contract. FinancialMetrics alone has 40+ optional fields (every fundamental ratio you'd find on a Bloomberg terminal). Models use Optional fields extensively because not every company reports every metric. The AnalystSignal model is the output schema — what agents produce after analysis.

Cache Behavior: Second Call Is Free

import time
from tools.api import get_prices

# First call: ~400ms (API roundtrip)
t0 = time.time()
prices1 = get_prices("NVDA", "2025-01-01", "2025-06-30")
print(f"First call: {time.time() - t0:.3f}s")  # ~0.400s

# Second call: <1ms (cache hit)
t1 = time.time()
prices2 = get_prices("NVDA", "2025-01-01", "2025-06-30")
print(f"Second call: {time.time() - t1:.6f}s")  # ~0.000012s

assert prices1 == prices2  # Same data

Error Handling Pattern

from tools.api import get_prices
from pydantic import ValidationError

try:
    prices = get_prices("INVALID_TICKER", "2025-01-01", "2025-12-31")
    if not prices:
        print("No data available for this ticker")
except ValidationError as e:
    print(f"API returned malformed data: {e}")
except Exception as e:
    print(f"API call failed: {e}")
